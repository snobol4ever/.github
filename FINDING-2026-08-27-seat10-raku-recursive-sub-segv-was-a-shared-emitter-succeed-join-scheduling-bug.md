# FINDING 2026-08-27 seat10 — raku-recursive-sub-segv: a shared-emitter SUCCEED-join scheduling bug, not a recursion bug at all

## GOAL (row `raku-recursive-sub-segv`, rank 1, minted ceo 2026-08-27)
Recursive Raku sub SEGFAULTS under m3 (rc=139): `sub fib($n) { if $n < 2 { return $n; }; return fib($n-1) + fib($n-2); } say fib(24);` → rc=139, Rakudo prints 46368.

## ROOT CAUSE, ISOLATED BY ABLATION (ASM-DIFF-FIRST, then a compiled-in diagnostic in place of gdb)
Minimal repro is **not about recursion** at all. `sub h($n) { if $n <= 0 { return 111; } return 222; }` — a pure two-literal if/else, zero calls, zero recursion — was ALSO broken: `h(0)`→111 (correct), `h(1)`→empty, `h(5)`→`2.5e-323` (garbage). Ablation matrix (13 witnesses, `/tmp/rk{A..K}.raku` this session, not preserved): every shape where an `if`'s true-branch does `return X;` and a **further statement follows** in the same block silently drops that further statement's compiled code. `--dump-bb` showed the box graph itself is correct — the bug is in **BB→x86 scheduling**, not lowering.

**Mechanism**, confirmed with the existing `SCRIP_OMEGA_DIAG=1` diagnostic (no gdb needed, per RULES.md's "asm-diff, then gdb" — a compiled-in per-node diagnostic was strictly more precise than a register dump here):

`lower_rblock` (and every other lowerer's block-sequencer — this is a `src/emitter/emit.cpp` mechanism, language-blind) threads the enclosing block's "next statement" continuation down as the `γ` (success) parameter of each statement it lowers. An `if`-statement's true-branch is lowered with that SAME `γ`. So `return 111;`'s own IR-level `γ` — vestigial; `IR_RETURN`'s emission always jumps straight to the proc's real exit port regardless of box-graph wiring — ends up **pointing at the exact same `IR_SUCCEED` join node** as the `if`-test's `ω` (false) edge, which is the **real, load-bearing** path to `return 222;`.

`codegen_flat_chain_body`'s scheduler (`RPO_PUSH`, `src/emitter/emit.cpp`) refuses to enqueue **any** `IR_SUCCEED` node — a blanket exclusion, presumably meant only for the graph's true terminal SUCCEED. Because the shared join is *only* reachable through edges the refusal blocks (RETURN's vestigial edge doesn't count as "reaching" it for scheduling purposes even under the old code, and the test's `ω` edge is refused the same way), `return 222;`'s five downstream boxes never enter the `nodes[]` array. Later, the per-node label-resolution loop's fallback — `if (nodes[i]->γ.node == NULL || ...->op == IR_SUCCEED) node_γ = &lbl_γ;`, and the equivalent for `ω` — treats "my target is a never-scheduled bare SUCCEED" as "this is the end, jump to the proc's exit port" for **any** node, not just RETURN. So the `if`-test's false path jumps straight to the function epilogue with whatever garbage is in rax/rdx, and `return 222;` is never emitted at all.

**Why 724 Raku smoke witnesses never caught this**: none of them apparently exercise "conditional early return, then a further top-level statement" in one block — a narrower shape than it sounds, since `if X {return A;} else {return B;}` (both branches terminal, RK-ZC's own territory) doesn't create the shared-join pattern; only trailing code *after* a bare early return does.

**Why this is shared-emitter, not Raku-specific, and why it survived undetected in six languages**: `RPO_PUSH`/the label-resolution loop are in `src/emitter/emit.cpp`, reached by every frontend. SNOBOL4/Icon/Prolog/Snocone/Rebus/Pascal simply don't (so far as the full regression sweep below shows) hit the specific "early-return-then-more-code, no `IR_STATEMENT_BEGIN` re-seed" combination in their own existing corpora at their current lowering shapes.

## THE FIX (`SCRIP/src/emitter/emit.cpp`, `codegen_flat_chain_body`)
1. `RPO_PUSH`: chase through a bare `IR_SUCCEED`'s own `γ` before the scheduling decision, instead of refusing it outright. A genuinely terminal SUCCEED (`γ.node == NULL`) is an immediate no-op, unchanged.
2. The per-node `gtgt`/`otgt` resolution: same chase, applied after the existing `IR_GOTO`-chase loops (which already do the equivalent thing for GOTO chains) — **except** for the always-exits family `IR_RETURN`/`IR_SUSPEND`/`IR_CORET`/`IR_COFAIL` (already grouped as one family elsewhere in this file, ~line 3342), whose own templates unconditionally jump to whatever this resolves to and must always mean "proc exit". A first version of this fix chased through unconditionally and **regressed** `h(0)` (111→222 — RETURN's own vestigial edge got redirected into the sibling statement) before this exemption was added; caught by immediately re-running the full ablation matrix after the first build, not assumed correct.
3. The `IR_FAIL` fallback for `γ` was changed from testing the raw `nodes[i]->γ.node` to testing the chased `gtgt`, for consistency with the (already-correct) `ω`/`otgt` handling — same shape, no new logic.
