## WHAT HAPPENED TO 2/2
Both dialect versions were already in corpus (`packages/snobol4/aisnobol/upstream/`, 31 files, `ec8714f67`). The graded `NAME.sno` files were the SNOBOL4+ (`.SNO`) versions, which the SPITBOL oracle refuses on dialect: ATN `&FULLSCAN` (274), HSORT its file name from `HOST(0)` (067 when fed stdin), KALAH (160), BUILDLIB (022), SIR/TEST `SNOCORE` (116). Four were filed UNGRADABLE on that refusal and two UNGRADED for a missing include; the suite graded the remaining two, ENDING and WANG, hence 2/2. The `.SPT` versions run clean under the same oracle with the drivers the diskette documents, and under SCRIP four of them already matched byte-for-byte (ENDING, WANG, HSORT with its argument, KALAH).

## THE RE-PIN
The graded set is the `.SPT` versions (PROVENANCE.md records it); `SPITCORE.sno` carries the two documented adaptations; `spitlib.spt`/`spitlib.idx` are the names the core opens; `HSORT.argv` declares the program argument; the package-level `*.IN` drivers were CRLF and are now the LF copies. **The package builder and the harness had no way to grade any of that:** the builder isolated each source as a one-file copy (an include or a data file beside it died as "oracle died") and had no program-argument mechanism; the harness materialised each entry into a bare temp dir. Now (`9870baf69` and this landing) every regular file of the package travels into the oracle's isolated cwd, a `<stem>.argv` sidecar becomes the container's `ALL.argv`, and on the run side an argv token or a quoted literal that names a file beside the suite travels with the entry. The suite's own runner reads `AISNOBOL_BOARD shipped=9 scored=7 excluded=2 m3_PASS=4 m4_PASS=4` (BUILDLIB excluded: no oracle has `SET`/`TELL`; SPITCORE: a module).

## THE ENGINE CURES, EACH WITH ITS WITNESS AGAINST sbl
ATN (four, `80589b7d5`): `INPUT(.X)` with no file set the stream but never bound the variable, so `ATNSOURCE` read the null string forever and ATN looped to ERROR 244 (the probe was `&STLIMIT`: the oracle finishes under 20,000 statements, SCRIP exceeded 800,000); `&STCOUNT` parity, measured per construct: `EVAL`'s wrapper statement was counted, `DEFINE` statements were not, blank lines were, and mode-4 runtime segments never were (the flag now persists through `SCRIP_SNO_STMTKW`, baked into compiled binaries). ATN prints its generated names from `&STCOUNT`, which is why the count had to be exact; it is now byte-identical to the oracle in both modes bar its sixteen timing lines. SIR and TEST (five, this landing): an OPSYN'd unary operator bound to a user function raised 029 (the dispatch needed a C function); binary `%` never consulted its alias; a goto inside a CODE segment to a label the segment defines was bound statically, so the core's loader idiom (a stub that CODEs the real function under the same label and jumps to it) looped forever — in a fragment such a goto is now deferred by name; `DEFINE` read its prototype and entry label as C strings, so a captured substring registered `ABS(X)` as the entry; `OUTPUT(.X)` with no file bound nothing, so every line the core's `PRT.VIA.OUTPUT` wrote vanished. With those, SIR and TEST run the core and the loaded library and print 297 and 380 bytes against 1705 and 14109: **the next bug is inside the LISP reader** (MAPCARV/MAPC receive a STRING where a CONS is expected).

## NOT CURED, NAMED
ATN's sixteen `... milliseconds compile time` lines: no oracle can pin a timing figure; the suite format has no volatile-line declaration (ASK to the ceo, sent). `DEFINE('G(A)', L)` at main level with `L` a pattern capture still registers the overread entry label through the static define site (cap8); the AIS shape (inside a function, el7) is cured. `OUTPUT(.Z, 6)` with no file: the oracle raises 160, SCRIP is silent (pre-existing). Statement-count parity inside a CODE segment that prints its own count is two short (sc7), not on any AIS path. BUILDLIB needs `SET()`/`TELL()` in SCRIP and has no oracle; the diskette's `SNOLIB.IDX` is the only ground truth.
