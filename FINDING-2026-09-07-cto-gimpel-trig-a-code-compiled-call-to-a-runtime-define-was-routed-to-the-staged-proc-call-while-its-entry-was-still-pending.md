## THE CLASS, CUT BY WITNESS
TRIG builds COS and TAN through gimpel's DEXP idiom: `CODE(NAME ' ' PROTO ...)` creates the body at run time, then `DEFINE(NAME ARGS)` with a computed prototype registers the function. Eight witnesses (scratch w1..w8) split the space:
- main-level call to such a function: **works** (COS(0.0) printed `1.`);
- a static body calling it (w2), a CODE body calling a static function (w1), a CODE body plus a *literal* DEFINE at main (w4), a static body plus a *computed* DEFINE (w5, w8): **all work**;
- a CODE-compiled body calling a function whose DEFINE ran at run time with a computed prototype and whose own body is CODE-created (w6, w7, the original): **ERROR 022**.
So the class is: **the caller is a run-time segment and the callee is a run-time DEFINE.** Instrumenting `rt_proc_call_open_p` under `SCRIP_DEBUG_APPLY` showed the staged call finding the callee's proc record with `fn=NULL, dyn_scope=1`, and `rt_ab_undef_fn_stub` is what the staged template jumps to when the open returns 0. No `[apply-err5]` / `[call-err5]` line: the by-name runtime never saw the call.

## WHY MAIN WORKED AND THE CODE BODY DID NOT
`bb_call_route_classify` (emit.cpp) routed **any** `rt_proc_is_registered()` callee to `CALL_ROUTE_PROC_STAGED`. A run-time DEFINE goes through `rt_sno_runtime_define`, which registers the proc with `fn = NULL`, `dyn_scope = 1`, `jmp_entry = 0`; its entry is a *label* that only the BYNAME route resolves, lazily, at call time (`rt_call_proc_descr` → `core_define_entry_label` → `rt_entry_resolve` → `rt_proc_enter_named`). When the static program was emitted the name was not registered at all, so main's `COS(0.0)` took `CALL_ROUTE_BYNAME` and worked. When TAN's segment was emitted, COS *was* registered (its DEFINE had run), so the router chose the staged template, whose `rt_proc_call_open` read the null fn and fell into the stub.

## THE CURE (2 files, +9/-1)
`rt.c` gains `rt_proc_entry_pending(name)`: registered ∧ `dyn_scope` ∧ `fn == NULL` ∧ `jmp_entry == 0` ∧ a DEFINE on record (`core_define_entry_label`). That is exactly the shape `rt_sno_runtime_define` leaves and nothing else: a static define site (`rt_define_site`) sets `jmp_entry = 1`, and an eval segment's own procs get `rt_proc_set_jmpentry` before `emit_chain`. The router returns `CALL_ROUTE_BYNAME` for a pending entry and `CALL_ROUTE_PROC_STAGED` as before for everything else. **The first cut was wrong twice and taught both terms:** without the `jmp_entry` term it rerouted static `SIN` at compile time (its fn binds at load, so it looked pending) and, because a registered name never reaches the router's final BYNAME line, fell to `CALL_ROUTE_FATAL` — `[IBB] FATAL bb_call: unsupported call shape fn='SIN'` in both modes. Hence the explicit BYNAME return and the `jmp_entry` term.
