## 0. The one sentence

An attributed variable is a variable cell with a new tag whose payload points at a heap block holding its attribute term; every site that binds a variable already value-trails the whole 16-byte cell, so binding an attributed variable costs one tag test, one heap cons onto a pending list, and one store to a header word of the trail arena; the lowerer emits, only in a program that uses attributed variables, a wake check at the call port of every body goal and at the clause exit, which drains that list through the ordinary meta-call box; CLP(FD) is SWI's own `library(clpfd)` compiled by SCRIP on top of that, with GNU's `fd_*` spelling as a Prolog layer over the same solver. No new box. No global. No second stack.

## 2. The attributed variable — `DT_PLATTV`, one tag, one heap block

**Today's cell** (`src/ir/descr.h:53-62`, 16 bytes: `v` tag byte, 3 bytes `src_node`, 4 bytes `slen`, 8-byte payload): an unbound variable is `v = DT_PLVAR (0x48)`, `slen` = its slot, `p` pointing at itself; a reference is the same tag with `p` at the target (`src/parsers/prolog/pl_cell.h:22,34`); `DT_SNUL`, `DT_FAIL` and a self-pointing `DT_N` also read as unbound (`pl_cell.h:36`, `by_name_dispatch.c:214`). The highest tag is `DT_EXTL = 0xB8` (`descr.h:13`).

**The design:** `DT_PLATTV = 0xC0`. The cell keeps `slen` = slot and `p` points at an ATTV BLOCK on the collected heap: two DESCRs, `[0]` the attribute term as SWI represents it — `att(Module, Value, MoreAtts)` or the atom `[]` — and `[1]` reserved zero. Dereference stops at a `DT_PLATTV` cell exactly as at a self-pointing `DT_PLVAR`: the variable's identity is the cell's address, never the block's. `var/1`, `nonvar/1`, `pl_cell_unbound`, `pl_is_var`, the asm `.Lun_both_unb` road (`rtx_plunify.s:186`) and every other "is this unbound" test answer YES for it; `attvar/1` is the one test that distinguishes the two. THE READERS ARE A CLASS: the census is `grep -n 'DT_PLVAR' src/ | wc -l` at the landing, and each reader that tests unboundness takes the `DT_PLATTV` arm in the same landing (CEO-556: a defect reachable through one member is a class defect).

**Why the block is on the heap and not in the frame (THE LIFETIME RULE):** `put_attr/3` runs inside a call that returns while the attribute must live as long as the variable, which may be a caller's slot or a heap cell; the datum escapes the scope that created it, so it is heap, allocated through `rt_gcheap_alloc` as a typed DESCR block the collector's visitors walk, and `put_attr/3` enters the allocating table (`scripts/util_gen_gc_allocating_table.py`, regenerated, never merged). The collector gets one visitor arm: a `DT_PLATTV` cell's `p` is a heap reference (a `DT_PLVAR`'s is not).

**Mutation is value-trailed, never a second mechanism.** `put_attr/3` and `del_attr/2` overwrite `block[0]` after `pl_tr_push` (`src/runtime/rt/rt_pl_trail.h:36-39`), exactly as `b_setval` does today (`rt_pl_b_set`, `unification.c:2871-2890`): an entry is `{cell, 0, old 16-byte DESCR}`, undo writes the old DESCR back, so an attribute change, a binding and the tag itself are all restored by the unwind that already exists (`x86_pl_tr_unwind_at`, `x86_asm.h:2085`; the clause retry `emit.cpp:4927-4936`; `.Lun_fail`, `rtx_plunify.s:318`; `rt_pl_tr_unwind_to`, `rt_pl_trail.c:43`). When `del_attr` empties the list the cell is rewritten `DT_PLVAR` self-pointing (trailed), so a variable with no attributes is a plain variable again.

## 3. Binding an attributed variable — the pending list and the wake check

**The bind sites, measured (no single choke point):** emitted inline through `PL_TRAIL` (`src/templates/bb/bb_pl_cell.h:55-79`) at `bb_unify_value.cpp:96-111`, `bb_unify_const.cpp:72-75`, `bb_unify_struct.cpp:88-92`, `bb_call_pl_leaf.cpp:344-348`; the asm leaf `rtx_pl_unify` binds at `rtx_plunify.s:162-166`, `:189-195`, `:208-212`; C binds at `plw_bind` (`by_name_dispatch.c:244`, trailed; `plw_unify_leaf :255`, `plw_unify_oc_leaf`, `plw_bind_x`) and `pl_bind` (`pl_cell.h:50`, UNTRAILED — used by `pl_unify`/`plc_unify_leaf` at `unification.c:1792-1809` and the variable-naming code). `bb_unify_first.cpp` only initialises a fresh slot and never binds an existing variable.

**The design at every bind site:** the write of the value into the cell is UNCHANGED (the old cell, tag and block pointer included, is already in the trail entry). Before the write, one byte compare: `cmp byte [cell], DT_PLATTV; jne store`. On the attv road: cons `wake(Atts, Value)` onto the PENDING LIST — a heap cons whose head is the term `wake(block[0], the value being bound)` and whose tail is the current list — and store the new list into the trail arena's header. `Value` is the other side of the unification: a non-variable, or, when two attributed variables meet, the OTHER attributed variable (the younger cell is bound to the older, the cto's representative row; the hook merges). The asm leaf and the inline sites share one asm helper for the cons, `rt_pl_attv_wake_push` (`src/runtime/rtx/`), which allocates through the same emitted-allocation discipline as every other 4-6 instruction site (RULES.md § LOGIC LIVES IN EMITTED BOXES); C's `plw_bind` calls the same helper; `pl_bind`'s untrailed road is not a binding road for program variables and gets a `_Static_assert`-grade note, not an arm.

**Where the pending list lives — the trail arena header, not a global and not a stack.** The arena (`rt_pl_trail.h:5-13`, 128 MB aligned, top in r12, B in r13) has a 32-byte header whose four words are taken (0 top, 8 ball, 16 the writer's slot vector, 24 the occurs-check mode). The design widens `PL_TR_HEADER_BYTES` to 64 and uses word 32 as `WAKE`: a single pointer to a heap list or 0. This is a single "current X" cell (RULES.md § NO GLOBAL HOLDS A STACK: *"A single 'current X' cell is not a stack"*), it lives in the r12 island Lon keeps, and the list it points at is a Prolog term on the collected heap, LIFO with the unification that built it. THE COLLECTOR VISITS IT AS A ROOT (`core_gc_roots`): a heap value no root walk visits is a collector defect, cured by the root visit, never by pinning. Every unwind that restores cells also stores 0 into `WAKE` — a pending wake-up from a unification that failed is never run.

**The wake check — placed by the lowerer, built from existing boxes.** In a program that USES ATTRIBUTED VARIABLES (the lowerer sees `put_attr/3`, `freeze/2`, `dif/2`, `when/2`, `use_module(library(clpfd))` or one of the GNU `fd_*` names anywhere in the tree after prelude injection), `lower_prolog.c` places `'$wake'` at the α of every body goal and at the γ of every clause (and after every directive goal). `'$wake'` is lowered as the ordinary if-then-else `( '$wake_pending'(L) -> '$wakeup'(L) ; true )` where `'$wake_pending'/1` is a six-instruction asm leaf that reads `WAKE`, fails on 0, else unifies its argument with the list and stores 0; `'$wakeup'/1` is Prolog in `PL_PRELUDE_SRC` (`prolog_parse.c:1154-1807`): for each `wake(att(M, A, Rest), V)` it calls `M:attr_unify_hook(A, V)` through the existing meta-call box (`bb_call_value.cpp:89-134`, `rt_pl_goal_resolve`, `rtx_plunify.s:45`) and then the rest. A hook that fails sends control to ω — backtracking needs nothing new. A hook that binds another attributed variable conses onto `WAKE` again and the same `'$wake'` loop drains it, which is propagation to a fixpoint with the worklist on the heap and the recursion on the machine stack. This is SWI's own protocol (its `$wakeup/1` runs at the next call port); ours also runs at the clause exit so a binding by the last body goal wakes before the caller continues — the one timing difference, named here so a hook with side effects that reads differently under swipl is measured against this paragraph, not bisected.

**Zero cost for every program that is not this one:** a program with no attributed-variable construct emits no `'$wake'` and no `rt_pl_wake_pending` call; the gate greps the emitted `.s` of a fixed non-attv witness for the leaf's name and reads 0 (the instruction, never a comment). The 100% suites of every other language and of Prolog's own ladders are untouched by construction, and the bind-site byte compare is the only cost they carry (one `cmp`/`jne` per binding; measured on the Prolog bench grid at the landing, both angles).

**THIS IS NOT A C→BB ROAD (CEO-1576):** C and asm leaves only write the heap list and the header word; the jump into the hook is made by the `'$wake'` box the lowerer placed. Nothing in C transfers into emitted code.

## 5. CLP(FD) proper — the library, the operators, the GNU layer

1. **Operators arrive with the directive.** Today `op/3` is dynamic at parse time (`register_op_directive`, `prolog_parse.c:1106,1115`, writing `g_uinfix` `:121-129`), but `use_module(library(X))` is skipped (`lower_prolog.c:475,3701`) and a file `use_module` is spliced in only after the main file is parsed (`pl_include_expand`, `:1964`), so its operators are invisible to the parse. The cfo's vendored-library generator emits, beside each library's clause table, its EXPORTED OPERATOR TABLE (clpfd's seventeen `op/3` entries from its export list, `clpfd.pl:77-167`); the parser, on `:- use_module(library(L))`, registers that table at once through the same `register_op_directive` road and marks `L` for injection. One parser change, no body parsed early.
2. **The library is SWI's `clpfd.pl`, compiled by SCRIP** under the cfo's scheme (parsed only when a program names one of its exports; helpers renamed into `'$clpfd_'`; the two compile-time cost gates), after SSU (CEO-1592) and after `apply`, `assoc`, `error`, `lists`, `pairs`. Its `goal_expansion` runs at load (hq_prolog's landed row), so `X #= Y + 1` on integers compiles to arithmetic as under swipl with `optimise_clpfd` true.
3. **GNU's spelling is a Prolog layer in the prelude** over the same solver: `fd_domain(Vs, L, U) :- Vs ins L..U.`, `fd_labeling(Vs) :- label(Vs).`, `fd_labelingff(Vs) :- labeling([ff], Vs).`, `fd_all_different(Vs) :- all_different(Vs).`, `fd_minimize(G, V) :- labeling([min(V)], …)` and so on for the names in § 1; the full-lookahead operators `#=# …` are aliases of the plain ones (GNU's documented difference is pruning strength, never the labelled solutions). `fd_dom/2` prints GNU's domain syntax (`1..3:5..7`) from `fd_dom/2`'s FD set — a measurement item against gprolog, not a guess. A program in GNU spelling is graded against gprolog (`gplc -o bin prog.pl && ./bin`), one in SWI spelling against swipl: ONE ORACLE PER DIALECT, the superset's standing rule.
4. **Not built, by ruling:** a native C or asm propagator. The performance phase (CEO-1562 order (2)) may later emit a constraint whose shape is known at compile time as its own box; the first landing is the library as shipped.

## 7. What this design refuses

- A side table keyed by cell address for attributes (no table the collector cannot walk; no global).
- A per-frame wake slot or a global pending stack (NO GLOBAL HOLDS A STACK; the header word is a single cell and the list is a heap term).
- A new box for the wake check (it is if-then-else + a leaf + the meta-call box; RULES.md § THE PROLOG REBUILD GATE: shared boxes first).
- A C entry that runs the hook (CEO-1576: the box the lowerer placed makes the jump).
- A `--compat` switch or a second operator table per dialect (the superset accepts both spellings; the oracle per dialect grades).
- Desugaring SSU inside a generator (CEO-1592).
