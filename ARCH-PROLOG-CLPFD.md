## 0. The one sentence

An attributed variable is an ordinary self-pointing unbound cell whose `slen` is one exact marker value, living as word 0 of a two-DESCR heap block whose word 1 is its attribute chain; every site that binds a variable already value-trails the whole 16-byte cell, so binding one costs a byte test on the hot road and, on the cold road, an unconditional trail push and one store of a trail OFFSET into a header word of the trail arena; in an ARMED program (one that names an attributed-variable construct) the lowerer places a wake probe after head unification and after every builtin, which hands the trail entries since that offset to a prelude `'$wakeup'` that calls each module's `attr_unify_hook` through the ordinary meta-call box; CLP(FD) is SWI's own `library(clpfd)` compiled by SCRIP on top of that, with GNU's `fd_*` spelling as a Prolog layer over the same solver. No new box, no new tag, no new collector visitor, no global, no second stack, no C road into a box.

## 2. The attributed variable — a flagged self word in a two-DESCR heap block (the cto's, adopted)

**Today's cell** (`src/ir/descr.h:53-62`, 16 bytes: `v` tag byte, 3 bytes `src_node`, 4 bytes `slen`, 8-byte payload): an unbound variable is `v = DT_PLVAR (0x48)`, `slen` = its slot, `p` pointing at itself; a reference is the same tag with `p` at the target (`src/parsers/prolog/pl_cell.h:22,34`); `DT_SNUL`, `DT_FAIL` and a self-pointing `DT_N` also read as unbound (`pl_cell.h:36`, `by_name_dispatch.c:214`).

**The design:** `'$attv_new'` allocates a two-DESCR block on the collected heap (`rt_ws_alloc_descr(2)`; the leaf enters the generated allocating table). Word 0 is `{DT_PLVAR, slen = PL_ATTV_SLEN, p = itself}` — an ordinary self-pointing unbound variable whose `slen` is THE MARKER, the exact value `0x56545441` (`ATTV`), tied to the asm literal in `rtx_plunify.s` by a `_Static_assert`; word 1 is the attribute chain as a DESCR, the atom `[]` or `att(Module, Value, More)` as SWI represents it. (The first draft said "bit 31"; the cto measured that `pl_init_var(v, -1)` writes `slen = 0xFFFFFFFF` on every fresh heap variable — `unification.c:559` and the copier at `:2437` — so a bit test would mark ordinary variables; an exact value cannot collide with `-1`, with a frame slot number, with `DT_N`'s 1 or with 0. CEO-1599.) The program's variable (a frame slot or a heap cell) is bound to word 0 as a reference, trailed like any binding. Consequences, which are the reason this beats a new tag: every existing reader — the C, asm and template derefs, `var/1`, `==`, `compare`, `write`, `term_variables`, `copy_term` — already treats word 0 as a variable, so there is NO READER CENSUS; the collector sees one DESCR block whose word 0 points at itself, so there is NO NEW VISITOR; the `MOD_OP` tag ceiling is untouched. The marker is read only on a DEREFERENCED UNBOUND cell; the audit of every `slen` reader is in the cto's baton QA. `attvar/1` is the one test that reads the marker.

**Why the block is on the heap and not in the frame (THE LIFETIME RULE):** `put_attr/3` runs inside a call that returns while the attribute must live as long as the variable, which may be a caller's slot; the datum escapes the scope that created it, so it is heap, typed, walked by the visitors that already exist.

**Mutation is value-trailed, never a second mechanism.** `'$attv_set_atts'` overwrites word 1 after `pl_tr_push` (`src/runtime/rt/rt_pl_trail.h:36-39`), exactly as `b_setval` does today (`rt_pl_b_set`, `unification.c:2871-2890`): an entry is `{cell, 0, old 16-byte DESCR}` and undo writes the old DESCR back, so an attribute change, a binding and the flag are all restored by the unwind that already exists (`x86_pl_tr_unwind_at`, `x86_asm.h:2085`; the clause retry `emit.cpp:4927-4936`; `.Lun_fail`, `rtx_plunify.s:318`; `rt_pl_tr_unwind_to`, `rt_pl_trail.c:43`).

## 3. Binding an attributed variable — the wake word is a trail offset, the probe is placed by the lowerer

**3.1 The bind sites, measured (no single choke point):** emitted inline through `PL_TRAIL` (`src/templates/bb/bb_pl_cell.h:55-79`) at `bb_unify_value.cpp` (two sites), `bb_unify_const.cpp`, `bb_unify_struct.cpp`, `bb_call_pl_leaf.cpp`; the asm leaf `rtx_pl_unify` binds at `rtx_plunify.s:162-166`, `:189-195`, `:208-212`; C binds at `plw_bind` and `plw_unify_leaf`'s var-var arm (`by_name_dispatch.c:244,255`), `pl_bind` and `pl_unify` (`pl_cell.h:50`; `unification.c:1792-1809`), and the `unification.c` push. `bb_unify_first.cpp` only initialises a fresh slot and never binds an existing variable.

**3.2 The wake word.** The trail arena header is 64 bytes since `b2d227bb4` (`rt_pl_trail.h:7`): +0 top, +8 ball, +16 the writer's slot vector, +24 occurs-check, +32 `PL_TR_CLEANUP_OFF` and +40 `PL_TR_PROBE_B_OFF` (setup_call_cleanup's), so the wake word is **+48, `PL_TR_WAKE_OFF`**, and the header stays 64. It holds the LOWEST TRAIL OFFSET of an attributed-variable binding not yet woken, 0 for none — an offset, never a pointer, so the collector reads nothing new and no root is added; one current-X cell in the r12 island (RULES.md § NO GLOBAL HOLDS A STACK: *"A single 'current X' cell is not a stack"*). A stale wake word after a failed unification only over-scans: the probe reads entries from the offset to the top, and an offset at or above the top is none.

**3.3 At every bind site:** the value write is UNCHANGED (the old cell, flag included, is already what the trail entry records). On the hot road three instructions — `mov edx, [cell+4]; cmp edx, PL_ATTV_SLEN; jne store` (the encoder has no compare of a memory dword against an immediate) — emitted ONLY IN AN ARMED PROGRAM; on the cold road the push is UNCONDITIONAL (`B` zero or not, the cell's address wherever it is: the entry names the binding, its `old` the flagged self word) and the wake word becomes `min(itself, the entry's offset)`; about ten instructions, then the existing store. The asm leaf sends any flagged cell at its three bind points and at both-unbound to `.Lun_restart`, the C road, which does the same. **Var-var:** a plain variable is bound TO the attributed one, never the reverse; two attributed variables bind the first to the second and wake the first with the second as its value (the hook merges, SWI's contract). An unarmed program emits byte-identical asm — the gate is a fixed non-attv witness whose `.s` carries no `attv` arm and no probe (the instruction, never a comment).

**3.4 The probe and the wake-up.** In an armed program the lowerer places an `IR_CLEANUP` sub-kind `WAKE` — `bb_cleanup.cpp`'s PROBE shape, the one setup_call_cleanup landed: `mov`/`and` from r12, `cmp` the wake word with 0, `je` onward — at each clause's body entry (after head unification; for a fact, before its exit) and after every body goal that is not a user-predicate call or a control construct (`=/2` and every builtin). A user call needs no probe after it: the callee's own body-entry probe wakes what its head bound, and its builtins' probes the rest. Inside an if-then-else CONDITION the probe sits BEFORE the commit, so `dif/2` can fail `A = b` and the else arm runs, as swipl's `B_UNIFY_EXIT` does. Non-zero takes γ into the prelude `'$wakeup'/0`: the allocating leaf `'$attv_take'(L)` walks the trail from the wake word to the top, collects `wake(Atts, Value)` for each entry whose `old` is a flagged self word (Atts from the block's word 1, Value the cell's content now), clears the wake word; `'$wakeup'` runs each module's hook in chain order through the meta-call box (`bb_call_value.cpp:89-134`). A hook that fails sends control to ω and the ordinary unwind restores everything. A hook that binds another attributed variable sets the wake word again and the next probe drains it: propagation to a fixpoint with the worklist on the trail and the recursion on the machine stack. THIS IS NOT A C→BB ROAD (CEO-1576): leaves write the trail and the header word; the jump into the hook is the box the lowerer placed.

**3.5 THE DESIGNER'S ONE CONDITION — the unconditional push must not make the arena a fixed limit.** A deterministic propagation loop (clpfd narrowing a thousand domains with no choice point live) pushes an entry per attributed binding that nothing ever unwinds; 128 MB over 32-byte entries is four million bindings and `rt_pl_tr_refuse` is a FIXED LIMIT (ARCH-DYNAMIC-STORAGE.md). `'$attv_take'` therefore RECLAIMS WHEN B IS ZERO: with no choice point live nothing can ever unwind those entries, and every entry from the wake offset to the top was pushed only to be woken (a conditional binding logs nothing when B is zero), so after the walk the trail top returns to the wake offset. With B non-zero the entries STAY, exactly as SWI's trail keeps them: the first draft's "or B's trail mark at or below the wake offset" was UNSOUND (the cto, CEO-1599) — a choice point made before those bindings needs every entry above its mark to restore an attributed variable that predates it, and `IR_BOUND`/`IR_UNMARK` bank B, not a trail offset, while a C leaf's trail mark is local to its call, so nothing else holds one. A deterministic propagation loop under a live older choice point therefore grows the trail as swipl's does; the arena's refusal on that road is the standing row `prolog-exhausting-the-heap-cap-or-the-trail-arena-ends-the-run-where-swipl-raises-a-catchable-resource-error` (hq_prolog, rank 2), not this design's. The cto proves the B-zero reclaim with a witness that runs a deterministic chain of a million attributed bindings under the default `-d` and `-s` without a refusal, and the receipt names the trail high-water mark.

**ARMED** means the prelude injects `'$wakeup'/0`, which it does when the source names `put_attr`, `get_attr`, `put_attrs`, `freeze`, `dif`, `when`, `attvar`, `term_attvars`, `copy_term/3`, `call_residue_vars`, `attr_unify_hook`, `use_module(library(clpfd))` or a GNU `fd_*` predicate (§ 5). At run time (an asserted clause's lowering, mode 4's fresh `g_stage2`) armedness reads whether `'$wakeup'/0` exists in the program, which also closes setup_call_cleanup's named mode-4 gap.

## 5. CLP(FD) proper — the library, the operators, the GNU layer (the cfo's rows)

1. **Operators arrive with the directive.** Today `op/3` is dynamic at parse time (`register_op_directive`, `prolog_parse.c:1106,1115`, writing `g_uinfix` `:121-129`), but `use_module(library(X))` is skipped (`lower_prolog.c:475,3701`) and a file `use_module` is spliced in only after the main file is parsed (`pl_include_expand`, `:1964`), so its operators are invisible to the parse. The cfo's vendored-library generator (`scripts/util_gen_prolog_prelude_libs.py`) emits, beside each library's clause table, its EXPORTED OPERATOR TABLE (clpfd's seventeen `op/3` entries from its export list, `clpfd.pl:77-167`); the parser, on `:- use_module(library(L))`, registers that table at once through the same `register_op_directive` road and marks `L` for injection. One parser change, no body parsed early.
2. **The library is SWI's `clpfd.pl`, compiled by SCRIP** under the cfo's CEO-1473 scheme (vendored verbatim, parsed only when a program names one of its exports, helpers renamed into `'$clpfd_'` by SWI's own reader so data is never renamed, the sync gate and the two cost gates), after SSU (CEO-1592) and after `apply`, `assoc`, `error`, `lists`, `pairs`. Its `goal_expansion` runs at load (hq_prolog's landed row), so `X #= Y + 1` on integers compiles to arithmetic as under swipl with `optimise_clpfd` true.
3. **GNU's spelling is a Prolog layer in the prelude** over the same solver: `fd_domain(Vs, L, U) :- Vs ins L..U.`, `fd_labeling(Vs) :- label(Vs).`, `fd_labelingff(Vs) :- labeling([ff], Vs).`, `fd_all_different(Vs) :- all_different(Vs).`, `fd_minimize(G, V) :- labeling([min(V)], …)` and so on for the names in § 1; the full-lookahead operators `#=# …` are aliases of the plain ones (GNU's documented difference is pruning strength, never the labelled solutions), declared in the prelude's own operator table. `fd_dom/2` prints GNU's domain syntax (`1..3:5..7`) from `fd_dom/2`'s FD set — a measurement item against gprolog, not a guess. ## 7. What this design refuses

- A new DESCR tag for attributed variables (the ceo's first draft; withdrawn 10:1x for the cto's marked self word, which needs no reader census and no visitor), and a FLAG BIT in `slen` (the second draft; withdrawn 10:4x for the exact marker, because `-1` already sets bit 31 on every fresh heap variable).
- Reclaiming wake entries under a live choice point (the second draft's § 3.5 clause; withdrawn 10:4x — those entries are the choice point's to unwind).
- A side table keyed by cell address for attributes (no table the collector cannot walk; no global).
- A per-frame wake slot, a global pending stack, or a heap pending list the collector must root (the wake word is an offset into the r12 island, the trail is the worklist).
- A new box for the wake probe (it is `bb_cleanup.cpp`'s PROBE sub-kind, the prelude and the meta-call box; RULES.md § THE PROLOG REBUILD GATE: shared boxes first).
- A C entry that runs the hook (CEO-1576: the box the lowerer placed makes the jump).
- A `--compat` switch or a second operator table per dialect (the superset accepts both spellings; the oracle per dialect grades).
- Desugaring SSU inside a generator (CEO-1592).
- A trail that only grows under deterministic propagation (§ 3.5).
