# ARCH-RT-CALL-PROTOCOL — design rationale recovered from `src/runtime/rt/rt.c`: the procedure call protocol

**What this is.** `src/runtime/rt/rt.c` is the C side of every procedure activation: the mode-3 outer thunk that enters a graph, the proc registry record, the open/prologue/epilogue leaves an emitted call site runs, the C-to-graph transfer shim, the by-name (dynamic) entry record, and the return-protocol discriminators. On **2026-08-20** commit `e25a5daf` stripped 6,919 comments tree-wide; this file went from 2276 to 1991 lines and lost **156 comment blocks**, most of them a measured contract with a witness program, a killswitch and an alignment argument, which is exactly the text a later reader of an `__asm__` string cannot reconstruct.

Recovered and relocated by **the cto, 2026-09-16**, row `rationale-rt-c`, per `RATIONALE-INDEX.md`. ⛔ **The comments are NOT going back into the source** (RULES.md, one comment form). This document takes the **call protocol** first, by the same criterion as `ARCH-FRAME-LAYOUT-FIXED-CELLS.md`: it is the densest cluster (about 70 of the 156 blocks carry an NCB-1 / GLOBALS-GONE / PROC-CONV / WIRE-STACK / TINY / PL-REGAIN / ICN-* tag), every block is a measured verdict, and it is the spine: the activation frame and the boundary between emitted code and C, which ARCH-ENGINE.md's CALLING-CONVENTION RULING governs. The remainder (the match-time by-name primitives, the B1c mode-4 seam, the AB-2 leaves, GENP in full, and the retired PL-FR-4 and ICN-FR-5 stacks as history) is row `rationale-rt-c-remainder`; until it lands, the raw text is `git -C SCRIP show e25a5daf^:src/runtime/rt/rt.c`.

⭐ **Everything below was re-verified against the LIVE tree (SCRIP `db4a6b1fc`, `src/runtime/rt/rt.c`, 2087 lines, 93 commits since the strip) before being written down.** The recovered text says what its author measured in July and August; the ✅/⛔/⚠ notes say what is true today, and where they disagree, today wins and the disagreement is recorded.

## §0 Vocabulary

- **The staged-args medium.** `g_call_args[CALL_ARGS_MAX]`, a process-lifetime DESCR array every call road writes its actuals into and every prologue reads from (the REGAIN-1 "arg medium" decision). Nothing rewrites its tail (§4, ICN-ARG-NULL), which is why the collector's root walk over all of it is live work for hq_prolog today.
- **Leaf.** A C function that calls no Byrd box: the open leaf selects the protocol and runs the prologue; the epilogue leaves close it. The emitted call site is `open → frame → transfer → epilogue`, protocol-agnostic (§3).
- **Regime.** Whether a proc's EMITTED body is a jmp-entry blob (self-allocating, exits by wire) or a call-regime body (entered by C `call` into a caller-made frame). Recorded on the proc record (`jmp_entry`), never re-derived (§2).
- **Wires.** The γ/ω landing addresses a body exits through. Today they ride a pushed pair at the callee's TOS (§5), not r10/r11 (ARCH-SNOBOL4-RTX.md: the r10/r11 product-wide wire registers are retired).
- **Floater.** The RETURN/FRETURN exit of a dynamic-scope (DEFINE) body, which reads the pair at TOS and pops it (§7).

## §1 `rt_outer_call` and `rt_outer_call_delta0` — the mode-3 entry thunk

**r12, three rulings in sequence.** R12-EXTERN (Lon s173): mode 3's OUTSIDE sets the environment register, the twin of the mode-4 wrapper's `mov r12,[RT_DCAP_TOP]`; the blob no longer self-seeds and every graph assumes r12 = the live pend/dcap top on entry. R12-FREE-1 (Lon 2026-07-29) DELETED that seed to vacate r12 for a frame register; ZW-3 (s23l) REVERSED it: r12 IS the live CAS/dcap top, `rt_outer_call` seeds it from the absolute slot `0x70000000` (`RT_DCAP_TOP == RT_PIN_BASE+0`, locked by a `_Static_assert` in `rtx_init.c` and again in `runtime_eval.c`) and saves/restores the CALLER's r12 across the call (SysV callee-saved).

**ONE-SHOT-BRIDGE-M3 (s22q): the alignment adjuster is 16, not 8, MEASURED not reasoned.** Mode 4's `main` jumps into α having moved 24 bytes (`sub rsp,8` + two pushes), so α arrives at rsp ≡ 0 (mod 16); mode 3 CALLs α through this thunk and the `call` pushes 8 more, so the old `sub $8` delivered α at rsp ≡ 8, an 8-byte skew inherited by every C call the graph then makes. Witness `002_output_integer_literal`: the graph-side `NV_SET_fn` entry measured rsp%16 = 8 in m3 versus 0 in m4, SIGSEGV in glibc `dl_iterate_phdr`'s `movaps` during `gc_static_segs_init`. `sub $16` puts α at ≡ 0 in both modes: the bridge's parity contract became one law.

**`rt_outer_call_delta0` (ICN-FR-5 RESTORE, s238): zero r14 once at program entry.** Icon's `&pos` compiles to r14+1 unconditionally (the `g_scan_regs_live` gate was deleted deliberately: a `?`-less scanning callee runs inline scan primitives on the caller's ambient subject, where the emit-time `in_scan` flag reads 0 but the registers are live) on the stated invariant "outside any scan r14 is 0", which nothing established: at `main` entry r14 holds libc residue and `&pos` read 4304233 (0x41B069). The two original init sites were both gated on `zframe_graph && !icn_cells_graph`, and Z-1 stamped `icn_cells_graph=1` by default, which silently disabled them on every arm. It is a SEPARATE SYMBOL rather than an edit to `rt_outer_call` because that thunk is shared with SNOBOL4/Prolog/Pascal/Raku and the SN4 match family also uses r14: the driver selects this variant for Icon only, so every other language stays byte-identical BY CONSTRUCTION. **ABI hardening (s238-b):** the first cut was `xor r14d,r14d; jmp rt_outer_call`, which RETURNS to its C caller with r14 destroyed; r14 is callee-saved and `rt_outer_call` returns normally (unlike `icn_zf_main_call`, whose `jmp` is correct because its target never returns). `main` allocated r14 zero times at the time, so it did not bite, but the ICN-FR-5 CLOBBER-FIX class had bitten once already; push/pop costs two instructions and removes the hazard permanently.

✅ **LIVE:** `rt_outer_call` is `push r12; sub $4194304,rsp; mov 0x70000000,r12; RTCC inbound load; push rcx; push rcx; jmp *rax`, landing `add $4194304,rsp; add $16,rsp; pop r12; ret`. Two changes since the strip: the `sub/add $16` adjuster became the two pushed landings (the WIRE-STACK pair of §5, both `rt_kw_return_level_zero`), and the thunk reserves **4 MB of ZLS headroom** under the graph (`9e6c187c8`, "zeta-frame-rsp-second-wild-write", matched by the mode-4 main prologue emitters). The parity arithmetic still lands α at ≡ 0: entry ≡ 8, `push r12` → 0, 4 MB is a multiple of 16, two pushes → 0. `rt_outer_call_delta0` is `push r14; xor; call rt_outer_call; pop r14; ret`, the hardened form.

## §2 `rt_proc_t`, the regime record, and the record's baked offsets

- **NPSPLIT (s22w): `nformals` is the FORMALS-ONLY bound** (arg-bind, excess-clamp, dc/slim admissions); `nparams` keeps the full-name-set meaning (save/restore span, pname bound, pad loop). SPITBOL Ch.8: ALL prototype names are saved and null-initialised, only formals bind, excess actuals are evaluated then IGNORED. `nformals == 0` means an unsplit registrant and consumers fall back to `nparams`. APPENDED LAST because the runtime asm bakes the earlier offsets.
- **`rest_kind` names WHAT differs about the variadic tail, never WHICH language asked:** 0 = the DT_DATA list `rt_make_list` builds; 1 = the SOH-joined flat aggregate (Raku's canonical from-slurpy-flat, `List.rakumod:271`) that `.elems`, subscripts and reductions already understand; 2 = nested aggregate.
- **`jmp_entry` (NCB-1d) is the REGIME RECORD:** 1 = the emitted body is a jmp-entry blob, armed by the driver proc loops (= `!is_generator` for table procs), in-process for mode 3 and via the printed startup registration for mode 4; blocks/rules/methods registered outside those loops keep 0 and stay on the call-regime C window. The C transfer functions select the window by THIS recorded fact, never by re-deriving the emit-side predicate.
- **`zstatic` (PS-1b, s151):** 1 iff the proc's blob graph was DEFER/VALUE-free with a known region; default 0 is conservative, so an unregistered proc reads as chain-path safe.
- **`rt_k_level_p` (RTX-FUNC-1): a hidden cell exported through a pointer, and why neither promotion works.** `bb_define`'s α does `k_level++` inline, so the m4 executable must name the cell, and a hidden symbol is absent from the `.so`'s `.dynsym` (every m4 DEFINE-bearing program would fail to link, the `g_cap_gen` class). But the hand-written `.S` reaches `rt_k_level` with a direct `R_X86_64_PC32`, legal ONLY while it is non-preemptible: promoting it fails the `.so` link outright (measured). The hidden visibility is LOAD-BEARING for the in-`.so` asm, so the cell stays hidden and the pointer carries it across the boundary; emitted code pays one extra load and both media use the identical shape.
- **ONE-REG (Lon s119): `rt_proc_register_rec` replays EXACTLY the per-proc call sequence the pre-s119 m4 startup block emitted**, same order, same skip conditions; `_Static_assert`s pin the 64-byte record layout the driver spells in `.quad`/`.long`, so a drift is a compile error, not a silent wrong-field read.

✅ **LIVE:** the asserts hold at `rt.c:428-430` (`fn` at 8, `name` at 0, `is_generator` at 0x4c, `dyn_scope` at 80, `sizeof == 128` for the `shl 7` stride) and the ONE-REG assert at 2069; `rt_k_level_p` at 420; a `gen_region_ft` field was added after the strip. ⚠ The assert messages still name `rtx_call.s`/`rtx_plcall.s`, which were deleted at s55 (§3); the offsets are now consumed by the surviving `rtx_*.s` files, and the message text is stale, not the constraint.

## §3 NCB-1 LEAF SPLIT, GLOBALS-GONE (s55), and the stubs it left

**The split (Lon's one-entry convention).** The dyn-scope call trampoline (V1 `rt_call_named_proc`, V2 `rt_call_proc_direct`, identical 16 steps differing only in how the record is found) was decomposed into two STRICT LEAVES with the frame and the `p->fn` transfer between them, in exactly the shape the emitted call site takes: `prologue leaf → frame (rsp bump) → call p->fn → release → epilogue leaf`. State that must survive the transfer (save base, Σ, want-name, result name, the record) rides a LIFO context stack rather than C locals, so the emitted site needs no ζ grant to hold it. **LIFO is sound BY THE LANGUAGE DEFINITION, not by luck:** SPITBOL's DEFINE saves formals AND locals on a pushdown stack and restores them on RETURN/FRETURN/NRETURN (manual Ch.8), so call nesting and save/restore nesting are the same nesting, which is precisely why an assembly call/ret may carry it.

**GLOBALS-GONE (Lon s55, in-chat: "Remove g_pcall* regardless of who uses them. We do not do that here.").** `rt_pcall_t`, `g_pcall`, `g_pcall_wires`, `rt_flat_wires_t`, `g_flat_ret_snapbuf`, `rt_pcall_grow`, the RTX-4 test accessors, `c_rt_flat_wire_adopt`, `rt_proc_epilogue_body` and the two `rtx_call.S`/`rtx_plcall.S` ports were ERADICATED; linkage rides the wires plus the stack. The leaves that used to read the record became stubs, each carrying an OWED note: `rt_proc_open_fn` returns 0 (fn now rides the open's own return, the rax channel), `rt_frame_prep` returns 0, `rt_jmp_frame_lexprep`/`lexprep2` no-op ("Icon/PL lexical prep OWED a stack-resident record"), `rt_gen_get_fb` returned 0 ("Icon FR-4 resume OWED a stack-resident carrier"), and the `[fb+0]` lift in `rt_proc_call_epilogue_ret` became a pass-through. **FN-RET OPEN (s104):** two consumers of the eradicated `rt_proc_open_fn` (the `rt_dcap_pump` COND flush and `rt_cap_open` IMM) were never migrated, so every computed-name capture transfer loaded `fbytes`, nulled it through the stub and jumped 0; `rt_proc_call_open_fnret` is the s55 rax-channel contract for them (admitted == nonzero == the transfer target).

**ALIAS LAYER COLLAPSED (s180, RT-CONSOLIDATION rung 1, Lon 2026-08-20: "We do not want two versions of the same code to maintain").** The unprefixed hot symbols had been kept alive as thin wrappers over `c_rt_*` bodies, staged for an RTX re-port "when the stack-resident record exists". The staging was retired: the C bodies carry the `rt_*` names directly (one function, one name), and a future RTX port lands as a WHOLE replacement `.S` defining `rt_*` and deleting the C body in the same commit, never a parallel twin. `rt_faildescr` is RTX asm (`rtx_misc.s`) and its C twin was deleted the same rung.

✅ **LIVE:** the stubs are still stubs (`rt_proc_open_fn` 1650, `rt_jmp_frame_lexprep` 1782, `lexprep2` 1787, `rt_frame_prep` 1792, all returning 0 or no-op); `rt_gen_get_fb` and the ICN-FR-5 state stack are gone entirely (Icon's generator resume lives in the ζ-frame regime now, ARCH-ICON-RTX.md). The `rtx/` directory holds no `rtx_call.s`.

## §4 The open leaves: `rt_proc_call_open`, the det family, the slim arm, and the two prologues

- **`rt_proc_call_open` (OPEN LEAF):** finds the proc, selects the protocol, runs the matching prologue, returns the 16-aligned frame byte count (0 = no body, the site's FAIL arm). Args are read from the staged medium. **Cells are resolved ONLY on the dyn path:** `NV_PTR_fn` interns a global cell per name, so resolving on the lexical path would mint spurious globals for the lexically-scoped frontends' formals.
- **`rt_proc_call_open_det` (PL-REGAIN-1 slice A, s100):** the emit-time-resolved det call's fused open: the caller lowered a LITERAL non-dyn callee, resolved its dense registry index at emission (registration order is identical in-process and in the mode-4 startup bake, so the index is stable in both media), and calls with the index: no name, no hash, no separate fn crossing. Guards precede every side effect, so a refuse is side-effect-free.
- **The FUSED DET OPEN family `rt_proc_call_open_det0..4` (PL-REGAIN-4):** the site passes CALLER-FRAME CELL POINTERS (`lea [___+slot]`) and the leaf copies them into `g_call_args`; ONE crossing replaces `{rt_arg_stage × nargs + open_det}`; nargs > 4 keeps the classic stage chain (tak/4 was the ceiling). **ICN-ARG-NULL (s239):** the classic path null-filled `[nargs, nparams)` inside `rt_frame_bind_args`; folding the staging into the open dropped it, so an UNDER-SUPPLIED call left the missing parameter holding the PREVIOUS activation's argument, because **`g_call_args` is a process-lifetime medium and nothing else rewrites the tail.** The Icon ζ-frame installer reads `g_call_args[0..np)` verbatim, so `try(p,a)` against `procedure try(p,a,b)` saw the prior call's `b`, `\b` succeeded, and `atan(x)` silently evaluated as `atan(x, 10.0)`. Each leaf now seeds the tail with NULVCL before the prologue, keyed on the callee record's arity, never on a language.
- **BP-7 SCC SLIM LEAVES (`rt_proc_call_open_slim`):** the static-save-set convention. The emitted static arm does the save-set old-value saves (GVA cell → caller rsp block) and the arg installs INLINE; the leaves carry only the per-call residue (Σ save/restore, want-name, monitor events, k_level, vtmark tidy). `open_slim` runs AFTER the inline saves and BEFORE the installs, and every guard is checked BEFORE any side effect so a 0 return falls back to the classic arm with nothing to undo. `rt_c2b_arm_trap` is the FATAL for "slim open refused at RUNTIME on an fc-armed call site".
- **`rt_proc_call_prologue` (dyn):** NPSPLIT clamps binding at the formals; the save push then null-inits every remaining name, locals included, which is the manual's locals discipline verbatim.
- **`rt_proc_call_prologue_lex` and ICN-VARARG:** a trailing `[]` parameter must receive a LIST of the surplus arguments (`icon-master/src/runtime/invoke.r:105-133`: `nparam<0` marks variable arity, short calls null-pad first). `rt_frame_bind_args` did that; the callee-carves-its-own-frame path never reached it because the two flat installers (`rt_icn_zframe_args_install`, `rt_lcl_proc_args_install`) are plain `slot[i] = g_call_args[i]` copies. Measured: `note("p0")` bound the STRING, so `!a` generated `'p','0'`; `note("x","y")` dropped `"y"`; `note()` bound `&null`. **This prologue is the ONE site holding BOTH the proc record and the true per-call-site nargs (every det open leaf funnels here)**, so normalising `g_call_args` to exactly `nparams` entries here fixes both media by construction. ⛔ **`jmp_entry` is the discriminator and it is load-bearing:** `rt_proc_call_gen_h` calls the open AND then `rt_frame_bind_args` on the same call, so an ungated collapse would run twice and nest the tail list inside itself; generators carry `jmp_entry=0`.
- **PL-DC (REGAIN-1 slice C, s108), `rt_pl_dc_ok`:** the emit-time-resolved DIRECT det call through a per-proc dc stub, ONE slim prep crossing, γ/ω ret-shims, no pcall record; the vtmark lives in a FRAME CELL the stub carved (the FACT RULE "no §10 global"; longjmp-immune for free). Eligibility is the ONE predicate both the site arm and the driver's stub arming read (table facts only; `p->fn` deliberately untested because it is unset at m4 compile time). `LBL__` main-program pseudo-procs are excluded structurally (s119): they are entered only through `rt_chain_enter`, and admitting them tripped the FATAL guard on CODE label transfer. Hatch `SCRIP_NO_DC=1`.

✅ **LIVE:** all present. `open_det0` seeds `[0, nparams)` with NULVCL (line +6 of its body); the VARARG arm is at 1662-1663 gated on `SCRIP_VARARG_TAIL` and `p->is_variadic && p->jmp_entry`; the `LBL__` exclusion at 1467. ⚠ The PL-DC vtmark frame-cell store as recovered (`region_bytes + 32`) no longer greps; the family was reshaped after the strip (`rt_pl_dc_ok` is read from five files), so cite the live `rt_pl_dc_*` bodies, not the recovered arithmetic.

## §5 `rt_proc_enter` — the two-landing transfer shim and the WIRE-STACK pair

**PROC-CONV (R12-FREE rung 2): γ and ω get SEPARATE landings, each statically knowing its port**, so the FAILDESCR sentinel round-trip (the proc-level LAST_OK) is deleted rather than re-derived (the s61 finding: the IR already knows the port; `lower_snobol4.c` routes RETURN to γ and FRETURN to ω; the call regime's `IS_FAIL_fn` round trip was an impedance mismatch, not information). ⚠ **EXACTLY FIVE PUSHES:** SysV 16-byte alignment is load-bearing through the jmp (rsp ≡ 8 at entry, +40 bytes ≡ 0; the blob's 16-multiple `sub rsp,K` carries it), the measured s60 correction. Under rsp frames (R12-ERAD s65) the blob's LIFO exits fully unwind BEFORE the jmp, so both landings arrive at the pre-jmp rsp and the r12 anchor is deleted.

**EXPR-THUNK RESULT (class B, s96):** the γ landing tail-calls `rt_proc_call_epilogue_γ(frame0)`, which returns what it received in rdi:rsi, but every wire-exiting body delivers its value in rax:rdx. Measured: `*(X 'b')`, `*GT(N,3)`, `*IDENT(X,'a')` reached the landing with the right value in rax:rdx and the C caller received whatever rdi:rsi held (the last operand load before the body's final C call), benign-looking null garbage for `*DIFFER(X)` shapes, whose MATCH was accidental. The landing forwards rax:rdx into rdi:rsi. **EXPR-THUNK EXITS (s96):** every emitted body exits through the wires, yet this opener delivered its landings only in rcx/rdx and the RTCC inbound load then seated the CALLER's banked wires last; `S BREAK(',') *DIFFER(X)` unwound cleanly and jumped through wire 0. Both arms seat the landings AFTER the load; a fresh C-entered activation OWNS its ports, and the caller's wires survive in `rtccb` and reload at its own return.

**WIRE-STACK rung 2 (Lon s194: "PUSH <fail_location> PUSH <succeed_location> at the CALLEE").** The C entry road is the one with no template pass site, so rung 1 converted the exits and left this entry speaking registers. ⛔ WHY THE PAIR AND NOT THE REGISTERS: `rtccb` banks r10/r11 and it is a FLAT GLOBAL with NO nesting; an inner activation entered through C overwrites the outer activation's banked wires, the measured M1 SIGSEGV (`r11 = rip = rtccb`). A pushed pair rides this activation's own frame and cannot be clobbered by a nested one. FAIL is pushed FIRST so it lands DEEPER: `[rsp+0]` = γ, `[rsp+8]` = ω, the same order `SCRIP_SLIM_PAIR` and `bb_glue_pass_wires_blob` use. The landing drops the pair (`addq $16`) BEFORE the callee-saves come back, the same 16 on both arms so γ and ω stay depth-symmetric at the epilogue join. It was BUILD-TIME rather than runtime DELIBERATELY: a runtime arm needs a flag variable in the runtime and RULES.md forbids a new global without Lon's grant, so the default build was byte-identical by construction.

✅ **LIVE (`rt.c:1510`):** five pushes, `lea 2f→rcx`, `lea 3f→rdx`, RTCC load, `push rdx; push rcx; jmp *rax`; both landings `addq $16` then five pops, then `jmp rt_proc_call_epilogue_γ` / `_ω`. No `#if` remains: the pair is the only form. `rt_chain_enter` is no longer defined in this file (it survives as the two `_Static_assert` messages in `runtime_eval.c` and as the `LBL__` route name in §4).

## §6 `rt_tiny_record_enter` — the by-name dynamic entry record (s104, ARG CONTRACT CORRECTED s118)

The C twin of the emitted TINY dyn call site, re-measured verbatim from the PASSING two-arg `R('a','b')` asm: the record is FIVE quads `{nargs, γ, ω, argbytes, argbase}` and the ARGS RIDE THE STACK ABOVE THE RESULT CELL IN REVERSE ORDER (last arg nearest, at `[rsp+16]`); the callee computes formal i at `caller_rsp + argbytes − 16i` and NEVER adds argbase, so the arg block is PINNED at `[rsp+16)` and cannot be relocated. s104 to s117 wrote a THREE-quad record AT `[rsp+16]`, on top of the arg block, so a by-name call published `nargs=0` and every formal bound null (the `GOT-` vs `GOT-ab` class); widening the count alone made the callee read the record's γ/ω quads as args (SIGSEGV), which is why the count and the layout had to move together. Contract in: rdi = fn (the sealed `alpha$` cell content), rsi = nargs, args from `g_call_args`. At the jmp: rsp = &result cell, `[rsp+16 .. 16+16n)` = args reversed, rcx = &record parked ABOVE the args. Back: the callee restores rsp, stores the DESCR into the cell and jmps the recorded landing, which re-seats rax:rdx and runs the same NRETURN consult the emitted landings run (`rt_nret_fix_tiny`). The frame is VARIABLE (56+16n), so the landings unwind off rbp, which is NOT in the VM register contract and which emitted bodies never touch or push/pop symmetrically. Alignment: entry ≡ 8, +8 rbp → 0, +40 five pushes → 8, −(56+16n) → 0 at the jmp.

**D-18c (s161): AN UNSEALED CELL IS NOT A TARGET.** `bb_ab_slot_for` initialises every fn cell to `rt_ab_undef_fn_stub` AND the cell allocator mints on first request, so `rt_dyn_alpha_fn`, asking for a name nobody sealed (every EVAL-fragment `EXPR$`/`PAT$` thunk: their chains carry no `<name>_α` label for the seal walk), minted a stub-holding cell and "preferred" it over the LIVE fallback: Error 22 at match time for every deferred call inside an EVAL-built pattern, both modes, beauty's grammar wall. The stub is the allocator's OWN sentinel, so testing against it is exact, not heuristic. **s108 (Lon: "if they need to be on, then turn them on"):** the NRET_CAP/DYN_ALPHA pair default ON (pair on = PASS, off = rc 134); `SCRIP_DYN_ALPHA=0` restores the prior default. **SPELLED-TWICE (s117):** `p->fn` from `rt_define_site` is the GENERIC ENTRY THUNK, the wrong protocol for an emitted body (`rip=_rtld_global`, the OPSYN `&` SIGSEGV); `rt_call_named_proc` takes the same sealed-`alpha$` arm as its sibling `rt_call_proc_descr`, verbatim, gated `SCRIP_BYNAME_ALPHA`. A THIRD by-name path (`rt_proc_enter((void *)p->fn)` at the tail of `rt_call_proc_direct`) was named a suspected twin and left verbatim because no witness reached it.

✅ **LIVE:** the entry at `rt.c:881` is six pushes (rbp + five), `sub 56+16n`, the `g_call_args` copy loop; the stub test at 979 and 1026; the s108 default and the `SCRIP_BYNAME_ALPHA` arm present. ⛔ **`rt_nret_fix_tiny` is now a plain pass-through** (`wn = rt_g_want_name; return rt_nret_fix(r, wn)`): the SN4-CAP-NAME-STRICT s178-c re-arm (want_name re-arming while a real DT_N rode up a two-landing chain, the 17-capture beauty skeleton witness) is gone from this landing; whatever holds that case now is not in this file.

## §7 The return protocols: γ, ω, the named twins, and the two discriminators

- **γ ENTRY is RETURN and NRETURN; ω ENTRY is FRETURN; there is no fifth port** (RULES.md: FOUR PORTS). NRETURN yields a NAME and is a γ citizen (the lowerer routes its node to the same exit as RETURN, the flag riding `rt_g_ret_by_name`). Arriving at ω IS the failure signal (s61 ruling 1); a failing lexical proc returns FAILDESCR (s62 ruling c). ⚠ The call-regime lexical arm was PORT-AGNOSTIC (read `[fb+0]` whether RETURN or FRETURN) and was preserved verbatim pending a ruling.
- **NAMED γ/ω TWINS (s112): the non-slim arm's missing return contract, MEASURED.** The classic `rt_proc_call_open` arm's landings called the bare epilogues, which did nothing but decrement the level and hand back whatever junk rode rdi:rsi, so a DEFINE'd proc reached through that arm returned NULL and NEVER restored its save set. Witness `probe/mon/mon_return_contract.sno`: oracle `R1=5 A=OUTER-A L=OUTER-L`, non-slim `R1= A=4 L=104` (the result lost AND the actual leaking over the caller's variable); manual Ch.8 pp.103-104 verbatim on both halves. Regime-independent (`SCRIP_SCC_OFF=1` reproduced it with GVA fully on).
