## 1. The one coordinate

Every graph that the depth planner (`zd_plan`, emit.cpp) arms has ONE coordinate: the **absolute depth** below the graph's frame base, in bytes. The frame base is where the prologue leaves rsp; rbp points at the frame header and nothing else (e41bf8a6a). For an armed box `i`:

- `K_i = zd_k(i)` -- the bytes the box carves at its α: its own cell (`zd_k_own`, 16 for a value box, 32 for TO, 16 for ARBNO, 0 for a box that carries nothing) plus the FORTH locals homed on it (`zst_s_of`).
- `X_i = base[claim_i] + zout_i` -- the box's **exit depth**: rsp after its carve, the depth at which its γ leaves and at which its β is re-entered.
- `E_i = X_i - K_i` -- the box's **entry depth**: rsp at its α.

A **run** (a claim) is a chain of boxes whose depths are relative to one base; `zd_pl_bases` gives every run of a Prolog or Icon-cells graph an absolute base from the entry in reverse post-order; a run whose base cannot be derived is `known = 0`. § 2 says what that means. THE EXTENSION this page orders: the absolute coordinate is computed for every language's armed graphs (`zd_pl_abs()` returns true for all seven), with SNOBOL4's statement landing kept as the DISCARD edge it already is (§ 1.2); SNOBOL4 reads 100 percent on the relative plan and must read byte-identical asm after the extension, which is the first small roll-out's smoke (CEO-1478).

### 1.1 The three edge laws (SNOBOL4's mechanism, as equations)

For every edge of an armed graph where both ends have a known base:

- **γ into an α** (the ordinary forward edge `i -> j`): `X_i - gpop_i = E_j`. The successor starts at the predecessor's exit depth; nothing is popped on success but what a compile-time-constant `gpop` names (a balanced skip, CEO-1759).
- **ω into a β** (failure to the immediate predecessor `i -> j`): `X_i - K_i - wpop_i = X_j`. The failing box pops ITS OWN carve and nothing else, and the predecessor is re-entered at its own exit depth with its carve intact -- a retry never restores rsp from anything.
- **γ into a β** (a backward γ: Prolog's retry of a choice point, a gate arm's redo, an Icon loop resuming its generator): `X_i - gpop_i = X_j`. The twin of the ω law (hq_prolog's e4301adbf rule 1).

An edge that violates its law is a **planner defect**, never an rbp need. Every Prolog and Icon red of 10-17 and 10-18 that was traced box by box in gdb was one of these (the GATE arm landing 16 bytes shallow; the second if-then-else's else run at depth 0 against its BOUND at 80; the FORTH local homed on a BOUND that carves nothing; the UNMARK popping 0 into a TO that exits at 64).

### 1.2 Discard edges

A **discard** resumes nothing and MAY drop rsp to a saved depth (CEO-1759): FENCE's β, Prolog's cut and the UNMARK that commits an if-then-else or finishes a findall, ARBNO's unbounded record, a SNOBOL4 statement's failure landing (`IR_STATEMENT_BEGIN`, the `zd` reset to 0 per statement), a bounded Icon expression's BOUND/UNMARK that frees its generators. A discard edge restores rsp from a RECORD -- a word in the frame written when the record was made -- and its arrival law is `rsp := record`, checked at run time, not at compile time. The planner marks an edge discard by the target kind and the port name; nothing else may pop by a non-constant. ~~A loop's re-entry into its generator is a discard of the loop body~~ -- **WITHDRAWN 12:4x the same day, the ceo's reading was wrong on both languages** (SCRIP 03cf9aa32): hq_icon measured with gdb that Icon's `every` loop-back POPS THROUGH THE CHAIN -- zd_plan's zdj_on block redirects the body's γ down its predecessors' βs (`zchn`), each popping its own carve, so the generator's β is re-entered at its exit depth; hq_zetas measured that Raku's TO β reads its counter at a fixed rsp distance and loads rsp from no record, so a Raku loop-back with gpop 0 was a REAL defect (`for 1..3 -> $x { print $x }` printed 1), which the skip hid. ## 2. Definiteness: the one test, for every language

A box is **definite** when `E_i` is a compile-time constant on every path that reaches it. The planner carries it per box as `zd_def[i]` (today `zd_xb[i] != INT_MIN`, the known base; hq_prolog's `op_zdef`). Exactly two things make a box indefinite, and they are the same two for every language:

1. **A retaining edge**: the γ out of a call that can return with its callee's frame still live below the caller, because the callee may be re-entered at its β -- in Prolog a CALL_PROC_STAGED to a predicate that retains (`bb_proc_target_retains`), CALL_VALUE, the db-walk TO, catch/3, the soft cut; in Icon a call to a procedure that suspends (`emit_graph_has_suspend`, `rt_proc_is_generator`) and PROC_GEN, when the caller may resume it; in Raku a gather's take. SNOBOL4, Snocone, Rebus and Pascal have none: a SNOBOL4 pattern call's frame is gone before its γ, so every SNOBOL4 box is definite, which is why SNOBOL4 is the model. After a retaining γ the next box heads a run whose base is unknown; `zd_pl_bases` never propagates a base through it.
2. **A push of non-constant size** (call/N's argument block, a VLA-style carve). Nothing after it in the run is rsp-addressable until a discard restores a record.

Definiteness is regained at a discard edge whose record is itself definite (an UNMARK whose BOUND is in a definite run gets the BOUND's depth, the existing `ub` rule). A merge point is definite iff every incoming edge is definite and the laws of § 1.1 agree.

THE TABLE OF RETAINING EDGES is ONE function in the shared planner, `zd_edge_retains(i)`, language-blind in form (IR kind plus the callee fact the lowerer recorded), with one arm per language named above. hq_prolog writes the function and the Prolog arms (its segments landing); hq_icon adds the Icon arms; the ceo the others. Nobody reasons about a language outside that table.

## 3. Lon's two tests as planner facts

Every cell starts on the RSP spine. The planner moves a cell off it only on one of these two facts, and names the fact beside the cell in the census:

- **TEST 1, an OPERAND**: a consumer `c` reads producer `p`'s cell by rsp distance `X_c' - X_p` (the staging read at `g_zd_read`). The distance is a compile-time constant iff `p` and `c` are both definite, or are in the same run with no retaining edge between them. Otherwise the cell is **frame-homed**: the producer also writes its value to its frame slot (`xop_frame_slot`, hq_prolog's R-C) and the consumer reads the slot through rbp. Nothing else is frame-homed.
- **TEST 2, a LOCAL**: a FORTH local is homed on a box `h` (its deepest non-looping common dominator that carves its own cell, `zst_plan`) at absolute depth `L`, read as `[rsp + zabs - L]`. The address is the same at every α and β of the graph iff `h` is definite and every use is definite. Otherwise the local keeps its frame slot and is read through rbp (hq_prolog's R-B). A parameter is a frame slot.
- **THE FRAME WORDS** (the header, BOUND and choice words, act words): `[rsp + off + zabs]` where the box is definite, `[rbp + off]` where it is not (R-A); the predicate's γ/ω/step and clause-retry code, entered from anywhere, read the header through rbp always (R-E).
- **THE THIRD LEVEL** (CEO-1751): the root graph's standing frame holds the global-type things, reached by the link chain; no construct-lifetime cell goes there.

### 3.1 State words: the declaration rule (CEO-1885, ruled by the cto under CEO-1888, 2026-10-22)

A **state word** is a frame word a box keeps beyond its operand cell: a word its own template reads or writes at a port other than the α that wrote it. Lon's rule for it is TEST 2 applied to the box's own state: the word stays in the RBP frame only where no fixed rsp distance reaches it at the port that reads it. Three facts force a state word, and each is a fact of the TEMPLATE, never of the language:

- **address-escapes**: the template hands the cell's ADDRESS to a runtime leaf (a `lea` of a frame cell into an argument register before a `call`) and that leaf reads or writes the cell while the box's child runs. The address must not move; a spine cell below a child's carve keeps its address too, but a child that RETAINS (a generator, a suspend, a retaining callee) can be re-entered at a different rsp, so the escaped address is a frame word. First customer: the Prolog table header (`IR_TABLE_HDR`, ARCH-PROLOG-TABLING-BOXES § 3), whose address the open leaf receives at α and the phase leaves read through the one trailed root cell.
- **beta-read**: the template reads the word at β, γ or ω after a child ran, and the box is not definite there (§ 2). The db generator state of `IR_TO` (`zls_frame_word_why` 2) and the resume word of a retaining `IR_DISJUNCTION` (`zls_frame_word_why` 1) are this class today, decided at lower from the graph's shape.
- **continuation words**: the graph's own resume and step words (the resumable callable's β continuation, the clause alternative's step), frame words by § 3's THE FRAME WORDS line.

Nothing else is a state word. In particular these are NOT, and each is a pre-allocation the owning switch row removes: a literal or global read staged into the frame at graph entry (the FCC tree, `fc_vlit_register`: staged at the box's α instead); a det-leaf call's `call.argv` block addressed by the C callee (address-escapes only while the callee runs and nothing retains across it, so a spine block carved at the call's α serves it); a box whose result is written to its frame key because the planner gave it no spine cell (`op_zres` 0: a placement defect of the regime, cured by the switch, never declared).

**THE DERIVATION.** The list is derived per kind from the template's own reads, never asserted by hand: `harness/scripts/util_template_state_words.py` (LANDED by the cfo, harness e9581ed, 2026-10-22: 28 of 142 kinds derive a state word; `--check` proves drift both ways and stays a census-time check, never a blocking arm, because it is line-keyed) reads every `src/templates/bb/*.cpp` and prints one row per kind and read -- the port (α β γ ω), the form (`RDQ("rbp"`, `FRQ(`, `ZRES(`, a `lea` of a frame cell before a `call`) and the class the form implies -- and `state_word_kinds.tsv` beside it is that output committed, one row per kind with the template file and the line that proves it; the instrument refuses a row whose cited line no longer carries the form. The lowerer declares the same set through `zls_frame_word_why` (shape-decided) or `zls_frame_resident_mark` (kind-decided, at `bb_program_add`), and under the `home_frame` fact (SCRIP 94ae59ccd) the layout lays the resident set first and `x86_zop` refuses at compile time a key the declaration missed. The placement census reads the table as a forcing test: a `home=RBP` on a declared kind with the declared `xfwhy` is **agree**; a declared kind with no home is **test_without_home**; `test_gate_frame_homes_agree_with_lons_tests.sh` grades both. **Four stages, not three.** The parser traverses text into the tree; LOWER traverses the tree into the graph, construct by construct, and never sees the graph whole; the EMITTER traverses the graph into templates, node by node, and decides nothing. The PLANNER is the stage between them: the one pass that holds the whole program's graphs and traverses them as a whole, applying § 1.1's three edge laws with each box kind's cell shape. Nothing in it needs an emitted byte, and nothing in it is a lowerer's business. It lives in `emit.cpp` today (`zd_plan`, 554 lines, 696 `zd_` references beside 27 placement predicates) only because that is where it was first written, and there its numbers exist only inside emission, so the frame map, the GC site table, the ZSM and the census each re-derive or trust them. THE PLANNER STAGE is `src/planner/`: the depth plan (`zeta_depth.c`), the home pass and the layout (`frame_layout.c` moves there from `src/ir/`), the GC site rules, and every consumer of a construct extent; the driver's `drive_slots_all` becomes the planner's entry, run once after every lowerer has finished and before the first template is instantiated: callees mark → home pass → depth plan → layout → site rules. LOWER marks what a construct carries because it is in the source (kinds, extents, state words); the EMITTER reads the plan table and emits. Its result is **THE PLAN TABLE**: per graph, one array indexed by the node's position in `g->all` (never a table keyed by node address), holding for each box its entry depth E, exit depth X, carve K, whether it is definite (§ 2), its home (-1, or the frame offset), whether its edge or callee retains, and its OWNER -- the construct (match, disjunction, bound, scan, generator) whose frame or cells enclose it and whether the box lies inside that construct's fenced region -- and per graph the frame words and the resident bytes. Everything downstream READS the table: the emitter in both modes, the frame map (ARCH-GC § 7), the GC site table (a site's rule is "rsp-based at depth D", or a declared rbp frame -- a match context, a pattern procedure, a state word -- named by the owner column; never an emission-order counter: SCRIP dbcfad57b is the last cure of that counter), the ZSM's declared values (§ 3.3), the placement census and the watch. `IR_t` does not grow (the PEERS rule stands); the facts live in the table.

**The IR's missing fact.** As a traversal structure the graph is proper: every pass we need is a walk over its edges and registry facts. As a carrier of the memory-model facts it is not: it does not say which boxes belong to which construct, and every emission-time reconstruction of an extent is where the shape-by-shape cures land (`emit_gc_match_reaches` rebuilt a match's extent and took the match's failure exit for its interior; the 27 predicates rebuild retention; `IR_release_scope` rebuilds a release range). - `pl_frame`, `emit_pl_frame()`, `zls_g_pl_frame()` -- "a resumable callable with a frame" (`resumable_callable && zframe_graph`) minus Icon. Icon's generator procedures are resumable callables too; ONE MECHANISM (CEO-1755) means the two become one fact and the minus goes.
- `icn_cells_graph`, `icn_retain` -- the planner's Icon arms. They exist because the planner cannot see the two kinds of boundary that differ between languages: a call that may return with its frame live (a retaining edge) and a statement landing (a discard that re-bases). THE CURE IS § 2's ONE TABLE MADE IR: lower emits an explicit boundary box at each retaining edge and marks each statement landing; zd_plan reads those boxes and no language flag, and most Icon and Prolog arms collapse into the one algorithm.
- The statement-shape tests -- read the statement landing box instead.

**THE ORDER** (LARGE CHUNKS): (1) the ratchet, landed; (2) the boundary boxes in lower for all seven languages, the planner reading them beside the flags, every core byte-identical (the ceo's landing, the § 2 table's natural home); (3) each spine HQ re-cuts its arms to read the boxes, hq_prolog the Prolog arms, hq_icon the Icon arms, hq_zetas the rest, each landing lowering its floors and proving every core byte-identical outside the language it moves; (4) the flags deleted, the gate's banned list grows. The conversion row's DONE-WHEN is the ratchet's total at 0.

## 6. What this page forbids

A third stack, a frame marker, a side-car ledger, an mmap frame store, a pre-carved maximum, a per-language branch in the emitter outside `zd_edge_retains`, a retry that loads rsp from a saved word, a cell moved to rbp for any reason but a named TEST-1 or TEST-2 fact, a cure that changes the plan for one language while another's asm moves without a telegram. Each is already law; this page only names the place in the planner where each would have to be written, so the review can read it.
