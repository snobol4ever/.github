## ⛔⭐⭐ THE MODEL — READ BEFORE ANYTHING ELSE. IT IS THE ONE THING SESSIONS KEEP GETTING WRONG. (Lon, s21x-r)

**THERE IS NO GRAPH FRAME. THERE IS NOT SUPPOSED TO BE ONE. NOT ONE PROGRAM REQUIRES PRE-ALLOCATION.**

Every BB, without exception: **allocates its own storage at α** (one `sub rsp, K`, K = a few bytes, *its own*) · **reads and writes ONLY its own cell** (never a slot someone else allocated) · **releases at γ/ω** · **jumps**. Boxes are wired statically (label/rel32) or, where the target is data, dynamically (indirect through a cell). **That is the entire execution model.** No pre-allocation, no whole-graph carve, no prefix-summed prologue, no zero-fill, no layout pass, no "region."

⭐ **THE ONE REFINEMENT, and it is Lon's own (s21x-y): a C-STYLE RBP, USED OCCASIONALLY.** The value spine rides RSP FORTH-style; the housekeeping that must survive an unwind rides a depth-immune RBP base. That is not a retreat from the model — it is law 4. ⛔ CORRECTED s22s from the source (emit.cpp:2695 STF-UNFLIP, s22b Lon directive — this paragraph had gone stale exactly the way the stale-assertion law predicts): `flat_stmt_frame` default is OFF (`SCRIP_STMT_FRAME=1` = opt-in); the per-STATEMENT bracket was a MODEL ERROR — law 4 licenses RBP for CONSTRUCT housekeeping that must survive an unwind (ARBNO/FENCE1/CALL), never one bracket per statement, and `op_zgpop` (the statement-terminal free) is the SOLE release authority. `bb_match_head`'s HKQ(k) arm exists but is dormant by default. **The sanctioned RBP class is CONSTRUCT HOUSEKEEPING — never the value spine, never per-statement ceremony.**

**THE WHOLE-GRAPH CARVE IS A CORPSE, NOT INFRASTRUCTURE.** `flat_frame_bytes` is debt; so are the ~1054 `FR`/`FRQ`/`FRQB` reader sites across ~109 templates. They are what is left of the pre-BB world, running *alongside* the per-BB cells. The job is not to reason about the frame, tune it, shrink it, or decide which constructs "need" it. **The job is to delete its customers until it has none, then delete it.**

### ⛔⭐⭐ HEAD RUNG — CARVE-ERAD (Lon directive, stated three times)

⭐ **THE ~1054 `FR`/`FRQ`/`FRQB` READER SITES NEED ZERO EDITS.** They resolve through ONE function carrying BOTH authorities on one line — `x86_asm.h:373 x86_frame_off()` returns `off + op_flat_disp + op_zdepth`, where `op_flat_disp` is LOWER's STATIC prefix sum (the carve's address side) and `op_zdepth` is the live per-BB side. **Delete the static term and every reader converts for free.** ⛔ Converting templates by hand (109 files / 1054 sites) was proposed twice and is WRONG both times — that is the failure mode this section exists to name.

**MANIFEST:** `flat_frame_bytes` 31 sites · `op_flat_disp` 24 · carve/`jcon_value_region` emission 7 · `x86_frame_off` 1 line.

⛔ **ORDER MATTERS — ONE OPERATION, NOT THREE:** (1) the per-BB address authority must be complete FIRST; (2) drop `op_flat_disp` from `x86_frame_off` and delete its 24 sites; (3) delete `flat_frame_bytes`, the 7 carve sites, and the exclusion list together. ⚠ **DO NOT cut the sites before (1) covers their readers** — deleting the static authority under unconverted readers regresses programs with no path back to green, and a half-finished eradication is the one outcome worse than the frame existing.

✅ **STEP (1) IS NO LONGER "MAKE `op_zdepth` A RUNNING SUM" — THAT SPELLING IS FALSIFIED AND SUPERSEDED (s21x-u/v).** A single depth CANNOT express an operand offset: two consumers at different depths reading one producer need different constants, and only the DIFFERENCE is invariant. The landed mechanism is `op_zread[k] = δ_out(consumer) − δ_out(producer)`, staged per consumer per operand by `zd_plan`. Four sessions refined a single depth before this was seen; do not restart that path.

### ⛔ THE FAILURE MODE, NAMED — one session hit every one of these

- **Treating the frame as a design element to reason about.** It is legacy. A rung that asks "which constructs need the frame?" is already wrong.
- **Clamping/removing the carve while readers still address into it, then reading the breakage as necessity.** TAUTOLOGICAL: shrink the backing store, unconverted readers fault. That run got 38 failures and concluded "38 programs still NEED the carve." **VOID** — the 38 is a DEBT COUNTER naming boxes nobody has converted yet.
- **Inventing an architectural rationale for the debt.** The claim that Ch.18 backtracking "needs a stable base to unwind to" is **WRONG**: backtracking is the FOUR PORTS plus LIFO per-box claim/release. A suspended box keeps its own cell and re-enters at β — that is all "unwinding" is. (`test_icon.c` is the reference embodiment: state in the per-box ζ block, fresh per α-entry, code shared.)
- **Misreading law 4's RBP constructs as licensing a GRAPH frame.** They name which BASE REGISTER a construct uses for its OWN housekeeping. Law 1 forbids a graph frame outright.
- **Mistaking the SPELLING sweep for the CONVERSION.** Closing the ζ-spelling sweep (raw rsp → `x86_zclaim`/`x86_zrelease`) is sound but is NOT conversion.

### ✅ THE ONLY DISCRIMINATING TEST

An experiment that removes the carve proves nothing while readers remain. **The discriminating move is the converse: convert one box's readers to its own cell, then watch the carve requirement DROP.** Progress = monotone decrease of the declined-statement census; each decline names the box it waits on. **COMPLETION GATE:** the census reaches zero → DELETE the carve and `flat_frame_bytes`; do not shrink them.

**WHY IT KEEPS GETTING MISREAD:** the frame is present in every `.s`, so it looks like infrastructure holding the program up. It is a corpse the new machinery runs beside.
