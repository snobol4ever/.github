## 1. The mechanism, measured twice — runtime drift and the plan's own arithmetic, agreeing to the byte

`zd_plan` (`emit.cpp:2503`) is a per-node scalar `zout[i]` filled by a single forward accumulator. A join reachable at two depths gets ONE fixed pop. Two shapes, one cause:

**Shape A — cross-run (sieve.pas).** The outer back-edge i=72 emits `add rsp,384`, calibrated for the long inner-loop path (400 deep, popping to i=31's entry depth 16). The short path — test i=38's ω → i=69 — enters the SAME ω-head run (h=65, seeded at `zout[49]=304`) at depth **0**, because 38's pop was computed in pass 0 while 69 was still unarmed and fell to pop-to-base. It then pushes 48 and meets the same 384 pop: **352 short per outer iteration**.
Runtime witness (gdb, `setarch -R`, break at `n31_var_bx`): rsp at successive arrivals `0x…df50, e0b0, e210, e370 … efd0, f130` — **+0x160 = 352 every iteration, 22 arrivals, then SIGSEGV** at `mov [rsp],rax` with rsp above the stack top. Bracketing the back-edge: steady state entry `e0f0` / back-edge `df70` (exactly 384 below); the drifting iteration reaches the back-edge at `e0d0` (32 below) via box 39's early exit, and `add rsp,384` lands at `e250`.
The planner's own census (`SCRIP_ZD_DEPTH=1`) names it: `WALL flat i=69 preds=16 first_depth=0 … zout=368` with preds 34–38 at depth 0.

**Shape B — in-run (bubble.pas, seat09's Site 1).** Test i=89's ω skips FORWARD IN THE SAME RUN to i=110 (`rpos` 18 → 39). In-run targets are `oin=1` → no pop; the ω port pops the own cell (`bb_glue_flat_leave`) and nothing else, so it arrives at its own exit depth **256** while 110's planned entry is **544** (`zout=560`, K=16). 110–112 push 48 → 304; the back-edge's fixed **512** then over-pops by **288 = 0x120** — exactly seat09's measured constant when the swap is skipped.

**hq_C's open question is answered:** seat05's +352 / +704 quantization is 1× / 2× of *which predecessor arrived* — the short arm — and that arm is statically the non-pushing one, so normalization is arithmetic, not analysis.

## 2. The cure already existed, scoped to one edge

`zd_plan`'s final block (`if (_zvd) { for … if (!zon[i] || !zvd_ok[i]) continue; …`) already re-derives an edge's pop so it lands at the target's planned entry depth — that is what emits `add rsp,-16` into n65 today. It ran only for the **one** `zvd_ok` test node that seeded an ω-head run. Every other edge into that run kept its pass-0 pop. **Census scoped to the wrong field, again** (RULES thirteenth batch).

- **Arm 1:** `if (!zon[i] || !(zvd_ok[i] || _zn)) continue;` — the final pass now covers every armed node's cross-run exit edges — **normalizing only to a target whose planned entry depth is > 0** (a mid-run node or an ω-head run seeded above base). Killswitch `SCRIP_ZD_NORMALIZE=0`.
- **Arm 2:** after `if (!zoin[i]) zwpop[i] = …` add `else if (_zni && oback >= 0 && claim[oback] == claim[i] && rpos[oback] > rpos[i] && !port_sz_beta(nodes[i]->ω.sz)) zwpop[i] = (zout[i] - K) - _obpre;` — an ω edge that is in-run, FORWARD, and lands on α is normalized; backward edges (backtracking) and β resumes are deliberately untouched (their protocols expect what they get today). A behavioural predicate, not a language or op filter. Killswitch `SCRIP_ZD_NORMALIZE_INRUN=0`.

### 2a. The first cut regressed SNOBOL4 — roman.sno core-dumped in both media — and the cause is exact
