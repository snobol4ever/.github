### The single biggest remainder item is not runtime cost at all — it is `main` and ~405 sibling BB-port labels being invisible to callgrind

`objdump`/`nm` on the compiled `.bin` show address `0x401276` is exactly where `main` begins, immediately followed by every Byrd-box port label the compiler emits for this program in sequence (`n0_statement_begin_α`, `n1_lit_integer_α`, … `STRING_MANIP_α`/`_γ`/`_ω`, … through the harness's own compiled statements) — **405 `NOTYPE` local symbols**, confirmed via `readelf -s | awk '$4=="NOTYPE"'`. Cross-checked against the `FUNC`-typed symbol list (`readelf -s | grep FUNC`): `main` itself is **absent** — every real, `.type foo,@function`-declared symbol in this binary is either glibc/ld-linux machinery or a named `libscrip_rt.so` runtime entry point (`rt_add`, `rt_call_arr_bl`, `NV_GET_fn`, …). **None of the compiler's own emitted BB-port labels carry `STT_FUNC` type or a `.size` directive.** Consequence: callgrind cannot subdivide "the user's own compiled program" into anything finer than one opaque span starting at the last real `FUNC` symbol before it (`frame_dummy`) — every instruction belonging to every statement in the ENTIRE program (not just the `ZBL` loop) collapses into one bucket, displayed as `???:0x0000000000401276` because callgrind found the address but the name lookup came up empty (the label at that exact address, `main`, is present in the symtab but untyped, which the annotator apparently does not trust as a function boundary the way it trusts `FUNC`-typed symbols).

**This is a general, project-wide measurement gap, not specific to `string_manip`:** every kernel ever profiled with `callgrind_annotate` under this build has had ~9%+ of its instruction count (whatever fraction the compiled program's own glue/dispatch/loop-control code represents) silently folded into one unreadable line, with no way to tell how much of it is loop overhead vs. call-site argument marshaling vs. relational-test/branch code vs. something inefficient. It is real work (confirmed genuine SCRIP-compiled x86, not an artifact — spot-disassembled a neighboring statement range, `0x401453`–`0x401585`, which decoded cleanly as the `&STLIMIT = -1` setup statement's compiled box wiring), but **"check before assuming it's all irreducible" cannot currently be answered for this piece at all** — there is no tooling to zoom in. **New row minted: `callgrind-opaque-bb-labels`** (below) — this is squarely a row-factory find: fixing the emitter to attach `.type`/`.size` to BB-port labels (or an equivalent valgrind-side fix) would unlock fine-grained self-cost attribution for every future perf session on every kernel, not just this one.
