## Root cause (SCRIP, `src/runtime/pattern_match.c`)

`rt_defer_get_pat_dtp` / `c_rt_defer_open` / `rt_defer_run_all` / `patv_slot` resolve a
by-name deferred pattern reference (`*Name` where `Name` is a variable holding a pattern) via
the **ordinary** `NV_GET_fn`. Since HQ-61's `SCRIP_KWSPACE_SPLIT` ruling, declared `&`-constants
are tagged `is_const` and **filtered out** of the ordinary walker — they live in keyword-space,
reachable only via `NV_KW_GET_fn`. None of these four functions were migrated when that split
landed, so a deferred reference to a declared-constant **pattern** (`*&Name` — exactly the idiom
beauty's WAVE-1 conversion uses everywhere, e.g. `Stmt = *Label`) silently found nothing, fell
through to a lesser fallback (`rt_defer_run_all`'s own internals), and **any match-time
`. *Fn()` capture-call embedded in that pattern's construction was dropped**.

beauty's `Parse = nPush() ARBNO(*Command) ("'Parse'" & 'nTop()') nPop()` depends on exactly this:
`nPush()`/`nPop()` are the CN-5 compiler-primitive family whose whole job is a match-time
capture-call (`epsilon . *PushCounter()`). Converting `Parse` alone (bisected via
`gen_beauty_c.py` with a truncated WAVE1 list against the trivial input `"START"`) was sufficient
to reproduce total parse failure on the smallest possible input.

**Minimal witness** (root-caused via ASM-DIFF-FIRST, one-token source diff `&Parse5` vs
`Parse5`, diffed `.s` down to the exact runtime call): `corpus/probe/cn/cn_defer_pushcounter_capture.sno`
— `depth=0` (wrong, capture dropped) vs `depth=1` (correct) before/after the fix.

**Fix:** a shared `rt_defer_nv_read()` helper checks `NV_CONST_ASSIGNED_fn` first and reads via
`NV_KW_GET_fn` for declared constants (mirroring the existing idiom at `keywords.c:368`), else
falls back to plain `NV_GET_fn`. SCRIP commit (post-rebase hash) `dac65d47`.

**Same-class, NOT fixed this session** (flagged, not silently left, per the no-per-op-filter
rule — these are the same mechanism, just not reachable through beauty's own construct set, so
not verified against a live symptom): the ASM veneer `rt_defer_get_pat_fn` in `rtx_match.S` has
the identical by-name-only `NV_GET_fn` call; `rt_subject_load_nv`/`rt_concat_parts_d`/
`rt_patv_freeze` (general by-name variable reads elsewhere in `pattern_match.c`) share the same
shape. Next seat touching SN4-CONSTANTS: check whether any of these are reachable with a
declared-constant argument before assuming the class is closed.

## The second, independent problem: the checked-in text was never a fixed point of its own engine

Both `beauty_c.sno` (the staging copy) and the promoted `beauty.sno` were generated by a regex
transform that only **inserts** `&` characters — it never recomputes the `ppStop` tab-column
padding beauty's own pretty-printer derives from identifier width. The other seat's commit
`53dd9ac0` added a targeted compensation (trim one padding space at defining occurrences), which
fixed most cases but not all: neighbouring *protected-keyword* lines whose shared alignment
column shifted, and lines that now overflow the wrap margin by one character and need a
continuation the hand-authored text never had.

**Cure (same methodology as the s117 ruling for classic beauty.sno):** run the file through its
own engine and check in what comes out, iterating to a stable point. `gen_beauty_c.py` now does
this automatically for `beauty_c.sno` (self-beautify pass, refuses to check in a non-fixed-point
result). `beauty.sno` itself was corrected by hand this session the same way (one pass reached a
stable, idempotent fixed point) — corpus commit `336f49d2`.

⭐ **UPDATE, same session:** HQ already has a far more precise lead than this section's raw
