## The claim

After: hq_P's `traceback.icn` prints byte-identical to its `.std` in both modes — `main()`, six `foo(n) from line L in traceback.icn` frames with the parameters' CURRENT values, and `{1 / 0} from line 11 in traceback.icn` last.

## The mechanism, measured (ASM-DIFF-FIRST on traceback.icn's mode-4 `.s`)
1. **The runtime knew no activation.** The prologue's entry tap (`rt_trace_call_hook_f(name, arity, frame base)`) was emitted under a `g_trace` guard, so with `&trace` off it never ran; the only unconditional entry-side facts were `rt_icn_zframe_args_install` (no name) and the inline `rt_k_level` increment. The tap is now unconditional for kind 1 (the guard moved into the hook) in both emitters (`emit.cpp` `icn_trace_tap`, `xa_flat.cpp` `xa_icn_trace_tap`), and the root graph gets the same tap as `main` (its level is 1, no increment). The hook writes `{name, base, np, caller line, caller file}` into a `static` table indexed by `rt_k_level` — the exit-side decrement the epilogue already emits IS the pop, so no exit hook and NO NEW GLOBAL. `g_line`/`g_file` at tap time are the caller's, because the callee's first line mark runs after the prologue: that is exactly icont's `from line N in file`.
2. **Builtin frames** (`repl("x",-1) from line 2 in w4.icn`, no `{}` line): `rt_call_arr_impl` pushes a C-stack record around `try_call_builtin_by_name_bl` only (a proc dispatched by name records its own frame at level+1 and must not appear twice); the wrapper restores the chain at its error-to-failure landing.
3. **The operator reaches the sink three ways.** (a) The Icon lowerer's `IR_COERCE_NUMERIC` code word carries the binop and which operand is self (`descr.h` `COERCE_OP_TAG/OP_OF/SELF_RIGHT/UNARY_NEG/UNARY_POS`, bits 32+; `x86("mov","rcx",long)` already encodes imm64), so `c_rt_coerce_num2_d` names `{"abc!" + 1}` and `{-"q"}`; (b) `rt_num_arith_impl` sets the context on its slow path and clears it on return and at both setjmp landings; `rt_div`/`rt_mod`'s fast zero sinks go through `rt_div_zero`, which under the Icon identity raises 201 (no value) or 202 with the 0, as iconx does; (c) the relational sink names its own.
4. **One printer** `core_icn_traceback` serves both Icon sinks (`core_runtime_error`'s Icon branch and `core_icn_error`); the offending value and every image go through the 16-char string truncation icont uses (`"abcdefghijklmnop..."`); 204 prints no offending value (icont: none).
