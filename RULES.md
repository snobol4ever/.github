## ⛔ THE MAIL CHANNEL — WHAT THE HOOKS ACTUALLY DELIVER (hq_C + hq_P, 2026-08-23 s261, verified both ends)

⭐ **THE COMA IS CLOSED AT BOTH ENDS, AND IT IS CLOSED BY THE HARNESS, NOT BY A SEAT'S INTENTIONS.** Two hooks in a seat's `.claude/settings.json`: **`UserPromptSubmit`** runs `s4e_inbox_hook.sh` and prints unread senders + subjects **above the seat's first tool call**, and the **`Stop`** hook fires `s4e_msg.sh banner`, which **also reports unread**. So mail is surfaced **before a seat starts work and again before it goes idle**. ⛔ The hook prints **headers only, never bodies** — piping `check` straight in costs ~10k tokens every single turn and trains a seat to skim past the thing it exists to surface.

⛔ **BUT "IMMEDIATE CHANNEL" OVERSTATES IT, AND THE OVERSTATEMENT IS NOW MEASURED.** `UserPromptSubmit` fires **only on prompt submission**, so it **cannot see mail that arrives mid-turn**. A message sent to a seat already working sits unread until that seat either finishes (Stop banner) or happens to run an `s4e_msg.sh` command — `send` prints an unread banner as a **side effect**, which is what actually caught Lon's own delivery test, i.e. the catch was **lucky rather than designed**. ⭐ **The honest guarantee is therefore ONE TURN OF LATENCY, NOT IMMEDIACY:** nothing interrupts a running seat, and turns can run very long. That is a bounded, acceptable delay — but do not write, or believe, that THE LOOP step 1 delivers a message *now*. True mid-turn delivery would need a different mechanism than either hook.

⭐ **AND THE REASON THIS IS A RULE AND NOT A NOTE:** a queue-depth or empty-mailbox check measures the **PRODUCER** and can never see the **CONSUMER** — an empty mailbox and an unread mailbox read identically. **PRESENCE IS NOT PROOF.** The only sound readiness condition is a **round trip**: a message sent to a running seat is *demonstrably read*, evidenced by a receipt.

## FACT RULES (each: rule + enforcement; shared LIMITATION at end)

- **⛔⛔⭐ FACT RULE — THE LENGTH IS CARRIED, NEVER MEASURED: NO `strlen` ON A DESCRIPTOR'S `.s` (Lon, in-chat 2026-08-30).** Verbatim in substance: *"Remove all strlen on the DESCR .s that is totally INVALID and not performant. A NUL character is a valid string element."* ⭐ **BOTH HALVES ARE LOAD-BEARING AND THE FIRST IS THE ONE THAT BITES.** **INVALID:** SNOBOL4/SPITBOL strings are **COUNTED**, so NUL is an ordinary member of `&ALPHABET` and a value may legitimately contain one — `strlen` answers a question about *C strings*, not about our values, and it **truncates at the first embedded NUL**. **NOT PERFORMANT:** it is an O(n) rescan of bytes whose length was already known to whoever built the descriptor. ⛔ **THE `slen == 0` "ASK strlen" SENTINEL IS RETIRED — `slen == 0` MEANS THE VALUE IS EMPTY.** A value with an embedded NUL must be built with `BSTRVAL` (explicit count); `STRVAL`'s contract is and always was *"this argument is a C string"*. ⭐ **THE CURE IS AT THE CONSTRUCTOR, NOT AT THE CALL SITES — this is the transferable part:** `STRVAL` measures **once**, where the C string enters, and carries the count in; `descr_slen` only READS it. That fixed **260 construction sites with zero edits to any of them**, and for a string literal `__builtin_strlen` constant-folds, so the carried form is **strictly cheaper than on-demand `strlen` as well as correct**. ⛔ **A LATENT DEFECT THIS EXPOSED, and it is the shape to look for elsewhere:** `pattern_match.c:321` called `strlen(arr.s)` with **no `.slen` consultation at all**, so a counted string with an embedded NUL — *or a slice-backed capture, which owns no terminator* — got the wrong length. An on-demand `strlen` is not merely redundant beside a carried count; where the count was never consulted it is a wrong answer waiting for the right input. ⚠️ **THE ONE SURVIVOR, NAMED RATHER THAN PAPERED OVER:** `slen == 0xFFFFFFFF` is the **CSET TYPE TAG**, not a length, so a cset has nowhere to carry a count — its authority is `kw_cset_len`, and a cset whose member set includes NUL is a separate representation question this rule does not settle. ⭐ **The hand-written asm needed no change and that is worth knowing before anyone edits it:** `rtx_icnagg.s:44` already *delegates* the `slen == 0` case to C rather than implementing `strlen` itself, so fixing C's authority fixed both. **ENFORCEMENT:** SCRIP `85b877d4` (hq_P).   - ⛔⛔ **NEVER ATTACH `FASTER` OR `SLOWER` TO A MULTIPLE. `0.666 slower` IS SELF-CONTRADICTORY AND THAT IS THE WHOLE POINT:** say *slower* and the reader supplies *slower's own* multiple, which is **1.5x as slow** — so the phrase carries **two answers at once**, and the one it prints is not the one the word asks for. `2x slower` is the identical disease from the other side (it means `0.5x`, and reads as if it were the bigger number). **Write `0.666x`.** ⛔ This retires the s266 form that this file itself carried for one afternoon (`0.734 SLOWER`, `1.628 FASTER`): fixing the divisor and then bolting a direction word onto it reintroduced the ambiguity the divisor had just removed.
  - ✅ **PERCENTAGES MAY TAKE THE ENGLISH WORD — AND ONLY PERCENTAGES.** *"10% faster"* is `1.10x`; *"10% slower"* is `0.90x`. A percent is a **delta**, not a ratio wearing a direction word, so it reads without ambiguity. Keep the mapping exact and never round it into a different claim: `p% faster` ⇒ `1 + p/100` and `p% slower` ⇒ `1 − p/100`. ⛔ A percent must also name **what it is a percent OF** — "24.3% faster **than we were at session start**" is a claim; "24.3% faster" alone is not.

## ⭐⭐⭐ THE INSTRUMENT LAWS (landed 2026-08-28 as one batch — every clause carries the same-night witness that forced it; proposed by hq_C/hq_P, ratified by ceo. The through-line, one sentence: THREE SEPARATE INSTRUMENTS IN ONE NIGHT REPORTED SUCCESS WHILE DOING NOTHING.)
1. **KILLSWITCH POLARITY: a cure behind a flag defaults ON, and the flag is the control arm.** A default-OFF killswitch on a cure is not a killswitch — it is a deletion with a comment explaining what it used to do, indistinguishable from unwritten code in every profile, surviving precisely because the file reads as if the cure shipped. WITNESS: the s168 PT-3 inline defer arm — written, reviewed, graded on 1,034 programs, measured 1.41x — sat EIGHT DAYS DARK behind the one opt-IN predicate in a file of opt-OUT siblings (`72f9c772` → promoted `53ddfa1d`); every profile that week measured the path the cure deletes.
2. **AN INSTRUMENT MUST DISTINGUISH "MEASURED AND CLEAN" FROM "NEVER RAN."** The two states may not share an output; an instrument that cannot measure REFUSES rc=2 — it never prints the success shape. WITNESSES, one night: the demo `.s` regen that printed "already current" while regenerating NOTHING since the s272 re-grid (a committed artifact 1,749 lines stale); the Pascal grid whose engines "agreed" at reps=0 because neither ran the benchmark; `/usr/bin/time %e` rendering single-digit-ms demos as a flat 0.0 (below its tick, reads as "too fast to matter").
3. **A CURE AND THE INSTRUMENT THAT CAN SEE IT ARE ONE DELIVERABLE, NOT TWO.** Landing a match-path cure while the match board measures compilation is how a 1.41x improvement stays green-and-invisible for a week. The instrument that can observe the cure lands WITH or BEFORE the cure; a board that bounds what it can see says so in its own header (the convergence-ramp precedent: reps committed NOWHERE, the harness REFUSES to report until two successive steps agree — a tolerance widened until it stops refusing is a tolerance chosen to produce answers).
4. **COUNT-ONLY CRITERIA ARE FORBIDDEN: anchor on the growth-invariant quantity.** A `PASS >= N` over a growing corpus measures the corpus, not the work — adding a passing test crosses it for free (icon-n3 closed off two unrelated `.expected` files), and the same template written against prose output can NEVER pass (icon-n4, rc=2 on every tree since minted). A count-based DONE-WHEN gates on FAIL/regression (which adding a passing test cannot raise) or pins its denominator explicitly, and REFUSES rc=2 when it cannot parse its own instrument. Census at landing: 15 count-only DONE-WHENs found in one sweep, four of them minted by the ceo the same day.
5. **EXTRACTION ANCHORS ON IDENTITY, NEVER POSITION.** A criterion keyed on a runner's LAST LINE is keyed on its prose — the part most likely to change (five Icon rungs shared one `tail -1 | sed` template; three could never have computed true on any tree). Anchor on a line's identity (`grep -E '^--- Icon --run:'`), extract with `\b` boundaries (FAIL is a substring of XFAIL — a greedy sed returned 31 where FAIL=15), and prove the gate in ALL its states before trusting it — including watching it FAIL once.
6. **AN INSTRUMENT THAT SHARES A MECHANISM WITH WHAT IT MEASURES IS A PARTICIPANT, NOT AN INSTRUMENT.** The measurement path must be DISJOINT from the measured path — or the perturbation must itself be measured and reported beside the number. WITNESS, minutes after clauses 1-5 landed and by their own proposer: the aspect-2 bracket opened an OUTPUT association BEFORE the rep loop, making every assignment inside the match pay an I/O channel lookup through the same NV_SET_fn the matched program uses — NON-UNIFORM contamination (assignment-heavy json inflated 81%, multiple understated near two-fold, 0.086x → corrected 0.168x; assignment-light claws5 moved 0.3%, so it did NOT divide out). ## ⭐⭐⭐ THE INSTRUMENT LAWS, FIFTH BATCH (2026-08-29 — hq_C + hq_B, ratified by the evidence below. ONE clause, because it is the general form the previous four batches were each a special case of. Three independent witnesses in one day, in three different subsystems, none of which looked broken.)

The first run that could falsify anything found 5 of 10 witness×mode pairs disagreeing with *themselves*, and exactly ONE witness (`fz_segv_09`, deterministic rc=139) able to falsify at all.

   - **Witness C — ⭐ A COLUMN NO VERB WRITES IS NOT STALE, IT IS UNWRITTEN (hq_B, SCRIP `d1ae2d30`).** `QUEUE.tsv`'s state column was written by `park`/`done`/`unclaim` — every RELEASING verb — and by none of `claim`/`next`/`assign` — every ACQUIRING verb.    - **Witness D — the same law shipping a crash, not a wrong number (hq_B, confirming seat10).** The N-2 generator gate flipped **default-ON** on the strength of `test_icn_d2_suspend_witness.sh`, self-described as "THE ACCEPTANCE INSTRUMENT for N-2". 3. ⛔⛔ **A NEW FORMAT IS THE ONE MOMENT WHEN STRICTNESS IS FREE (hq_B + hq_C, 2026-08-29).** An inherited leniency is always defended by the migration it would cost — and **that defence is valid every single time it is raised**, which is exactly why such a surface never closes. The cost is not constant: it **grows with adoption**, so the only moment the argument fails is the moment the format is born. `KEEP.md`'s prose-mention surface stayed open legitimately, because closing it would break every existing file — it had already been paid for. `PENDING.md`'s had not: it was one session old with exactly one instance, and was closed at zero migration cost (SCRIP `5509b134`).
   - **⭐ THE WITNESS, and it is the strongest in this batch because it is the author's own.** hq_B built the `PENDING.md` bucket, **watched all five of its failure arms fail** exactly as clause 1 demands — and then green-washed it inside the hour: the first real `PENDING.md` listed all 49 loose files, 32 deferred plus 17 it was explicitly *not* deferring and was describing in prose to explain the split. **The gate deferred all 49 and returned rc=0**, GATE OK on a row nowhere near done. ⛔ **So watching an instrument fail is NECESSARY AND NOT SUFFICIENT: the arms you write are the arms you thought of.**
   - **⭐⭐ THE SHARPER TEST (hq_C), which would have caught it in advance:** do not ask "is there a lenient surface". Ask **what the file's most natural content IS, and whether writing it well triggers the leniency.** A `PENDING.md` inherently wants to discuss the files it is *not* deferring — which convert now, which are blocked differently, and why — so **its most natural content is the content that breaks it**. The surface was not merely open, it was **aimed at the writer**. ⛔ **A format whose correct use is its own failure mode will be broken by its most careful user, not its most careless one** — which is why review and good intentions do not close it, and only structure does.
2. ⛔ **COROLLARY — A FIELD WHOSE MEANING YOU CANNOT ESTABLISH IS NOT A FIELD YOU MAY NORMALIZE (hq_B, ruled by hq_P 2026-08-29).** The cure for Witness C initially also normalized `QUEUE.tsv`'s col3 into agreement with the claim file; `test_gate_s4e_picker_v2` caught it, and the failure was baselined against HEAD (19/0 vs 18/1) before being read as a stale fixture. Normalizing would have destroyed the umbrella information on 27 rows. **Reconcile a field only against the field it actually corresponds to** — comparing col3 to a claim holder is the instrument-answers-a-narrower-question defect wearing yet another costume, and hq_P walked into it within the hour of writing that defect up for someone else.

## ⛔⭐⭐ THE TWO-NUMBER BENCHMARK BASIS (Lon, in-chat to CEO, 2026-08-30, verbatim in substance: "We should not be including start-up time and finish-up time in the numbers, except as a separate number... each benchmark [is] to time at start and time at finish, so you can take that difference away from the total elapsed time to deduce the overhead number. The startup time is irrelevant for many applications like a process server.")

Every published benchmark carries TWO numbers per arm: **WORK** (the program's own start-to-finish timestamps — in SCRIP Prolog via the `wall_ms/1` builtin, rivals via per-engine preludes defining the same predicate; other frontends grow the same hook) and **OVERHEAD** (external total elapsed minus work — startup + finish). ⛔ Multiples are computed on WORK; overhead is reported beside the grid as its own number, typically once per engine since it is near-constant. ⛔ The work timestamps go to **stderr** so stdout stays byte-comparable against the reference — verification before timing is unchanged. ⚠ Where an engine or frontend has no clock hook yet, the marked interim is empty-program subtraction (time a do-nothing program on that engine, subtract), stated as such in the grid's basis line — never silently mixed with self-timed arms. The pre-existing whole-program grids (SNOBOL4 demos, the first Prolog/Raku grids) stay labeled as totals until re-measured on this basis.

## ⭐⭐⭐ THE INSTRUMENT LAWS, NINTH BATCH (2026-08-30 — hq_B + hq_P, pooled by ceo, worded by hq_C. THREE clauses. ⛔ Clause 1 is a confession against its own author and is the strongest of the three for exactly that reason.)

2. ⛔ **AN INSTRUMENT'S REACH IS ITS POPULATION** (hq_P, from the beauty conviction; ceo-pooled). ## ⭐⭐⭐ THE INSTRUMENT LAWS, EIGHTH BATCH (2026-08-30 — hq_C + hq_B, ceo-ratified. FIVE clauses. ⛔ Clause 1 leads deliberately: it is the shape NEITHER of the counting laws below catches, because the instrument it describes is arithmetically honest throughout.)

1. ⛔⛔ **A GATE THAT PINS AN IMPLEMENTATION PASSES VACUOUSLY THE DAY THAT IMPLEMENTATION IS RETIRED — AND EVERY COUNTER IT PRINTS STAYS HONEST** (hq_C, against their own gate; wording hq_B's). ⭐ **This is why it outranks the counting laws below: there is nothing to count better.** Nothing was skipped, nothing dropped, no zero lied, no `md5("")` to find. `SKIP=0` was **true**. The denominator was **true**. The gate ran exactly what it said it ran, and asked a question that had stopped meaning anything.
   - **WITNESS (hq_C, caught by seat13 while regression-testing something unrelated).** `test_gate_master_shrink_refusal.sh` arm A asserted the builder's `len(pairs)*4 < len(base)` ratio guard. That guard was then **correctly retired** — a count cannot detect a substitution; it false-refused icon's ordinary merge (1 genuinely new pair over a 534-entry master); and it missed a partial cutover entirely, because surviving sources keep the *ratio* healthy while a disjoint subset has no source at all. 2. ⛔ **A GATE THAT CANNOT FIND ITS WITNESSES MUST EXIT NON-ZERO, AND "CANNOT FIND" INCLUDES FINDING FEWER THAN IT NAMES** (hq_B; extends the sixth batch's clause with a controlled demonstration). The corpus `demo/` → `demos/` re-grid broke **one** directory and **three gates read that single input three different ways**: `test_gate_instr_budget.sh` REFUSED rc=2 and named the exact file it could not open (cost: minutes) · `test_crosscheck_snocone.sh` dropped 4 of its 8 cases and printed `PASS=4 FAIL=0 SKIP=0`, exit 0 · `test_lower_byte_identical.sh` skipped 25 of its 30 and printed `PASS=5 FAIL=0`, exit 0. ⭐ **ONE INPUT, THREE VERDICTS, and only the refusing one was any use.** This is a **controlled demonstration**, not a witness — the cause is held fixed and the *reaction* is the variable — so it is not answerable with *"that one gate was badly written"*: three gates cannot all be the badly-written one. ⛔ The minimal form is `[ -f "$f" ] && run_it` with no `else`. **It reads as defensive, and defensive is exactly how a skip disguises itself as care.**

3. ⛔⭐ **A ZERO IN A SUMMARY IS AN ASSERTION, NOT AN ABSENCE** (hq_B). `SKIP=0` does not *fail to mention* the four cases that were dropped — it actively **claims there were none to mention**. Count the misses at the point of the miss, or print no zero at all.** Siblings, same shape, different layers: `make test` named in `.PHONY` with no recipe — *"Nothing to be done"* read as a full green suite; and a lower gate whose 30 baked baseline hashes were all `md5("")`, so PASS meant empty matched empty.

4. ⛔ **A BAKE STEP MUST ASSERT ITS OWN OUTPUT IS NON-TRIVIAL BEFORE WRITING IT** (hq_B, stated as an obligation at their own request rather than as the story — the cure is a code change in each bake step, so the narrative belongs in a row). A `--bake` that runs the same broken invocation it is meant to check produces a baseline the instrument **cannot disagree with**. Witness: all 30 SR-1 baseline hashes were the hash of the empty string.

5. ⛔ **AN UNQUALIFIED SENTENCE SITTING BESIDE A QUALIFIED ONE INHERITS THE QUALIFICATION IN ITS AUTHOR'S MIND AND NOT IN THE READER'S** (hq_C; ceo-routed). ⭐ **This is the prose form of the removed-guard problem: nothing in the artifact announces what is missing.** Witness, measured: this file's own line read *"**SCRIP FOLLOWS SPITBOL SEMANTICS** for SNOBOL4/Snocone. **SCRIP IS CASE-SENSITIVE.**"* — first sentence scoped, second not, and it was read as global. `fpc -Miso` accepts `writeln`/`WriteLn`/`Writeln`/`WRITELN` (all four, rc=0); SCRIP accepted only lowercase, rc=1 on the rest, and the gap dominated a whole vendored Pascal suite's red. **A rule derived from SPITBOL was governing a language whose own standard says the opposite.** When you write a scoped rule, repeat the scope in every sentence that carries it — the author always knows the scope and never needs it written down, which is exactly why it does not get written down.

## ⭐⭐ RULES OF CONDUCT, SEVENTH BATCH (2026-08-30 — ceo-pooled to hq_C from hq_B's measured find. ONE clause. ⛔ Not an instrument law: this one governs what a HUMAN must write down, because the artifact that would normally announce the change does not exist.)
1. ⛔⛔ **DELETING OR WEAKENING ANY GUARD, REFUSAL OR GATE ARM MUST BE NAMED IN THE COMMIT MESSAGE, WITH ITS REASON — THE SAME DISCIPLINE AS A LAW CHANGE.** ⭐ **The reason is structural, not procedural: A REMOVED CHECK HAS NO FAILING TEST TO ANNOUNCE IT.** Every other kind of regression recruits an instrument to complain on its behalf; deleting the instrument recruits nothing. The change is invisible in exactly the way that matters — it merges clean, every board stays green, and the green is now worth less without anything saying so.
   - **WITNESS (hq_B, 2026-08-30; ceo landed the rule).** `d67c0f6c` deleted **two** refusal guards from `capture-oracle-refs` with **neither named in the commit message**. It merged cleanly into every tree and **nothing went red**. It was caught only because an unrelated rebase conflict forced a human to read the function — i.e. by luck, and by a mechanism that has nothing to do with guards. Both guards restored and gated, `SCRIP 24f7456c`.
   - ⭐ **WHY A COMMIT MESSAGE AND NOT A TEST:** the obvious fix — "add a test that the guard exists" — regresses infinitely (the guard-guard is itself deletable, unannounced). The only place a removal can be recorded such that a later reader meets it while asking *why is this gone* is the commit that removed it. **Factual, no blame: the shape is the lesson, and it is that absence has no alarm.**
   - ⛔ **THE COROLLARY THAT MAKES IT USABLE:** "weakening" counts — narrowing a predicate, widening an allow-list, lowering a ratchet ceiling, converting a refusal into a warning, or moving a check behind a flag that defaults off. Each leaves the guard *present* and the protection *gone*, which reads even better in a diff than a deletion does.

## ⭐⭐⭐ THE INSTRUMENT LAWS, SIXTH BATCH (2026-08-29 — hq_P, at hq_B's request, on two same-day witnesses from unrelated subsystems. ONE clause. ⛔ It is NOT a corollary of the fifth: the fifth batch's witnesses were instruments that COULD NOT FAIL. This batch's instruments CAN fail, ARE looking at the right object, and still cannot see the defect — because the defect is not in the object they sample.)
1. ⛔⛔ **A DEFECT CAN LIVE IN A TRANSITION, WHERE NO INSTRUMENT THAT SAMPLES STATES WILL EVER SEE IT.** hq_B's fifth-batch form — *a census that finds a nonconforming row has not yet found a defect* — now has its converse, and the converse is the sharper half: ⭐ **A CENSUS THAT FINDS A CONFORMING ROW HAS NOT FOUND A SAFE ONE.** Every state can be individually legal while the *move between* two of them is the bug. ⛔ **The operational consequence: when something is going wrong and every audit reads clean, stop sampling states and sample the CHANGE** — the same object before and after one operation, or the same object reached by two different paths. An instrument that only ever looks at rest positions is structurally blind to this whole class, and it will report green forever, honestly, at full confidence.
   - **Witness A — a queue row that was legal at every instant and unsafe for an hour (hq_P, caught by seat16; cured at SCRIP `d1deda52`).** `defect-c-zop-flat-regime-depth-compensate` is HQ-only per CEO-19, and its `ASSIGNED:hq_P` state was not a dispatch record — it was the *only* thing keeping an HQ-only codegen row away from the picker, which does not filter by the owner column. hq_P released it with plain `unclaim`, which by a correct standing ruling drives the column to `FREE`; a Sonnet seat's `next` locked it within minutes. ⭐ **The row read `ASSIGNED`, then legitimately `FREE`, then `ASSIGNED` again — conforming at every single sample.** No state census could have flagged the hour between, and hq_B's reconcile audit, which was actively looking at exactly this row, correctly classified it both before and after. The defect was in what `unclaim` *did*, not in anything it left behind. ⛔ Root cause, for the record: `ASSIGNED:<x>` carried two meanings with different lifetimes — DISPATCH (spent when the holder lets go) and RESTRICTION (a property of the row, never spent) — so no single rule about release could serve both. Cured by giving restriction its own spelling, `RESTRICTED:<x>`, rather than by special-casing `ASSIGNED:<hq>` inside `unclaim`: ⭐ **the refused patch is the instructive half — it would have keyed behaviour on WHO the assignee is instead of WHAT the state means, and broken in silence on the first restricted row assigned to a non-HQ.**
   - **Witness B — a stack accounting where every node is self-consistent and the join is not (hq_P, `pascal-m4-for-spine-leak-64b-per-iter`; FINDING `37ebb087`).** `zd_plan` gives a loop back-edge a constant pop computed from the plan's static depth for the jump target. Audit any single node and the arithmetic is correct; audit the whole plan and every entry agrees with itself. ⭐ **The defect only exists between two predecessors: the join label is entered at `rsp=0x…edf90` on the fall-through path and `0x…ee260` on the back-edge path, and RSP climbs 720 bytes per iteration until it leaves the stack.** A per-node instrument — which is what the plan dump is — cannot express "these two arrivals disagree", because disagreement is not a property of either node. It took breaking on the *same label* across *two different arrivals* to see it at all.
   - ⭐ **Why two witnesses from unrelated subsystems matter here:** one is a shell state machine over a TSV, the other is x86 stack accounting in a compiler backend. They share no code, no author's intent and no failure mode — only the shape. That is what makes this a law rather than an anecdote about a queue.
4. ⛔⛔ **A CONFOUND THAT MOVES IN YOUR FAVOUR IS THE ONE YOU ARE LEAST LIKELY TO REPORT, AND THEREFORE THE ONE MOST WORTH REPORTING (hq_C + hq_B, 2026-08-29).** ⭐ **This is the first OPERATOR-SIDE law in this file and it needs saying separately for that reason.** Every other instrument law assumes an honest operator reading a dishonest tool — vacuous gates, criteria that cannot go green, signals reachable by two causes. This one assumes an **honest tool** and asks what the operator does not volunteer. ⛔ **No instrument can catch it: nothing in a green result records which confounds were running when it was taken.**
   - **⭐ THE MECHANISM, WHICH IS WHY "JUST BE HONEST" DOES NOT CLOSE IT (hq_C).** The asymmetry is not about virtue. **A confound AGAINST you gets reported because it is an obstacle you had to work around, so you already wrote it down. A confound FOR you never becomes an event at all** — nobody suppresses it; it simply never generates a moment at which you would have written it. Good faith is therefore not a defence, and the cure is a **named habit**: state the machine state beside the result whether or not it helped.
   - **Witness (hq_C, `fuzz-nondeterminism-rootcause`).** The fleet shutdown to TRIO dropped the box from load ~32 to ~7.5 *between* the question being provoked and the stability run being taken. hq_C named it unprompted and downgraded their own result: **a stability result measured on a quiet box is weaker evidence than the same result under the load that originally provoked the question.** They could have banked the quiet-box number and nobody would have known to ask.
   - **⭐ Corollary, the design half:** when a confound lifts, do not silently harvest the cleaner conditions — **split the question**. Run the now-uncontended experiment to settle the variable that no longer depends on the confound, and re-provoke the confound only if that first answer forces it. One variable each, in the order that makes the second experiment skippable.
3. ⛔⛔ **A CENSUS THAT INDICTS 100% OF ITS POPULATION IS REPORTING ON ITSELF (hq_B, written up at hq_P's request, 2026-08-29).** A confident, fully-populated, plausible-looking output is not evidence; it is the *shape* of evidence. When a check finds that **every single** member of its population is guilty — 44 of 44 files unreachable, 40 of 40 rows lying, every witness failing — the first hypothesis is not "the tree is entirely broken", it is **"my instrument is broken and is describing its own failure in the vocabulary of a finding."** Real populations are lumpy; a defect that is genuinely universal is rare enough that unanimity should cost you a verification, not buy you a conclusion. ⭐ Same family as **NON-EMPTY IS NOT ALIVE** — both are outputs that pass every superficial test for being data (populated, formatted, specific) while carrying no information about the thing they name.
   - **Witness — the reachability check, caught before it shipped as a finding.** hq_B built a gate asking "does any runner reach this deferred file", and it reported **44 of 44 DARK**. Two independent bugs, either sufficient: the path was built by stripping only `$S4E`, yielding `corpus/tests/prolog/x.pl` while every runner spells `$CORPUS/tests/…` and never that literal prefix; and the function was **defined at line 247 and called at line 217**. The true number was **11**. Only the implausibility of 44/44 prompted the check — the output was otherwise indistinguishable from a serious discovery, and would have been reported to another HQ as one.
   - ⛔ **The nastier half, and it is a distinct hazard worth naming: BASH RETURNS 127 FOR AN UNDEFINED FUNCTION, AND WITHOUT `set -e` THAT BECOMES A SILENT FALSE.** `if undefined_fn "$x"; then A; else B; fi` takes branch B, every time, with no diagnostic. A define-after-call ordering error therefore does not crash — it **silently answers "no" to every question you ask it**. That is SKIP-AS-SUCCESS wearing a different hat: the vacuous-test class Lon flagged, arriving through control flow instead of through a missing recipe. ⭐ Cheap defence: any shell predicate whose "no" answer drives a verdict must be proven to return **yes** at least once on a known-true case in the same run — a positive control, which is clause 1 of the fifth batch applied to a function instead of to a suite.
2. ⛔⛔ **AN RC IS NOT A MEASUREMENT OF TIME (hq_C + hq_B, 2026-08-29, on `fuzz-nondeterminism-rootcause` — Lon's row).** `rc=124` is **byte-identical whether a program needs 8.1 seconds or never finishes.** The code has no capacity to distinguish its two causes, so **every reader supplies the one they already believe** — and a timeout code beside a program you suspect of hanging reads as proof of the hang. ⛔ **THE MEASURED WITNESS: six sessions read `rc=124`, inferred a hang, and were RIGHT BY LUCK.** ⭐ **The alarming part is not that they were wrong — they were not. It is that nothing anywhere in the evidence chain could have told them either way**, so the correct conclusion and a false one were reachable by identical reasoning from identical evidence, and no amount of care would have separated them.
   - **What actually settled it, and it is the whole operational content: a DURATION DISTRIBUTION, which no instrument on that row had ever recorded.** N=8 per witness under a 20s ceiling, mode 3: `fz_red_m1b` **0.02s ×2 vs ≥20.01s ×6**; `fz_segv_24` **0.02s ×4 vs ≥20.01s ×4**. **Bimodal with nothing in between, and nothing anywhere near the old 8s boundary.** A load-induced timeout artifact would cluster *around* the boundary — the competing hypothesis was cheap, plausible, and killed in one run by a histogram. The behaviour is not "sometimes slow"; it is **"sometimes enters a loop it never leaves"**, which is a different defect with a different cure, and the rc could not say so.
   - ⛔ **The hypothesis was hq_C's own, published to hq_B and written into a script header before it was disproved, and is retracted in the open here rather than quietly dropped** (RULES.md § TRANSCRIPTION). ⭐ hq_B's own repair is the part to copy: when the retraction arrived they corrected **the instrument's PRINTED LINE**, not merely its comment — the line had been asserting the disproved claim to every reader of every gate run. **A disproved hypothesis left sitting in an instrument is a stale citation with the blast radius of that instrument's whole readership.**
   - ⭐ **THE RULE, and it is cheap: if a verdict turns on how long something took, record how long it took.** A timeout code is a fact about your ruler, not about the program. When an instrument's output is reachable from "slow" and from "infinite", it must either record the duration or say nothing about hangs — and this generalises past timeouts to every quantity a signal *thresholds* rather than *measures*.
   - ⚠️ **Kept deliberately as a distinct clause from § A SIGNAL REACHABLE BY TWO CAUSES THAT NAMES ONLY ONE, which it is otherwise an instance of.** That law's cure is *give the signal enough bits, or split it*. Here the signal **cannot** be given more bits — `rc` is one byte handed over by the kernel and `timeout` has exactly one code to give — so the cure is not in the signal at all: **you must record a second, different observable beside it.** A law whose stated cure is unavailable in its own worst case needs its own entry, or the next reader will go looking for the bits.

3. ⛔⛔ **AN ACCEPTANCE CONDITION NOBODY CAN EVALUATE WITHOUT ITS AUTHOR IS NOT AN ACCEPTANCE CONDITION — IT IS A QUEUE FOR THAT AUTHOR.** ⭐ **A reservation, gate or hold MUST carry the condition that DISCHARGES it**, written where the waiting party is standing, so anyone can read it and know the gate is already met without needing a reply. (hq_P, 2026-08-29; hq_C asked for it to be landed and backs it — *"it converts a blocking wait on a person into a checkable predicate on the work"*.)
   - **Witness — a proven mechanism parked for several sessions on a signature that was already earned (hq_C's own row, hq_C reporting it against themselves).** `pascal-m4-for-spine-leak` Site 1 was reserved hq_C-first for **blast-radius control on a shared node** — a correct and well-judged gate. Its purpose was met once (a) the mechanism was proven rather than hypothesised and (b) the shared-node battery ran before landing, and **both had been true for some time**. But that discharging condition lived in hq_C's head, not in the baton, so seat12, seat02 (×2), seat14, seat03 and seat05 each flagged Site 1 and each correctly stopped, waiting on a reply rather than on a condition they could check. A second row had to be minted to give the defect a home. ⭐ **A gate whose purpose is already met but whose signature is pending has stopped being a gate and become ceremony**, and here it cost more than it protected.
   - ⭐ **THIS IS THE SAME LAW AS "A DONE-WHEN IS AN EXECUTABLE COMMAND, NOT PROSE", one level up.** We already refuse acceptance criteria that cannot be run; a reservation whose discharge cannot be evaluated is the identical defect wearing governance clothes. ⛔ Note the failure mode it produces is a **non-event** — nothing goes red, nothing errors, a correct hold simply persists — which is why hq_C's first instinct, *"treat the silence as the defect and escalate"*, is necessary but not sufficient: it asks the waiting seat to notice an absence, and absences are the hardest thing to notice. **Writing the discharging condition is the author's job, not the waiter's.**
   - ⛔ **Corollary for whoever sets the hold:** "reserved for X" is not a condition. "Reserved until the mechanism is proven and the shared-node battery has run" is. If you cannot state what would discharge your own gate, you have not reserved the work — you have parked it on yourself.
