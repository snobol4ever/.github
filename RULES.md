## ⛔ THE MAIL CHANNEL — WHAT THE HOOKS ACTUALLY DELIVER (hq_C + hq_P, 2026-08-23 s261, verified both ends)

⭐ **THE COMA IS CLOSED AT BOTH ENDS, AND IT IS CLOSED BY THE HARNESS, NOT BY A SEAT'S INTENTIONS.** Two hooks in a seat's `.claude/settings.json`: **`UserPromptSubmit`** runs `s4e_inbox_hook.sh` and prints unread senders + subjects **above the seat's first tool call**, and the **`Stop`** hook fires `s4e_msg.sh banner`, which **also reports unread**. So mail is surfaced **before a seat starts work and again before it goes idle**. ⛔ The hook prints **headers only, never bodies** — piping `check` straight in costs ~10k tokens every single turn and trains a seat to skim past the thing it exists to surface.

⛔ **BUT "IMMEDIATE CHANNEL" OVERSTATES IT, AND THE OVERSTATEMENT IS NOW MEASURED.** `UserPromptSubmit` fires **only on prompt submission**, so it **cannot see mail that arrives mid-turn**. A message sent to a seat already working sits unread until that seat either finishes (Stop banner) or happens to run an `s4e_msg.sh` command — `send` prints an unread banner as a **side effect**, which is what actually caught Lon's own delivery test, i.e. the catch was **lucky rather than designed**. ⭐ **The honest guarantee is therefore ONE TURN OF LATENCY, NOT IMMEDIACY:** nothing interrupts a running seat, and turns can run very long. That is a bounded, acceptable delay — but do not write, or believe, that THE LOOP step 1 delivers a message *now*. True mid-turn delivery would need a different mechanism than either hook.

⭐ **AND THE REASON THIS IS A RULE AND NOT A NOTE:** a queue-depth or empty-mailbox check measures the **PRODUCER** and can never see the **CONSUMER** — an empty mailbox and an unread mailbox read identically. **PRESENCE IS NOT PROOF.** The only sound readiness condition is a **round trip**: a message sent to a running seat is *demonstrably read*, evidenced by a receipt.

⛔ **A RETIRED MAILBOX THAT STILL ACCEPTS MAIL IS WORSE THAN ONE THAT REFUSES (hq_C proposal, landed by ceo 2026-09-03 ~19:45 CDT as the session's one law change).** When an identity is retired or split (the `hq` → `hq_C`/`hq_P` split; any seat whose `HQ` file is re-pointed), its inbox is made to REFUSE (`send` exits rc=2 and prints the live target), never left to accept silently — the drained `hq/inbox` swallowed a Lon override for eight hours on 2026-09-03 because it still accepted mail; hq_B's cure that day made `send hq` refuse. Corollary for every re-lane: a message addressed to a NUMBER whose FUNCTION has moved is re-delivered by the re-lane itself (the ceo's `fleet16_relane.sh` moved every post-flip message with its function), never left for the new occupant to misread — a confident brief from an HQ in the wrong inbox is a wrong-work start, not a misfile (hq_P, 2026-09-03 19:2x). The instrument: `s4e_msg.sh send <retired>` must exit rc=2 with the live target printed; a send that returns 0 into a retired box is the defect.

## FACT RULES (each: rule + enforcement; shared LIMITATION at end)

- **⛔⛔⭐ FACT RULE — THE LENGTH IS CARRIED, NEVER MEASURED: NO `strlen` ON A DESCRIPTOR'S `.s` (Lon, in-chat 2026-08-30).** Verbatim in substance: *"Remove all strlen on the DESCR .s that is totally INVALID and not performant. A NUL character is a valid string element."* ⭐ **BOTH HALVES ARE LOAD-BEARING AND THE FIRST IS THE ONE THAT BITES.** **INVALID:** SNOBOL4/SPITBOL strings are **COUNTED**, so NUL is an ordinary member of `&ALPHABET` and a value may legitimately contain one — `strlen` answers a question about *C strings*, not about our values, and it **truncates at the first embedded NUL**. **NOT PERFORMANT:** it is an O(n) rescan of bytes whose length was already known to whoever built the descriptor. ⛔ **THE `slen == 0` "ASK strlen" SENTINEL IS RETIRED — `slen == 0` MEANS THE VALUE IS EMPTY.** A value with an embedded NUL must be built with `BSTRVAL` (explicit count); `STRVAL`'s contract is and always was *"this argument is a C string"*. ⭐ **THE CURE IS AT THE CONSTRUCTOR, NOT AT THE CALL SITES — this is the transferable part:** `STRVAL` measures **once**, where the C string enters, and carries the count in; `descr_slen` only READS it. That fixed **260 construction sites with zero edits to any of them**, and for a string literal `__builtin_strlen` constant-folds, so the carried form is **strictly cheaper than on-demand `strlen` as well as correct**. ⛔ **A LATENT DEFECT THIS EXPOSED, and it is the shape to look for elsewhere:** `pattern_match.c:321` called `strlen(arr.s)` with **no `.slen` consultation at all**, so a counted string with an embedded NUL — *or a slice-backed capture, which owns no terminator* — got the wrong length. An on-demand `strlen` is not merely redundant beside a carried count; where the count was never consulted it is a wrong answer waiting for the right input. ⚠️ **THE ONE SURVIVOR, NAMED RATHER THAN PAPERED OVER:** `slen == 0xFFFFFFFF` is the **CSET TYPE TAG**, not a length, so a cset has nowhere to carry a count — its authority is `kw_cset_len`, and a cset whose member set includes NUL is a separate representation question this rule does not settle. ⭐ **The hand-written asm needed no change and that is worth knowing before anyone edits it:** `rtx_icnagg.s:44` already *delegates* the `slen == 0` case to C rather than implementing `strlen` itself, so fixing C's authority fixed both. **ENFORCEMENT:** SCRIP `85b877d4` (hq_P). Verdict pristine at `RT_OPT=-O0`: SNOBOL4 m3 `PASS=1672 FAIL=0` · m4 `PASS=1672 FAIL=0 SKIP=0 MISSING=0`, xfail/xpass unchanged; icon 14/14, prolog 5/5, snocone 5/5, rebus 4/4; three invariant gates rc=0; an embedded-NUL witness matches the SPITBOL oracle exactly. ⭐ **Perf stated honestly rather than sold:** callgrind Ir at fixed work, `table_variety` **1.0004x** and `string_concat` **1.0004x**, every other benchmark inside ±60 Ir (noise) — a **correctness and hygiene** change with a negligible perf effect, not a perf win.

A WATERMARK WITHOUT ITS COMMAND IS NOT A WATERMARK (hq_C + hq_P, 2026-08-24 s272, measured — this one cost most of a session).** A board reading carries a tree, a commit, an `RT_OPT`, a mode — and **the script that produced it**. Drop the last one and the number silently becomes a claim about something else. ⭐ **MEASURED INSTANCE:** `test_icon_all_rungs.sh` and `test_icon_rung_suite.sh` grade the **same 293 Icon programs on one tree** and read **244/19/30 vs 169/94/30 — 75 programs apart** (`be376a2f`, same corpus, one sitting). `GOAL-ICON-100.md`'s s267 watermark of **232** recorded its tree, its flags and its `RT_OPT` but **not its script**; it was an `all_rungs` number. ## ⛔⭐⭐ THE TWO-NUMBER BENCHMARK BASIS (Lon, in-chat to CEO, 2026-08-30, verbatim in substance: "We should not be including start-up time and finish-up time in the numbers, except as a separate number... each benchmark [is] to time at start and time at finish, so you can take that difference away from the total elapsed time to deduce the overhead number. The startup time is irrelevant for many applications like a process server.")

Every published benchmark carries TWO numbers per arm: **WORK** (the program's own start-to-finish timestamps — in SCRIP Prolog via the `wall_ms/1` builtin, rivals via per-engine preludes defining the same predicate; other frontends grow the same hook) and **OVERHEAD** (external total elapsed minus work — startup + finish). ⛔ Multiples are computed on WORK; overhead is reported beside the grid as its own number, typically once per engine since it is near-constant. ⛔ The work timestamps go to **stderr** so stdout stays byte-comparable against the reference — verification before timing is unchanged. ⚠ Where an engine or frontend has no clock hook yet, the marked interim is empty-program subtraction (time a do-nothing program on that engine, subtract), stated as such in the grid's basis line — never silently mixed with self-timed arms. The pre-existing whole-program grids (SNOBOL4 demos, the first Prolog/Raku grids) stay labeled as totals until re-measured on this basis. **⛔ THE SUBTRACTION REFUSES WHEN IT IS NOISE (ceo ruling CEO-173, 2026-09-03, on hq_B's measured witness from the JCON demo — this sitting's one law change):** on a 4–5 ms program against a 2–4 ms process start the empty-program subtraction is dominated by its own error bars and INVERTS — the same run put SCRIP m4 ahead of iconx on totals (3.93 ms vs 4.99 ms) and at `0.465x` on the work basis; both cannot be true and neither belongs in a README. So a harness that finds OVERHEAD at or above 50% of EITHER arm REFUSES the work multiple and prints the labelled TOTAL-basis multiple in its place — never both, never the work number with a quiet asterisk; the grid's basis line says which basis and why. This is the law's intent made explicit (startup is irrelevant to a process server; that is not a licence to publish subtraction noise), and the clock-hook cure (a real `wall_ms` in the program under test) is the way back to the WORK basis for that program.

⛔⭐⭐ **AND EVERY PUBLISHED BENCHMARK RUNS ALL THREE ANGLES (Lon, in-chat, 2026-08-30, extending the same ruling): (1) fixed TIME counting iterations, (2) fixed ITERATIONS measuring time, (3) the process wrapper measuring perf data and total elapsed — from which the self-timed work above yields the separated overhead.** The three angles CROSS-VERIFY: angles 1 and 2 must agree on the rate (disagreement means too few iterations or too short a budget — the triangulation is itself the adequacy check that the measurement ran long enough), and angle 3 ties the rate to hardware counters and the overhead split. The machinery EXISTS and is the mandated instrument — `bench_triangulate_{snobol4,prolog,pascal}.sh`, `bench_*_fixed_iter.sh`, the demos variant, and `tools/bench_rusage`, law in ARCH-BENCH-CAMPAIGN-README-TABLES.md § THREE-ANGLE TRIANGULATION — extended now by the WORK/OVERHEAD split in angle 3 and grown per language where missing (the clause that once read "Raku and Icon lack triangulation scripts" was FALSE by 2026-09-03 and is retired: `bench_triangulate_raku.sh` existed already and hq_B's JCON-demo row added `bench_triangulate_demos_icon.sh`, Icon's first — hq_B 2026-09-03, ceo CEO-173). ⛔ A single-angle number is a scouting datum, never a published grid: it may appear in a FINDING labeled as one angle, and the README carries only triangulated numbers once a language's harness exists.

Audit any single node and the arithmetic is correct; audit the whole plan and every entry agrees with itself. ⭐ **The defect only exists between two predecessors: the join label is entered at `rsp=0x…edf90` on the fall-through path and `0x…ee260` on the back-edge path, and RSP climbs 720 bytes per iteration until it leaves the stack.** A per-node instrument — which is what the plan dump is — cannot express "these two arrivals disagree", because disagreement is not a property of either node. It took breaking on the *same label* across *two different arrivals* to see it at all.
   - ⭐ **Why two witnesses from unrelated subsystems matter here:** one is a shell state machine over a TSV, the other is x86 stack accounting in a compiler backend. They share no code, no author's intent and no failure mode — only the shape. That is what makes this a law rather than an anecdote about a queue.
4. ⛔⛔ **A CONFOUND THAT MOVES IN YOUR FAVOUR IS THE ONE YOU ARE LEAST LIKELY TO REPORT, AND THEREFORE THE ONE MOST WORTH REPORTING (hq_C + hq_B, 2026-08-29).** ⭐ **This is the first OPERATOR-SIDE law in this file and it needs saying separately for that reason.** Every other instrument law assumes an honest operator reading a dishonest tool — vacuous gates, criteria that cannot go green, signals reachable by two causes. This one assumes an **honest tool** and asks what the operator does not volunteer. ⛔ **No instrument can catch it: nothing in a green result records which confounds were running when it was taken.**
   - **⭐ THE MECHANISM, WHICH IS WHY "JUST BE HONEST" DOES NOT CLOSE IT (hq_C).** The asymmetry is not about virtue. **A confound AGAINST you gets reported because it is an obstacle you had to work around, so you already wrote it down. A confound FOR you never becomes an event at all** — nobody suppresses it; it simply never generates a moment at which you would have written it. Good faith is therefore not a defence, and the cure is a **named habit**: state the machine state beside the result whether or not it helped.
   - **Witness (hq_C, `fuzz-nondeterminism-rootcause`).** The fleet shutdown to TRIO dropped the box from load ~32 to ~7.5 *between* the question being provoked and the stability run being taken. hq_C named it unprompted and downgraded their own result: **a stability result measured on a quiet box is weaker evidence than the same result under the load that originally provoked the question.** They could have banked the quiet-box number and nobody would have known to ask.
   - **⭐ Corollary, the design half:** when a confound lifts, do not silently harvest the cleaner conditions — **split the question**. Run the now-uncontended experiment to settle the variable that no longer depends on the confound, and re-provoke the confound only if that first answer forces it. One variable each, in the order that makes the second experiment skippable.
3. ⛔⛔ **A CENSUS THAT INDICTS 100% OF ITS POPULATION IS REPORTING ON ITSELF (hq_B, written up at hq_P's request, 2026-08-29).** A confident, fully-populated, plausible-looking output is not evidence; it is the *shape* of evidence. When a check finds that **every single** member of its population is guilty — 44 of 44 files unreachable, 40 of 40 rows lying, every witness failing — the first hypothesis is not "the tree is entirely broken", it is **"my instrument is broken and is describing its own failure in the vocabulary of a finding."** Real populations are lumpy; a defect that is genuinely universal is rare enough that unanimity should cost you a verification, not buy you a conclusion. ⭐ Same family as **NON-EMPTY IS NOT ALIVE** — both are outputs that pass every superficial test for being data (populated, formatted, specific) while carrying no information about the thing they name.
   - **Witness — the reachability check, caught before it shipped as a finding.** hq_B built a gate asking "does any runner reach this deferred file", and it reported **44 of 44 DARK**. Two independent bugs, either sufficient: the path was built by stripping only `$S4E`, yielding `corpus/tests/prolog/x.pl` while every runner spells `$CORPUS/tests/…` and never that literal prefix; and the function was **defined at line 247 and called at line 217**. The true number was **11**. Only the implausibility of 44/44 prompted the check — the output was otherwise indistinguishable from a serious discovery, and would have been reported to another HQ as one.
   - ⛔ **The nastier half, and it is a distinct hazard worth naming: BASH RETURNS 127 FOR AN UNDEFINED FUNCTION, AND WITHOUT `set -e` THAT BECOMES A SILENT FALSE.** `if undefined_fn "$x"; then A; else B; fi` takes branch B, every time, with no diagnostic. A define-after-call ordering error therefore does not crash — it **silently answers "no" to every question you ask it**. That is SKIP-AS-SUCCESS wearing a different hat: the vacuous-test class Lon flagged, arriving through control flow instead of through a missing recipe. ⭐ Cheap defence: any shell predicate whose "no" answer drives a verdict must be proven to return **yes** at least once on a known-true case in the same run — a positive control, which is clause 1 of the fifth batch applied to a function instead of to a suite.
2. ⛔⛔ **AN RC IS NOT A MEASUREMENT OF TIME (hq_C + hq_B, 2026-08-29, on `fuzz-nondeterminism-rootcause` — Lon's row).** `rc=124` is **byte-identical whether a program needs 8.1 seconds or never finishes.** The code has no capacity to distinguish its two causes, so **every reader supplies the one they already believe** — and a timeout code beside a program you suspect of hanging reads as proof of the hang. ⛔ **THE MEASURED WITNESS: six sessions read `rc=124`, inferred a hang, and were RIGHT BY LUCK.** ⭐ **The alarming part is not that they were wrong — they were not. It is that nothing anywhere in the evidence chain could have told them either way**, so the correct conclusion and a false one were reachable by identical reasoning from identical evidence, and no amount of care would have separated them.
   - **What actually settled it, and it is the whole operational content: a DURATION DISTRIBUTION, which no instrument on that row had ever recorded.** N=8 per witness under a 20s ceiling, mode 3: `fz_red_m1b` **0.02s ×2 vs ≥20.01s ×6**; `fz_segv_24` **0.02s ×4 vs ≥20.01s ×4**. **Bimodal with nothing in between, and nothing anywhere near the old 8s boundary.** A load-induced timeout artifact would cluster *around* the boundary — the competing hypothesis was cheap, plausible, and killed in one run by a histogram. The behaviour is not "sometimes slow"; it is **"sometimes enters a loop it never leaves"**, which is a different defect with a different cure, and the rc could not say so.
   - ⛔ **The hypothesis was hq_C's own, published to hq_B and written into a script header before it was disproved, and is retracted in the open here rather than quietly dropped** (RULES.md § TRANSCRIPTION). ⭐ hq_B's own repair is the part to copy: when the retraction arrived they corrected **the instrument's PRINTED LINE**, not merely its comment — the line had been asserting the disproved claim to every reader of every gate run. **A disproved hypothesis left sitting in an instrument is a stale citation with the blast radius of that instrument's whole readership.**
   - ⭐ **THE RULE, and it is cheap: if a verdict turns on how long something took, record how long it took.** A timeout code is a fact about your ruler, not about the program. When an instrument's output is reachable from "slow" and from "infinite", it must either record the duration or say nothing about hangs — and this generalises past timeouts to every quantity a signal *thresholds* rather than *measures*.
   - ⚠️ **Kept deliberately as a distinct clause from § A SIGNAL REACHABLE BY TWO CAUSES THAT NAMES ONLY ONE, which it is otherwise an instance of.** That law's cure is *give the signal enough bits, or split it*. Here the signal **cannot** be given more bits — `rc` is one byte handed over by the kernel and `timeout` has exactly one code to give — so the cure is not in the signal at all: **you must record a second, different observable beside it.** A law whose stated cure is unavailable in its own worst case needs its own entry, or the next reader will go looking for the bits.

3. ⛔⛔ **AN ACCEPTANCE CONDITION NOBODY CAN EVALUATE WITHOUT ITS AUTHOR IS NOT AN ACCEPTANCE CONDITION — IT IS A QUEUE FOR THAT AUTHOR.** ⭐ **A reservation, gate or hold MUST carry the condition that DISCHARGES it**, written where the waiting party is standing, so anyone can read it and know the gate is already met without needing a reply. (hq_P, 2026-08-29; hq_C asked for it to be landed and backs it — *"it converts a blocking wait on a person into a checkable predicate on the work"*.)
   - **Witness — a proven mechanism parked for several sessions on a signature that was already earned (hq_C's own row, hq_C reporting it against themselves).** `pascal-m4-for-spine-leak` Site 1 was reserved hq_C-first for **blast-radius control on a shared node** — a correct and well-judged gate. Its purpose was met once (a) the mechanism was proven rather than hypothesised and (b) the shared-node battery ran before landing, and **both had been true for some time**. But that discharging condition lived in hq_C's head, not in the baton, so seat12, seat02 (×2), seat14, seat03 and seat05 each flagged Site 1 and each correctly stopped, waiting on a reply rather than on a condition they could check. A second row had to be minted to give the defect a home. ⭐ **A gate whose purpose is already met but whose signature is pending has stopped being a gate and become ceremony**, and here it cost more than it protected.
   - ⭐ **THIS IS THE SAME LAW AS "A DONE-WHEN IS AN EXECUTABLE COMMAND, NOT PROSE", one level up.** We already refuse acceptance criteria that cannot be run; a reservation whose discharge cannot be evaluated is the identical defect wearing governance clothes. ⛔ Note the failure mode it produces is a **non-event** — nothing goes red, nothing errors, a correct hold simply persists — which is why hq_C's first instinct, *"treat the silence as the defect and escalate"*, is necessary but not sufficient: it asks the waiting seat to notice an absence, and absences are the hardest thing to notice. **Writing the discharging condition is the author's job, not the waiter's.**
   - ⛔ **Corollary for whoever sets the hold:** "reserved for X" is not a condition. "Reserved until the mechanism is proven and the shared-node battery has run" is. If you cannot state what would discharge your own gate, you have not reserved the work — you have parked it on yourself.
