## ⛔ THE MAIL CHANNEL — WHAT THE HOOKS ACTUALLY DELIVER (hq_C + hq_P, 2026-08-23 s261, verified both ends)

⭐ **THE COMA IS CLOSED AT BOTH ENDS, AND IT IS CLOSED BY THE HARNESS, NOT BY A SEAT'S INTENTIONS.** Two hooks in a seat's `.claude/settings.json`: **`UserPromptSubmit`** runs `s4e_inbox_hook.sh` and prints unread senders + subjects **above the seat's first tool call**, and the **`Stop`** hook fires `s4e_msg.sh banner`, which **also reports unread**. So mail is surfaced **before a seat starts work and again before it goes idle**. ⛔ The hook prints **headers only, never bodies** — piping `check` straight in costs ~10k tokens every single turn and trains a seat to skim past the thing it exists to surface.

⛔ **BUT "IMMEDIATE CHANNEL" OVERSTATES IT, AND THE OVERSTATEMENT IS NOW MEASURED.** `UserPromptSubmit` fires **only on prompt submission**, so it **cannot see mail that arrives mid-turn**. A message sent to a seat already working sits unread until that seat either finishes (Stop banner) or happens to run an `s4e_msg.sh` command — `send` prints an unread banner as a **side effect**, which is what actually caught Lon's own delivery test, i.e. the catch was **lucky rather than designed**. ⭐ **The honest guarantee is therefore ONE TURN OF LATENCY, NOT IMMEDIACY:** nothing interrupts a running seat, and turns can run very long. That is a bounded, acceptable delay — but do not write, or believe, that THE LOOP step 1 delivers a message *now*. True mid-turn delivery would need a different mechanism than either hook.

⭐ **AND THE REASON THIS IS A RULE AND NOT A NOTE:** a queue-depth or empty-mailbox check measures the **PRODUCER** and can never see the **CONSUMER** — an empty mailbox and an unread mailbox read identically. **PRESENCE IS NOT PROOF.** The only sound readiness condition is a **round trip**: a message sent to a running seat is *demonstrably read*, evidenced by a receipt.

Keep the mapping exact and never round it into a different claim: `p% faster` ⇒ `1 + p/100` and `p% slower` ⇒ `1 − p/100`. ⛔ A percent must also name **what it is a percent OF** — "24.3% faster **than we were at session start**" is a claim; "24.3% faster" alone is not.
  - ⭐ **IN A GRID THE AXIS IS NAMED ONCE, IN THE HEADER** (`× vs SPITBOL`), and **the rows carry bare multiples**. A column that argues its direction row by row has stopped being a column.
  - ⭐ **COLOUR WHERE THE MEDIUM SUPPORTS IT (Lon, s266): BELOW `1.00x` IN RED, AT OR ABOVE `1.00x` IN GREEN.** Colour is a **second** channel and never the only one — every number must still read correctly with the colour stripped, because it will be: pipes, logs, CI capture and `less` all lose it. **Terminal output:** ANSI (`\033[31m` / `\033[92m`) via `SCRIP/scripts/lib_perf_fmt.sh`, which is the ONE AUTHORITY for printing a multiple (`perf_mult`, `perf_pct`, `perf_row`) — a harness that cannot load it must REFUSE rather than invent a private format, same law as `lib_oracle_flags.sh`. **Markdown:** a table cannot carry colour on GitHub, so when the colour signal matters more than the grid, use a ` ```diff ` fence — lines opening `-` render red and `+` render green — and keep the multiple itself unchanged inside it.
  - ⛔ **APPLES TO APPLES, AND THE DIRECTION DOES NOT SATISFY IT.** Rows share a grid only when they share: the **instrument** (Ir at fixed work, or wall clock — never mixed); the **basis** (a SLOPE is not a TOTAL — a total carries process startup and may never share a column with a slope); the **`RT_OPT` arm**; the **mode** (m3/m4); the **ζ selector**; and the **oracle binary + flags** (`sbl_clean_bin()` for timing, never the ~2.3x-handicapped `x64/bin/sbl`). ⭐ **INPUT is per-ROW** — each row names its own file — **but its KIND may not vary down the grid:** a `.input` grading run and a `.dat` throughput run answer different questions and never share a table. **State the shared axes in ONE line above the grid.** A grid without that line is unreadable; a grid that contradicts it is a **false table**, not a rounding problem.
  - ⛔ **A NUMBER'S TREE IS PART OF ITS LABEL.** Never head a column with a SESSION that did not produce it: a baseline measured this session on last session's tree is **this** session's number, and mislabelling it attributes work that never happened — and can silently equate two different workloads.
  - ⛔ **CONVERSION IS ARITHMETIC (`new = 1 / old`) AND NEEDS NO RE-RUN — but only when the old ORIENTATION was stated.** Orientation unstated ⇒ re-measure or drop. ⛔ **And a number carried into a NEW column must be RE-MEASURED, not copied:** copying asserts a currency nobody checked.
  - **Enforcement:** the reviewer rejects any multiple carrying the word `faster`/`slower`, any "Nx slower" phrasing, any grid mixing a slope with a total, and any grid without its shared-axis line.
- **⛔ CONFIGURATION-AXIS LAW (proposed hq_C s258; landed CEO s259, 2026-08-22 — the session's one law):** a correctness verdict must name EVERY configuration axis it was taken on (RT_OPT arm, mode m3/m4, ζ selector, oracle + flags), and a verdict on one arm of a selectable axis is a verdict about THAT ARM ONLY — never about the product. Extends O0-DEV-O2-BENCH's labeling duty from perf numbers to correctness verdicts, where it matters more: a mislabeled perf number is merely wrong, while an unlabeled correctness verdict closes a milestone that is still broken. Evidence: RUNG C-0 reported CLOSED on `-O0` evidence alone while `-O1`/`-O2` remained broken (278-byte beauty self-host, both media); Lon caught it from memory before the second arm was measured. Enforcement: gates print their arm (`test_gate_m1_self_host_fixed_point.sh` prints RT_OPT since s258, ratified); review rejects any CURED/DONE/PASS claim omitting an axis the build selects.
- **⛔ SNOBOL4 SOURCE READS LIKE PROSE — NAME-16 (Lon, 2026-08-21 in-chat, s249):** every NEW SNOBOL4/Snocone program we write — benchmarks, crosscheck cases, smokes, demos, probes — uses **descriptive lower-case identifiers of ordinary length, and SPELLS THE THING OUT instead of encoding it.** (a) **≤ 16 characters** is the ceiling for a variable, label or function name — the 6/8/12-character ceilings that shaped 1960s SNOBOL4 style are gone and their cryptograms go with them; `ZKN`, `ZBL`, `ZE`, `ZD` are what we are getting away from, and a 30-character Java-ism is the opposite error, not the cure. (b) **Say what it is:** `iterations`, `batch_size`, `elapsed_ns`, `check_value` — not `ZKN`/`ZK`/`ZE`. A reader should not have to decode. (c) **Lower case for everything WE name** — variables, labels, program-defined functions. ⛔ The language's own spellings stay UPPER: `OUTPUT`, `INPUT`, `DEFINE`, `END`, `TIME`, `LT`, `SIZE`, `&TRIM`, `:S()`/`:F()` — SCRIP is case-sensitive and `sbl -bf` is the only correct oracle arm (s189), so `output` is NOT the builtin and never will be. The wall-to-wall UPPERCASE in the existing corpus is a card-punch fossil, not a requirement. (d) **Code horizontally to the 200-character margin** and start a new line only when the margin is hit — the same margin the C style already uses; do not wrap early out of 80-column habit. Enforcement: applies to NEW programs on sight; existing corpus is converted only when a rung already owns the file — a mass rename would rewrite `.ref` provenance for no gain, and provenance is the thing this project has been repeatedly bitten by. ⭐ **s264 addendum (Lon, in-chat): never name your own identifiers `null`, `epsilon`, or `dummy` — they are "RESERVED but NOT REALLY"** (engine lore claims them: the ε null pattern, the lambda sugar's implicit `dummy` NRETURN target), *"you would be a DUMMY if you tried to use them."* The engine keeps its own synthetic names ANONYMOUS regardless (NAMESPACE LAW), so a collision can only ever confuse a reader — never change a program's meaning.

LIMITATION (all rules above): a markdown rule cannot coerce compliance; it makes the correct thing cheap, visible, and checkable. The human reviewer is the enforcer — reject handoffs that violate them.
