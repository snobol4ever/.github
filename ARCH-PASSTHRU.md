## THE LAW (amended per Lon 2026-08-20 in-chat, verbatim in substance — the pass-thru marching orders)
0. **PARTITION BY ACTIVATION.** The unit of pass-thru is the ACTIVATION — a closed set with exactly TWO exits (γ succeed, ω concede). Every seam question is asked and answered at an activation boundary, never mid-box.
0a. **THE PUSH-PAIR MOVE — THE way to move, almost everywhere (Lon: "the wonderful trick").** At a crossing, push γ and ω on the stack as RETURN LOCATIONS; the exit CHOOSES by a pop/ret combo (the RETURN/FRETURN trick) depending on which way it goes. ⛔ **ONE MECHANISM, NOT TWO (Lon 2026-08-20 follow-up): EITHER r10/r11 always-live OR the stack pair + pop/ret — never both.** Today the tree pays for both: r10/r11 claimed machine-wide AND the pair spelled to the stack at every suspension (blob head rbp−8/−16, γ-records push {res,r10,r11,rbp}, rtccb+56/+64 spill/reload around every C call). ⛔ **RULED (Lon 2026-08-20 in-chat): THE STACK PAIR WINS — r10/r11 are FREED (two registers back).** The pair is stored ONCE, right at RBP ([rbp+8]=γ, [rbp+16]=ω, pushed by the caller before entry); exits are the RETURN/FRETURN adjust/ret trick (γ: `mov rsp,rbp; pop rbp; ret` + landing owns `add rsp,8` · ω: `mov rsp,rbp; pop rbp; add rsp,8; ret`); γ-suspend keeps the frame and pushes the retained rbp as the ONE-SLOT β-handle; β re-entry = `mov rbp,[rsp]; jmp [rbp−16]` (the frame's own resume slot). "The registers looked cool, but then you stored them — should have just stored in the first place." (Original recommendation text kept below for the record:) the STACK PAIR WINS and r10/r11 are freed — (1) the pair is activation state and the stack is where activation state lives: pushing IS the banking, β finds the pair at a fixed offset in its own activation; (2) registers do not survive interior C calls (the whole rtccb veneer tax) while stack slots need no protection; (3) exits get cheaper (γ = `ret`, ω = `add rsp,8; ret`); (4) the machine is register-starved — two GPRs back. Migration is per-crossing-protocol, measured, one rung each.
0a′. **⛔⭐⭐⭐ TWO EXIT FORMS, NOT ONE — RETIRE vs SUSPEND (Lon 2026-08-20 s195 in-chat, stated and then self-corrected within the slice; the correction IS the law).** Lon first specified *"the CALLER will do PUSH F; PUSH S, and the CALLEE will do the same as RETURN and FRETURN labels in the emitted code,"* then corrected: *"that is only if returning. If you are yielding, i.e. suspending, it is different. Then you just load the address and JUMP."* **Correct, and it is the whole defect.** The two cases have OPPOSITE FRAME LIFETIMES and cannot share one exit: **RETURN (γ, done)** the frame RETIRES — restore depth from the frame, then `ret` (pops S), landing owns `add rsp,8`; **FRETURN (ω, done)** retires — restore depth, `add rsp,8`, `ret` (pops F); **γ-SUSPEND (yield)** the frame STAYS ALIVE — **load the address and `jmp`**, pair and frame both stay put because β must still find them; **β re-entry** = `mov rbp,[rsp]; jmp [rbp−16]`. ⛔ **MEASURED s195: the tree emits ONE form for both** — `bb_glue_wire_exit()` is `jmp [rsp+0]`/`jmp [rsp+8]` with the landing owning `add rsp,16`, **and it carries NO depth restoration at all**, so every callee that carves locals reads its own locals as a continuation address. **`SCRIP_WIRE_STACK=1` measures 1/82 on the class 0–9 grid, both modes** (default arm 82/82), isolated to the EMITTER half — identical collapse with a `-DSCRIP_WIRE_STACK_RT` runtime. The s194 rungs proved their OFF arms only (*"off-arm byte-identical over 80 programs"*); **a killswitch proven inert proves the killswitch, never the feature.** ⭐ The discrimination already exists in ONE box and is the migration precedent: `bb_define.cpp:250-255` restores rsp from a saved entry-rsp slot (`mov rsp,[rsi+AB_OFF_ERSP]`, stored `:76`) and selects the port by `cmp AB_TC_REG_D, AB_TC_FRETURN ; je L6`. Make that the ONE authority; do not re-spell it per crossing. See `FINDING-2026-08-20-s195-the-stack-pair-was-never-run-and-one-exit-form-cannot-serve-return-and-yield.md`.
0b. **RBP CORRECT AT β, EVERY BOX.** Save/restore logic ties to the γ/ω transitions; a box whose β runs with a stale RBP is a defect regardless of whether the run happens to survive.
0c. **THE THREE-TIER ESCALATION LADDER (storage is a ladder, never a choice).** (1) **RSP**: fixed offsets computed from the position in the execution sequence of the operand boxes that led to the operator box. (2) When an operator BB must reach PAST AN UNKNOWN NUMBER OR TYPE of BBs it CANNOT use RSP — escalate: allocate a SLOT in the RBP activation frame. (3) When RSP and the RBP frame both fail, the slot allocates at the **STANDING (base) frame with ONE indirection** — the standing pointer is passed down in every frame precisely so this tier always exists. The standing activation (`S ? P`) is special: its pointer rides all the way down for MATCH_BEGIN housekeeping.
0d. **NO-DENY LAW.** A failure case is never denied — no admission filter, no shape refusal, no "unsupported" arm. Stop the world, minimize, fix it.
1. **TWO CONTINUATIONS, ONE DISCIPLINE.** Every BB graph's external contract is the pair {γ-continuation, ω-continuation} riding the r10/r11 wires. EVERY crossing between graphs = bank the caller's pair, install the callee-relative pair, run; the callee's γ/ω restore the banked pair. Nothing else may carry cross-graph linkage: no pushed landing pads, no flat depth assumptions leaking across the seam, no per-road glue.
2. **THE PAIR IS ACTIVATION STATE, NOT A CALL ARTIFACT.** Graphs suspend (γ) and are re-entered (β). Whatever holds the suspension holds the banked pair, and β re-entry reinstalls it — "switching back as they move" holds in BOTH directions. Existence proof already in-tree: the PAT$ blob head (`blob_frame_bytes`: saved rbp @+0, γ wire r10 @−8, ω wire r11 @−16).
3a. **⛔ THE RESULT LAW, STABILIZATION FORM (Lon 2026-08-20 in-chat, amending 3): EVERY BB ALLOCATES A RESULT SLOT — uniformly, register-resident results included — TEMPORARY UNTIL STABILIZED.** The point is the calculation: uniform allocation makes slot number = box index and carve = n_boxes × granule, so the offset math has NO per-box cases and NO candidacy — the registry's candidate scans (the last admission machinery) go dead. A register result may stay CACHED in its register; the cell exists regardless, so a consumer can never find no home ("caught ahead of time"). Frame bloat is accepted scaffolding; after the pass-thru ladder stabilizes, cells un-allocate box-by-box, each with its own measurement — never wholesale, never by filter.
3. **⛔ THE RESULT LAW (Lon 2026-08-20).** EVERY BB has a RESULT and a DECLARED HOME for it (a register or a cell named by the lattice) — declared at compile time, uniformly, so a consumer can never discover a missing result at runtime. The s174 operand-slot flat read (needle read resolving to caller territory inside an ALT arm) is the conviction: a result whose home was an assumption. Register-resident results are fine — the law is that the home is DECLARED, not that it is memory. Enforcement joins the ZDP lattice (the one per-box ζ-semantics authority, `zeta_depth.c`) and the ZDP/ZSM/canary instruments check declared-vs-actual.

## PROVENANCE STAMPING — Lon's s181 idea, MEASURED (why the byte cannot go in the DESCR, and where it must go instead)
**The idea (Lon, in-chat):** stamp the producing BB's NODE ID into the DESCR, so a value says who made it. **Refined by Lon in the same slice, and this is the load-bearing half: "at β you want to check something ... you cannot depend on RBP to check RBP. Chicken-egg."** Correct, and it is the governing constraint for every frame-integrity instrument: a check whose witness is reached THROUGH the register under test is not a check — if the register is wrong the check reads garbage and may pass. The witness must be OUT OF BAND. (The ZSM already obeys this by accident of design: the node id arrives as an IMMEDIATE in the emitted event call and the expected frame lives in a side table keyed by that id, so nothing is validated through the register being validated. s179's ZSM-ALL extended that to every box.)
**MEASURED, at SCRIP s181 (`src/contracts/descr.h`, receipts by compiled offsetof probe):** `sizeof(DESCR_t) == 16` — `v` (DTYPE_t, 4B, offset 0) + `slen` (uint32, 4B, offset 4) + payload union (8B, offset 8). **There is NO padding hole.** Lon's own refinement that a node id needs TWO bytes (correct — the ZSM hashes `node & 65535`, so 16 bits is the real width) makes the fit strictly harder. The three candidate homes and why each is closed TODAY:
1. **High bits of `v`** — ⛔ **RE-OPENED BY LON, SAME SLICE, AND HE IS RIGHT: "DT_NOTSTR_MASK is not really reserving them, it could use some leading zeroes there."** The mask is a CONSTANT, not a constraint. Narrow it from `0xFFFFFFFD` to `0x0000FFFD` and the string test examines only the low half, leaving **bits 16-31 of `v` free — exactly the two bytes a node id needs, and exactly the width the ZSM already hashes to (`node & 65535`)**. HQ's first pass called this CLOSED by reading the mask as load-bearing; it is not, and the measured blast radius is small: `DT_NOTSTR_MASK` has **9 references in the whole tree** — 7 inside descr.h (the definition, its commentary, and three `static_assert`s that all stay true under narrowing) and 2 RTX asm readers (`rtx_match.S`, `rtx_arith.S`) that use the macro BY NAME and inherit the narrowing for free. THE REAL COST, named honestly so the rung is priced: (a) the joint-tag forms `and eax,ecx ; cmp eax, DT_I` / `DT_R` (BOTH-INT, BOTH-REAL) compare the FULL 32 bits, so two stamped tags AND to a stamped result and the compare fails — they must become 16-bit operand forms (`and ax,cx ; cmp ax, DT_I`), which is template-only, both-media encoder work at ~20 candidate sites; descr.h's own warning that the string tests must NOT be 8-bit is satisfied by 16-bit, since the tag magnitude (stride-8 user datatypes top out near 0x248) fits in 16 bits with room; (b) the bit-tests (`test eax, DT_NUMERIC_BIT` / `DT_REAL_BIT` / `DT_CHARS_BIT`) and BOTH-NUMERIC's 8-bit `test al` are unaffected by a high-half stamp and need no change at all. **VERDICT REVISED: candidate 1 is OPEN and is the cheapest home for a value-borne node id.** What follows below about value IDENTITY still stands and is the remaining real item, but it too is narrower than first stated — see it. (Original CLOSED reasoning, kept for the record:) the tag algebra in descr.h is built on "no other bits set". `DT_NOTSTR_MASK = 0xFFFFFFFD` and the is-string test is `test eax, DT_NOTSTR_MASK -> Z`. Any stamp in the upper bits makes every stamped string STOP BEING A STRING. The same file already warns the tests must be 32-bit because user datatypes run past one byte, so the upper bits are not spare, they are RESERVED for the tag's own magnitude.
2. **`slen`** — CLOSED: fully used for strings, and OVERLOADED as a discriminator for DT_N (`IS_NAMETRAP_fn`: slen==2; slen==1 ptr; slen==0 name).
3. **Payload union** — CLOSED: pointers.
**AND THE REMAINING REAL ITEM — VALUE IDENTITY (narrower than HQ first stated; census: TWO memcmp sites tree-wide, and NO whole-DESCR hashing exists for table keys):** `runtime/values.c` compares descriptors with a whole-struct `memcmp(&a,&b,sizeof(DESCR_t))` on its fallback arm. A provenance byte makes two semantically EQUAL values compare UNEQUAL, which reaches IDENT, table keys, and equality. Any DESCR-borne stamp must therefore be ignored by that comparison — but it is ONE function, not a systemic sweep: the fallback becomes an explicit field compare with `v` masked to its low half. Grep receipt: exactly 2 `memcmp` sites touch a DESCR tree-wide (this one and the rtx golden battery), and no table-key path hashes the struct wholesale.
**⭐ THE RULING THAT FOLLOWS — STAMP THE CELL, NOT THE VALUE (the ζ-cell header / STACK DOPING this file already owes under INSTRUMENTS).** A ζ cell is compiler-private: never compared, never hashed, never GC-identity, and its size and offsets are computed by ONE authority (`zdp` / `zw_carve_k`), so widening it under a killswitch is a planner change, not 129 template edits. Write `{magic, nid16, op8, depth}` at α-carve; at every operand read, compare the header against the compile-time immediate the consumer already knows. **This satisfies the chicken-egg constraint exactly:** the consumer derefs the address it was ALREADY going to use, and if that address is wrong (stale RBP, wrong base, wrong offset) the magic/nid mismatch is the report — no correct RBP is required for the check to be valid. It also detects the case a value-borne stamp structurally cannot: reading something that is NOT a descriptor at all (the s177 wound read a banked γ wire — a code address — and got pc=0x1; a doped cell header names that instantly, a DESCR stamp is simply absent).
**WHAT THE VALUE-BORNE STAMP WOULD STILL BUY, kept for the record:** provenance that survives ESCAPE — a value copied into a GVA cell, table, array, or stored pattern outlives its cell, so "who produced this wrong value three statements ago" is answerable only by a value-borne mark. Cell doping answers PLACEMENT (across space); value stamping answers PROVENANCE (across time). The recent wall census is overwhelmingly placement. **If the time axis is ever needed: do NOT carve into the 16 bytes — build a DEBUG-WIDENED 24-byte DESCR behind a build flag.** The 16-byte stride is baked into emitted code (`RT_GVA_VA + k*16`, FRQ offsets, blob head layout), but every one of those is COMPUTED BY THE EMITTER, so a compile-time widening is mechanically reachable: everything recompiles and re-emits, and no shipped byte changes.
