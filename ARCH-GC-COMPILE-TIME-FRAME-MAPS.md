## 1. What is on the stack today, and why guessing became corruption

Three kinds of memory, measured at SCRIP `db4a6b1fc`:

1. **Zeta slots in emitted frames** — ζ-ACTIVATION-FRAME on RBP, ζ-SPINE on RSP. The compiler lays every slot out in `src/ir/frame_layout.c` and records its kind in `zls_field_t.kind`: `ZK_DESCR` (a 16-byte descriptor), `ZK_PTR_GC` (a raw 8-byte pointer into the collected heap: bucket vectors, field arrays, array data), `ZK_RAW` (counters, cursors, watermarks, saved rsp — never a pointer). 64 registrations today. The compiler knows every slot's kind and never tells the collector.
2. **The runtime's own C frames** — locals of `rt_*` functions holding a raw heap pointer across a call that can collect. The 24-site register-spill class (CEO-803) and hq_prolog's twelve stress SIGSEGVs are this kind.
3. **Registered slots** — coexpressions (`rt_coexpr.c`), the Prolog trail (`rt_pl_trail.c`), `rtcc_init.c`: precise, registered through `rt_gc_slot_reg`/`rt_gc_root_range_add`. This path is correct and is the model.

`gc_zeta_frame` (gc_heap.c:557–563) walks every registered range word by word: 16 bytes that parse as a valid descriptor are visited precisely; otherwise each 8-byte word is handed to `gc_blk_of`, and any word inside a heap block is MARKED and its slot REGISTERED FOR REWRITE when the block slides. That is the Boehm guess, and worse than Boehm: Boehm never moves, so a wrong guess leaks; here a wrong guess moves the block and overwrites a word that was an integer or the length-and-tag half of a descriptor. Under the pinned class the guessed blocks did not move, so the guess cost nothing; deleting pinning (CEO-803, `3b79683b5`) turned the leak into gc2. hq_icon measured it: 100–270 guessed words rewritten per collection on gc2; under `setarch -R env -i` with equal-length knobs the verdict is a function of the stack offset alone (BAD over a band of 32 of 64 offsets; a mark-only arm halves the band to 34..49 and cannot close it, because mark-only stops relocating genuine roots too). The poison detector does not reach this defect (0 of 36): a block that slid DOWN leaves its old bytes inside live data.

## 2. The design: compile-time maps, and the allocator never collects

**Rule 1 — the map is compile-time data.** For every safe point (§ 3) the emitter writes a static table entry beside the code, in BOTH media (in the sealed mode-3 slab; in `.rodata` under a label in mode 4): `{ return-PC, spine depth at that PC, [ (offset, kind) for every live slot of the RBP frame and the RSP spine at that PC ], [ callee-saved registers that hold a ZK_DESCR/ZK_PTR_GC at that PC ] }`, generated from `zls_field_t` and the emitter's own knowledge of which registers it assigned. Nothing is built at run time; there is no registration call per activation. Keyed by return PC, the collector finds each frame by walking the RBP chain (the runtime is `-fno-omit-frame-pointer`; emitted activation frames are RBP frames by the BB FRAME-PLACEMENT CRITERION) and binary-searches the table.

**Rule 2 — the collector walks maps, not words.** `gc_collect_ex` visits exactly the slots the map names: `ZK_DESCR` through `rt_gc_visit_descr`, `ZK_PTR_GC` through `rt_gc_visit_raw`, `ZK_RAW` never. The word scan, the 16-byte descriptor sniff, `cons_stack` and the `rt_cas_live_span` byte scan are DELETED, not gated. Coexpression stacks are chains of mapped frames walked from the coexpression's saved RBP. Registered slots (kind 3 above) stay precise roots.

**Rule 3 — the allocator never collects.** Today `rt_gcheap_alloc` (gc_heap.c:206–207) calls `rt_gc_collect` from inside the runtime, with every runtime C frame live and unmapped — which is the only reason kind 2 was ever scanned. Under this design the allocator sets `g_gc_pending` (it already exists and is already set by the stress and budget pacers) and, when the line is crossed, GROWS the arena window rather than collecting; the collection runs at the next safe point, where the only live C frame is the poll's own call into the collector. Therefore no runtime C frame is ever scanned, and the 24-site spill class and the twelve SIGSEGVs are cured by construction rather than site by site. The arena must be growable to the next safe point; the bound is one runtime call's own allocation (a `DUPL` of a gigabyte grows the window by a gigabyte and the next safe point compacts).

**Rule 4 — the one residual, enumerable.** A runtime C frame that CALLS BACK into emitted code (`by_name_dispatch.c`, `gen_runtime.c`: APPLY, EVAL, by-name calls, sort comparators, generator resumption) has a safe point BELOW it on the stack. Such a frame may not hold a raw heap pointer across the callback: it registers the slot precisely (the coexpression way) or re-reads through a handle after the callback returns. These sites are found by grep of the callback entry points, not by scanning; a gate censuses them.

Do you see the problem in which I refer? The alpha/omega transitions would have to be known, i.e. the path would have to be known at the time GC began and you would have a graph not just a linear map."* He is right, and Rule 1 as written above is WRONG for the ζ-SPINE: a per-PC map describes only the box that is executing. What lies below it on the RSP spine is the residue of every box that suspended on the way — after an alternation the spine holds arm A's records or arm B's, at the same PC; ARBNO leaves one record per iteration; a recursive procedure interleaves activation frames. The spine's shape at a safe point is a function of the α/β/γ/ω history, a path through the graph, and no static table keyed by PC can name it.

**The cure is not to know the path; it is to make the spine describe itself, cell by cell — Lon's "I thought they were all DESCR" made true.** Rule 1 is replaced:

- **Rule 1a — THE ζ-SPINE IS TAGGED CELLS ONLY.** Every spine cell is a 16-byte descriptor-shaped cell whose tag word (`d->v`) is always valid: `DT_S`/`DT_N`… for values (the collector visits `d->s` precisely, exactly as `rt_gc_visit_descr` does today), and a `DT_RAW` tag for every counter, cursor, watermark, saved RSP and code pointer a box keeps (`ZK_RAW`, `ZK_PTR_CODE` — 95 of the 120 `zls_field` registrations today; the payload rides in the cell's `s`/`slen` words and is never visited). A box writes a cell's tag when it pushes the cell, before anything can collect. The collector walks the spine from RSP to its base as an array of cells, reading tags: precise, path-independent, no map, no sniff, no guess. `ZK_PTR_GC` raw pointers on the spine (7 registrations: bucket vectors, field arrays) become `DT_A`/`DT_T`-tagged cells or move to the RBP frame.
- **Rule 1b — THE RBP ACTIVATION FRAMES ARE MAPPED PER CALL SITE** as § 2 Rule 1 says: a call frame is path-independent within itself (one layout per graph, one return PC per call), so the emitter's compile-time table keyed by return PC over the RBP chain is exactly right THERE, and only there. Where a frame slot is itself a tagged cell, the map may say so and the collector reads the tag.
- **Rule 2b — THE HEAP IS TYPED VISITORS, NEVER A WORD SCAN (the cfo's gap, measured at gc_heap.c:619–621):** the mark worklist hands every `HB_WS`, `HB_DINST`, `HB_ARR` and `HB_PLJ` payload to the same `gc_zeta_frame` word walker — a heap-interior sniff with the same raw-word rewrite (hq_raku's `DATINST_t.type` reading 0xdbdbdbdb after a slide is that scan skipping a slot inside an `HB_DINST` block, not a stack root; `SCRIP_GC_COVERAGE` counts ranges, not worklist payloads, so it would read 0 while this remains). Every block kind gets a TYPED visitor: `HB_DINST` = one type pointer plus n descriptors (already the layout), `HB_ARR` = proto + data (precise through `DT_A`), `HB_PLJ` = the trail's registered layout; `HB_WS` — the raw workspace `rt_ws_alloc` hands to ~336 sites for mixed use — has no layout and is SPLIT BY ALLOCATION SITE into kinds that do (a per-site kind at the allocator is the heap twin of the frame map); `hb_scan_interior` is deleted with the stack scan.

**What this does to the rows:** the cto's load-bearing row becomes the SPINE-CELL DISCIPLINE (every spine cell pushed with a valid tag; `ZK_RAW`/`ZK_PTR_CODE` payloads in `DT_RAW` cells; `ZK_PTR_GC` re-shaped; the per-PC table kept for RBP frames only); the cfo's collector row walks the spine by tags and the RBP chain by map and the heap by typed visitors; the `HB_WS` split is a new row (the cfo's, the runtime side); the coo's coverage counts worklist payloads too. Cost to measure, not assume: a tag store per pushed cell on the pattern-match hot path, and spine growth where an 8-byte raw word becomes a 16-byte cell (two raw words share one cell where they are pushed together, as `span.cnt/cur`, `bal.n/start/depth`, `to.I counter/limit` already are).

## 3. Lon's question: how are the safe points chosen?

Not by box. `MATCH_BEGIN`, `MATCH_END` and every other box kind are irrelevant to the choice. **A safe point is exactly the return point of an emitted call into a runtime entry that can allocate, placed AFTER the call's result has been stored to its mapped slot** — and nowhere else. The reasons:

- **It is where collection is needed.** Memory is consumed only inside allocating runtime calls; a box that never allocates never needs a safe point; a program that allocates nothing never collects. Loop back-edges need no poll because a loop that allocates passes a safe point every iteration by construction.
- **It is where the map is knowable.** At a call's return PC the spine depth is a compile-time constant (RESULT/LOCALS live on the RSP spine only where every consumer reaches them at a fixed compile-time offset — the FRAME-PLACEMENT CRITERION already guarantees it), the RBP frame's layout is `zls_field_t`, caller-saved registers are dead across the call, and the callee-saved registers the emitter assigned are known. Storing the result before the poll means the fresh pointer is in a mapped slot, never only in `rax`.
- **It is cheap.** The poll is `cmp dword [rip+g_gc_pending], 0 ; jne slow` — the shape `bb_call_proc_staged.cpp` already emits at the staged call boundary — beside a call that just allocated. The slow path spills the callee-saved registers to a known frame and calls the collector with the map key.
- **It is complete.** Because Rule 3 removes every other collection site, the set of safe points IS the set of allocating call returns; a runtime entry that allocates and has no poll at its return is the gate's red (a census over the runtime's allocating entry points against the emitter's poll sites), and the residual of Rule 4 is the only other place a collection can begin.

The compiler already annotates one field *"dead at safe points"* (frame_layout.c:107): the notion exists; this design makes it the whole root policy.

## 6. The map format — FIXED 2026-09-17 10:5x CDT by the cto under § 7 F1 (hq_icon is paused, CEO-814; CTO-65), frozen with the page

§ 7 F1 replaced "a table keyed by return PC" with "everything on the emitted stack is a DESCR", so the map is no longer a per-safe-point slot list: the cells describe themselves, and the map carries only what a cell cannot — where the frame's one non-DESCR (the return address `call` pushed) sits, and which graph the frame belongs to. Measured on SCRIP `162e8a172` before anything was written: a procedure frame already reserves `[+0,+16)` for the RETURN/SUSPEND value (`frame_layout.c:454`, `bb_return.cpp:22`), params start at `+16`, and every activation frame carries a raw WIRE HEADER at its top (`[kt-24]=γ`, `[kt-16]=ω`, `[kt-8]=caller base`; `xa_flat.cpp` zframe prologue, `emit.cpp:3158` the lcl_proc prologue) directly under the return address; `main` is `sub rsp, 65544` with no header and two raw words (`push rdi; push rsi` = argv/argc) below it. So the map cell goes at the frame's TOP, not its bottom — no existing offset moves.

**6.1 Two type codes, no more (`descr.h`, `descr_tags.inc`, verified by `util_tag_layout_verify.py` like every other tag):** `DT_RAW = 0x98` — a cell whose `slen` and payload word are a value-never-a-pointer (a counter, a cursor, a saved rsp/rbp, a code pointer, a watermark); the collector never visits it. `DT_MAP = 0xA0` — the map cell; the collector never visits it as a value but reads it as a frame boundary. Both carry `DT_NOTSTR` and no `DT_NUMERIC_BIT`; a static assert pins them above `DT_ORDER`; the three open-ended `v >= DT_DATA` tests in the tree (`driver_data.c:440`, `core.c:3798`, `by_name_dispatch.c:6149` — each already admits `DT_BIG`..`DT_ORDER` and survives only by a second guard) take an explicit `v < DT_RAW` bound in the same landing, and the assert names them. Nothing else is added: a counter a box already mints as `DT_I` stays `DT_I`; an outer Σ/Δ pair a pattern box saves is a `DT_S` cell `{ v=DT_S, slen=Δ, s=Σ }`, exactly the string descriptor it is, so the collector visits and relocates the suspended subject precisely (today it is `push r13` — an 8-byte raw word that only the conservative sniff ever found).

**6.2 The map cell (one per activation frame, written by the prologue, never rewritten):** a `DESCR_t` at frame offset `map_off = frame_bytes - header_bytes - 16`, i.e. the highest cell of the frame, immediately under the raw wire header and the return address:

```
{ v = DT_MAP, mint_op = 0, src_node = 0, slen = frame_bytes, p = &<graph's static map> }
```

`frame_bytes` is the prologue's `sub rsp, N` (so `map_cell + 16 + header_bytes` is the return address slot and `map_cell + slen` is the caller's RSP after the return address is popped — the walker needs no division and no lookup to step to the next segment cell); `header_bytes` is 24 for a wired frame, 0 for `main`. Because the walker reads cells UPWARD from the safe point's RSP and every cell below the map cell is a DESCR (F1), it needs no frame size in advance: it visits cells until it meets `DT_MAP`, then skips `16 + header_bytes + 8` bytes and continues in the caller's segment. `main`'s frame grows by 16 (65544 → 65560, still ≡ 8 mod 16) to hold its cell, and its `push rdi; push rsi` becomes one `DT_RAW` cell `{ slen = argc, p = argv }` (the two readers at `rt_main_progname_stage`/`rt_main_args_stage` move by a word).

**6.3 The static map (32 bytes, one per graph, `_Static_assert(sizeof(gc_frame_map_t) == 32)`):**

```
typedef struct gc_frame_map_t {
    uint32_t magic;          /* 0x50414D5A 'ZMAP' — the reporter refuses a cell whose map lacks it */
    uint32_t frame_bytes;    /* == the map cell's slen; the double-entry the census compares */
    uint32_t header_bytes;   /* 0 (main) or 24 (γ, ω, caller base) */
    uint32_t flags;          /* bit 0 ROOT: this frame is the base of a segment (main, a coexpression entry, the mode-3 outer thunk's callee) — the walker stops here instead of stepping through the return address */
    const char * graph_name; /* the frame_layout graph name, for the reporter and --dump-zeta */
    uint64_t reserved;       /* 0, AND IT STAYS 0 — see 6.5a: it is NOT the register mask. A later field lands here without moving the assert, but not that one. */
} gc_frame_map_t;
```

It is emitted in BOTH media through the ONE mechanism the emitter already has for static quads beside the code — the internal-slot pool (`x86_ro_seal_q` → a `D` record sealed in the slab in mode 3, `.Lx<uid>_<n>: .quad` in mode 4; `x86_lea_rip_id` takes its address either way) — four sealed quads at the graph's prologue node; the prologue does `lea rax, [rip + map]` and stores the cell. No `.rodata` section and no runtime-built structure: mode 4 shows the map as `.quad` lines directly under the prologue label, mode 3 seals it into the slab between the same two boxes.

**6.4 The program table and the one exported symbol:** the driver emits `__gc_frame_maps` (a `.quad` list of every graph's map address, `.align 8`, after `__label_names`, mode 4) and installs it from `main`'s prologue exactly as `__label_names` is installed: `lea rdi, [rip + __gc_frame_maps]; mov esi, <n>; call rt_gc_frame_maps_install@PLT`; in mode 3 the driver calls `rt_gc_frame_maps_install` itself after `bb_seal` with the sealed addresses. **The one symbol is `rt_gc_frame_maps_install(const gc_frame_map_t *const *maps, int n)` (`src/runtime/rt/gc_heap.c`), and its reader `const gc_frame_map_t *const *rt_gc_frame_maps(int *n)`**; storage is file-static beside the collector, as the label table's is beside the driver (no new global). The collector's WALK never consults the table — it finds every frame through its cell — the table exists for the coo's maps census (every emitted prologue's cell names a map in the table and every map is named by exactly one prologue) and for `--dump-zeta`, which prints one `MAP` line per graph (`frame_bytes header_bytes map_off flags`) so the mode-3 reading and the mode-4 `.quad` reading are compared line for line by the census. A mode-3 dump flag beyond `--dump-zeta` is not needed and not added.

**6.5 What the map does NOT carry, and why:** no slot list (every slot is a DESCR — F1), no spine depth (path-dependent — § 2b, Lon's objection), no return-PC key (there is no per-PC anything), and NO REGISTER MASK: the callee-saved registers are made visible at the poll itself, not in a map. At every allocating return the poll's slow path (§ 3, F6 step 4) pushes a SPILL RECORD of tagged cells below the current RSP before calling the collector — one `DESCR_t` per callee-saved register the emitter knows to be live there, tagged by what the register holds AT THAT SITE (inside a pattern blob: `{DT_S, slen=r15d, s=r13}` for the subject, `DT_RAW` for `r12`/`r14`/`rbp`; in a Prolog frame `r12`=trail top, `r14`=the quad context address, `r13`/`r15`=choice/ball — all `DT_RAW`, none a collected-heap pointer; `rbx` is transient in the scan boxes and dead at every poll) — then reloads them from the record after the collector returns, so a relocated subject re-enters `r13` fixed up. The record is self-describing and the collector walks it like any other cells; the `floor` argument `rt_gc_collect_c` already takes is the record's lowest cell. The emitter knows the register facts per site at compile time (it assigned them); the collector learns them from the tags. Measured basis for the register facts (SCRIP `162e8a172`): `rtx_abi.inc` pins `r13`=Σ, `r14`=δ, `r15`=Δ; `rt_match_enter` returns Σ in `rax`→`r13` and Δ in `rdx`→`r15` (`bb_match_begin.cpp:136-137`), so `r13` is the ONE callee-saved register that holds a collected-heap pointer at an allocating return, and only inside a match; `rbx` = "arena heap top" in the same header is dead history (`rtx_alloc.s` never names it; the templates use it as a call-transient in `bb_scan_many/any/upto/bal` and as an rsp save in `bb_return`/`bb_suspend`).
