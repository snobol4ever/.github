# FINDING 2026-09-12 (cto, CEO-617, Prolog ISO ladder rung 1): a directive assert was never marked dynamic, a call-local cut pruned its caller, and the database builtins refused at compile time instead of raising the ISO error term

**Claim.** Three engine defects sat under the largest red classes of the Prolog ISO suites' database and control sections, and every one of them was in the lowerer, not the runtime. Measured on SCRIP `47c2fba7a` + this landing, against the coo's Logtalk board of 2026-09-12T15:59:54 (scrip `55aaa01ad`) and a per-goal INRIA probe of the same shape as the runner's.

## 1. `:- assertz(foo(1)).` raised permission_error(modify, static_procedure, foo/1)

`prolog_lower.c` marks a predicate dynamic when an `assert*` names it in a CLAUSE BODY (`pld_mark_scan(tr, mark_assertz)`), and since `be912e760` (rung 10b) it passed `!_isdir` -- a DIRECTIVE's asserts were deliberately not marked, because the pre-cut machine hoisted directive asserts into a static clause list and the hoist was being deleted. The hoist went; the exclusion stayed. So `t :- assertz(foo(1)).` worked and `:- assertz(foo(1)).` was refused as modifying a static procedure -- which is exactly the shape of every INRIA `asserta`/`assertz` goal (the runner wraps each goal in a directive) and of Logtalk's `{asserta(...)}` cases. Cure: mark from directives too (one argument). asserta_1 and assertz_1 went 4/24 -> 16/24 each.

## 2. A cut inside `call/1` pruned the enclosing clause's alternatives, and after the first cure it pruned nothing

`(call(!), fail ; true)` read failure (ISO 7.8.3.3: the cut is local to the call, so the disjunction's second branch must run). Two sites treated every IR_CUT as the clause's cut: `pl_lower_disj` turned a branch's redo into the clause barrier when ANY cut box lay in the branch, and `pl_lower_conj` rewired every cut's ω to the clause barrier. Marking the cut "opaque" (ival=1, which the template already reads to suppress the frame barrier) and skipping both rewires over-corrected: `((!, fail) ; true)` (same scope) then read success, and `call((p1(X), !)), write(X), fail` printed `123` because the goals after the call receded straight into `p1`.

The cure is a SCOPE STAMP, not a boolean: `lcx_t` counts barrier scopes (`cut_scope`/`scope_seq`, opened by the meta-call path and the catch/cleanup sites), every IR_CUT carries its scope id in `ival` (0 = the clause, nonzero = opaque -- the template's boolean read is unchanged), and both wirers prune only a cut whose id equals the scope they are lowering in. And the meta-call path no longer returns the inner goal's first box: it allocates one IR_GOTO `callω` as the call's fail continuation, lowers the goal as a conjunction with `callω` as its ωbase and cut barrier, and hands the conjunction its REAL redo point through `cx->meta_redo` (the inner conjunction's own `redo_out`: NULL after a cut with no generator behind it). The enclosing conjunction wires `callω`'s γ to the previous goal's redo like any GOTO and, when a redo was handed back, recedes into it. Measured, both modes: `1done` · `a-1 b-1 done2` · all nine `p1×p2` pairs · `1-x 1-y done4` · `alt` · `q6second`; ladder witness `call_n_call_of_cut_is_local` flipped; cut_0 13 -> 16, call_1 15 -> 16, if_then_else_3 and disjunction_2 unchanged.

## 3. `asserta(4)`, `abolish(foo/a)`, `clause(4, B)`, `current_predicate(dog)` exited 2 with "not on the ladder yet"

Every database builtin refused at compile time when its argument was not a literal head or Name/Arity -- including literal NON-callables, whose ISO answer is a runtime error term, never a compile refusal. The lowerer now emits the term for a literal argument: type_error(callable, T) for a number in head or body position (`(foo :- 4)`, `(foo :- fail, 4)`), permission_error(modify, static_procedure, PI) for a control construct or builtin head (`pl_pi_is_static_builtin`: the control list, the det-leaf table by arity, the rung tables), permission_error(access, private_procedure, PI) for clause/2 on one, type_error(predicate_indicator, S) for a non-PI, and abolish's type_error(atom, N) / type_error(integer, A) / domain_error(not_less_than_zero, A) / representation_error(max_arity). The same builtin filter now guards `pl_dyn_mark`, so `asserta((true :- true))` can no longer mint a dynamic `true/0` whose enumerator would shadow the builtin. A number in goal position (`call((write(3), 1))`, `\+ 3`, `once(3)`) raises type_error(callable, G) from `goal()` BEFORE anything runs -- the body is walked at lowering, so `write(3)` never prints. Two smaller cures rode along: `max_arity` is 1024 and returned as an integer (it was the atom `'unbounded'`, so `X is A + 1` was a type_error(evaluable) and functor/3 could never raise representation_error), and standard order puts 1.0 before 1 (ISO 7.2.1; the comparator returned 0 on equal value).

## What is still red in these sections, and why it is rung 2

A head or spec that is a VARIABLE at compile time (`asserta(_)`, `four(F), asserta(F)`, `abolish(foo/X)`, `clause(_, B)`, `current_predicate(F/1)`) still refuses: there is no runtime cell for a predicate the lowerer never named, and `call(assertz(foo(1)))` raises existence_error(procedure, assertz/1) because the meta-call wrappers exist only for det leaves. That is one design (a runtime key -> store map beside the 64 root cells, wrappers for the database builtins over it) and it is the next rung. Also seen and left: the `$fc/3` helper is unreachable from a meta-called `,`/2 inside findall/3 (`findall(X, (G = ((X=1;X=2), !), call(G)), L)` raises existence_error('$fc'/3) while the same goal outside findall answers) -- pre-existing on the board (cut_0 09 and 18), engine-shaped, filed here for the rung that takes the meta-call wrappers.
