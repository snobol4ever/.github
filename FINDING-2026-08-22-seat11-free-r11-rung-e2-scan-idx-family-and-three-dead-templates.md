## 2. RUNG `E-2` — WHAT THIS SESSION ACTUALLY DID: 15 FILES, 56 OCCURRENCES, ZERO REGRESSION, MEASURED THREE WAYS

Every site in this rung was read in full (not sampled) before editing, and falls into exactly two mechanically distinct, individually-verified shapes:

**(a) Pure alignment padding — `push r11[; push r11]` immediately before a `call`, matching `pop r11[; pop r11]` immediately after, nothing in between reads r11.** Converted to `sub rsp, N` / `add rsp, N` (N=8 single, N=16 double) — an idiom this codebase already uses identically elsewhere (`bb_define.cpp`, `bb_arith.cpp`, `bb_call.cpp`, `bb_glue_framed.cpp`, confirmed by grep before writing a single edit). This is **strictly safer** than a register rename: it removes the dependency on ANY register's liveness, since no register content is read or written at all — only `rsp` moves, identically to what the original `push`/`pop` pair already did. Two sub-shapes both handled: the plain single/double form (`bb_scan_any/alternate/find/many/move/sequence/tab/upto/initial/glit/gcc.cpp`), and a trickier form in `bb_scan_bal/many/upto.cpp` where the r11 padding is *interleaved* with an unrelated `push rax`/`pop rax` save-restore (the callee's result is read via `test rax,rax` — which does not affect flags via `pop` — *before* the original `rax` is restored, so the pattern preserves both the call's boolean result and the loop's position counter in one register). Traced instruction-by-instruction per site; the stack-pointer trajectory is byte-identical whether the padding slot holds a stale r11 value or is just `sub`'d space, so the interleaving is unaffected by the substitution.
`bb_subject.cpp` additionally wraps its `push`/`pop r11` around `x86_align_enter()`/`x86_align_leave()` (`x86_asm.h:1670-1683`) — read those definitions before touching this file: they are a no-op under the default `ZC_FRAME_RSP` config and an independent dynamic 16-byte alignment trick under `ZC_FRAME_RBP` (their own `push rsp; push [rsp]; and rsp,-16` / `mov rsp,[rsp+8]`), so they neither read nor depend on what the surrounding r11 slot holds either way.

**(b) Genuine scratch pointer — `bb_idx_get.cpp`/`bb_idx_set.cpp`.** r11 holds a computed array/table data-pointer across several instructions (`mov r11,[rsi+24]` ... `[r11+rcx*8]` ... `add r11,8` ... `[r11+rcx*8]`). Per-site liveness traced by hand: `rax`/`rdx`/`rcx` are all live (result/index registers) across the span; `rdi` is dead throughout the entire fast-path arm in both files (last write is the second `NV_GET_fn`/`subscript_get`/`subscript_set` call-arg setup, several instructions earlier; next write is on the `L(0)` fallback path, reached only via jump, never fallthrough). Renamed `r11`→`rdi` (whole-file `replace_all`, safe — no other token in either file contains the substring `r11`).
