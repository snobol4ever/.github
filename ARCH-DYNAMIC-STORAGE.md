## 3. WHERE EACH POPULATION LIVES — THE ONE PLACE LON'S WORD MEETS A STANDING RULING

- **RUNTIME populations → THE GC HEAP**, as Lon said: a typed vector block (`HB_DVEC` for DESCR elements, `HB_PVEC` for pointers to heap blocks, a raw kind for words the collector must never read as pointers), ROOTED, SLIDING with every collection like every other live aggregate (`ARCH-GC-COMPILE-TIME-FRAME-MAPS.md` § 7: the collector guesses nothing; the heap walks typed visitors).
- **⛔⭐⭐⭐⭐ COMPILE-TIME populations → THE COMPILE-TIME ARENA (`src/ir/ct_arena.c`), GROWN GEOMETRICALLY BY ALLOC, COPY, ABANDON (Lon 2026-09-24 12:4x CDT, in-chat to the cfo, verbatim: *"Use the special compile-time heap, and use alloc/copy/abandon at geometric growth for dynamic arrays and buffers."*; ruled by the ceo as CEO-1244, .github 51c2c249; section rewritten in place 2026-09-25 by the cfo with the landing that made it true for `cv_t`):** every table, vector or buffer the compiler fills from the program lives in the arena, NEVER on the GC heap -- nothing collects during a compile, the GC heap's hard cap is a few MB (a 3000-statement compile died with error 204 when four indexes sat there, CFO-161), and the arena does not move, so an address a compile bakes into code or into another table stays good (the CTO-151 hazard below cannot arise in it). ## 4. THE MECHANISM — two vectors, one shape, growth by doubling

### 4.0 THE ONE PRIMITIVE IS REALLOC, AND NOTHING FANCIER (Lon 2026-09-23 15:2x CDT, in-chat to the ceo, verbatim: *"So do not do anything more fancy then a grown in place and copy and grown just like realloc does. Of course grow in place only occurs at the frontier. So we will have some alloc and move into doubling areas. Right?"* — right; CEO-1211)

Both allocators are bump allocators with ONE frontier — the GC heap's `g_hp_top` (below `g_hp_end`, inside the hard cap `g_hp_cap_end`), the compile-time arena's `ct_cur` (inside the current 4 MB chunk). A grow of block `p` to `n` bytes is exactly realloc's three cases, in this order:
1. **It fits.** `n` is within the block's capacity: return `p`. (Arena blocks are power-of-two size classes, so the slack is often already there; heap blocks are exact to 16 bytes.)
2. **It is the last block at the frontier.** The block ends at the frontier: extend it IN PLACE by advancing the frontier by the difference. On the GC heap the difference is carved exactly as a fresh allocation carves it — the pacing line check that sets `g_gc_pending` (never a collection inside), the lazy commit inside the hard cap, the quarantine release, the zero-unless-virgin rule, the birth ledger told — and then the header's `size` grows; in the arena `ct_cur` advances and the header takes the larger class.
3. **Otherwise it moves.** Allocate `n` at the frontier, copy the old payload, return the new block, and the old block is left behind: on the GC heap the collector frees it (it is unreferenced once the root is rewritten; a sliding heap has no other free); in the compile-time arena it is ABANDONED -- never returned to a bin (CEO-1244, Lon 2026-09-24: "alloc/copy/abandon"; SCRIP `ct_grow` since `852444a1b`, gate `test_gate_ct_grow_grows_in_place_at_the_frontier_or_allocs_copies_and_abandons.sh`, which reds if the old block is painted or recycled). RECORD: from SCRIP `d2efe8a8f` (cfo, 2026-09-23 17:29 CDT) to that landing, case 3 dropped the old block to its bin through `ct_drop` (realloc's free), which Lon's 09-24 word retired; the one caller the drop broke (bb_ab_emit_nodes restoring a snapshot of a grown `op_arg_slot`) keeps its carry and its arm. A block above the largest bin (8 MB) is its own mapping: map new, copy, and the old mapping is abandoned too.

The growth POLICY is the vector's: doubling, `newcap = max(2*cap, need)`. The realloc only decides WHERE: a vector that is the most recent allocation keeps doubling in place; once something is allocated after it, its next grow moves it to the frontier at double the size, where it can grow in place again. **Nothing fancier:** no segmented or chunked vectors, no free-list search for an interior gap to grow into (the heap's secondary carve window after a compaction is NOT a growth frontier — a block carved there moves when it grows), no `mremap`, no shrink. The contract is realloc's own: after a move the old pointer is dead — and on a moving heap a pointer is also dead after any safe point, which is THE RE-READ RULE below. Primitive names: `rt_gcheap_realloc(p, n)` beside `rt_gcheap_alloc` in `gc_heap.c` (the cto's row) and `ct_grow` given this contract in `ct_arena.c` (the cfo's row: read the 53 existing call sites in 31 files for an alias held across a grow before the drop lands, and run the masters under `SCRIP_CT_POISON=1`, which paints a dropped block 0xDD so a stale alias reads garbage loudly; the four flex scanners call it as `yyrealloc`, whose contract already is realloc's).

**Runtime, `gv_t` (src/runtime/rt/gc_vec.h, the cto's row):** a header OUTSIDE the heap — a static per table, registered once as a root in `core_gc_roots` — holding `DESCR_t blk` (the heap block, typed by its kind), `uint32_t len, cap, esz`. `gv_reserve(v, kind, need)`: when `need > cap`, `newcap = max(2*cap, need, 8)`, `rt_gcheap_alloc(kind, newcap*esz)`, `memcpy` the live prefix, point `blk` at the new block — through `rt_gcheap_realloc` (§ 4.0): in place when the block ends at `g_hp_top`, else a doubled block at the frontier with the old one left for the collector; the allocator never collects (CEO-812), so a grow from C is safe at any point. The header replaces the table's own fixed static in place, so a conversion adds no global (RULES.md § FACT RULES). Element access is ALWAYS `gv_at(v, i)` through the header: ⛔ THE RE-READ RULE — a C local holding an element pointer across any call that can reach a safe point is the CTO-151/holder class (`c_rt_assign_var_body`'s stale `vc` today); index, never cache. Kinds: DESCR elements → `HB_DVEC` (visited as an array of DESCR); pointers to heap blocks → `HB_PVEC` (typed by target kind in the layout); raw words → the raw kind (no pointers, never scanned). One root per table; the collector relocates the block and rewrites the root like every root.

**Compile-time, `cv_t` (src/ir/ct_vec.h, the cfo's row):** `void *p; uint32_t len, cap, esz`; `cv_reserve` doubles through `ct_grow` (§ 4.0) -- in place at `ct_cur`, else a doubled block with the old one abandoned -- and zeroes the new capacity, so a reader of reserved slots sees what the collected heap used to give it. There is no `cv_gc_root`: the block is arena memory the collector does not own and never moves. Every fixed table of § 6's compile-time list becomes a `cv_t` (or an arena map in the `g_znb`/`g_fcn` shape: open addressing keyed by node, a generation stamp for reset) owned by the structure that owned it, initialized empty, grown at its first write.

**Hash tables with a fixed bucket count** (`VAR_BUCKETS` 512, `STAGE2_PL_PRED_TABLE_SIZE` 256, `HT_INIT_SIZE` 512) are class C in disguise: a fixed bucket array degrades to a linear chain; they rehash at load factor 1 into a vector twice the size (a `gv_t`/`cv_t` of buckets).

## 5. THE DISCIPLINE (the law line in RULES.md § FACT RULES points here)

1. A population grows on demand; **the ONLY refusal is allocator exhaustion**, loud, naming the table and the size it asked for. No silent drop, no silent truncation, no silent FAIL, no wrong value — the four shapes § 1 measured are each a defect class.
2. Until a table is converted it COMPARES AND REFUSES LOUDLY at its cap (the zls row's discipline, kept): the 49 unguarded tables get their comparison first (the coo's row), then their conversion (the owning officer's row).
3. **The ratchet:** `util_dyn_caps_witness.sh census` reads the census against `scripts/fixtures/dyn_caps/BASELINE` (read the number THERE, never here) — the count may only fall, and a landing that lowers it lowers BASELINE in the same commit; a new fixed table is RED unless this page names it class A or B first. The coo wires it as a blocking arm (`test_gate_dyn_caps_ratchet.sh`).
4. **Every conversion lands with a witness that exceeds the OLD cap and reads the ORACLE's answer** (the three of `util_dyn_caps_gen.py` are the first; each converted table adds its own), plus the gates it touched and `make preflight`; a shared-node conversion owes the CEO-757 arms.
5. A cap macro that survives as a GROWTH HINT (initial capacity) is renamed `*_INIT` so the census stops reading it as a limit; a macro that survives as a class-A bound is listed in § 2.
