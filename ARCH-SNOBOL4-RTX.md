| rbp | ζ frame base IN PINNED GRAPHS ONLY (suspended generators, pattern blobs, deep-arrival — prologue seeds `mov rbp,rsp`); **rsp** for depth-static determinate graphs (free GPR; `op_flat_disp` compensation). ⛔ **CORRECTED s205: prior entry said "ζ frame base" unconditionally — WRONG since FLATDISP-8 (s197) made the selection per-graph.** ONE selector: `x86_fb_pinned()` = `emit_rec_pin()`. **NEVER hardcode `[rbp+off]` or `[rsp+off]` in RTX asm or templates — use `FR(off)`/`FRQ(off)` which resolve via `x86_fb()` → `x86_fb_pinned()`.** Verified from `x86_asm.h:347-361`. |
**These six GP pins are exactly the SysV callee-saved set — the historical reason C runtime interop was free. RTX routines called via C signatures inherit that safety automatically; hand-written entries that clobber any pin must save/restore it explicitly. ⛔ r12 is NOT in this set (see above) — it is free.**

**RTX working set (free at every blob→runtime entry, zero boundary cost):** rax rcx rdx rsi rdi r8 r9 r10 r11 + xmm0-15. Internal role conventions (SPITBOL lessons, adopted):
| reg | RTX internal role |
|---|---|
| rax | value word of the descriptor pair; result; W0 |
| rdx | tag:slen word of the descriptor pair; mul/div companion |
| rsi / rdi | string source / dest — movs/lods/stos/scas/cmps native (SPITBOL xl/xr) |
| rcx | length/count — rep and shift-count native; `cl` for char work (SPITBOL wa) |
| r10 | idiv divisor scratch — keeps rdx clear of the div blast zone (SPITBOL's exact trick). ⛔ **DOCUMENTED BUT MEASURED UNUSED (2026-08-22 free-r10 census):** no `idiv`/`div` instruction anywhere in `src/templates/`, `src/runtime/rtx/*.S`, or the runtime C sources actually divides through r10 today — this row is aspirational, not a live claim. |
| r8 r9 r11 | scratch / secondary args. ⛔ **r11's "scratch" is NOT unqualified (2026-08-22 free-r11 census):** it is genuinely free scratch in most of the tree, but two live mechanisms still carry a real γ/ω value through it — see the bullets below. |
| xmm0 | REAL scratch (mxcsr note: set once at init; save/restore around libc math calls — int.asm precedent) |
**Condition results use EFLAGS + setcc/jcc, never SPITBOL's memory `fl` byte. `cld` is a global invariant: set at init; any `std` user restores before return.**

## 3. BOUNDARY PROTOCOLS
**blob→RTX (phase 1):** every exported symbol keeps its EXACT current C signature. Speed comes from the bodies (no -O0 C, fused fast paths, register discipline, rep-string idioms), not the call convention. Templates untouched ⇒ no `.s` regen, no both-medium work, in this phase.
**blob→RTX (phase 2, RTX-CC):** per-family registerized signatures; every template call-sequence change goes through `x86(...)` encoders in `x86_asm.h` per RULES (TEMPLATE-ONLY EMISSION, BOTH-MEDIUM); `.s` regen ×3 fires.
**RTX→libc:** `and rsp,-16`-equivalent alignment guarantee (track parity; the entry from blob is a `call`, so rsp≡8 mod 16 at entry — one push realigns), save live volatiles on the stack, `call foo@PLT` (m4) / `call foo` (m3 — same source, PLT relaxes), restore. **No SPITBOL-style global reg_block:** libc never inspects SCRIP state (unlike SPITBOL's osint functions, which read compiler registers from globals — int.asm:127-137). The pins are callee-saved, so libc preserves them for free.

## 8. SPITBOL LESSONS — ADOPTED vs REJECTED
**Adopted:** register-pinned runtime discipline; xl/xr/wa physical mapping (rsi/rdi/rcx) for the string engine; rdx/r10 div discipline; low-byte aliases (cl/dl) for char work; hardware stack as THE stack; cld invariant; mxcsr management; boundary save protocol (simplified — no global block).
**Rejected:** Minimal's 9-register ceiling (r8 r9 r11 r14 r15 rbp are UNUSED in all 19,064 lines of sbl.asm — we design for 15); the cp interpreter code-pointer (we are compiled, no interpreter loop); memory `fl` condition byte (EFLAGS); the N-exit-points-after-call convention (our α/β/γ/ω port model already covers multi-exit); two-stack compsp/osisp switching (our ζ is already on rsp); SPITBOL's block/descriptor formats (ours are `src/contracts/descr.h`, full stop).

## 9. DESCRIPTOR PROVENANCE STAMP — the three free bytes in the tag word (Lon 2026-08-22, in-chat, HQ-designed)
**Lon's ask, verbatim in substance:** *"stamp DESCR with the node id that created it, and the node id that last modified it."* Purpose is the same as the r10/r11 telemetry ladder: **know at failure what we normally cannot** — not which box was *running* (r11 answers that) but which box **built the data** that killed us. The two are complements; do not merge them.

**MEASURED LAYOUT (HQ, compiled — not remembered):** `sizeof(DESCR_t) = 16`, `alignof = 8`, **zero tail padding**. `DTYPE_t v` @0 (4B) · `uint32_t slen` @4 (4B) · union @8 (8B, `char*`/`int64_t`/`double`/`void*`/`ARBLK*`/`TBBLK*`/`DATINST*`). ⛔ **The pointer is LAST, not first**, and there is no spare byte at the end — a common mis-recollection.

**⛔ 16 BYTES IS AN ABI BOUNDARY, NOT A LAYOUT CHOICE.** An all-INTEGER 16-byte struct passes in two GPRs and returns in `rax:rdx`; `rtx_misc.S` states it as the contract ("a DESCR_t argument pair in, a DESCR_t return pair out"). At 17 bytes DESCR becomes MEMORY class and **4,009 lines of hand-written asm across 14 `.S` files** change calling convention (`rtx_match.S` alone at 43 sites). **DESCR MAY NOT GROW.** Any proposal that widens it is an ABI migration of the whole runtime, and it would also double every descriptor in every array and table — moving GC and cache behaviour, i.e. instrumenting the program into a different program, the exact sin the SPITBOL oracle was convicted of.

**WHERE THE ROOM IS — the tag word, and only there.** `v` maxes at `DT_DATA = 0x70 = 112`. ⭐ **Nothing in the tree ever mints `DT_DATA + 8k`:** every `.v =` assignment is a bare enum constant (measured, all sites), and `DT_DATA_STRIDE` is referenced in exactly ONE place — the static assert in `descr.h` — and nowhere else. It is **vestigial design intent, not a live mechanism**; user datatypes are discriminated by the `DATBLK_t *type` pointer behind `obj.u` (`driver_data.c:391`), and `>= DT_DATA` is a flat range test with one value at or above it. So the tag needs **one byte** and **three bytes are free**.
⛔ Not free, and why: `slen` carries sentinels in its high range (`rt_proc_value` stamps `0xFFFFFFFE`; `IS_NAMETRAP_fn`/`IS_VARREF_fn` discriminate on `slen ∈ {0,1,2}`). The union holds a full `int64_t` and a full `double` — no spare bits, ever.

**THE SHAPE: SPLIT THE TAG WORD INTO NAMED FIELDS — DO NOT PACK.**
```c
uint8_t  v;          /* 0     tag, max 112 — semantics unchanged                    */
uint8_t  mod_op;     /* 1     IR op that last modified, stored +1 (0 = unstamped)   */
uint16_t src_node;   /* 2-3   node id that created it (0 = unstamped)               */
uint32_t slen;       /* 4-7   unchanged                                             */
union { ... };       /* 8-15  unchanged                                             */
```
⭐ **Why split beats pack, measured:** all **642** C tag tests are `d.v == DT_x` shaped. Against a `uint8_t v` they compile and behave **identically** — the stamp lives in different *named* fields and never enters the comparison. The 3 relational `>= DT_DATA` tests stay correct too. **C is zero-change.** Packing into a 4-byte `v` would have broken all 645.
**Both counts fit a byte with room:** `IR_OP_COUNT = 129` (compiled, contiguous 0..128, no explicit values) and 129 `bb_*.cpp` boxes. So `mod_op` carries the **exact IR op**, not a family abstraction. ⛔ PLAN.md's `GOAL-IR-IMMUTABLE-EMIT` row still says *"collapse 224 opcodes"* — **stale by 95**; the live count is 129.

**⛔ THREE HAZARDS, EACH FOUND BY MEASUREMENT — a brief that omits any of them ships a lying instrument.**
1. **0 MUST MEAN UNSTAMPED, AND OP 0 IS REAL.** `IR_ACTIVATE` is op 0, so a raw op stamp cannot distinguish "IR_ACTIVATE touched it" from "nothing touched it" — store `op + 1`. `bb_node_id` is already safe: it returns 0 only for a NULL node and real ids begin at `++g_nid_count == 1`.
2. **THE 16-BIT NODE FIELD REQUIRES THE DENSE-NID PATH, AND CAN STILL OVERFLOW.** The non-dense arm returns `(uintptr_t)nd % 100000u` — range 0..99,999, which **overflows `uint16_t` and can return 0 for a real node**. Even on the dense arm `++g_nid_count` is unbounded (beauty reaches 12,000; a larger program can pass 65,535). ⛔ **On overflow the stamp must SATURATE to a reserved 0xFFFF ("id too large"), never wrap** — a wrapped id aliases two nodes and yields a *confidently wrong* attribution, which is strictly worse for a debugging tool than no attribution.
3. **⛔ THE ASM FAST PATHS WILL SILENTLY ERASE THE STAMP.** `rt_faildescr` mints its pair as `mov eax, DT_FAIL` — one 32-bit move that sets the tag *and* zeroes `slen`, and with the split also zeroes `mod_op` and `src_node`. Every asm mint site of that shape drops the stamp rather than corrupting it, so the stamp reads "unstamped" **exactly on the hand-written hot paths where it is most wanted**. Telemetry reliably present on C paths and reliably absent on fast ones is worse than none — it reads as "no box touched this." The asm mint sweep is therefore load-bearing, not cleanup.

**COST, PRICED:** **65 asm + 103 template** sites do `cmp exx, DT_x` — a 32-bit read that would now include the stamp bytes. Each becomes an 8-bit `cmp al, DT_x`, a **shorter encoding** (2 bytes vs 3–6), so the conversion is instruction-count neutral or favourable. ⛔ Also check before committing: anything taking `&d.v` or passing it as a `DTYPE_t` parameter. **No new global is needed** — creator node id and modifying op are known at emit time and bake as immediates.

⛔ **HAZARD 4, FOUND AFTER LANDING — A NAMED-CONSTANT MASK IS NOT A NAMED-CONSTANT VALUE (HQ FINDING s256, cured same day, seat12).** `DT_NOTSTR_MASK` (`descr.h`) is a **multi-bit** mask (`0xFFFFFFFD` — every bit except bit 1), unlike `DT_NUMERIC_BIT`/`DT_CHARS_BIT`/`DT_REAL_BIT` (each a **single** bit). A single-bit `test` is width-blind: bits 8-31 being nonzero can never flip its zero/nonzero verdict. A multi-bit mask is NOT width-blind — its upper 24 bits are 1s, so ANY nonzero garbage in bits 8-31 (which is exactly where a stamped descriptor's `mod_op`/`src_node` now live) makes a genuine string test nonzero and misclassifies it as not-a-string. Three sites read `DT_NOTSTR_MASK` against a **32-bit** register (`rtx_match.S:946` `rt_dcap_step`, `rtx_arith.S:78` `rt_cmp_d`'s string arm, plus `rtx_abi.inc:63`'s rule text asserting the 32-bit form was correct) — all three predate this stamp design and were never revisited when it landed. Measured: `SCRIP_DESCR_STAMP=1` on `corpus/crosscheck/functions/060_pred_operand_edge.sno` silently dropped the `LGT`/`LEQ` output lines (string-family lexical predicates), both modes. **CURE:** narrow all three to the 8-bit tag — `test <r8-class>, (DT_NOTSTR_MASK & 0xFF)` (`dil`/`r10b`, not `edi`/`r10d`) — an expression, not a hand-copied `0xFD`, so it tracks the named constant if it ever changes. `descr.h`'s three `DT_NOTSTR_MASK` static asserts (lines 41-43) re-expressed the same way, so the pinned invariant matches what the asm now actually executes. Witness re-verified MATCH both modes; full corpus OFF-arm (default) byte-for-byte unregressed (357/2 m3, 355/2+2skip m4, identical fail-set to the standing baseline). **⛔ NOT CURED BY THIS FIX, FLAGGED FOR THE NEXT ROW:** running the SAME corpus with the killswitch ON as a second arm (per this row's own brief) surfaces 34 (m3) / 5 (m4) FURTHER failures spanning GC/array/DEFINE/EVAL witnesses that do **not** touch `rt_dcap_step` or `rt_cmp_d` (e.g. `032_goto_loop_count` never leaves the DT_I/DT_I hot arm) — these are a **different** hazard class, consistent with seat1's own `descr-stamp-fields` FINDING §3 (whole-tag-word 32-bit zero-compares elsewhere, e.g. `bb_unop.cpp`'s `IR_NULLTEST_VAR` arm) and/or other unaudited 32-bit tag reads. **Only scalar-literal mints are stamped today; the ON arm remains broadly unsafe for anything beyond this row's one named witness** — do not flip the killswitch's default before that broader sweep lands. Also stale, not fixed here (out of this row's scope, flagged only): this section's own DESCR_t ABI note above and `rtx_abi.inc`'s mirror of it still describe the **pre-split** 2-field `(slen<<32)|v` register packing — true of the tag's low 32 bits either way (the split lives entirely inside what was `v`), but worth a pass by whoever next touches that paragraph.
