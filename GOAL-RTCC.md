## ⭐⭐ DESIGN OF RECORD (minted s0 — falsify by probe, not by argument)
**THE REGISTER MAP.** Callee-saved set already SCRIP-owned and untouched by this goal: RBX=heap frontier · RBP=law-4 frames · R12=CAS/DCAP top · R13=Σ · R14=δ · R15=Δ · RSP=ζ spine. THE LIBERATION TARGET is the caller-saved set, split by role: **SCRATCH TIER** {R10, R11, R8, R9, XMM8–15} — never (R10/R11) or rarely (R8/R9 = SysV args 5/6) used for C-call argument staging; claimable with ZERO template changes. **ARG TIER** {RAX, RCX, RDX, RSI, RDI} — the SysV argument/return registers; claiming them forces the arg-staging re-plumb (RC-4). DESCR_t is 16B ⇒ C returns ride RAX:RDX — the RC-4 veneer must capture the return to its destination slot BEFORE the global reload (encoder overload `x86("call_rt", sym, result_slot)` owns the post-call store; the templates' current post-call `mov FRQ,rax/rdx` idiom migrates INTO the encoder). Varargs symbols (printf-class): AL = #xmm-args must be staged post-save — registry marks them.
**BLOCK-CANONICAL, NOT STACK-SAVE (the load-bearing decision).** The boundary is BIDIRECTIONAL and re-entrant: generated→C→generated is the NORM (`rt_call_arr`→proc bodies · `rt_dcap_pump`→PAT$ blobs · `rt_chain_enter`/EVAL · `runtime_eval.c:303/308/312/379/412`). A stack save buries the VM globals in an ancestor veneer frame where inbound edges cannot reach them — DISQUALIFIED. The SPITBOL model holds instead, read as CACHE SEMANTICS: the RTCC BLOCK (one cache-aligned bss region) is the CANONICAL home of the VM globals; registers are a cache VALID ONLY INSIDE GENERATED CODE. Outbound crossing = WRITEBACK (regs→block); inbound crossing = LOAD (block→regs). Nested crossings compose by induction — the block holds the latest values at every boundary, and an inner generated region advancing the VM state is CORRECTLY seen by the outer region on its reload. C code never reads the claimed registers as meaningful; gcc may clobber them freely. **Consequences bought for free:** (a) GC ROOT SET — at any point GC can run (inside C), every heap pointer cached in a claimed register is sitting in the block; register the block with the collector, and the "GC can't see register roots" problem never exists. (b) The block is ~72–136B hot in L1.
**TWO OPEN DESIGN ITEMS (RC-0(d) closes them):** (i) COEXPR/THREADS — m3 co-expressions are pthreads (`rt_coexpr.c`); one global block races two VM states. Candidate answers: TLS block (fs-relative addressing — new encoder arm) OR block swap folded into the existing coexpr context switch. Lon rules at RC-0 close. (ii) SIGNAL WINDOWS — the two-instruction gap between call and writeback completion; likely moot (SCRIP handles no async signals that re-enter generated code) but say so from census, not assumption.
**COST HONESTY.** The boundary is HOT (string_manip ≈10M rt calls/run; SPITBOL pays its toll RARELY, SCRIP pays per-call). Writeback+reload ≈ 2×(set size) movs to one hot line. The bet is register freedom in ALL generated code + RC-6 bypasses outweigh it — a BET UNTIL THE RAIL SAYS SO, and the rail cannot say anything until RC-0(a). ⛔ NO SPEED CLAIM in any RC FINDING without the min-of-N instrument.

## ⛔ LAWS & TRAPS (binding)
- **BLOCK-CANONICAL LAW**: registers are a cache valid only inside generated code; every crossing writeback/loads. A C function reading a claimed register is reading garbage BY CONTRACT.
- **RETURN-BEFORE-RELOAD**: RAX:RDX capture precedes global reload at every RC-4 site — encoder-owned, never template-owned.
- **NEVER VENEER A GENERATED TARGET**: PAT$/proc/port-label calls stay direct; veneering one deadlocks the cache semantics (generated code expects live registers). Registry is the ONE authority; an unclassified target is a BUILD ERROR, not a default.
- **THE BOUNDARY IS HOT**: no speed number without the RC-0(a) instrument, N stated, min-of-N. "The window was too short" is a falsified excuse (RTX s224).
