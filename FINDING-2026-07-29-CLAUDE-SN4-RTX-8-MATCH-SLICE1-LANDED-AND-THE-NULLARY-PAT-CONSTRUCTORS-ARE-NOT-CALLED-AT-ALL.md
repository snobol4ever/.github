## 3. ⭐⭐ THE LESSON, AND IT IS ABOUT MY REASONING, NOT THE TREE
I explicitly skipped **step 0(d)** on the grounds that *an eradication port does not need a hot-window proof*. **That reasoning is wrong, and the error is not about speed.** 0(d) is what supplies the **correctness net**: if nothing in the suite calls the symbol, there is no regression evidence available at any price, the falsification probe is silent by construction, and the port is unfalsifiable. **0(d) is a PREREQUISITE FOR ERADICATION PORTS TOO — arguably more so, since eradication has no speed number to fall back on.**
⛔ **And my batch-2 "verification" was worth nothing as evidence for the port.** "All seven oracle-exact vs SPITBOL" was true and **could not have distinguished the arms** — pristine and corrupted builds produce byte-identical output. Same class as the s212 WRONG-TEMPLATE-ARM trap: a green behavioural test that is structurally blind to which code ran. **Discriminate on something only the ported arm can change.**
