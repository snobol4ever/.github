**The mechanism (RULES.md § NO RUNTIME INTERPRETER, the EVAL/CODE doctrine).** `pl_goal_key_live` rewrites an unregistered key `Name/N` to `$mc:Name/N`. On first use it calls `pl_runtime_define_goal_wrapper` (`src/lower/lower_prolog.c`), which builds the clause `$mc:Name(_A0.._An-1) :- Name(_A0.._An-1)` as a tree, runs it through `pl_runtime_clause_tree` and `pl_runtime_define_pred` — the same path an asserted clause takes: the ordinary goal lowerer, `fl_derive_tier`, slot assignment, `emit_chain`, a registered generator with a pinned frame. The staged goal arguments become the wrapper's parameters; the ordinary generator protocol (`rt_proc_call_gen_h`, `rt_call_value_resume_h`) carries the redo, so `findall(X, call(G), L)` over a generator collects every solution. The second call to the same Name/Arity finds `$mc:Name/N` registered and pays nothing.

**The loop guard.** The goal lowerer's own fallback for an unknown name is a run-time meta-call of the term (`pl_user_call` → `pl_meta_call_dyn`), which would come straight back to the resolver with the same key. `pl_mc_graph_fell_back` scans the wrapper's lowered graph for an `IR_CALL_VALUE "goal"` whose operand is a `$mkc` of the same functor and arity (or the bare atom for arity 0); when it finds one the wrapper is REDEFINED as `$mc:Name(..) :- throw(error(existence_error(procedure, Name/N), Name/N))`, or as `fail` when `rt_pl_unknown_suppress` says the `unknown` flag is `fail`. The witness calls `foo(1)` twice and prints the ball twice; under `unknown=fail` an unknown name fails twice. No per-key state is kept anywhere: the registry is the memory.

**One refusal turned into an error.** The two `pl_refuse("builtin", ...)` sites in the goal lowerer (a rung builtin the leaf tables do not wire) `exit(2)`; a program naming such a builtin at run time inside `catch/3` would have died instead of catching. They are skipped while `g_rt_fragment_emit` is set (a run-time fragment is being emitted), so the wrapper falls to the unknown-name path and raises `existence_error` like any other absent procedure. Compile-time behaviour is unchanged.
