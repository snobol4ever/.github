## Headline
Confirmed by direct `--dump-ir` comparison (not inferred from a downstream diagnostic): SNOBOL4's `roman(n)` recursive self-call, inside its own `DEFINE`d body, lowers to plain `IR_CALL` in a single-language build and to `IR_CALL_PROC_STAGED` in an otherwise byte-identical polyglot build — same source text, same lowerer, same call sites. This directly confirms seat07's "op-selection, not emission" theory (`FINDING-2026-08-29-seat07-...divergence-is-pre-bb-call-proc-staged.md`) with a byte-for-byte IR proof instead of the `SCRIP_TINY_DIAG` diagnostic's indirect signal.

## Reproduction (cheap: `--dump-ir` only, no build-and-run, no gdb)
- `roman_single.sno`: `roman.scrip`'s SNOBOL4 section, verbatim, saved standalone with `.sno` extension.
- `roman_poly.scrip`: the same SNOBOL4 section unmodified, plus trivial Icon (`procedure main(){write("icon-trivial")}`) and Prolog (`main :- write('prolog-trivial'), nl.`) sections with **no name overlap** with SNOBOL4's `roman` — rules out the case-collision / shared-probe red herring seat07 already flagged and partially ruled out.

  - single: 4 sites, all `CALL [..] "roman"` (plain `IR_CALL`)
  - poly: the same 4 sites, all `CALL_PROC_STAGED [..] "roman"`
  - Control: `CALL "REPLACE"` and `CALL "SNO$NRET"` in the same dumps stay plain `IR_CALL` in **both** builds — the divergence is specific to `roman`, not a global CALL-kind shift under polyglot.

## Where this can and cannot come from (all read directly, not assumed)
- `src/lower/lower_snobol4.c` **never** constructs or assigns `IR_CALL_PROC_STAGED` or `IR_CALL_SNOBOL4` anywhere — `grep -c` of both literal strings against the file is 0. The SNOBOL4 lowerer itself cannot be where this is decided.
- Tree-wide, only two sites literally assign `->op = IR_CALL_PROC_STAGED`: `src/lower/lower_icon.c:1436` (`else if (pi >= 0) nd->op = IR_CALL_PROC_STAGED;`) and `src/lower/lower_raku.c:494` (`if (rk_proc_known(fn)) nd->op = IR_CALL_PROC_STAGED;`). Both retag only that language's own AST-derived nodes while lowering that language's own syntax — neither is reachable while lowering a SNOBOL4 node.
- `src/driver/polyglot.c` (the segment-merge driver) has **zero** references to `IR_CALL` or `->op` anywhere in the file — the merge step itself does not touch call ops.
- The one live consumer of registration state at emission time: `src/emitter/emit.cpp:946-963` routes a plain `IR_CALL` to `CALL_ROUTE_PROC_STAGED` when `rt_proc_is_registered(fn)` is true at the point that call site is routed. The registry it reads is populated by `src/driver/scrip.c:1327-1349` — **one unconditional loop over the combined `s2->proc_table`, covering every proc from every segment**, calling `rt_proc_register()` for each, that runs **after** `sm_preamble(ast_prog, segs, nsegs)` builds the merged `stage2_t` and **before** any per-proc emission.
- ⚠️ **I read that registration loop in full (scrip.c:1320-1349): it is not gated on `nsegs` and runs identically whether `nsegs` is 1 or 3.** It cannot by itself be the divergence. `emit.cpp`'s routing also does not relabel `--dump-ir`'s displayed node kind — routing picks an emission path for an IR node that already has its final `op`; dump-ir output is captured **before** any routing decision. So the actual retag to `IR_CALL_PROC_STAGED` is real IR construction, and it happens somewhere between `sm_preamble()`'s per-segment lowering and the point `--dump-ir` reads the graph — a point this session located but did not reach before its time-box closed.
