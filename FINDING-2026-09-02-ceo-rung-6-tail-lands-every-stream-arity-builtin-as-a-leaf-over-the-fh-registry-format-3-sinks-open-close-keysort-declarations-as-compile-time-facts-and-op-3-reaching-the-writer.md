## 1. What landed, in the tail's own order

1. **A stream is a value the leaves resolve, not a mode of the runtime.** `pl_stream_idx(DESCR, dir)` (`by_name_dispatch.c`) maps the alias atoms `user_input`/`user_output`/`user_error` to fh indices 0/1/2 by direction and `'$stream'(N)` to a live fh index; anything else returns −1 and the leaf FAILS — the ISO stream error terms are rung 9's catch/throw, not a leaf's business. The registry is the driver's existing `fh_` table (`driver_globals.c`, already inside `libscrip_rt.so`): no new global, no new table, no Prolog-only state.
2. **Nine output leaves with a stream first argument** — `write/2 writeq/2 print/2 write_canonical/2 writeln/2 nl/1 tab/2 put_char/2 flush_output/1` — are ONE macro (`PL_OUT_LEAF`) over the landed 1-arg bodies: resolve, `fh_set_output(idx)`, call the 1-arg body on `args+1`, restore. Print-only, no ctx, no trampoline. `tab/2` lowers like `tab/1` (stream lvalue + arithmetic value).
3. **Three input leaves** — `read/2 get_char/2 peek_char/2` — are the same shape over the current INPUT (`PL_IN_LEAF`), binding through the ctx like their 1-arg parents; and the 1-arg readers (`get_char/1 peek_char/1 read/1`, `pl_read_term_text`) come off bare `stdin` onto `fh_cur_in_fp()`, so `set_input/1` means something.
4. **Stream control:** `open/3,4` (`read|write|append|update`; options ignored — `type(binary)` and the byte family are NOT landed, see § 3) binds `'$stream'(N)` through the ctx; `close/1,2` closes and frees an index ≥ 3 and re-homes a current stream that pointed at it; `current_output/1 current_input/1` bind `'$stream'(idx)`; `set_output/1 set_input/1` are det.
5. **`format/3`:** a stream sink is (2) over `format/2`; the `atom(A)/string(S)/codes(C)/chars(C)` sinks run `format/2` under the driver's `fh_capture_begin/end` memstream and bind through the ctx (`rt_pl_dop_format3`, one trampoline). `string(S)` binds the same `DT_S` an atom does — SCRIP has no string/atom distinction (the parser reads `"…"` as `TT_QLIT`), stated, not hidden.

## 4. Four lessons worth the next seat's minute

1. **swipl's `read/1` does NOT consume the layout character after the end dot.** SCRIP's reader did; the mixed `read(R,T), get_char(R,C)` witness printed `xyy` where swipl printed a newline first. Fixed in `pl_read_term_text` (the char after `.` is always pushed back); hq_B's `rung06_read_get_char` still passes. An oracle-cut ref found it in one run; reasoning about ISO would not have.
2. **The parser's own lowering pass rewrites some directives into predicates.** `:- dynamic counter/1.` arrived as `pj_dir_0 :- dynamic(counter/1).` + `:- initialization(pj_dir_0).`, so the "directive" the lowerer saw was a CLAUSE and the refusal said `builtin dynamic`. `--dump-ast` before theorizing.
3. **`resolve_pred_table_insert` stores the key POINTER** (`e->key = key`); a stack-buffer key vanished on return and the lookup missed silently — the symptom was an existence-error refusal for a predicate that was "certainly" recorded. `strdup` the key; the table's other caller passes an AST string.
4. **`op/3` has two consumers.** Reading is the parser's; PRINTING is the writer's; a compiled binary has no parse-time table. A rung-6 witness that only wrote atoms would have called the directive "a no-op" and been wrong in every mode-4 binary.
