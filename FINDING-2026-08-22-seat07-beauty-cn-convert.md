## WHY THE CONVERSION DOES NOT (AND WAS NEVER GOING TO) CURE M1 BY ITSELF

FINDING s182 already measured this precisely and it holds again here: beauty's grammar is **built at runtime by `EVAL`** inside `shift`/`reduce` (the whole `semantic.inc`/`ShiftReduce.inc`/`omega.inc` idiom) — declaring the top-level pattern *names* as constants does not touch that runtime construction, so the EVAL-composed road is exercised identically whether the name holding the eventual pattern value is a plain variable or a declared constant. Whether partial-evaluating the semantic layer at compile time would let the `&PATTERNS` conversion actually help is explicitly **Lon's open ruling, not costed, not attempted** (s182, unchanged by this session).
