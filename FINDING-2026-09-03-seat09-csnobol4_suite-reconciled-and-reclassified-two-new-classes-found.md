## Part 8 — `case1.sno`'s `-CASE` directive, resolved: NOT a defect (2026-09-03, fifth pass)
`case1.sno` deliberately exercises the `-CASE` compile-time directive across its whole body (`-case 1`/`-case`/`-case 0` toggling identifier case-folding; lines like `output = .one` under case-insensitive mode expect `.one` — a pointer/name reference to an uninitialized variable — to print its canonically-folded name `ONE`). SCRIP diffs from `.ref` on 4 of 8 lines and drops 2 entirely (the two `output = ...`, lowercase-keyword, statements: under real case-folding `output` should be recognized as `OUTPUT`, but SCRIP never folds, so these are plain-variable assignments that print nothing). Root cause: `-CASE` is not implemented at all — SCRIP is unconditionally case-sensitive/uppercase-only regardless of the directive.
**This is NOT a cure candidate.** `snoflake-suite-scrip-only-gap.task.md` already carries Lon's own final, explicit ruling on this exact feature (2026-08-28, in-chat to ceo, verbatim, reversing an earlier two-state proposal the same day): *"I changed my mind. We will only support UPPER case reserved/keywords."* That row's own SF-0 partition additionally confirms the analogous snoflake fixture (`case-fold-disabled`) fails under the **csnobol4 oracle itself**, not just SCRIP — case-folding is a dialect feature CSNOBOL4 supports inconsistently at best, and SCRIP's project-level design (RULES.md: case-sensitive, uppercase-only) has already ruled it permanently out of scope, no `--compat` switch. `case1.sno`'s non-pass is therefore EXPECTED, same family as class #1 (lowercase keyword) — not minted as a new row. This also resolves this task's own earlier open question about `label.sno` (Part 3/this FINDING): `label.sno` opens with the SAME `-CASE 0` directive and its missing final line stems from the identical out-of-scope mechanism (there via the runtime `&CASE` keyword, not the compile-time directive — mechanically distinct trigger, same ruled-out feature) — `snobol4-csnobol4-label-output-duplicated`'s task file has been corrected accordingly: its real, in-scope bug is `LABEL()` returning the matched name instead of null on success (confirmed by re-reading the witness's own `LABEL(L) L` idiom, a standard null-on-success predicate pattern), NOT the case-folding gap, and its DONE-WHEN was rewritten to check only the achievable 4-line subset since a byte-exact suite-board pass is structurally unreachable while case-folding stays out of scope.
⚠️ **Also caught and fixed this pass, unrelated to the above:** 5 of the 7 rows minted earlier this session had a real bug — `s4e_msg.sh mint --stdin` does not read an embedded `DONE-WHEN:` line out of the piped GOAL text as a distinct field; it always appends its own placeholder-refusal DONE-WHEN afterward regardless.
