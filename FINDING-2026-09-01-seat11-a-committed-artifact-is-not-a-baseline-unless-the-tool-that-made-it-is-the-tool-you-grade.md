# FINDING 2026-09-01 seat11 — a committed artifact is not a baseline unless the tool that made it is the tool you are grading

**Tree:** SCRIP `32cce542`+`54088178` · corpus `e2f3496fd` · measured 2026-09-01, seat `seat11`, row
`prolog-two-programs-broken-post-churn`.

## The row said two programs regressed. One never worked.

The baton (minted seat14, 2026-08-24) opened: *"2 Prolog programs with real prior committed .s now fail
under today's tree"*, and for `coverage_pl_nodes.pl` it cited a **53,574-byte committed `.s`** as proof
the file had built before. That number is real and the file is real. The inference is still wrong.

The artifact's own first two lines say what made it:

```
; generated by scrip-cc -pl -asm
; compile: nasm -f elf64 prog.s -o prog.o
;            src/frontend/prolog/prolog_atom.o
```

`scrip-cc` is the **retired** front-door; the output is **NASM**, not the GNU-as Intel syntax today's
`./scrip --compile` emits; and `src/frontend/` was deleted 2026-08-29 (`96665b70`). Corroborated from the
other side: `callable_with_args`, the allowlist whose absence produces the failure, traces to `713c581b`
— the **initial commit**. It never regressed. Mode-4 x86 never built that file.

⭐ **The generalisation, which is the point of writing this down:** a committed artifact proves a tool
once produced it, and nothing more. Before treating one as a baseline, read its header and ask which
binary wrote it. In a repo that has changed front-doors, assemblers and directory layout inside one
month, "there is a big .s in git" is not evidence about today's compiler. **Size is especially seductive
— 53KB reads as "real output" and says nothing about provenance.**

The baton was minted **2026-08-24, four days earlier**. The ruling never propagated into it, so the row
kept asking a seat to fix a file a standing ruling forbids converting. This is the same shape as
`FINDING-2026-09-01-seat08-a-lon-ruling-reached-one-row-and-not-its-sibling`: **rulings propagate to the
artifact they were written about, and not to the rows that point at it.** A row older than a ruling is
not evidence the ruling is absent — check the target's neighbours (`KEEP.md`, `PENDING.md`) before
working it.

## What the real defect turned out to be, and why the brief pointed elsewhere

`src/emitter/emit.h:37` — `BB_LABEL_NAME_MAX` is 80, and every label name was `vsnprintf`-truncated to 79
chars at three sites with **no diagnostic**. A Prolog atom of 120 dash characters (line 190 of
`rung10_programs_puzzles.pl` is a bare `#` + 119 dashes: no `%`, no terminating `.`) mangles to 360
chars, so its α/β/γ/ω port labels — the suffix is the **last** thing on the string — all cut to the same
79 bytes. Measured on the emitted `.s`: 6 label definitions, **1** distinct symbol, ending in a bare `$`,
cut mid-escape. `as` accepted the first and rejected 5.

⭐ The brief named the right **remedy** ("append an index/hash suffix rather than truncating") and the
wrong **site**, and offered two same-day commits as likely causes. Neither was involved. The mangling
function truncates at 250, never fires here, and the 80-byte field predates both commits. **A correct
remedy attached to a guessed cause still sends the next actor to the wrong file.**

Cured by `32cce542` (`bb_label_name_set`: verbatim under the limit; over it a 62-char prefix plus a
16-hex FNV-1a of the *full* name, backing the cut off a UTF-8 boundary because the port suffixes are
multi-byte). Pinned by `54088178`. Board on a pristine tree: `total=1726 m3_fail=0 m3_crash=0`, m4
identical.
