## 1. The model: real threads, ONE BATON

Every Prolog thread is a pthread with its own machine stack, exactly as an Icon co-expression is today (`src/runtime/rt/rt_coexpr.c`), and **exactly one thread runs SCRIP code at any instant**: it holds the baton. A thread gives the baton up only at a point where its stack is described by the frame maps, so every thread not running is a parked context the collector already knows how to read.

- **Why one baton and not parallel mutators.** The collector's law is one mutator: the allocator never collects, emitted code polls at the return of an allocating runtime call, and a collection reads every frame through the maps (ARCH-GC-COMPILE-TIME-FRAME-MAPS § 7, § 13). Parallel mutators need a safepoint rendezvous, a per-thread bump region, and a lock on every runtime table (atoms, the dynamic database, flags, streams, the slab). None of the 86 cases measures speed; every one measures semantics that a single baton delivers (ownership, ordering, status, signals, wake-ups). Parallel execution is a PERFORMANCE design under CEO-1562 (2), written when a bench asks for it, never smuggled into this one.
- **The handoff is the co-expression handoff.** The thread giving the baton up records its park site (`rt_gc_park_site`: park pc, park r, park srbp, and its rsp/rbp), saves the runtime registers (`rtcc_coexpr_save`), posts the next thread's semaphore and waits on its own; the thread taking it restores and returns into its own code. No C function decides which box to enter (CEO-1086): a thread resumes by returning from the call that parked it, and a NEW thread enters its goal through the same trampoline a Prolog generator procedure uses today (`rt_genp_thread_entry`, `src/runtime/rt/rt.c`), which is the program's-first-entry shape CEO-913 admits.
- **Preemption costs no instruction.** Every emitted safe point already reads `g_gc_pending` and calls `rt_gc_poll_asm` when it is non-zero (`x86_gc_gate`, `src/templates/x86/x86_asm.h`). A timer (one helper pthread sleeping a quantum, 10 ms, only while two or more threads are runnable) stores a YIELD value into that word; the poll's slow path sees it, clears it, re-raises a real collection request if one was pending, and hands the baton to the next runnable thread. The 4-6 instruction allocation sequence (CEO-996) is untouched. A loop that never reaches a safe point is not preempted; that is a measured limitation to be counted on the population when L2 lands, not assumed away.
- **Blocking is a handoff.** `thread_get_message` on an empty queue, `thread_join` on a running thread, `mutex_lock` on a mutex another thread holds, `thread_wait` with its condition false, `sleep/1`, and a read on a pipe with no data mark the thread WAITING with its reason and hand the baton on. A deadline (`timeout(T)`, `deadline(D)`, `sleep/1`) is checked by the scheduler; when nothing is runnable it sleeps until the earliest deadline. When nothing is runnable and no deadline exists the program is deadlocked; swipl hangs there, which under CEO-1696 is no oracle answer, so SCRIP is free to say so: a SCRIP error naming every thread and what it waits on, rc 2.

## 2. What each thread owns

| datum | where it lives | why |
|---|---|---|
| its frames, choice headers, retained frames | its own pthread's machine stack, sized from `thread_create`'s `stack_limit` option, else the program's declared `-s` (hard-cap clause 8 (g)) | THE MACHINE STACK IS THE STACK; no global holds a thread's activations |
| its trail (the Prolog r12 island) and the trail header's per-run words (the ball at +8, the occurs_check mode at +24, cleanup at +32, the cut probe's B at +40, the attvar wake word at +48, the residue depth at +56) | its own arena from `rt_pl_tr_init` (`src/runtime/rt/rt_pl_trail.c`), made on the thread before its goal runs; r12 points into it | the arena is found by masking r12, so a second arena needs no new code in any template; `rt_gc_root_range_add_topword` already registers every arena with the collector, so the collector visits each thread's trail with no new walk |
| r13, its newest choice | the register, 0 at its goal's entry, saved and restored by the handoff with the other runtime registers | a thread never backtracks into another thread's choice: goals and messages are COPIED between threads, so no variable is shared |
| its chain | parked: entered from its park site, exactly as `gc_heap.c` enters a parked co-expression's chain today (`sc->park_pc`, `park_r`, `park_srbp`); running: from the poll, as today | the collector's chain per thread is the co-expression's chain per context, already walked |
| its thread record | §3 | outlives the construct that made it (until join or a detached exit), so it is heap under THE LIFETIME RULE |

The **switch set** -- the runtime cells that are per running mutator and must be saved and restored at a handoff -- starts as exactly the set a Prolog generator procedure already swaps (the co-expression switch plus `rt_plco_*`), because Prolog predicates run on co-expression threads today and that set is proven by the generator rows. Added for threads, each named and measured in its landing: the SWI global variables (`b_setval`/`nb_setval` are thread-local in swipl), the current input and output streams (thread-local in swipl), and `rt_k_level`. A cell found later goes into the set in the landing whose witness found it; nothing is made thread-local by guess.

## 3. The thread record and the primitives

A thread record extends the co-expression context (`scrip_coctx_t`), as `rt_genp_s` does: its pthread, its semaphore, its park site, its saved registers and switch set, plus the thread's id (an integer, `main` is 1), its alias atom, its status (`running`, `true`, `false`, `exception(E)`, `exited(T)`), its detached flag, its goal copy and its result copy (DESCR slots the collector visits through the thread list, as `co_gc_visit_record` visits a context today), its message queue, its pending signals (goals, run when it next takes the baton, which is where swipl runs them: at a safe point), its wait reason and deadline, and its at_exit goals.

The C core is small and is a set of LEAVES that compute and return (CEO-985): create, yield, block on a reason, wake, and the queue and mutex operations. They are C so that each is atomic under the baton (a C leaf contains no safe point, so no preemption can split it); every policy above them -- option lists, `thread_property/2` enumeration, `with_mutex/2`, `concurrent/3`, `concurrent_maplist`, `first_solution/3`, `thread_pool` -- is Prolog in the prelude over those leaves. A message queue is a record with typed DESCR slot storage of copied terms and a waiter list (NO DELIMITER-JOINED AGGREGATES); a mutex is a record with an owner thread and a recursion count. `thread_wait/2` and `thread_update/2` are a generation word on the dynamic database plus a wait reason, woken by `thread_update` and by every assert or retract while a waiter exists.

**The design: an engine IS a generator context.** `engine_create(Templ, Goal, E, Opts)`: `copy_term(Templ-Goal, T2-G2)` (SWI copies; the engine shares no
variable with its creator, so no binding ever crosses the switch), then create an `rt_genp_s` whose body is the prelude predicate
`'$engine_body'(T2, G2)` -- `call(G2)`, on each solution `'$engine_answer'(T2)`: the answer is COPIED TO THE HEAP (it outlives the engine's stack and its trail
segment: THE LIFETIME RULE; `findall/3`'s own copy, `rt_findall_copy`) and transmitted by `rt_genp_deliver_γ`; on exhaustion `rt_genp_deliver_ω`. `E` is a
heap blob of kind `HB_ENGINE` holding the context pointer, the alias, the mailbox DESCR and the state (created, running, suspended, done); the blob is the
collector's root of the context (`scrip_co_gc_link`), the context's stack is scanned as a root set as a co-expression's is today, and the context's trail
segment is scanned by the same visitor the generator road uses.

- **`engine_next(E, T)`** activates (`scrip_coexpr_activate`): the body runs to its next answer, which arrives in `xmit`; `T` unifies with the heap copy. A
  second `engine_next` backtracks INTO the body's own choice points, which live on the engine's stack and in its trail segment -- the engine's choice points
  are LIFO with the engine's activations, never interleaved with the caller's (r12 is saved and restored by the switch as the generator road already does it:
  `rt_genp_thread_entry` loads r12-r15 from the record). On `scrip_cofail` the engine is `done`, `engine_next` fails, `engine_next_reified(E, no)`.
- **`engine_yield(T)`** inside the body: copy `T` to the heap, `rt_genp_deliver_γ`; the body continues after the yield on the next activation (the park kind
  distinguishes a yield from an answer only for `engine_next_reified`'s `the(T)` form, which both give).
- **`engine_post(E, T)`** writes the blob's mailbox (a heap copy); `engine_fetch(T)` inside the body reads and clears it, or throws
  `existence_error(term, delivery, E)` when it is empty (`no_data`); `engine_post(E, T, Reply)` is post then next.
- **An exception in the body** (`error`): the body is wrapped in `catch/3` by `'$engine_body'`; the ball is copied to the heap and transmitted with the park kind
  THROW; `engine_next` re-throws it in the caller (`engine_next_reified` gives `throw(Ball)`) and the engine is `done`. No ball ever crosses a stack switch as a
  ball: it crosses as data and is re-thrown on the caller's stack (CEO-1576: a C road returns the address, the box jumps; here the prelude re-throws).
- **`engine_destroy(E)`** marks the blob dead and `scrip_coexpr_destroy`s the context (its stack unmapped, its trail segment released); a `done` engine is
  destroyed implicitly after its last answer unless an alias holds it. **`gc`..`gc4`:** an UNREACHABLE engine blob is reclaimed by the collector like any heap
  blob, and the sweep of an `HB_ENGINE` blob destroys its context -- the one finaliser-shaped step, done inside the collector's sweep of a typed block, which
  already knows the block's kind; no finaliser list, no second pass. 100 undestroyed engines of `gc_engines/2` therefore stay bounded.
- **`alias(Name)`** registers the blob under `Name` in a registry root cell (`'$engine_aliases'`, a heap assoc rooted there, CEO-1542's single current-X cell);
  `engine_create` with a taken alias throws `permission_error(create, engine, Name)` (`rdef_alias`); `current_engine/1` enumerates the registry and the live
  blobs; `engine_self(E)` reads the current context's blob (`g_scrip_co_current` → its `rt_genp_s` → the blob back-pointer).
- **`stack(Limit)` / `stack_limit`** sizes the context's mmap'd stack at create (`scrip_coexpr_create`'s `frame_bytes`/`below_bytes` already size it; the option
  becomes those numbers); `statistics(stack_limit, L)` inside the engine reads the record (`stack_limit`: `TheLimit =:= 1_000_000`).
- **`whisper`:** engines creating engines: an engine's body may `engine_create` and `engine_next` another; the activator chain (`activator`) is the one the
  co-expression already keeps.

## 7. New runtime state (asked of Lon BEFORE L1, never at the push)
