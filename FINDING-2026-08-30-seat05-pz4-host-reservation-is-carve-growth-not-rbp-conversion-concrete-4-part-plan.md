## 1. What was attempted

Clause (c): make the caller's landing after a suspend-capable call **consume** the base clause (b) already produces (`xa_flat.cpp:385-390`, under `pl_gamma_retain_on()`: `mov rax,rsp` instead of `add rsp,kt; jmp rcx` — hands the callee's own un-popped frame pointer to the caller in `rax`, currently written nowhere), and make the retry path **restore-and-jump** into that retained frame instead of the existing global-mailbox re-invocation (`rt_pl_cp_pop3`/`rt_pl_zf_resume_set`/fresh `rt_proc_call_open_det`).

## 2. Bug 1 — found and FIXED: the gating condition was scoped to the wrong graph

First attempt gated the new code on `g_emit_cfg->pl_cells_graph` (mirroring `icn_gen_regime()`'s `icn_cells_graph` check by analogy). **Measured false on the row's own standard witness** (`fact(a).fact(b).fact(c). main :- fact(X), write(X), nl, fail ; true.`) via a temporary instrumented build: `pl_cells_graph=0` at the call site even with `SCRIP_PL_GAMMA_RETAIN=1` armed, because `g_emit_cfg` at a call site describes the **caller's** graph (`main`), not the callee's (`fact/1`) — and `main` itself is not `pl_cells_graph`-classified. The already-existing, already-correctly-scoped local `pl_zf_resume` (`g_emit.zframe_graph && zls_g_resume_by_name(_.op_sval) >= 0` — a callee-name-keyed lookup, the exact boolean this row's own pre-existing mailbox mechanism has used for its entire history with no cross-language contamination reported) is the right condition. **Fixed**: both new branches now gate on `(pl_zf_resume && emit_pl_gamma_retain())`, which is provably no broader than the existing mailbox mechanism's own reach — it only ever adds the flag as a further restriction, never widens anything. No standalone `pl_gen_regime()` predicate was kept; it would have needed to be parameterized by the call-site-local `zf_cont_off`/callee name to be correct, which stops it being a simple `g_emit_cfg`-only function in the `icn_gen_regime()` shape.

## 3. Bug 2 — found and DIAGNOSED, not fixed: the callee-frame-size registry disagrees with the Prolog epilogue's own arithmetic

With the gating fixed, arming the flag on the minimal witness produced a SIGSEGV. ASM-diffed armed vs unarmed (`fact2.pl`, the row's 2-clause minimal repro): the only difference was clause (b)'s own two lines (`add rsp,384;jmp rcx` → `mov rax,rsp;jmp rcx`) — **my new caller-side code was not firing at all** (confirmed the Bug 1 diagnosis above). After fixing Bug 1, a fresh SIGSEGV appeared, this time from the new code. Traced with a temporary instrumented build:

- `emit_patzeta_frame_reserve("fact/1", &fb)` returns **400**.
- The actual `add rsp,N` `fact$2F1` itself uses at its own (unarmed) exit is **384** (read directly from `--compile` output).
- Delta: exactly **16 = (nparams+nlocals)×16** for `fact/1` (1 param, 0 locals). A second callee in the same witness (`$disj0/1`) showed the identical pattern: registered 592, actual carve 560, delta 32 = 2×16.

Root cause, read from source: the `pz[]` registration comment at `src/driver/scrip.c:152` states outright — *"fp term = (np+nl)*16, MIRRORING the callee alpha's own frame_total = flat_frame_bytes + (np+nl)*16"* — i.e. the registry uniformly stores `flat_frame_bytes + (nparams+nlocals)*16` for every registered proc. That formula is correct for an `icn_cells_graph` callee, whose own epilogue (`xa_flat.cpp:366-367`) explicitly adds that same term back onto `kt` before releasing. A **pure Prolog `zframe_graph` callee's epilogue does not** — that `if` is `icn_cells_graph`-gated — so for Prolog the registry overstates the true carve by exactly `(nparams+nlocals)*16` bytes. **This has been true since the registry existed; nothing prior ever surfaced it because every prior reader of `emit_patzeta_frame_reserve()` was itself `icn_gen_regime()`-gated, i.e. always reading it in the one context where the formula is correct.** This pass is the first to read it from a pure-Prolog call site. No `rt_proc_nlocals()`-by-name accessor exists to subtract the term safely from `bb_call_proc_staged.cpp` today; building one is a small, real, shared-code decision (touches the same registry both Icon's N-2 and this row now depend on) better made deliberately than improvised under this row's own time pressure.
