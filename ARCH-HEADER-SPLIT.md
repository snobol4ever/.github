## 1. THE RULE (written so a gate can check it)

**R1, ONE HEADER, ONE STRUCTURE.** A header is one of exactly two kinds. A TYPE HEADER declares ONE structure (or one closely bound family: a struct with its entry and bucket records, an enum with its name table) together with its fields, enums, constants, macros, one-line accessors and the prototypes of the functions that take or return that type. An INTERFACE HEADER `foo.h` declares the functions that `foo.c` (or `foo.cpp`) defines and nothing else. There is no third kind: no header that only includes other headers (an umbrella), no header that collects the prototypes of several files (a grab-bag), no header that holds data tables (data is a `.inc` included by one unit).

**R2, INCLUDE WHAT YOU USE, AND ONLY THAT.** A unit includes DIRECTLY every header whose declarations it names, and no header whose declarations it does not name. A header includes only what its own declarations need to compile; a pointer or reference to a struct needs a forward declaration (`struct IR_graph_t;`), not the struct's header. Includes are written by their path from `src/` (`#include "ir/ir_node.h"`), and the one `-I src` is the include path, so a header's directory is its layer.

**R3, NO INLINE BODIES BUT ONE-LINERS.** A function body in a header is at most one expression (an accessor, a predicate, a tag test) over the header's own type, or an `always_inline` the hot path has been measured to need (descr.h's predicates, the asm leaves' twins). Every other body is compiled once in a `.c`/`.cpp`. At -O0 (the fleet's build) an inline body is not inlined anyway: it is a static copy per unit, which costs compile time and buys nothing.

**R4, THE FAN-IN CEILING.** For every header H, fan-in(H) is the number of units whose dependency file names H (directly or through another header). users(H) is the number of units that name an identifier H declares. The rule, for every header OUTSIDE THE BASE SET: fan-in(H) ≤ users(H) + 4, and fan-in(H) ≤ one third of the units (99 of 296; 374 of 1,122). A base-set header is read by neither rule (RULED by the cto 2026-10-31 18:5x CDT on the 1b+5 landing, CEO-555: the text here once said "users + 4 for every header" while the gate's description below always said "every non-base header"; the measurement decided it: every header that declares a DESCR_t prototype reaches ir/descr.h and so ir/descr_tags.h, so their fan-in is the count of such headers' units, 245, against 106 and 120 users, structurally and forever; the instrument's over() now skips the base set and the baseline's rows for descr.h, ct_vec.h and descr_tags.h are inert). THE BASE SET, each wide for a stated reason and for no other: `ir/descr_tags.h` (the value tags every language, template and asm leaf names), `ir/descr.h` (the value cell DESCR_t, the one value type of every language), `ir/ct_arena.h` and `ir/ct_vec.h` (the compile-time allocator and vector of every compile-time object: parsers, lower, optimizer, planner, emitter, driver), `ir/ast.h` (the pruned parse tree, every parser's and lowerer's), `runtime/core/name_t.h` (the name cell), `runtime/rt/rt_diag.h` (the six-line diagnostic switch), `templates/bb/bb_template_common.h`, `emitter/emit_state.h`, `emitter/bb_label.h` and `templates/x86/x86_ops.h` (what every template reads: the emitter state, the labels and the encoder's API; their fan-in is the template count by construction). ## 2. THE INSTRUMENTS AND THE GATE (hq_templates builds them first, step 1a)

- **THE DATA .inc RULE (the cto, step 7, 2026-10-31).** The unused arm leaves a `.inc` include alone: a data .inc (an initializer, a table, a setting's source; renamed .inc at step 6A to say so) is spliced text, and its definitions are not declarations a unit names (rk_syntax.c and raku_setting.inc read as an unused include until this rule). THE MEMBER HOP (the cto, step 7): the member path is followed one hop through a record's pointer member -- `->u->type` names the header that holds the body of the record u points at -- so aggregates.c's k->u->type and pl_rat.c's a.u->fields count as uses of datatype.h (they are: the build fails without the body); the scan of pointer members looks behind for the separating semicolon rather than consuming it, or it sees every other member of a union (tbl, not u); the gate's ARM 9 holds the control pair (hold_t carries two pointer members q and p; m5.c reads g_hold->p->w and is a user of rec.h, m6.c reads g_hold->p alone and is not). ## 6. What a builder must not do

- Move a declaration and change its text: a move is a move (R5 proves it). A fix found on the way is its own landing.
- Create a new umbrella to make a step pass (a `common.h` that includes the split headers). The gate's arm 2 reads 0.
- Add a header to the base set, or raise the ceiling, without a ruling on this page.
- Land a large step outside the ceo's quiet window, or without the last-minute rebase: a header move that conflicts is reverted, not merged by hand.
- Leave the tracker or the poll family in a header the zeta steps will delete: step 2 puts each in its own file.
