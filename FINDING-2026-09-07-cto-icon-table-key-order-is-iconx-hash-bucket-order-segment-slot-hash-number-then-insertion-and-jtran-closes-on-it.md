## THE DEFECT

## ICONX'S ORDER, FROM THE SOURCE (rstruct.r, rmisc.r)
`hgfirst`/`hgnext` walk slot segments: segment 0 has 16 slots, segment s has 16<<(s-1); within a segment slot by slot; within a slot the chain sorted by hash number, equal numbers in insertion order (`memb` appends after equals, `hgrow` keeps relative order). The slot is `hn & mask`; `mask` starts at 15 and doubles whenever `size > 5*(mask+1)` (TooCrowded); a table never shrinks on delete (hshrink is only called by set operations and copy). `hash()`: strings sum the first ten bytes scaled by 37 plus the length; integers `13255*n>>10`; reals `r*1129.27586206896558`; records, lists, tables and sets by their serial id. Record ids are per record type (`recid`), which SCRIP's `DatType.serial_next` already matches.

## THE CURE (4 files, +59/-17)
`TBBLK_t` carries `icn_mask`, advanced on every new-key insert by iconx's rule; `table_icn_nth(tbl, idx)` orders the live entries by (segment, slot, hash, insertion) and the two Icon walk paths (`rt_list_bang_at` for `!t`, `rt_list_bang_key_at` for `key(t)`) read through it. Only `lower_icon.c` emits `IR_LIST_BANG`/`IR_ITERATE`, so nothing else moves. **Two things the witnesses taught:** the first cut hashed structures by pointer and the symbolic stage stayed a permutation, because jtran's keys are `ir_Label` RECORDS; records now hash by their per-type serial. And set creation went through `table_new`, consuming a TABLE serial before taking its set serial, so tables were numbered past iconx (visible in `image()` and in the table-key hash); `set_new()` returns the serial (4 sites).
