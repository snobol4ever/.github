## The three defects found (one cured class at a time, innermost first)

### 1. ⛔⭐ `scrip_coswitch`'s gc_spill inline asm was missing an "rax" clobber — EVERY coexpression activation corrupted its caller's frame on this build
`rt_coexpr.c:73` smuggles rbp past the compiler as `.byte 0x48,0x89,0xe8` (= `mov %rbp,%rax`, since rbp cannot be named in a clobber list), then stores `mov %rax,8(%0)`. **rax was never declared clobbered, so GCC was free to choose rax for `%0` — and on this build it did.** The hidden move destroyed the operand pointer mid-asm, turning the store into `mov %rax,8(%rax)`: it wrote rbp's value into `[rbp+8]`, which in coswitch's -O0 frame is the **caller's saved return address**. Main then slept in `sem_wait`, woke, and `ret` jumped into its own stack (SIGBUS at a stack rip — the symptom that varied run-to-run and resisted every backtrace, because the frame the evidence lived in was the frame that was destroyed). **Caught live by a hardware watchpoint on the saved-rip slot: the writer was coswitch itself, at the gc_spill line.** Cure: `"rax"` added to the clobber list, with a load-bearing comment. ⭐ Latent-until-regalloc-moves is the nastiest sub-class of s272's "correct procedure, false explanation": the asm was byte-identical for its whole life, and only a *different translation unit build* armed it. Any inline asm that hides a register write behind `.byte` MUST clobber-declare that register; a sweep found no other instance in `src/runtime`.

### 2. The N-2 apply-call gap itself (seat10's report) — cured by giving the coexpr C-window a real region
`bb_call_value`'s spine transfer pushes only the wire pair, so a region-resident (N-2) callee read garbage at `[rsp+16]`; the coexpr fallback window (`rt_genp_spine_enter`) was equally unsound — it pushes literal zeros where the region pointer belongs. **Also proven: `SCRIP_ICN_GENFRAME2=0` (pre-N-2 protocol) crashes on the same witness — apply-call to a generator has NEVER had a green baseline in any regime.** The cure, three pieces, no formula duplicated:
- **One predicate, one registry:** `emit_icn_n2_gen_region_ft()` (emit.cpp, beside `emit_jmp_entry_for_proc`) answers "will this proc's α take the region-resident prologue, and what frame_total did it bake" — mirroring the α arm selection term-for-term and reading ft from the pz[] registry via `emit_patzeta_frame_reserve()`. The driver stamps it into the runtime proc table (`rt_proc_set_gen_region_ft`; field slotted into the 4-byte hole at offset 52 of `rt_proc_t` — sizeof stays 128, every rtx-baked offset unmoved, asserts fence it). Mode-4 twin emitted in the ONE_REG startup lane (the first attempt sat in the legacy `_onereg==0` lane that never runs — caught because the .s had zero stamps).
- **The window speaks the armed protocol:** `rt_genp_spine_enter_n2` (rt.c) allocates the region slice `[R, R+ft+48)` from `rt_zls_alloc` (zeroed, GC-walkable, non-LIFO release; freed in `rt_genp_destroy`), pushes the five-word entry stack `[γ ω REGION L7 depth-seed]` at staged parity (anchor ≡ 0 mod 16), and its γ-wire shim is three-state: retire (`al=DT_FAIL`) → deliver_ω; suspend (`rdx=H`) → value from `[H−align16(ft)]`, first-γ epilogue, coret; resume → the staged β dance byte-for-byte (`rax=H; rsp=[H+24]−40; jmp [H+32]`).
- **The un-wired spine path refuses:** `rt_call_value_spine_prep` returns NULL for stamped procs, routing every value/apply generator call through the cured window. The direct spine fast path for apply (region reservation at IR_CALL_VALUE sites, the five-word push, N-2 landing arms in bb_call_value) is real follow-on work — asked hq_B to mint the row.
