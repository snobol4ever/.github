## Part 2 — actual execution triage (not just coverage-mapping)

The parent brief's DONE-WHEN requires the ungated ones be "triaged by running them against the oracle under timeout" — Part 1 maps coverage, but mapping isn't triage. This part ran `timeout 8 scrip --run <file>` (parallel, `-P 16`, `timeout -k 2` to force-kill genuine hangs) across the **1,574 files** in the confirmed-ungated-for-execution-correctness populations identified in Part 1 and the prior FINDING: `programs/icon/{ipl,parser}` (1,004), `programs/prolog/{gnu_prolog,parser}` (198), `programs/snobol4/parser` (88), `programs/rebus/parser` (96), `programs/raku/{parser,parser-coverage}` (186), `programs/pascal/{bench,grammar}` (2). Raw per-file TSV survives at the scratch path above (`sweep/results.tsv`, `sweep/run_one.sh` is the exact invocation, reusable).

**Result: 374 clean exit (OK), 950 nonzero-but-clean exit (NONZERO — overwhelmingly expected: these are library/utility source files being run standalone with no args/stdin, e.g. GNU Prolog's own BIPS source or IPL procedure libraries meant to be `link`ed, not run — a nonzero exit with a sane message is CORRECT behavior for those, not a bug, and no row was minted for this bucket), 231 CRASH (abnormal termination, rc≥128), 19 HANG (timeout, rc 124).**

## Part 3 — policy proposal for HQ to rule on

**This session ENDORSES the prior FINDING's 6-point policy proposal as-is** (primary-corpus-3,254 denominator; `ipl/` gets a "mine it" not "gate it" policy; `probe/`'s 63 unconfirmed subdirs need per-subdirectory liveness checks, not blanket gating; genuine gaps follow the proven `demo-corpus-coverage-audit` three-way classify method; exclusion reasons belong in a directory-local `EXCLUDED.md`, not only a FINDING; runtime-cost-check before wiring `crosscheck/snocone` or Icon `parser/` into a live gate). **Adds, from this session's evidence:**

7. **Do not gate the 1,574-file execution-triage population wholesale.** It was swept once, cheaply (a few minutes, parallel, timeout-bounded), specifically to catch crash/hang defects — a valuable PERIODIC health check, not a per-commit gate. Re-running it (the exact `sweep/run_one.sh` invocation is reusable) after each of the 11 rows above lands would measure real progress; wiring all 1,574 files into `test_gate_*` machinery would recreate the "30-minute gate" problem the parent brief explicitly warns against, for files most of which (per the prior FINDING's `ipl/` framing) aren't meant to be individually graded anyway.
8. **The legacy-dash-flag family (`legacy-dash-flags-dead-scripts`) needs an explicit per-script ruling — fix vs. retire — not a blanket "fix them all."** Several targets are DORMANT backends (JVM/.NET/WASM) that RULES.md's "X86 ONLY FOR NOW" law says aren't supposed to be live yet; fixing their CLI flags alone wouldn't make them useful. Only the x86-targeting subset (`crosscheck-snocone-dead-runner-181-files` and its siblings named in that row) is unambiguously worth fixing now.
9. **The ~9-way redundant full-crosscheck-sweep scripts are a consolidation candidate**, not a coverage gap — but nobody has decided which one is canonical. Recommend HQ nominate one (likely `test_corpus_snobol4.sh`, since it's the one CLAUDE.md's testing table already documents by name) and mark the other 8 clearly as either retired or intentionally-different-purpose (e.g. `test_mode34_parity.sh`'s m3-vs-m4 divergence focus is a genuinely different question than `test_corpus_snobol4.sh`'s pass/fail).
