# FINDING-2026-07-25-CLAUDE-SN4-RTX-2-ALLOC-PHANTOM-FAMILY-AND-THE-CARVE-FAST-PATH

**Rung:** SN4-RTX-2 (ALLOC). **Session:** s163. **Repos:** SCRIP, .github.

## 1. ⭐⭐ THE HEADLINE: RTX-2 WAS AIMED AT SYMBOLS THE COMPILER NEVER EMITS

`ARCH-SNOBOL4-RTX.md` §5 named the ALLOC family **`blk_alloc` / `blk_free`**. Both are dead:

| check | result |
|---|---|
| live `--compile` call sites | **ZERO** (26 live artifacts swept) |
| C definition in `src/` | **none** — sits in `archive/backend/blk_alloc.c`, not in any build rule |
| where the 15/30 "static sites" came from | 5 legacy artifacts only |

`util_rtx_symbol_inventory.sh` — the script the s162 cursor calls "ground truth" and instructs every RTX session to run — swept **33** `.s` files without separating live compiler output from legacy. Of those 33: **26 live** (first line `.intel_syntax noprefix`, the Lon-ruled GNU-as form), **5 legacy** (`.byrd-reference.s` ×4 plus `f13_eval_code.s`, all headed `; generated by scrip-cc -asm` — a tool that no longer exists — in nasm syntax, `[rel x]` / `qword [x]`), **2 macro libraries** (`bb_macros.s`, `sm_macros.s`).

The legacy 7 contributed an entire phantom family (`blk_*`) and the whole dead `stmt_*` set (`stmt_get` 78, `stmt_set` 66, `stmt_concat` 40 …). **Fixed s163:** the script now filters on the `.intel_syntax` marker and reports `26 LIVE (of 33 found)`; the phantom symbols are gone from its output.

**THE LADDER ORDER SURVIVED.** On the clean sweep the CALL/STR head is byte-for-byte what s162 reported — `rt_call_arr` 232 · `rt_proc_call_epilogue_` 178 · `str_concat_d` 152 · `rt_proc_open_fn` 138. So s162's "independent static confirmation of the s161 NRETURN finding" **stands**; only ALLOC's contents were wrong.

### ⚠ Two standing consequences (these outlive this rung)
**(a) A static blob→runtime call count RANKS THE CALL BOUNDARY, NOT THE HOT PATH.** `rt_gcheap_alloc` — which every string, aggregate, WSC and PLJ block on the system carves from — has **zero** blob call sites, because blobs reach it *through* `str_concat_d`, `rt_subscript_var`, etc. A family can be universal and invisible to this table simultaneously. Rank work with dynamic evidence (s161-style ablation); use the table only for what it measures.
**(b) `grep` the symbols in `src/` before porting a family.** Two minutes would have caught this. Added to the ARCH §7 read-first checklist.

## 2. WHAT THE LIVE ALLOC FAMILY ACTUALLY IS

`rt/gc_heap.c` (NOT `rt_arena.c` — that file is Prolog cterm/cellws islands and belongs to no SNOBOL4 family):

- **`rt_gcheap_alloc(type, payload)`** — the SIL bump mint. Manual p.216 model: bump until exhaustion, then storage regeneration; `COLLECT(i)` forces it and returns free words.
- `rt_str_alloc` / `rt_str_dup` — the DT_S entry (n chars + NUL).
- `rt_ws_alloc` (285 in-runtime sites) + `_realloc` / `_strdup` / `_alloc_c` / `_strdup_c` — the immortal workspace island.
- `rt_agg_alloc`, `rt_plj_alloc`; `rt_gcheap_carve` (static; fused into the port).

## 3. THE PORT — `src/runtime/rtx/rtx_alloc.S`, gate `SCRIP_RTX_ALLOC` (default ON)

Ported: **the detax fast path only** — armed, room at the frontier, and the carve landing at/above the HP-2 `virgin` high-water so **no payload zeroing is owed**. 21 instructions, no call, no memset, straight-line in the hot case.

Deliberately NOT ported, each tail-jumping to `c_rt_gcheap_alloc` with `edi`/`rsi` untouched (so the jump needs no argument staging and *is* the byte-identity path): lazy heap init · GC trigger and storage regeneration · the fill-window second cursor · every memset-owing path (recycled memory below `virgin`, or `SCRIP_ZSKIP_OFF=1`) · the allocation histogram · exhaustion. **`rt_gc_collect` can never run under the asm's feet** — we leave before any condition that could provoke it.

`rt_str_alloc` fuses in: `armed` already encodes "histogram is off", so the histogram call is not skipped but **eliminated**; the entry falls into the carve with no call at all.

**Two facts that shaped the code:**
- **PL-SINK-3 had already done this once.** `bb_call_fn.cpp`'s `sink_carve48` inlines this exact carve for one fixed shape (HB_PLJ/48B) over the exported `g_hp_fr` cell. The asm is the *general form* of a proven-correct reference — if you change one, read the other. `virgin` and `zfull` were promoted into that same cell (appended at the tail: **offsets 0/8/16/24 are baked by the template and MUST NOT MOVE**; new `_Static_assert`s anchor 32/40, so a layout mistake fails the BUILD, not a test).
- **`g_hp_fr` is exported and therefore preemptible**, so it is reached via `@GOTPCREL`, not `lea [rip+sym]` — unlike the `.hidden` gate byte. This was the one link failure (`R_X86_64_PC32 ... recompile with -fPIC`).

## 5. MEASUREMENT — NO SPEED CLAIM (RT_OPT=-O0, `RTX_ALLOC=on/off`, 1-core container, 5 interleaved rounds, medians)

| program | ON | OFF | read |
|---|---|---|---|
| string_concat | 15 ms | 15 ms | window far below the rail's 800 ms floor — noise only |
| mixed_workload | 382 ms | 405 ms | ~6% but ON rounds swung 371→1498 ms |
| roman | 569 ms | 592 ms | ~4%, same noise class |
| func_call | 683 ms | 677 ms | ~1% **slower**, i.e. noise |

**HONEST VERDICT: nothing here is a measurable win.** `bench_sno_rail.sh`'s own header warns that windows under ~1 s swing 1.4×–3.9×, and the 1498/1162 ms outliers are exactly that. This is **expected and structural**, not a disappointment: the C detax path was already a handful of operations, and s161 measured the real weight in the CALL path and TABLE work. **Do not quote a rail number off RTX-2** — the same caveat RTX-1 carries. First real speed evidence remains RTX-3 (STR) / RTX-4 (CALL), as ARCH §6 predicted.

What RTX-2 *does* deliver: the ALLOC family is now behind a proven two-sided kill-switch with a differential battery, one call is eliminated from every `rt_str_alloc`, and the family map is no longer fiction.
