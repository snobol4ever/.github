## 1. The malfunction

An error is a transfer of control out of the box that raised it to the construct that handles it, and in six languages SCRIP performs that transfer in C: by `longjmp` over emitted frames, by reloading the machine's depth from a snapshot a C function saved, or by exiting at the raise. Each of those is a DEPTH DECIDED IN C (the second-source flaw of ARCH-ZETA-LAYOUT-ONE-SOURCE-OF-TRUTH in its C form), each one skips the ω road of every box it crosses (Lon: *"skipping omega"*), and each language has its own copy: Icon's `&error` through the errjmp chain, SNOBOL4's SETEXIT through the snapshot, Raku's handlers through a second chain (`g_rk_cbh_cur`), Pascal and the uncaught cases through `exit(1)` at the raise. Only Prolog's road obeys the laws, and it is the one road with no catcher, no snapshot and no bomb.

## 2. The laws this design is under

- NO C FUNCTION ENTERS A BOX (CEO-1576): a C road that would transfer control RETURNS; `longjmp` into or across emitted frames is a transfer.
- A RETRY NEVER LOADS RSP FROM MEMORY (ARCH-ZETA-ONE-COORDINATE § 6); the DISCARD LAW: a discard restores rsp to the depth its continuation is entered at, which the PLAN declares.
- NO GLOBAL HOLDS A STACK (CEO-1542): the errjmp chain is one.
- LOGIC LIVES IN EMITTED BOXES, NOT IN C (CEO-985): whether an error is handled, converted or fatal is decided by the construct that owns the decision, in emitted code; C records facts.
- STATIC WIRING ONLY, UNLESS IT IS AN IF-TYPE CONSTRUCT (CEO-694): a box's ball exit is wired at compile time to its enclosing catch gate; SETEXIT's handler and `:(CONTINUE)` are if-type gates with a stored resume target, the Proebsting shape.
- ONE SCRIP-SHAPED ERROR VOICE for every language (`core_error_voice`, CEO-625; the equivalence list `util_render_error_voice.py`), spoken ONCE, at the root.
- THE LANGUAGE SURFACE IS SETTLED: `&ERRLIMIT`, SETEXIT, `&ERRTYPE`, `&error`, `&errornumber`, `runerr`, `catch/3`, `try`/`CATCH` keep their meanings from the oracles; the refs are the oracles'.
- LARGE CHUNKS (CEO-1478), THE ORDER OF WORK (CEO-1886), THE IDENTITY (CEO-1992), A ROW ONLY WHILE MEASURED (CEO-1386).

## 3. THE PROTOCOL (the Prolog road, made the law for every language)

**P1. THE BALL RECORD.** One record in the context (`g_runtime.abi.ball`, an asm-readable member of the granted struct, A GC ROOT): `{ class, code, text, value (DESCR_t), src_node, stno, exit_code }`. `class` is one of: FATAL (uncaught by construction: the root speaks and exits), HANDLED (a catch construct will consume it), CONVERTED (the raise already turned it into a plain failure and armed nothing; the record holds the keywords' data only). The Prolog BALL (r15 and `PL_TR_BALL_SLOT`) stays as Prolog's cached arm of the same record; `PL_BALL_ARM` writes both.

**P2. A RAISE RETURNS.** `rt_raise(class, code, msg, val)` records the ball and RETURNS `FAILDESCR`. Every C function on a raise path returns its verdict to its caller (`FAILDESCR`, or the family's failure value), the caller returns at once, until the runtime entry returns to the box. No `setjmp`, no `longjmp`, no `exit`, no snapshot. The bookkeeping a language's keywords need (`&ERRTYPE`, `&ERRTEXT`, `&ERRLIMIT` counting down, `&errornumber`, `&errortext`, `&errorvalue`, `&error` counting down) is DATA written by the raise through `rt_kw_publish_error`, as today. The CONVERTED class is the whole of Icon's `&error` conversion and SNOBOL4's bare `&ERRLIMIT` failure: the raise publishes and returns a plain failure, and the box fails along its ordinary ω, at no cost in emitted code. A COMPILE-TIME CALLER OF THE RUNTIME (the constant folder's `cf_eval`, the SNOBOL4 lowerer's `sno_fold`) reads the same verdict: `FAILDESCR` with the record armed means DO NOT FOLD (the SNOBOL4 lowerer reports it as the compile error SPITBOL reports, § 0 fact 2; the optimizer leaves the operation to raise at run time, which is what Icon's oracle does), then `rt_ball_clear()`; their two `setjmp` catchers go with the rest (step 3b).

**P3. THE OMEGA BALL TEST.** A box that can receive a ball (the planner's `raises` fact: it calls a runtime entry whose row says `raises`, or it calls a box or procedure that raises; the fact is closed over the graph and the call graph, and a run-time-compiled fragment is assumed to raise) tests `[ball.class] != 0` at the head of its ω road, one load and one branch on the FAILURE path only, and jumps to its enclosing catch gate's BALL ENTRY, which is wired at compile time (the construct nesting is static: `IR_construct_t`). A box with no enclosing catch jumps to the chain root's ball exit. A call box whose callee returned with the ball armed does the same at its landing: a ball crosses a procedure boundary as a failed return, never as a C transfer. The ball is never propagated β by β: a ball is not a retry.

**P4. THE CATCH GATE.** A catch construct is `IR_BOUND` (records the marks: the trail top, the CAS depth, the Icon scan bank) + body + `IR_UNMARK` + a GATE with a BALL ENTRY. The ball entry (i) restores rsp to the GATE's PLANNED depth (the DISCARD LAW; the plan knows it; `x86_pl_ball_rule_omega` and the GATE of `bb_gate.cpp` are the shape), (ii) unwinds the islands to the BOUND's marks (the trail: `x86_pl_tr_unwind_at`; the CAS stack: its twin; the scan bank: the leave node's restore), (iii) runs the handler as the gate's arm, which reads the ball record, decides (the handler's own logic: Prolog unifies the catcher, Raku matches `when`, SNOBOL4 jumps to the SETEXIT label, Icon's `&error` has no handler because P2 converted it), and either CLEARS the ball and continues at the gate's γ, or re-arms it and jumps to the next enclosing gate's ball entry (rethrow). The construct is lowered by every language from ONE builder in `lower_common.c` (`lc_catch(bound, body, handler)`): the IR carries the construct, never the language (CEO-1838).

**P5. THE ROOT SPEAKS ONCE.** The chain root's ball exit is THE ONE VOICE SITE (`rt_root_ball_exit`): it flushes the program's output, calls `core_error_voice` with the record (the language's shape through the equivalence list, the statement and line from `src_node` and `stno` recorded at the raise), and exits with `exit_code` (the oracle's: SPITBOL's, Icon's 1, fpc's 200-class codes, Raku's 1, Prolog's). A co-expression thread's root is a root: a FATAL ball there speaks and exits from that thread. The only `exit()` calls left in the runtime are this site and the RESOURCE REFUSALS (the arena cap 204, the trail arena, the code pool, a stack overflow: a program that cannot continue, named in a list the gate reads).

**P6. THE IF-TYPE GATES SNOBOL4 NEEDS.** `SETEXIT(.L)` writes the resolved label's address into the context's SETEXIT slot (data); the STATEMENT box's ball entry (every SNOBOL4 statement is a catch construct when the graph fact `uses_setexit` is set, else no test is emitted) jumps THROUGH that slot (an if-type construct selecting its continuation at run time, CEO-694's one exception) after writing the CONTINUE slot (the statement's successor label, a static address the box knows) and the RETURN context; `:(CONTINUE)`, `:(ABORT)`, `:(RETURN)` in the handler are indirect gotos through those slots; a SETEXIT slot that is empty makes the statement's ball exit the root's. hq_snobol4's CEO-2008/2011 rows (CONTINUE retakes a direct goto, CONTINUE after an error in evaluated code, an error no handler takes uses the continuation, the statement in error of a failed CODE) are INSTANCES of this gate and land on it.

## 7. What a builder must not do

- Add a `setjmp`, a handler chain, a snapshot, a `_Unwind_Backtrace`, or an `exit()` outside the root and the resource list. A raise returns.
- Decide in C whether an error is handled. C records the ball; the construct decides in emitted code.
- Propagate a ball β by β (a retry), or price the ball's landing from anything but the plan's depth of the catch gate.
- Print the voice anywhere but the root; print it twice; print it to stdout.
- Change what the oracle says: `&ERRLIMIT`, SETEXIT, `&error`, `runerr`, `catch/3`, `try`/`CATCH` mean what SPITBOL, Icon, swipl and Rakudo say they mean; a disagreement is a ref question, never a protocol question.
- Land a language's step before the shared runtime returns (3b): a converted language on an unconverted core raises through a catcher that no longer exists.
- Call `done` on a step the harness has not graded GREEN.
