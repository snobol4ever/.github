## 1. The malfunction, in the shape Lon already ruled on

Two deciders, and more. The LOWERER knows the name, the arity and the vocabulary of every builtin call, because the call is in the source; yet what the call IS is decided in three stages by FIVE deciders, and the last of them decides it again at every call:

1. LOWER, `src/lower/lower_call_forms.c` (`lower_call_route`, `lower_call_road_kind`, 199 lines): reads four vocabularies that live elsewhere: `rt_builtin_is_known` (a static list of 316 names in `by_name_dispatch.c:426`), `icn_builtin_is_known` / `icn_builtin_arity` / `icn_builtin_is_generator` (`icn_bi_tbl`, 95 names with arity, `by_name_dispatch.c:220`), `dop_direct_leaf_known` (defined in THE EMITTER), the `bid_of` hash (186 names, `builtin_ids.h`), `sn4_is_leaf_fn`/`sn4_is_system_fn`, `rt_pas_bi_index`, `pl_leaf_inline_known`; and reads `nd->dval == 2.0 / 3.0` as a vocabulary flag.
2. THE EMITTER, `src/emitter/emit.cpp:4734` `dop_direct_fp`: a table of 183 names (`$` Prolog ops, `SNO$` ops, `dop_write`...) with arity and function pointer, the registry a call must be in to be emitted as `call_direct`; `emit.cpp:4468` `sn4_byname_sym`/`sn4_byname_fp`: five runtime entries chosen by `sn4_byname_kind`.
3. THE RUNTIME, per call: `rt_call_bid_sn4` (asm, `rtx_misc.s:3`: `g_bn_direct[bid]` for 22 SNOBOL4 leaves, else C), `icn_bi_direct` (a few Icon ids), the DATA-constructor inline cache keyed by the name's address, then `rt_call_arr_bl_s` → `try_call_builtin_by_name_bl_s_rq` (`by_name_dispatch.c:21744`, 4,600 lines: the data-instance field probe at its head, the argument materialization loop, then a LINEAR chain of `_bid == BID_x` compares over 186 names plus 12 `strcmp` arms), → `script_try_call_builtin_by_name_rq` (`:14741`, the `__rk_` prefix test, then 276 `strcmp(fn, "...")` arms), → `rt_str_method` (`:3399`, 101 `strcmp(meth, "...")` arms by receiver type) for a method, → the user procedure (`rt_call_open_by_name`, `APPLY_fn`). 26,371 lines; 335 distinct `strcmp(fn, "...")` arms; 1,398 string compares; 12 of the runtime's 25 `rt_c2bb_bomb` sites (TWEAK, BUILD, grammar actions, `__rk_eval`, callsame, `rk_proc_descr_rq`: every one a road where C reached user code BY NAME).

This is the memory model's two-decider malfunction (CEO-1895: the layout granted, the emitter re-decided per shape) over CALLS instead of cells, with the emitter holding a registry LOWER must ask (the same layering the planner stage ended, CEO-1988). Placement is decided once in the planner; a builtin call is decided once in LOWER.

## 2. The laws this design is under

- LANGUAGE IDENTITY STOPS AT LOWER (CEO-1838): a vocabulary is the lowerer's; the runtime never decides by a name's spelling (`fn[0] == '_' && fn[1] == '_' && fn[2] == 'r' && fn[3] == 'k'` is the defect).
- A RUNTIME ENTRY IS NAMED ON THE NODE AS DATA (CEO-1836): the row, not the string.
- NO C FUNCTION ENTERS A BOX (CEO-1576): a builtin that may reach user code returns the address and the box jumps; the table says which rows may (`conv=open`).
- LOGIC LIVES IN EMITTED BOXES, NOT IN C (CEO-985); NO INTERPRETER: one hash lookup for a run-time name is a lookup, not a dispatch loop.
- NO ACCESSOR LAYER (Lon: deciders are deleted, not wrapped): the emitter reads a row as a struct.
- NO FIXED LIMIT A PROGRAM CAN REACH (CEO-1210): the static table is generated and closed; what a program adds at run time (an OPSYN alias, a user class's methods) lives in a rooted, growable structure of its own.
- LARGE CHUNKS (CEO-1478): the table once, then one language small and smoked, then everywhere, then the deletion, then ultracode.
- THE ORDER OF WORK (CEO-1886): every step keeps every suite row at or above its last reading; the instruction counts are the finish line's measure (CEO-1912), never its rank.

## 3. THE TABLE: `harness/scripts/builtins.tsv` → `src/runtime/builtin_table.inc` (+ `builtin_table.h`), by `util_gen_builtin_table.py`, gated by `test_gate_builtin_table_is_current.sh`

One row per builtin per vocabulary. The columns:

| column | meaning |
|---|---|
| `bid` | the row's integer id, assigned once and NEVER renumbered or reused (the 186 ids of `builtin_ids.h` keep their numbers; a new row takes the next free id; a deleted row's id stays dark). The id is the only thing emitted code and the runtime share. |
| `vocab` | which frontend spells this row: `sno` (SNOBOL4, which Snocone and Rebus lower through), `icn`, `rk` (a Raku sub or runtime helper), `rkm` (a Raku METHOD), `pas`, `pl`; `all` for a name every vocabulary means the same way. A name with two meanings is two rows (Icon `pos` and SNOBOL4 `POS`; Icon `map` and Raku's method `map`), the lowerer choosing by ITS vocabulary. |
| `name` | the spelling in the source. |
| `min`, `max` | arity bounds; `max = -1` is variadic. Below `min` the LOWERER pads with the vocabulary's null (SNOBOL4 the null string, Icon `&null`); above `max` the lowerer applies the vocabulary's rule at compile time (Icon evaluates and drops the extra, SNOBOL4 lowers the error). A leaf never counts arguments to decide a name. |
| `entry` | the C or asm symbol of the leaf, the one the box calls: `bt_size`, `icn_map`, `rk_write`, `rt_pl_dop_functor`. |
| `conv` | ONE OF FOUR: `leaf` = `DESCR_t f(DESCR_t *args, int nargs)` (the existing direct shape of `dop_direct_fp`'s rows; THE shape for a value builtin; failure is `FAILDESCR`); `gen` = `DESCR_t f(DESCR_t *args, int nargs, int64_t *state)` (a resumable builtin: Icon `find`, `upto`, `bal`, `key`, `!`; the `bb_call_gen` box, which keeps `state` in its own carve and re-enters on β); `open` = `rt_call_next_t f(DESCR_t *args, int nargs, void *rec)` (a builtin that may hand back an address to ENTER: Raku's methods and redispatch, SNOBOL4 `APPLY`, `EVAL`, the TWEAK/BUILD/grammar-action roads; the box does the jump, CEO-1576); `inline` = no leaf, a template emits it (Prolog's `$ax_*`/`$cmp_*` PL_LEAF kinds, Pascal's `pas_bi` index), the row naming the kind. |
| `recv` | `rkm` rows only: the receiver's type class (`Str Int Num Rat Complex Bool List Array Hash Map Range Code Any`), `*` for every class. |
| `flags` | `scan` (reads or writes the scan environment: Icon's nine and the `tab`/`move` cursor pair, today's `op_call_scansync`/`op_call_curmov`); `mut` (takes a variable by reference: `script_try_mutating_builtin_by_name`'s clients). `alloc` is NOT a column: the allocating-table generator derives it from the entry symbol, as it does for every direct call today. NO `shadow` flag and no shadow byte: MEASURED on the witnesses, SPITBOL refuses `DEFINE`/`OPSYN` of a system function's name at run time (ERROR 248, attempted redefinition of system function) and SCRIP already answers the same error 248; Icon and Raku rebind a builtin's name only in the source, which the lowerer sees. A resolved builtin call is final. |
| `op` | a small integer the leaf receives when one entry serves several rows (today's `bn_direct_t.op`); 0 otherwise. |

THE SOURCES THE FIRST CUT HARVESTS (step 1 proves the union, nothing invented): `dop_direct_fp`'s 183 rows (vocab by prefix: `$` is `pl`, `SNO$` is `sno`), `g_bn_direct`'s 22, `icn_bi_tbl`'s 95 (with arity), `rt_builtin_is_known`'s 316, `rt_builtin_is_generator`'s list, the 186 `builtin_ids.h` names, every `strcmp(fn, "...")` arm of the three chains (335), `rt_str_method`'s 101 `strcmp(meth, "...")` arms as `rkm` rows, `rt_pas_bi_index`'s list, the 137 `__rk_*`/`rk_*` names `lower_raku.c` spells as call targets, `pl_leaf_kind`'s inline kinds. About 800 rows. A name harvested from a chain whose arm is not yet a separate function gets its row with the entry it WILL have (`bt_<name>`), and step 2 writes that function.

THE RUNTIME SIDE (generated): `const bt_row_t g_builtins[BT_ROWS]` (`sym`, `fp`, `min`, `max`, `conv`, `flags`, `op`), indexed by bid; `bt_bid_of(vocab, name, len)` the open-addressed hash of the static rows (the shape of today's `g_bid_tab`, keyed by vocab and name); `bt_alias` a small rooted run-time hash for names a program adds (`OPSYN('SZ', 'SIZE')` makes `SZ` an alias of row `SIZE`; `OPSYN` onto a system function's own name stays error 248), consulted by the dynamic road after the static hash. The compiler links the runtime, so a row's `fp` is the mode-3 address and its `sym` the mode-4 symbol: the gate's old hazard (a `.s` baked under one numbering linked against another runtime dispatching a different builtin) is gone for every direct call, because the `.s` names the symbol.

## 4. THE LOWERER RESOLVES (`src/lower/lower_call_forms.c` becomes table-driven; every frontend's lowerer stamps its vocabulary)

- A lowerer that builds a call to a LITERAL name looks it up in ITS vocabulary: `bt_lookup(VOCAB_ICN, "map")` → the row; it writes the bid into the node's integer literal (`IR_LIT(nd).ival`; `sval` keeps the name for the dumps and the dynamic road) and the op `IR_CALL_BUILTIN`. `IR_CALL_ICON`, `IR_CALL_SNOBOL4` and the `dval == 2.0 / 3.0` flags are the vocabulary stamps of today and are DELETED when the bid replaces them (step 3).
- THE PROGRAM'S OWN DEFINITION WINS, decided at lower as today: a name the program defines (a registered procedure, an Icon `procedure map()`, a Raku `sub chars`, an Icon global reassigned, a SNOBOL4 `DEFINE` with a literal string) is not a builtin call; `lower_call_route`'s registry checks keep that order and run BEFORE the table. The table never shadows the program.
- `lower_call_road_kind` reads the row: `conv=leaf` → `IR_CALL_DIRECT`; `gen` → `IR_CALL_GEN`; `open` → `IR_CALL_METHOD` / `IR_CALL_REDISP` / `IR_CALL_APPLY` / `IR_CALL_EVAL` by the row's named open kind (one `IR_CALL_OPEN` with the kind in the row would be cleaner, but those four ops exist and their templates are right; they stay, their callee read from the row); `inline` → `IR_CALL_PL_LEAF` / `IR_CALL_PAS_BI` as today. No row and no definition → the DYNAMIC road `IR_CALL_BYNAME` (a DATA constructor or field name SNOBOL4 defines at run time, a name computed at run time) — the only by-name call left.
- ARITY is the lowerer's: pad below `min`, apply the vocabulary's over-arity rule above `max`, so every leaf receives `min <= nargs <= max` and never pads (today `c_rt_call_bid_sn4` pads through `core_fn_arity_norm` at run time, per call).
- The run-time compile roads (`runtime_eval.c` calls `lower_call_forms_graph` at four sites) resolve the same way with no change: a `CODE`/`EVAL` body or an asserted clause is lowered by the same lowerer.

## 5. THE EMITTER READS THE ROW AND DECIDES NOTHING

- `bb_call_direct` keeps its shape (`lea rdi, [args]; mov esi, nargs; call <entry>`, the result in rax:rdx, the GC poll decided by the entry's class in `gc_allocating_table.inc`): the callee symbol and address are `g_builtins[nd->ival].sym` and `.fp`, read as struct fields; `dop_direct_fp`, `dop_direct_leaf_known`, `sn4_byname_sym`, `sn4_byname_fp`, `bid_bake_of` and `sn4_byname_kind` are DELETED from the emitter (step 3). The template serves ONE form per `conv`; no `.string` of a builtin's name is emitted for a resolved call.
- `bb_call_gen` calls the row's `gen` entry directly, its state word in the box's own carve (CTO-349); the `_bynamegenfn` label and `rt_call_arr_gen(name, ...)` go.
- `bb_call_method`/`redisp`/`apply`/`eval`/`try` call the row's `open` entry (`rk_method_open` and its kin ARE the open entries; they become rows and lose their name argument), then `bb_glue_enter_c2bb` jumps where the entry says, as today.
- `bb_call_byname` is the DYNAMIC road alone: `rt_call_dyn(vocab, name, args, nargs)`; the five `sn4_byname_sym` entries collapse to that one.

## 6. THE RUNTIME: LEAVES, ONE HASH, THE DYNAMIC ROAD, THE METHOD TABLE

- EVERY CHAIN ARM BECOMES A LEAF of its row's `conv` (step 2): `bt_<name>(args, nargs)`; the 22 `bn_*` leaves of `g_bn_direct` change their shape from `int f(args, nargs, out, op)` to `leaf` (the `op` becomes the row's `op`, passed by a two-row entry's wrapper where two rows share a body). The chains themselves become the lookup for the one step in which emitted code still calls them: `try_call_builtin_by_name_bl_s_rq(fn, ...)` = `g_builtins[bt_bid_of(fn)].fp(args, nargs)` — byte-identical emitted code, the walk gone — and are deleted in step 6 when no box calls them.
- THE DYNAMIC ROAD `rt_call_dyn(vocab, name, args, nargs)`: static hash → the leaf; miss → the alias hash → the user-procedure registry (`rt_call_open_by_name` returns the address, the box jumps) → the DATA constructor and field roads (today's inline cache lives here, its only client) → the error voice. Clients: SNOBOL4 `APPLY`, `$`-computed names, `OPSYN` targets, `DEFINE` of a computed string; Icon string invocation `"map"(s)` and `proc("map")`; Raku `&::("name")` and `$obj."$m"()`; `CODE`/`EVAL` text naming a function defined later.
- RAKU METHODS: `rk_mtab[RK_NCLASS][BT_RKM_ROWS]` (generated from the `rkm` rows: receiver class × method bid → entry) replaces `rt_str_method`'s 101 arms, `rk_rat_dispatch`, `rk_str_norm_method`, `rk_is_rakudo_method` and `rk_qh_hook`; the lowerer bakes the method's bid (the name is literal in `.chars`); `rk_method_open` reads `rk_mtab[class_of(recv)][bid]`; a user class's methods are a per-class table keyed by the same bid space (a method name a user class introduces is interned into the alias hash at definition, its bid above the static rows), with the MRO folded in at definition (so `rk_redispatch_open`'s `sprintf("%s__%s")` and linear `strcmp` over `proc_table` go). The Raku rewrite design (`design-raku-rewrite-ceo-1998`) takes this id space and the class table as its given.
- WHAT THE RUNTIME DELETES (step 6): `try_call_builtin_by_name*` (five entries), `script_try_call_builtin_by_name*`, `rt_call_arr_bl*` (the five SNOBOL4 kinds and the try/strict pair), `rt_call_bid_sn4` and `g_bn_direct`, `icn_bi_direct`, `icn_bi_tbl` and its three readers, `rt_builtin_is_known`'s list, `rt_builtin_is_generator`'s list, `rt_str_method`, the `__rk_` prefix test, `builtin_ids.h`'s hand-kept table, the spent `gen_builtin_ids.py`.

## 9. What it is not, and what is forbidden

Not an interpreter (one hash lookup for a run-time name). Not a per-language emitter branch (one template per `conv`; the vocabularies are the lowerers'). Not an accessor layer (a row is a struct the emitter reads). Not a frame or stack change (the call's cells are the planner's as today; `cf_marshal` and the zd copy are untouched). FORBIDDEN: a builtin's name as a `.string` on a resolved call; a new name list anywhere but the TSV; a `strcmp` on a builtin's name in `src/runtime`; a fifth `conv`; a run-time insertion into the static table (aliases and user methods have the rooted hash); a shadow byte or any run-time rebinding of a resolved builtin (the oracles refuse it); a leaf that counts its arguments to decide WHICH builtin it is; renumbering a bid.
