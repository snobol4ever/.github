2. The whole FCC pass (`zls_build:339`) only fires for `IR_ASSIGN` nodes whose target is a **global variable** (`is_global(vn) && !graph_has_local(g, vn)`). `$trail_mark`/`unify` builtin calls are executed for their side effect / boolean result, not assigned into a global — the outer trigger condition doesn't match this call shape at all.

4. Structurally: `fc_vlit_register`/`fc_vwpop_register` write into their own private tables (`fvl[]`/`fvw[]`, `:674`/`:693`), which are **never fed through `zls_field`** — they are a different bookkeeping system than the `zv[]`/scope-slot layout `--dump-zeta` prints.
