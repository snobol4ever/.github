## 1. The law

1. **CHR IS COMPILED, NEVER INTERPRETED.** A CHR program is source: its rules are constructs the parser recognises and the LOWERER places (ARCH-PROLOG-CONSTRAINTS section 3). A library engine that matches heads one way against rule facts and loops partners at run time is a dispatch loop over rule terms -- the runtime interpreter ARCH-ENGINE forbids -- and is refused (the second answer of 2026-10-28).
2. **THE GENERATED PROGRAM IS SWIPL'S DEBUG-OFF TRANSLATION, FIELD FOR FIELD** (the layout answer): the suspension record, the global store lists newest first, the `v(Mask, L1..Lk)` attribute, the occurrence order, the firing order. The printed answers (store order, `find_chr_constraint` order) depend on that layout and on the refined operational semantics' textual firing order, and both are reproduced by construction. The OCCURRENCE code is generated per occurrence from a FIXED TEMPLATE FAMILY (R3); the STORE MECHANICS (attach, detach, run_suspensions, the unify hook's merge, enumerate) are ONE GENERIC SET in SCRIP's `library(chr)` indexed by the constraint's number -- no rule logic in the library, no store mechanics in the generated code beyond the calls, the same output as swipl's specialised copies.
3. **THE STANDARD ORDER OF UNBOUND VARIABLES IS THEIR CREATION ORDER, INDEPENDENT OF PLACEMENT.** swipl and gprolog agree; the planner decides where a cell lives (CEO-1988) and that decision must not change a program's answer, so the order is carried by the variable, not read from its address.

## 2. The rulings

- **R1 THE PASS.** `pl_chr_rewrite(prog)` in `src/lower/lower_prolog_chr.c`, called FIRST in `lower_pl_stage2`'s rewrite chain (before `pl_blockop_rewrite`; lower_prolog.c 5571), the program tree in and out, as `pl_table_rewrite` is shaped. It runs only when a `:- chr_constraint` declaration exists. It consumes `:- chr_constraint c/N, ...` (with argument modes `+ - ?` and types accepted and ignored: no corpus program carries one, and swipl checks types only under an option), `:- chr_option(_, _)` (debug is off and the translator's optimisations are not reproduced, so every option is ignored), `:- chr_type` (recorded, unchecked), and the rule facts `@/2`, `<=>/2`, `==>/2` with `|/2` guards and `\\/2` simpagation heads, `pragma/2` accepted and ignored; the rules are numbered in textual order, the occurrences per constraint in rule order, removed heads before kept heads inside a simpagation rule, as swipl numbers them.
- **R2 THE GENERATED PROGRAM.** Per constraint `c/N` (constraint number i in declaration order, k constraints): the ACTIVATION predicate `c/N`; the OCCURRENCE predicates `c___N__j/(N+1)` for j = 0..J, the last clause `c___N__J(_, S) :- setarg(2, S, active)`; the store cell `'$chr_store_global_list_<M>____c___N'` (M the module), read by `nb_getval` and written by `b_setval` newest first; one `'$chr_constraint'(c/N, i, StoreKey)` fact per constraint (declaration order) from which the generic support enumerates; `'$chr_initialization'/0` setting every store cell to `[]` and `:- initialization('$chr_initialization')` placed BEFORE the program's own initialization goals; `chr:'$chr_module'(M)`. The suspension record is `suspension(Id, State, History, Generation, Continuation, Name, A1..AN)` (arity 6+N; State one of active, inactive, triggered, removed; Generation 0 at creation; Continuation `M:c___N__0(A1..AN, Self)`), the attribute `v(Mask, L1..Lk)` with bit 2^(i-1) and list i for constraint i, exactly as swipl's translation writes them (ps3_hand2.pl is the reference text).
- **R3 THE TEMPLATE FAMILY.** Every generated clause is one of these shapes with its holes filled (the constraint name and arity, the module, the occurrence index, the argument positions, the partner list, the rule's id tuple): (a) ACTIVATION -- `c(A1..AN) :- S = suspension(Id, active, _, 0, M:c___N__0(A1..AN, S), c, A1..AN), term_variables(args, Vs), 'chr none_locked'(Vs), 'chr gen_id'(Id), <push S on the store cell>, '$chr_attach'(i, k, Vs, S), setarg(2, S, inactive), c___N__0(A1..AN, S).`; (b) SELF-REMOVED, NO PARTNERS (a single-head `<=>`) -- `c___N__j(Args, S) :- <head match>, <guard>, !, <remove S>, <body>.` where the HEAD MATCH is compiled from the head's pattern (a variable matches; a nonvar pattern `nonvar(A), A = pat`; an atomic `A == atom`; a repeated head variable `==`), the GUARD is inlined as a Prolog goal after the match (swipl's default: no `\\+ \\+`, no binding check; a CHR constraint posted inside a guard runs as the oracle runs it), the cut follows the guard, REMOVE is `setarg(2, S, removed), term_variables(args, Vs), <delete S from the store cell by 'chr sbag_del_element'>, '$chr_detach'(i, k, Vs, S)`; (c) WITH PARTNERS -- one LOOP predicate per (occurrence, partner position) `c___N__j__p__q(PartnerList, Args, S)` iterating the partner's store, read through `'chr newvia_1'(SharedVar, V), get_attr(V, M, v(..))`'s list when the two heads share a variable, else the global cell; each candidate `P = suspension(_, active, _, _, _, _, PArgs)` then the partner's head match, the guard, the removals (every removed head), the body; CONTINUATION by role: a KEPT self is re-activated (`setarg(2, S, active)`) and, if still active, set inactive and the loop continued on the rest of the list; a REMOVED self stops after the first firing; a kept partner stays, a removed partner is deleted and the loop continues; (d) PROPAGATION -- shape (c) with no removals and the history: `'chr novel_production'(S, Tuple)` before the body and `'chr extend_history'(S, Tuple)` after, the tuple the rule number with the partners' ids; a single-head `==>` fires once per constraint by the same history; (e) THE GENERIC SUPPORT in `library(chr)` (one set, not per program): `'$chr_attach'(I, K, Vars, S)` and `'$chr_detach'(I, K, Vars, S)` over `v(Mask, L1..LK)` by index (the mask bit, the list, `del_attr` when the mask reaches 0), `'$chr_attach_increment'`, `'$chr_run_suspensions'(L)` (the triggered/active protocol), `attr_unify_hook(v(..), Other)` for the module (the sorted merge of every list, then run_suspensions per constraint in declaration order -- the order swipl's specialised hook runs them), `'$enumerate_constraints'/1,2` reading the `'$chr_constraint'/3` facts in declaration order and each store newest first, `attribute_goals/3`. The holes are filled by one walk at lowering; the templates live once, as Prolog clause text in a `.inc` beside the pass or as tree constructors in C -- the builder's choice, the output identical.
- **R4 WAKE-UP.** A constraint on an unbound variable is attached to that variable's attribute (module M); binding it, or unifying it with another attributed variable, runs `attr_unify_hook` (ARCH-PROLOG-CLPFD section 3's road, no second mechanism), which merges the attributes and re-runs the suspensions of every list in declaration order; a re-run constraint re-enters its first occurrence with its Generation incremented. - **R5 THE STORE CELLS.** Each global store list is one registry root cell named as swipl names it, created by `'$chr_initialization'` and trailed through `b_setval` (CEO-1542's single current-X cell: a list on the heap rooted there; no global of SCRIP's own holds a store).
- **R6 MODULES.** Inside `:- module(M, ...)` the pass keeps the generated clauses in the module section; the continuation goal is `M:c___N__0(...)`, the attribute module is M, the store keys carry M; a plain file is module `user`.
- **R7 INSPECTION.** `find_chr_constraint/1`, `current_chr_constraint/1` and `chr_show_store/1` are the vendored runtime's, over the generic `'$enumerate_constraints'/2`: constraints in DECLARATION order, each store NEWEST FIRST (measured: `[c(2),c(1),d(b,y),d(a,x)]`; chr_show_store one constraint per line in the same order).
- **R8 THE ORDER OF FRESH VARIABLES.** THE LAW: two unbound variables compare by CREATION order; a clause's fresh variables are created at their FIRST TEXTUAL OCCURRENCE, left to right (the head, then each body goal in order, each term in reading order), never inner-first by the term builder. An address is REFUSED as the order (the collector relocates cells; the planner places them). The term builder's change is in `lower_prolog.c`: the fresh variables of a goal's terms are created in textual order before the structure that references them. ## 6. R8 settled: the serial's home, its shape and who builds it (the cto, 2026-10-28 18:2x CDT; CEO-2006, Lon's grant; hq_prolog's baton QA Q-A/Q-B/Q-C on row prolog-clpr-chr-step-8-fresh-variables-in-creation-order-ceo-2005; SCRIP e28823366)

Measured by hq_prolog (nothing changed on disk): `compare/3` of two unbound variables is the cell ADDRESS (unification.c 2234), and the address order is the PLACEMENT's, not the creation's: frame-slot variables descend with creation, heap cells inside a built compound ascend (swipl o1 `<` o2 `>` o3 `<` o4 `<`; SCRIP o1 `>` o2 `<` o3 `<` o4 `>`); the term builder already chains a compound's kids left to right (`mkc_node`), so the lowerer's half is a proof, not a reordering. The three rulings:

- **Q-A THE HOME: A STANDING CELL OF THE ROOT RECORD, NOT A C GLOBAL.** The counter is standing cell `PL_SERIAL_CELL = PL_DB_FRAME_CELLS - 1` (255) of the Prolog root frame: the word at `[r14 - 24 - 8 * 255]` from any Prolog box (xa_flat.cpp: the standing cells are "reached from any depth as [r14 - 24 - 8k]") and `(char *) cx->r14 - 24 - 8 * 255` from a C leaf (`pl_tr_ctx_t` carries r14; a creation site with no context in hand takes it from its caller as `plc_copy_cx` does, and a site with no road to r14 is a design question back to this page, never a global). It is never handed out: `pl_dyn_index` stops at the 64 compile-time cells and `rt_pl_db_cell_for`'s `next_cell` stops at `PL_DB_FRAME_CELLS - 1` before the overflow vector. ITS WORD IS RAW IN THE ROOT FRAME'S MAP: emit.cpp ~2933 lays the standing region as one `GC_LAY_PTR_GC` of `8 * nc`; it becomes the RAW word at `clo` (the lowest address, cell 255) plus `GC_LAY_PTR_GC` of `8 * (nc - 1)` from `clo + 8`, so the collector never reads a serial as a pointer (gc_frame_map.h's note names the cell). It is SEEDED at the root's entry (the successor of `pl_standing_cells_zero`, which zeroes the others) with the word `DT_PLVAR | 512` (serial 1; serial 0 means "no serial", below). Lon's grant (CEO-2006) is NOT spent: no `g_` field, no static. Each root frame owns one, so a Prolog thread (ARCH-PROLOG-THREADS, CEO-1764) draws without atomics and a term crossing threads is copied and draws fresh serials.
- **Q-B THE SHAPE: THE SERIAL LIVES IN THE TAG WORD; THE SELF-POINTER STAYS.** Neither (i) nor (ii) of R8: word 0 of an unbound cell is `(serial << 9) | (attv << 8) | DT_PLVAR` and word 1 is the self-pointer as today. The counter word holds exactly the next cell's word 0 (the serial pre-shifted, the low byte the tag) and advances by 512, so an emitted creation is `mov rax, [r14 - 2064]; add qword [r14 - 2064], 512; mov [cell], rax; lea rcx, [cell]; mov [cell + 8], rcx` (one instruction more than today's immediate store); 55 bits of serial never wrap (3.6e16 creations). WHY THIS SHAPE: every unbound test in C (the 13 self-pointer sites of pl_cell.h, unification.c and by_name_dispatch.c) and in the templates (PL_DEREF and PL_UNBOUND compare `al`; bb_unify_value.cpp masks `eax`/`ecx` with 255 before its compares) reads the TAG BYTE and the SELF-POINTER only, so nothing that tests, derefs, binds (`*to = r` overwrites both words), trails (an entry saves the whole 16-byte old cell and restores it whole) or collects (the DT_PLVAR arm of gc_heap.c marks and relocates the self-pointer as today; word 0 is never a pointer) changes; a PLVAR is never stamped (`descr_set_src_node` is the error voice's, for values), so the 24 src_node bits and the 32 slen bits are free. THE ATTRIBUTED MARK moves from `slen == PL_ATTV_SLEN` to bit 8 of word 0: `pl_attv_is` reads it; the writers (unification.c 3048 and 3132, by_name_dispatch.c 7995 and 8069) set it; the trail-restore test at 8021 and the template PL_TRAIL's `cmp edx, PL_ATTV_SLEN` read bit 8; `PL_ATTV_SLEN` goes. `pl_init_var(c, slot)` loses its dead `slot` argument (only the two test files pass one) and draws the serial. THE COMPARE: class 0 of `rt_pl_cell_compare_leaf` compares `word0 >> 9` as unsigned (read the 64-bit word, not `slen`); equal serials are the same cell (`a == b`, 0). A cell with serial 0 (DT_SNUL, DT_FAIL, a DT_N self name, a cell no creation site minted) sorts below every serialled cell, by address among themselves: transitional, never reached once the lowerer creates every first occurrence, and a witness that reaches it names a missing creation site.
- **THE CREATION SITES, EVERY ONE DRAWS:** templates bb_unify_first.cpp 37, bb_unify_struct.cpp 24 and 30, bb_call_pl_leaf.cpp 343, 347, 350, bb_call_proc_staged.cpp 731 and 733; rtx_plunify.s 234 and 238; in C `pl_init_var` (pl_cell.h 22, the one body) and the ad-hoc stores by_name_dispatch.c 408 (DT_SNUL or DT_FAIL to PLVAR is a creation), 7979 (the fresh `j`), 7995 (`blk[0]`, attributed), unification.c 3048 and 3132 (attributed fresh). ## 7. Rulings on hq_runtime's CHR step-1 landing (the cto, 2026-10-28 18:3x CDT; SCRIP aa807f09f, harness cd992e6; cc01 equals swipl in both modes)

- **ATTACH AND DETACH TAKE THE MODULE FIRST, ARITY 5: ACCEPTED.** The generic set in library chr cannot read the attribute module from anywhere but its caller, and R6 needs exactly that hook (the attribute module is M inside `:- module(M, ...)`, `user` in a plain file); R3's "4" is amended to 5 (module, variable, constraint index, suspension, mask).
- **THE ACTIVATION PASSES EVERY ARGUMENT TO term_variables: ACCEPTED FOR STEPS 1-4, STEP 5's LOWERING PASS NARROWS IT.** swipl's translation attaches the suspension only to the variables of the arguments some rule matches; waking on a variable no rule mentions changes no answer (the suspension re-runs its occurrences and finds no partner) and only adds re-activations, which an instruction count would see and no witness does. The matched-argument analysis is step 5's (the propagation history and the occurrence order are where the set of matched positions is first needed), not earlier.
- **STEP 2 IS MODULE-AWARE FROM THE START**: ethiopian-multiplication-4 is a module program (`:- module(ethiopia, [test/0, mul/3])`, mul/3 itself a constraint), so step 2 meets `ethiopia:<=>/2` keys at once; hq_runtime builds the pass module-aware and step 7 then proves only that the continuation goal and the attribute module carry the name. The splice lesson stands as a page fact: a library call that only generated code makes is invisible to the parser stage, so its support keys are seeded in `prolog_inject_prelude` in BOTH sets (name and arity, which selects the library; the names, which the keep pass reads and which alone keeps a dollar-named clause).
