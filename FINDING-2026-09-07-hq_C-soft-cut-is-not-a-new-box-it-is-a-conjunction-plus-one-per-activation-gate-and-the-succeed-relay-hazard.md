## THE DESIGN RULING HELD, WITH ONE CORRECTION TO ITS OWN CORRECTION
The baton's ## NEXT already ruled "not a new box — build it from `IR_MOVE_LABEL` + `IR_INDIRECT_GOTO`". That held. What the build made precise: **when C has a solution, `( C *-> T ; E )` IS `C, T`** — T's ω resumes C's redo exactly as a later conjunct's ω does (`pl_lower_conj`'s `redo_out`, flipped to β with `pl_mark_into`), and the ONLY machinery `->` has that soft cut needs is the E arm, which must run when and only when C never succeeded. That is per-activation state, so it is a frame slot: a second `IR_INDIRECT_GOTO` (`eg`) whose slot is banked with E's entry on the way in and re-banked with `eg`'s own concede at C's every success (idempotent, so re-entry needs no guard); C's exhaustion dispatches through it at `eg`'s β. Two gates, two slots (`zeta_storage.c` grants one region per `IR_INDIRECT_GOTO`, "harmless with ONE such box live and a core dump with two" was the rung-5 bug, already cured). Cut inside C stays local by the same `cutω`/`mark` pair `->` uses. No new template, no new IR kind, no global.

**One emitter edit, gated so it cannot move an existing program:** `emit.cpp`'s IR_MOVE_LABEL block forced every banker's γ to the gate's γ (right for `->`'s arm banker, whose γ IS the construct's success). Soft cut banks twice on the way IN and must land on C's entry and on T's entry. The override now applies only to a banker with **no γ of its own**; `IR_MOVE_LABEL` is built nowhere but `lower_prolog.c` (`grep -rn IR_MOVE_LABEL src/lower src/optimizer` → two builders, both Prolog), and `pl_lower_ite` never sets one, so the `->` emission is unchanged by construction. SNOBOL4 and Icon control arms below say the same by measurement.

## HAZARD 1 — A RELAY OP THAT TWO CONSUMERS SHORT-CIRCUIT TO THE GRAPH'S LABEL
First build: `( false *-> true ; true )` printed **nothing** — not `b`, not a failure, nothing. `true` lowers to a bare `IR_SUCCEED` relay, and BOTH consumers of an entry node short-circuit that op to the **graph's** success label: the γ resolver (`gtgt->op == IR_SUCCEED → node_γ = &lbl_γ`) and the banker beside it. Banking E's entry banked the clause's own success, and the clause returned from the middle of the construct. `pl_disj_entry` already walks relays off for a disjunct; `pl_sc_entry` does the same for the three soft-cut entries. ⭐ The general form: an op that means "continue" is legal as an ENTRY, and a resolver that treats it as "the graph succeeded" is right for a tail and silently wrong for a head. The optimizer's `branch_chain` hides this on control edges (t1 was green with C = `true`); it cannot hide it on an operand, which is why only the banked E showed it.

## HAZARD 2 — THE META-CALL PATH IS A SECOND LOWERING, AND IT EXPOSED A PRE-EXISTING `->` DEFECT
`call(( true *-> write(a) ; write(b) ))` was green; `G = ( true *-> write(c) ; write(d) ), call(G)` printed **d**. A goal reached through a VARIABLE is not lowered — it dispatches to synthetic predicates (`';'(A,B) :- A = (C -> T), !, ( call(C) -> call(T) ; call(B) )` and friends, `lower_prolog.c` `pl_meta_ctrl`), and there was no `*->/2` and no `*->` clause of `;/2`. Both added (the bare `'*->'(A,B) :- call(A), call(B)` is a conjunction, which is the same statement as the design ruling above). plunit runs every test body this way, so this half is the one that actually unblocked `snip`. Then the control arm: `i1(T) :- ( true -> call(T) ).` with `i1(d(X))` over three facts prints **a(1)** where swipl prints a(1) a(2) a(3) — **pre-existing in `->`**, nothing to do with soft cut: a `CALL_VALUE` β banked into the gate's slot and reached by `jmp [slot]` does not resume, while the same β reached by a static jump from a later conjunct's ω does (`call(C), call(T)` enumerates). Every ite reached through `call/1` therefore yields at most one solution. Minted as `prolog-ite-gate-cannot-resume-a-meta-called-arm-so-call-slash-1-inside-arrow-and-softcut-yields-one-solution` (rank 1, DONE-WHEN proven red both modes as written). Not widened into this row: one bug per row, and it is a different bug.

## WHAT TO CARRY
1. **Before writing a lowering, ask what the construct IS when its state is known.** Soft cut with a solution is a conjunction; the whole design collapsed to "wire it as `C, T` and add one gate" once that was said out loud. The baton's earlier "NEW BOX SHAPE" line and my own first sketch (a flag, a dispatcher, an unmark) were both bigger than the thing.
2. **An entry can be a relay; a resolver that short-circuits the relay's op is wrong for entries.** Walk relays off before banking or wiring an entry (`pl_disj_entry`, now `pl_sc_entry`).
3. **A construct has two lowerings here — static and meta-called — and a green on one says nothing about the other.** Grade `call(G)` with G bound at run time, not only `call((literal))`, which `pl_meta_goal` expands statically.
4. **A control arm that reds the OLD construct is a finding, not a scope change.** Mint it, prove its DONE-WHEN red as written, and finish the row in hand.
