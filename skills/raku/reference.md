## 7. Rulings a Raku landing must not break (receipts in GOAL-RAKU-100.md and GOAL-CEO.md)

- **Every Raku value is ONE DESCR** (§ 1.1): the tag names the setting's class; a lexical's slot holds its value (THE LIFETIME RULE); `:=` between lexicals of one scope is a compile-time alias; a run-time binding and an itemized element hold a REF to a heap Scalar dereferenced by a tag test in the box, never in C; a native is a planner cell kind, unboxed on the spine.
- **Raku is a Seq language: one four-port pull protocol**, identical to Icon's generator pump (yield-one-at-β); no new iterator machinery, no second protocol.
- **The setting is Raku** (§ 1.2 (c)): a core method is written in Raku and the C body it replaces is deleted in the same landing; the primitives are the closed vocabulary of kernel boxes and asm leaves; no C core method the setting can write, no leaf in C that ASM can carry, no leaf that calls a box or loops over user code (CEO-1576).
- **Never** lower a construct to a C function by name, add an `IR_CALL <name>` to `lower_raku.c`, a `strcmp` chain or a by-name table on a Raku path, or a desugar to `rk_tree.c` or `rk_syntax.c` (§ 10). A name set Rakudo's own grammar decides at parse (the seven meta-methods `WHAT HOW WHO WHERE VAR REPR DEFINITE` of `Actions.nqp` `methodop`, which rakudo never curries) is the recognizer's translation of that grammar, not a by-name table (CTO-494).
- **The parser reaches 100% before lower and runtime** (Lon 2026-09-16); the recognizer is translated from Rakudo's grammar, never a second grammar.
- **A kernel box is born with its family's first rung, never ahead of one**; a rung lands with its forms' refs cut from rakudo 2026.05 and proven red against a corrupted ref; a Roast file is cured by its rung, never by its name; a feature is tested on top of green ones only (Lon 2026-10-29).
- **RakRungs and RakBench never fall below 100 at a landing**; a Raku number is published from `results.tsv` and the LEAF_SHARE line only, never a wall clock.
- **S17 (concurrency) stays closed until Lon opens it**; a program is placed on the map by the generator and the instrument, never by hand.
- The absolute rules stand under Raku: no global, no side table, no frame marker, no second stack, no stack held by the runtime, no fixed limit a program can reach; the Raku smoke runs before every push, all eight for shared code.

## 8. DESIGN: Raku to 100, re-designed from the Byrd-box machine up (CEO-2044/2045/2046, the cto 2026-10-30; Lon: Raku climbs the rung ladder, CEO-1931/2070)

- **The value model**: every Raku value is ONE DESCR; the tag names the setting's class (a type id the lowerer assigns per class at load); Int (small), Num, Bool, Nil and the type objects are immediate; everything else is a heap block of a typed collector class.
- **The five layers**: (a) the parser stays the pruned parse tree (`rk_syntax.c`, `rk_tree.c`, `rk_regex.c`; `parser_raku.sc` tree for tree against it) and loses every desugar; (b) the lowerer places every construct as boxes; (c) the setting is Raku (embedded `raku_setting.inc` from `setting/`, `util_gen_raku_setting.py`), and until typed multi dispatch lands the program's own names win and a lib-path export does not beat the setting (the named interim); (d) the primitives are asm leaves (`rtx_rk_str_*`, `rtx_rk_bigint_*`, `rtx_rk_rat_*`, `rtx_rk_io_*`); (e) the planner places the cells.
- **The kernel boxes** (designed, none built on 2026-11-01): `bb_rk_coerce`, `bb_rk_scalar`, `bb_rk_aggr`, `bb_rk_iter` (THE ONE ITERATOR: pull-one over List, Range, Seq, gather, a lazy source), `bb_rk_block`, `bb_rk_sig`, `bb_rk_dispatch` (per-type tables built at load, C3 MRO, never a `strcmp` chain), `bb_rk_type`, `bb_rk_control` (next, last, redo, return, take, die, fail as the one protocol's balls), `bb_rk_smartmatch`, `bb_rk_junction`, `bb_rk_hyper`, `bb_rk_num`, `bb_rk_sets`, `bb_rk_phaser`, and native cells as typed cell forms. Each is born small with its family's first rung, never landed whole ahead of a rung that proves it, and the C road a rung replaces is deleted in the same landing (CEO-2045).
- **The ladder**: families F01 to F20 in dependency order (literals and values; variables, containers and declarators; operators; control flow; subs, signatures and dispatch; blocks and topics; lists, arrays, hashes and sequences; strings; numerics; classes, roles and the MOP; exceptions; ...), each rung one construct of at most 20 lines with its ref cut from rakudo 2026.05. No work aimed at Roast or RakDemo programs until half the ladder reads green (CEO-2070).
- **The rows**: `raku-ladder-f01-f02-...` ASSIGNED to hq_raku; every later family BLOCKED in dependency order behind it.
