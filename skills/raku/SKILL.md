# SCRIP Raku

The record is GOAL-RAKU-100.md (LIVE CURSOR on top); the design is `reference.md` § 8. Raku builds at rank 9 (CEO-1931) and climbs the cto's rung ladder, not the suites, until half the rungs are green (CEO-2070). Suite tables, file maps and receipts in full are in `reference.md` beside this file.

## 1. The oracle

- **rakudo 2026.05; the spec is the roast** (`/home/resources/roast-master`). The binary through `rakudo_bin()` in `harness/scripts/lib_oracle_flags.sh`; the `raku` on PATH (2022.12) is never the oracle. One dialect, no switch.
- A ref is cut from rakudo; a ref cut from our output is a SELF-PIN, not an oracle; no XFAIL. Refusal, crash or hang (`timeout -k 5`) is `NO_ORACLE_ANSWER` (CEO-1696); an implementation accident is no answer (CEO-1934). Gotchas: `OUTER` is a pseudo-package, a mid-line `}` needs `;`, EVAL of a string needs `MONKEY-SEE-NO-EVAL`.
- Interim (the re-design's layer (c), `reference.md` § 8): the program's own names win; a lib-path export does not beat the setting until F05's typed multi dispatch lands.
- Test is Rakudo's `src/parsers/raku/setting/Test.rakumod`, vendored as the setting's first file.

## 6. Debugging a red

1. `bash ../harness/scripts/monitor_run.sh prog.raku --oracle` (the rakudo-mon fork); never a Raku-private monitor.
2. Asm-diff the smallest repro beside a passing sibling within one mode.
3. Parse questions: `util_raku_syntax_agreement.py` (scrip `--syntax` against `raku -c`); roast reds ranked by `util_raku_roast_ablation_ranker.sh`.
4. gdb last, with a breakpoint and a hit count.

## 7. Rulings a landing must not break

- Every Raku value is ONE DESCR; a lexical's slot holds its value; `:=` in one scope is a compile-time alias; a run-time binding holds a REF to a heap Scalar, dereferenced in the box, never in C.
- One four-port pull protocol, Icon's generator pump; no second iterator machinery.
- The setting is Raku: a core method is written in Raku and its C body deleted in the same landing; no leaf that calls a box or loops over user code (CEO-1576).
- Never lower a construct to a C function by name, add an `IR_CALL <name>`, a `strcmp` chain or by-name table, or a desugar in `rk_tree.c`/`rk_syntax.c` (§ 10).
- The parser reaches 100% first; the recognizer is translated from Rakudo's grammar.
- A kernel box is born with its family's first rung; a Roast file is cured by its rung, never by its name; RakRungs and RakBench never fall below 100 at a landing.
- S17 (concurrency) stays closed until Lon opens it. No global, side table, frame marker, second stack or fixed limit; the Raku smoke before every push (all eight for shared code).

- **D-STATE, a `state` variable belongs to the closure clone that declares it** (the cto 2026-11-05, hq_raku's ask on raku-a-state-variable-in-a-block-nested-in-a-routine-restarts-on-each-entry-of-the-routine). MEASURED by hq_raku on rakudo 2026.05: a `state` variable or `$++` inside a for, bare, closure, if, given, repeat or while body restarts on each CALL of the enclosing routine (012/012), and inside a block nested in a loop body it restarts on each EVALUATION of the statement that owns the literal (`sub f5 { for 1..2 { for 1..2 { print $++ } } }` prints 0101 0101); SCRIP continues across calls (012/345) because every state site is a program-wide global (lower_raku.c rk_register_state_globals, rk_state_desugar). THE RULE (Raku's own, S04): a block literal is instanced (cloned) each time the statement containing it is evaluated; `state` variables are initialised ONCE PER CLONE, on the clone's first execution of the declaration; a routine's body is cloned when its declaration is evaluated (once for a unit-level sub, so its state persists across calls); the per-evaluation rule subsumes the per-call rule, and the row's GOAL is read as the per-evaluation rule. THE DESIGN: (1) the fact reaches the lowerer as a PARSE FACT, not a desugar: the recognizer (rk_syntax.c, where Grammar.nqp's `pblock`/`block` is recognised, the state names at line 2955) marks the body node of every block literal and routine body as a block (a kind or a flag word on the TT_SEQ_EXPR/TT_RETURN node, `v.ival = RK_BLOCK_LITERAL`); section 10 forbids rewriting the tree in rk_tree.c/rk_syntax.c, a marker that records what the grammar matched is not a rewrite. (2) In lower_raku.c a state variable is a FIELD OF THE CLOSURE ENVIRONMENT of the block that declares it, exactly as a captured outer lexical is (rk_cap_block / __blk_close build the closure record when the literal is evaluated): the record gains one slot per state name, created UNSET at instancing; the declaration lowers to `if env.state_k is UNSET then env.state_k := init` (the initialiser runs once per clone); `$++`'s hidden name is a state name of the innermost block literal (rk_tree.c line 1787 mints the name; the lowering places it). (3) A named routine's clone is the closure record created when its declaration is evaluated, held by the declaring scope's frame (a unit-level sub: the program's main frame cell), never a C global; rk_register_state_globals and rk_state_desugar are DELETED in the landing, not wrapped (no program-wide state globals remain). Witnesses: hq_raku's shapes.raku and locals.raku plus f5 as a rung (`util_add_ladder_witness.py --lang raku`, ref from rakudo); RakRungs stays 100 at the landing.
