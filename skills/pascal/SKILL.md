# SCRIP Pascal

The record is GOAL-PASCAL-100.md (LIVE FRONT on top); a page beats this skill. Pascal's front-end design is hq_pascal's (CEO-1933); the cto reviews shared nodes. Suite tables, file maps and receipts in full are in `reference.md` beside this file.

## 1. The oracle and the dialect

- **fpc 3.2.2 in the program's own mode** through `fpc_bin()` in `harness/scripts/lib_oracle_flags.sh`: ISO 7185 under `fpc -Miso`, FPC/Turbo plain, `-Mobjfpc`, `-Mdelphi`. ISO 7185 wins where `-Miso` is lax (CEO-1225).
- **The program's dialect decides its oracle**, one switch per program: a `{$mode X}` directive, else ISO until the first construct `-Miso` refuses (`string` in a type position, `otherwise`, `string[n]`, `uses`, `unit`, `class`, `object`, `try`, and a `write` or `writeln` of an enumeration value: `-Miso` refuses it and `-Mobjfpc` prints the identifier, so it selects objfpc like the others, CTO-524 on worker_17's measurement) (CEO-1624). Never guessed from a filename; no `--compat`. **Exclusion classes a Pascal program may carry** (CTO-525): `NO_ORACLE_ANSWER` (fpc refuses, crashes, hangs or answers differently twice), `FAKEABLE_NO_OBSERVABLE`, `NEEDS_NETWORK` (sockets, unix, fphttpclient), `NEEDS_TERMINAL` (an answer that is a function of the oracle's TERM, the ncurses binding included), `NEEDS_C_LIBRARY` (a C library SCRIP has no Pascal-source stand-in for: libgmp's mpf family; the mpz family is `prelude/gmp.pas`, SCRIP's own, and is NOT excluded). Each row names the routine or unit that forces it.
- ISO Pascal is CASE-INSENSITIVE. `string` is `ShortString(255)` without `{$H+}`, `AnsiString` with it and in delphi mode.
- A ref is cut from the oracle; no XFAIL; what fpc refuses, crashes on or hangs is `NO_ORACLE_ANSWER` (CEO-1696). A unit's `finalization` output never appears (fpc closed the files first, CEO-1617).
- **reset of an unterminated textfile appends one end-of-line** (ISO 7185 6.6.5.2 reset: f.R = f0.L ~ f0.R ~ X, X = S(end-of-line) when the textfile is non-empty and its last component is not an end-of-line; 6.4.3.5 rule a: a textfile under inspection is a line-sequence). It holds for every textfile, a program parameter or a named file alike, so after the last character `eoln` is true and `eof` false for one more read. `fpc -Miso` does not append (`eof` true at the last character), which is `-Miso`'s laxity, never adopted (CEO-1225). SCRIP does it in `pas_reset_closed_copy` (`src/runtime/by_name_dispatch.c`, commit 035a60347). A program whose answer turns on the difference is cured in its INPUT, not in the runtime: the fixture gets its last line terminated and the ref is re-cut from `fpc -Miso` (officer_03 2026-11-12, on junior_04's pcom measurement: with `demos/pascal/p5/pcom/prd` terminated, `fpc -Miso` and SCRIP mode 3 both read `Errors in program: 0`, byte-equal; the old ref's errors 6 and 21 at `end.` were fpc's missing end-of-line).

## 7. Rulings a landing must not break

- One type model, built by lower, keyed by symbol, never by name; no second model beside the typer.
- DESCR cells, ARBLK arrays, records as slot arrays; a pointer is (base cell, element index), never an interior pointer (R5); `extended` is an INLINE DESCR kind `DT_XR` (R6 as amended, CTO-486 on hq_pascal's reading of descr.h: the 64-bit mantissa in the value word, sign and exponent in slen's low 16 bits, nothing allocated, no visitor, the cfo reviews the tag), no x87 in the emitter.
- ShortString(N): a store truncates to N, `sizeof` is N+1, `s[0]` is the length byte (R4).
- A char array is its declared width, NULs included, in an fpc-dialect program (senior_03 2026-11-12, stanford-pascal `testpgm/testset3`, probed against `fpc -Mfpc`): a short literal assigned to or passed by value to `array [1..n] of char` leaves components past its length at zero, and `write` of the array emits all n bytes. `pas_alpha_wrap` hands `__pas_alpha_str` a third argument in that dialect and the runtime takes `pas_chars_full` (every component, the length carried); the call site encodes a literal actual to the formal type's declared high (`pas_arrtype_high`). ISO programs keep `pas_chars_of`, which ends the text at the first zero component, and every other caller of it is unchanged.
- The entry graph is `main`; a user routine named `main` is renamed by the duplicate-name pass.
- Features land in rungs of at most 20 lines, one construct, ref cut from fpc, red once (CEO-1680); rung N+1 opens when N is green in both modes.
- The PAT rejection tests are the ISO strictness: never adopt `-Miso`'s laxity.
- Regenerate the grammar, prelude list and builtin table before building; a cure that trades programs never lands (CEO-589); a prelude or runtime change runs all eight smokes.
- Declared sizes are a hard cap (CEO-1353/1354).

## 8. DESIGN: pascal-packed-arrays (R-2119, the cto 2026-11-04, on the cfo's PasRosetta reds fusc-sequence, strong-and-weak-primes, unprimeable-numbers-2; amended CTO-490 the same day on the measurement of the element roads)

A Pascal array, bounded or dynamic, one- or multi-dimensional, a variable, a field or an element, whose element type is a flat ordinal of width 1, 2, 4 or 8 bytes (byte, shortint, char, boolean, word, smallint, longword, longint, int64, qword, an enumeration, a subrange of any of them) is stored as ONE raw block: the ARBLK header (lo, hi, ndim, lo2, hi2, and new: `ewidth`, 0 for DESCR elements, and `esigned`) and one data block of a new heap kind `HB_RVEC`, the element bytes contiguous, no DESCR per element. The collector never scans inside an HB_RVEC (as HB_WSB: it guesses nothing because the kind says raw) and moves it as it moves HB_DVEC, re-pointing the owning ARBLK's data pointer. The choice is made ONCE in `lower_pascal` from the declared element type ALONE and rides as an IR fact the planner, the emitter and `--dump-ir` read: the array is made by the builtin call `arr_make_raw(lo, hi, width, signed)` in place of `arr_make`. MEASURED (the cto, 2026-11-04, `--dump-ir` and `by_name_dispatch.c`): every road over an element already passes through one cell, so no component use disqualifies a raw block: a var actual `a[i]` is `__pas_elem_ref` (a DT_PCELL) read by `__pas_ref_val` and copied back by `arr_set_pure`; `@a[i]`, `inc(p)` and `p^` are `__pas_addr`, `__pas_deref` and `__pas_deref_set` over the DT_PCELL view road, which already carries a width and a signedness (`pas_view_load`, `pas_view_store`); so the roads read the header's `ewidth` and `esigned` (a `movzx`/`movsx` load into an integer DESCR, a truncating store, no range check, as fpc without `-Cr`), and a pointer into a raw block is the existing view cell with a raw flag (byte offset, width, signedness); the value copy of an array (an assignment, a value actual), setlength, high, low, length and sizeof read the same header. The element roads stay the builtin calls `arr_get` and `arr_set_pure` reading the width in the runtime: no new IR kind and no template, because speed is not opened for Pascal (R-2035) and the builtin table is the one builtin road. Every other element type (real, string, record, set, pointer, array, file) stays `arr_make` and DESCR elements; a pointer stays (base cell, element index) (R5). MEASURED (the cfo, 2026-11-04): the three programs ask for one kind-214 block of 20, 8 and 16 GB before any collection (0.5 to 1.25 billion elements at 16 bytes where fpc holds 1 to 4), over the grader's 8 GB cap, so no declaration serves them; (the cto, 2026-11-04) the rung `pa01_bytes` (100,000,000 bytes at a declared 262,144 KB) asks for one 1,600,000,000-byte kind-214 block at 0 collections, error 204, in both modes. THE PLAN: `harness/designs/packed_arrays/STEPS.tsv` and `harness/scripts/test_design_pascal_packed_arrays_steps.sh` (`--list`, `--step N`; the witnesses are the entries `packed_arrays__<name>` of the pascal master, CIO-56; tokens `heap=`, `stress=1`, `sym=`, `kind=`, `irgrep=`, `irzero=`, `entries=`): step 1 the witnesses and the table (the cto, green 2026-11-04: six regression witnesses green in both modes and under stress); step 2 the HB_RVEC kind and `rt_ws_alloc_raw` in the collector (hq_collector); step 3 the lowerer's decision, `arr_make_raw` and every pas_* road reading the width, the rung green at 256 MB (hq_pascal); step 4 the three programs green in both modes at a declared heap under 8 GB (ALL.csv's heap_kb raised to fpc's own element size plus the rest: fusc-sequence 1,253,000,000 longwords = 5,012 MB, strong-and-weak-primes 551,000,000 bytes = 526 MB, unprimeable-numbers-2 about 1,000,000,000 booleans = 954 MB, re-measured by the executor) and the test request (hq_pascal); step 5 the block header's size counted in 16-byte granules so a block over 4 GiB (fusc-sequence's 5,012 MB) is possible at all (hq_collector, CTO-492; the design text in the gc-collector skill's DESIGN section; step 4 depends on 3 and 5). A red found while cutting the witnesses and left to its own row: `setlength(keep[i], 2000)` on an element of a static array of dynamic arrays, then `keep[i][j] := v`, ends with `ISO 7185 6.5.3.2: an index value is not assignment-compatible` in both modes (fpc runs it).

## 9. DESIGN: management operators (CTO-632, the cto 2026-11-11, on officer_04's tb0707 measurement)

FPC's `class operator Initialize/Finalize/Copy/AddRef(...)` of an advanced record are procedure-shaped (TT_PROCEDURE, sval operator). The class pass (`lower_pascal_class.c`) alone decides a record is managed (declares one of the four, or a field is a managed record; a specialized generic included, since the generics prepass runs first) and writes every hook as an ordinary call in the pruned tree: one init walk (fields in order, then the own Initialize) and one finalize walk (own Finalize, then fields reversed) per managed type; the walk passes fields by reference and never loads them (tb0707's `Initialize(T(nil^))`). A block's managed variables are initialized at entry and finalized at every exit but halt, both in declaration order (CTO-633, fpc's m4); the program's globals get no finalize walk (CEO-1617). An assignment from an lvalue calls Copy; a function result is written into its destination, never initialized by the callee, with no Copy and no finalize of the old value (CTO-633, fpc's m6); a result used as an actual is a caller temporary in its var part, initialized at the caller's entry and finalized at its exit before the declared locals; a value actual is copied then AddRef'd; a const/constref/var actual is not copied. The class pass folds `IsManagedType` for a managed record. No IR kind, no runtime leaf. Rungs R1 to R6 (grammar and a global; nested walk and the intrinsic; tb0707; locals; Copy and IsManagedType, tw36738; the move, temporaries and AddRef, tw40392); arrays of managed records and exception unwinding are cut when a program needs them.

## 10. DESIGN: untyped formals and the pointer pun (the cto 2026-11-11, on officer_05's TMemoryStream reading)

An untyped formal (`const b`, `var b`, `out b` with no type) receives the pointer value `@actual` would be: the R5 view of the actual's flat ordinal storage with its own width and kind. Inside the callee, `b` has three uses only: `@b`, a typecast `T(b)` (read or written through the same view), or passing it on to another untyped formal. An actual that `pas_view_kind` refuses (a string, a set, a record) keeps the R5 amended (5) refusal until a measured program needs it. The trap: `pas_pun_view` used to build the pun only when an address was assigned to a pointer variable, so `PT(@K)^` read the whole variable and a store corrupted it. A pointer typecast over an address goes through the same builder, and a view under the cast keeps its element image while the cast replaces the target width and kind. **move between two strings** (the coo 2026-11-12, on officer_04's rung-4 measurement of row tply-red-pyacc: yaccbase.newStr does `getmem(strp, succ(length(str)))` then `move(str, strp^, succ(length(str)))`, which matched none of the three fpc move cases in the lowerer and fell to a by-name call with values, so the pointer held the string and `pname = nil` compared a string to nil; the 20-line witness is `/home/resources/postoffice/escalations/tply-red-pyacc.defect3-newstr-move.pas`, fpc -Mfpc printing TRUE FALSE error FALSE abc): when move's source and destination are both strings (a ShortString, an AnsiString, or a dereferenced ^String), `move(src, dst, n)` lowers to the whole-string store `dst := src` (truncating to dst's capacity, R4) when n >= succ(length(src)) at run time, because fpc's n bytes are src's length byte and every character, so dst reads the same string; n = 0 is no store; any other n, a partial byte image, keeps the refusal until a measured program needs it. TStream and TMemoryStream are pure Pascal in prelude `classes.pas` over a byte array, copying through `PByte(@Buffer)[i]`; component streaming (published-property RTTI) is a design of its own.
