## 1. The oracle and the dialect

- **fpc 3.2.2 in the program's own mode** through `fpc_bin()` in `harness/scripts/lib_oracle_flags.sh`: ISO 7185 under `fpc -Miso`, FPC/Turbo plain, `-Mobjfpc`, `-Mdelphi`. ISO 7185 wins where `-Miso` is lax (CEO-1225).
- **The program's dialect decides its oracle**, one switch per program: a `{$mode X}` directive, else ISO until the first construct `-Miso` refuses (`string` in a type position, `otherwise`, `string[n]`, `uses`, `unit`, `class`, `object`, `try`, and a `write` or `writeln` of an enumeration value: `-Miso` refuses it and `-Mobjfpc` prints the identifier, so it selects objfpc like the others, CTO-524 on worker_17's measurement) (CEO-1624). Never guessed from a filename; no `--compat`. **Exclusion classes a Pascal program may carry** (CTO-525): `NO_ORACLE_ANSWER` (fpc refuses, crashes, hangs or answers differently twice), `FAKEABLE_NO_OBSERVABLE`, `NEEDS_NETWORK` (sockets, unix, fphttpclient), `NEEDS_TERMINAL` (an answer that is a function of the oracle's TERM, the ncurses binding included), `NEEDS_C_LIBRARY` (a C library SCRIP has no Pascal-source stand-in for: libgmp's mpf family; the mpz family is `prelude/gmp.pas`, SCRIP's own, and is NOT excluded). Each row names the routine or unit that forces it. **`INLINE_ASSEMBLER_RULED_OUT_BY_LON`** (Lon 2026-11-13 13:3x CST, in the cto's window, verbatim: "You can excluded Pascal with inline assembler."; on the cto's cut of the fpc-source parse refusals): a program whose source has an `asm ... end` block or a routine with the `assembler` directive is excluded, its evidence the line of the first one. Inline assembler is the host processor's language, not Pascal, and SCRIP emits its own machine code. MEASURED that hour (a scan of every `ALL.csv` entry of package `freepascal_tree`, comments and string literals stripped): 65 graded programs have one, 64 of them red; the list is `/home/resources/progress/causes-2026-11-13/fpc-source-inline-assembler.members.tsv`. A program that is green today stays graded (`webtbs/tw0961`); the class word joins `lib_excluded.sh` and the rows `EXCLUDED.tsv` by the coo's hand.
- ISO Pascal is CASE-INSENSITIVE. `string` is `ShortString(255)` without `{$H+}`, `AnsiString` with it and in delphi mode.
- A ref is cut from the oracle; no XFAIL; what fpc refuses, crashes on or hangs is `NO_ORACLE_ANSWER` (CEO-1696). A unit's `finalization` output never appears (fpc closed the files first, CEO-1617).
- **reset of an unterminated textfile appends one end-of-line** (ISO 7185 6.6.5.2 reset: f.R = f0.L ~ f0.R ~ X, X = S(end-of-line) when the textfile is non-empty and its last component is not an end-of-line; 6.4.3.5 rule a: a textfile under inspection is a line-sequence). It holds for every textfile, a program parameter or a named file alike, so after the last character `eoln` is true and `eof` false for one more read. `fpc -Miso` does not append (`eof` true at the last character), which is `-Miso`'s laxity, never adopted (CEO-1225). SCRIP does it in `pas_reset_closed_copy` (`src/runtime/by_name_dispatch.c`, commit 035a60347). A program whose answer turns on the difference is cured in its INPUT, not in the runtime: the fixture gets its last line terminated and the ref is re-cut from `fpc -Miso` (officer_03 2026-11-12, on junior_04's pcom measurement: with `demos/pascal/p5/pcom/prd` terminated, `fpc -Miso` and SCRIP mode 3 both read `Errors in program: 0`, byte-equal; the old ref's errors 6 and 21 at `end.` were fpc's missing end-of-line).

## 7. Rulings a landing must not break

- One type model, built by lower, keyed by symbol, never by name; no second model beside the typer.
- DESCR cells, ARBLK arrays, records as slot arrays; a pointer is (base cell, element index), never an interior pointer (R5); `extended` is an INLINE DESCR kind `DT_XR` (R6 as amended, CTO-486 on hq_pascal's reading of descr.h: the 64-bit mantissa in the value word, sign and exponent in slen's low 16 bits, nothing allocated, no visitor, the cfo reviews the tag), no x87 in the emitter.
- ShortString(N): a store truncates to N, `sizeof` is N+1, `s[0]` is the length byte (R4).
- A char array is its declared width, NULs included, in an fpc-dialect program (senior_03 2026-11-12, stanford-pascal `testpgm/testset3`, probed against `fpc -Mfpc`): a short literal assigned to or passed by value to `array [1..n] of char` leaves components past its length at zero, and `write` of the array emits all n bytes. `pas_alpha_wrap` hands `__pas_alpha_str` a third argument in that dialect and the runtime takes `pas_chars_full` (every component, the length carried); the call site encodes a literal actual to the formal type's declared high (`pas_arrtype_high`). ISO programs keep `pas_chars_of`, which ends the text at the first zero component, and every other caller of it is unchanged.
- The entry graph is `main`; a user routine named `main` is renamed by the duplicate-name pass.
- Features land in rungs of at most 20 lines, one construct, ref cut from fpc, red once (CEO-1680); rung N+1 opens when N is green in both modes.
- The PAT rejection tests are the ISO strictness: never adopt `-Miso`'s laxity.
- Regenerate the grammar, prelude list and builtin table before building; a cure that trades programs never lands (CEO-589); a prelude or runtime change runs all eight smokes.
- Declared sizes are a hard cap (CEO-1353/1354).

## 8. DESIGN: pascal-packed-arrays (R-2119, the cto 2026-11-04, on the cfo's PasRosetta reds fusc-sequence, strong-and-weak-primes, unprimeable-numbers-2; amended CTO-490 the same day on the measurement of the element roads)

A Pascal array, bounded or dynamic, one- or multi-dimensional, a variable, a field or an element, whose element type is a flat ordinal of width 1, 2, 4 or 8 bytes (byte, shortint, char, boolean, word, smallint, longword, longint, int64, qword, an enumeration, a subrange of any of them) is stored as ONE raw block: the ARBLK header (lo, hi, ndim, lo2, hi2, and new: `ewidth`, 0 for DESCR elements, and `esigned`) and one data block of a new heap kind `HB_RVEC`, the element bytes contiguous, no DESCR per element. The collector never scans inside an HB_RVEC (as HB_WSB: it guesses nothing because the kind says raw) and moves it as it moves HB_DVEC, re-pointing the owning ARBLK's data pointer. The choice is made ONCE in `lower_pascal` from the declared element type ALONE and rides as an IR fact the planner, the emitter and `--dump-ir` read: the array is made by the builtin call `arr_make_raw(lo, hi, width, signed)` in place of `arr_make`. Every other element type (real, string, record, set, pointer, array, file) stays `arr_make` and DESCR elements; a pointer stays (base cell, element index) (R5). ## 9. DESIGN: management operators (CTO-632, the cto 2026-11-11, on officer_04's tb0707 measurement)

FPC's `class operator Initialize/Finalize/Copy/AddRef(...)` of an advanced record are procedure-shaped (TT_PROCEDURE, sval operator). The class pass (`lower_pascal_class.c`) alone decides a record is managed (declares one of the four, or a field is a managed record; a specialized generic included, since the generics prepass runs first) and writes every hook as an ordinary call in the pruned tree: one init walk (fields in order, then the own Initialize) and one finalize walk (own Finalize, then fields reversed) per managed type; the walk passes fields by reference and never loads them (tb0707's `Initialize(T(nil^))`). A block's managed variables are initialized at entry and finalized at every exit but halt, both in declaration order (CTO-633, fpc's m4); the program's globals get no finalize walk (CEO-1617). An assignment from an lvalue calls Copy; a function result is written into its destination, never initialized by the callee, with no Copy and no finalize of the old value (CTO-633, fpc's m6); a result used as an actual is a caller temporary in its var part, initialized at the caller's entry and finalized at its exit before the declared locals; a value actual is copied then AddRef'd; a const/constref/var actual is not copied. The class pass folds `IsManagedType` for a managed record. No IR kind, no runtime leaf. Rungs R1 to R6 (grammar and a global; nested walk and the intrinsic; tb0707; locals; Copy and IsManagedType, tw36738; the move, temporaries and AddRef, tw40392); arrays of managed records and exception unwinding are cut when a program needs them.

## 10. DESIGN: untyped formals and the pointer pun (the cto 2026-11-11, on officer_05's TMemoryStream reading)

An untyped formal (`const b`, `var b`, `out b` with no type) receives the pointer value `@actual` would be: the R5 view of the actual's flat ordinal storage with its own width and kind. Inside the callee, `b` has three uses only: `@b`, a typecast `T(b)` (read or written through the same view), or passing it on to another untyped formal. An actual that `pas_view_kind` refuses (a string, a set, a record) keeps the R5 amended (5) refusal until a measured program needs it. The trap: `pas_pun_view` used to build the pun only when an address was assigned to a pointer variable, so `PT(@K)^` read the whole variable and a store corrupted it. A pointer typecast over an address goes through the same builder, and a view under the cast keeps its element image while the cast replaces the target width and kind. **move between two strings** (the coo 2026-11-12, on officer_04's rung-4 measurement of row tply-red-pyacc: yaccbase.newStr does `getmem(strp, succ(length(str)))` then `move(str, strp^, succ(length(str)))`, which matched none of the three fpc move cases in the lowerer and fell to a by-name call with values, so the pointer held the string and `pname = nil` compared a string to nil; the 20-line witness is `/home/resources/postoffice/escalations/tply-red-pyacc.defect3-newstr-move.pas`, fpc -Mfpc printing TRUE FALSE error FALSE abc): when move's source and destination are both strings (a ShortString, an AnsiString, or a dereferenced ^String), `move(src, dst, n)` lowers to the whole-string store `dst := src` (truncating to dst's capacity, R4) when n >= succ(length(src)) at run time, because fpc's n bytes are src's length byte and every character, so dst reads the same string; n = 0 is no store; any other n, a partial byte image, keeps the refusal until a measured program needs it. **THE RE-VIEW (officer_01, 2026-11-12 19:0x CST, on senior_06's rung-3 ask, row pas-rungs-red-ladder-rung27-untyped-formal-is-a-view-of-the-actual): a view cell already records its own width, so no new field is owed.** A DT_PCELL view carries the element image's width in `src_node0`, the target width in `src_node1`, and in `src_node2` the element kind (bits 0 to 2), the target kind (bits 3 and 4) and signedness (bit 5), beside `PAS_VIEW_STR` 64 and `PAS_VIEW_RAW` 128 (`bn_head.h`; `pas_view_load` and `pas_view_store`, `bn_17_pas.c`, read nothing else). So: (1) THE CALLER makes the actual of an untyped formal a SELF VIEW at the actual's own static type, `__pas_pview(@actual, w | w << 8 | kinds)` with the source and target halves equal (`pas_view_kind` of the actual's type for both; a same-width view loads and stores the one element image, measured by reading `pas_view_load`: W == w reads b[e] alone); an actual `pas_view_kind` refuses keeps the R5 amended (5) refusal, at the caller, where the type is known. (2) THE CALLEE re-views at run time through one new builtin `__pas_preview(cell, code)`: it keeps the cell's base, index, element width and element kind and the STR and RAW flags, and replaces only the target width (`src_node1`) and the target kind and sign bits from `code`, the static type of the pointer or cast it serves; `p := b` for a typed pointer p, `PT(b)` and `T(b)` (as `PT(b)^`) all lower through it, never through `__pas_pview`, which scales the index by the source width and would re-scale a view. A cell that is no view (`src_node0` 0) is returned as it is. (3) b handed on to another untyped formal passes as it is. Senior_06's spike for the grammar (`VARSY id_list`, `CONSTSY id_list`, plus out, a TT_DECL whose type child is TT_VAR `__untyped`; saved at `/home/resources/postoffice/escalations/worktrees/senior_06-r27-20261113T004242Z.patch`) is the parse step; its bison conflict is read against origin's count before it lands. ## 13. DESIGN: helpers (the cto 2026-11-13, the largest Pascal parse class of the cause census; the plan `harness/designs/pascal_helpers/STEPS.tsv`, witnesses `harness/fixtures/pascal_helpers/hp01..hp07`)

MEASURED (`/home/resources/progress/causes-2026-11-13/fpc-source-parse-refusals.members.tsv`, SCRIP 67486bdcd7): of the 103 fpc-source programs the parser refuses at a class, object or interface type form, 55 stop at a helper header (`class helper for` 33, `record helper for` 14, `type helper for` 9; 36 in delphi mode, 19 in objfpc), and the front end knows no helper (grep of `pascal.y` and `lower_pascal_class.c`). What the 55 use: class methods 25, a parent helper 17, `inherited` 14, properties 8, `Self` 7, a unit 7, a const 4, `static` 4, a typecast or literal receiver 4, multihelpers 1, a generic 1.

**The rules, each MEASURED on fpc 3.2.2 `-Mobjfpc` (the witness beside it; every ref cut twice):**
1. `H = class helper [(ParentHelper)] for T ... end`, and the same with `record` and `type`. `helper` is no reserved word. objfpc needs `{$modeswitch advancedrecords}` for a record helper and `{$modeswitch typehelpers}` for a type helper; delphi mode needs neither. A helper declares methods, class methods, properties and constants, never a field. `SizeOf(H)` is `SizeOf(Pointer)` (hp01).
2. A member `n` of a receiver whose static type is the class C is looked up along C and its ancestors, and at each class K the active helper of K, then that helper's parents, are searched BEFORE K's own members. So a helper hides the type's own method (`a.Name` prints `helper`), an ancestor's helper reaches a descendant (`b.Twice`), and a descendant's own member beats an ancestor's helper (`b.Own` prints `b-own`) (hp02).
3. The active helper of a type is the last one declared in scope; an earlier helper's members are reached only when the later one names it as its parent (hp07 prints 3). `{$modeswitch multihelpers}` (one program) is cut when it is read.
4. `Self` in a class helper is the instance. In a record helper and a type helper it is the receiver by reference: a store to a field, or `Self := e`, changes the receiver, an array element included (hp03, hp04). A typecast receiver (`LongInt(7).Sq`) is a caller temporary. `(i + 1).Sq` is refused by fpc (Illegal qualifier) and stays refused.
5. `inherited M` inside a helper method calls the EXTENDED TYPE's own `M` when it has one, and the parent helper's `M` only otherwise (hp05 prints `101 10`, not 111).
6. A helper's class method is called through the extended type's name or an instance; a helper's constant through the helper's name, and unqualified inside its methods; a helper's property reads and writes through its accessors (hp06).

**The lowering: the class pass alone** (`lower_pascal_class.c`), no IR kind, no runtime leaf, no second type model, as section 9. A helper is a `pc_class` with no fields and two facts: `ext`, the `pc_class` it extends or the type tree of a simple type, and that its `Self` is by reference (record and type helpers). Its methods become the ordinary routines every class method becomes (`pc_impl_name`, `__pc_H__m`), `Self` typed as the extended type. `pc_collect` records the helper as its type's active helper, replacing an earlier one (rule 3). The lookups `pc_find_meth`, `pc_find_prop`, `pc_is_member` and the overload pick `pc_pick` search by rule 2. For a receiver whose static type is no class (a record, an ordinal, a string), `pc_type` and `pc_resolve` read a table of helpers keyed by the type's name through its aliases. `pc_inherited` applies rule 5. Each step names its functions in the step table.

**The steps** (the table; a step's witness joins the pascal master as `helpers__hpNN` in that step's landing, never before: a red entry is a junior's work order): 1 the header parses and its size folds; 2 a class helper's methods and the lookup; 3 a record helper; 4 a type helper; 5 `inherited`; 6 class methods, constants and properties; 7 the cto reads the 55 programs again and cuts what remains (units, generics, static, multihelpers).

## 16. RULING: signals (the cto 2026-11-13, on officer_04's baseunix question, row fpc-source-baseunix-unit-syscalls-and-signal-handlers)

No signal handler runs asynchronously and no C function enters user code. `fpSignal` with a handler blocks the signal (`sigprocmask`) and stores the handler in a Pascal array of procedural variables in prelude `baseunix.pas`; the kernel holds the pending set, so the runtime gains no state and no global. The unit runs the handler itself, by an ordinary Pascal call, at the return of its own calls that can see a delivery (`fpKill`, `fpPause`, `fpAlarm`, `fpSleep`, `Sleep`, `fpRead`): it asks a builtin for one pending handled signal (`sigtimedwait`, zero timeout) and calls the stored handler while there is one; `fpPause` is the wait (`sigwaitinfo`) and returns -1 with the unit's errno `ESysEINTR`. errno is the unit's own Pascal variable, set from a builtin's negative result. A system call is a C builtin of integers; a call that takes a record is marshalled field by field in its own builtin, because a record is a slot array and never a byte image. MEASURED: tw14149 (alarm, pause) and tw14514 (kill to self) are served; a handler that must interrupt a computation calling nothing of the unit is excluded when one is read.
A program whose answer is a hardware fault on a raw machine address (tbs/tb0089: a SIGSEGV handler and a store through `pointer(-2)`) stays red as debt: SCRIP's Pascal has no raw address (R5). An exclusion class is cut for a measured population, never for one member.

## 17. DESIGN: declaration sections in a structured type's body (the cto 2026-11-13; the plan `harness/designs/pascal_sections/STEPS.tsv`, witnesses `harness/fixtures/pascal_sections/sc00..sc06`)

MEASURED (the 48 members of the cause census's class parse:class-object-interface-type-forms whose refused line holds no helper, SCRIP 3eb173ee0): about 24 stop at a section word inside a class, object or record body (`private type`, `public type`, `class var`, `class threadvar`, `strict private const`, a `const` or `var` block after the header). The grammar's `class_member` knows a visibility word, a field, a method and a property, and no section.

**The rules, each MEASURED on fpc 3.2.2 `-Mobjfpc` (every ref cut twice):**
1. In the body of a class, an object or an advanced record the words `type`, `const`, `var`, `class var` and `class threadvar` open a section that governs every declaration after it until the next section word or a visibility word; a visibility word alone returns to instance fields. So a field written after `class var Tag: Integer;` with no word between is itself a class var (sc06 prints `2 2 3 4 5 6`; sc03's `v` is shared). After `var` the fields are instance fields (sc00).
2. A constant of the body is read through the type's name, an instance, a descendant's name, and unqualified inside the methods of the type and its descendants (sc01 prints `7 7 ta 11 14 7`).
3. A class var is ONE variable for its declaring type, shared by every instance and every descendant: `TB.Tag` is `TA.Tag` (sc03 prints `3 3 3 3 xyz xyz xyz`). It is read and written through the type's name, an instance, or unqualified in a method. A `class threadvar` is a class var: SCRIP runs one thread (sc05).
4. A type of the body is named `T.TInner` outside the type and by its bare name inside the type's body and methods; the values of an enumeration declared there are in scope where the type is (sc02 prints `7 8 1 0`).
5. The same sections stand in an object and in an advanced record, beside their visibility words (sc04 prints `6 5 4 12 3 2`).
Visibility is accepted and not enforced, as today.

**The lowering: the class pass alone** (`lower_pascal_class.c`), no IR kind, no runtime leaf. `pc_class_members` keeps a section state as it walks the body. A body constant is a member of a new kind holding its expression, found along the parent chain like a method. A class var becomes one program-level variable named from its declaring class (`pc_name`), emitted by `pc_type_part`. A body type is hoisted to a program-level type declared before the class's own record type, and `pc_resolve` reads `T.TInner` and the bare name inside the class. Each step names its functions in the step table.

**The steps**: 1 the section words parse and a `var` section is instance fields; 2 body constants; 3 class vars and where a section ends; 4 body types; 5 objects and advanced records; 6 the cto reads the 24 programs again. A helper's constant (section 13, step 6) is the same member kind: whichever of the two steps lands first writes it and the other reuses it.
