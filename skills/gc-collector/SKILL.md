# The collector

The law is RULES.md (THE COLLECTOR GUESSES NOTHING, NO FRAME MARKERS, NO PINNING, NO MALLOC) and the frozen design of 2026-09-17 (CEO-818/905/1368/1371/1492). Detail, the site rules and the debugging method are in `reference.md`; the placement the maps describe is skill `scrip-memory-model`.

## 1. The frozen design (no seat reopens any of it)

1. **The collector guesses nothing**: it reads a DESCR's tag or a compiler-generated layout, never a word's value. No conservative scan, no sniff, no rewrite on a guess.
2. **A cell on the emitted stack is a DESCR read by its tag, or a raw word a small static layout names** (Lon 2026-09-19, CEO-905: "You do not have to use DESCR for everything on the stack, if static maps which are small can be generated by the compiler."). Nothing is tagged beyond that (Lon 2026-10-03: "We do NOT want everything on the stack tagged.").
3. **No pinning**, in any form or name (Lon 2026-09-17: "Get rid of any code that pins blocks in the GC.").
4. **An unrooted holder gets a root, never another allocator**; SCRIP calls no `malloc`, `calloc`, `realloc` or `free` (CEO-832).
5. **The allocator never collects**: it sets `g_gc_pending`; collection happens at the next safe point.
6. **A safe point is the return of an emitted call into an allocating runtime entry, after the result is stored**; the poll there collects. A runtime C frame that calls back into emitted code holds no raw heap pointer across the callback.
7. **The maps stay; no frame markers; no second stack** (Lon 2026-10-03: "W do not want markers on the stack. We do want the stack mapped.").
8. **Lon's acceptance, five clauses on one tree**: all sliding, no pinning, all rooted, all mapped, all working (CEO-895).

## 2. How a collection finds its roots (the chain over the maps, landed 2026-10-14)

- **The maps**: one `gc_frame_map_t` per activation frame (`src/ir/gc_frame_map.h`), its layout quads `GC_LAY_DESCR`, `GC_LAY_RAW`, `GC_LAY_PTR_GC`, `GC_LAY_PTR_CODE` produced from `frame_layout.c`; installed in both media (the `__gc_frame_maps` table in mode 4; `rt_gc_frame_maps_add` per graph in mode 3 and for every run-time compiled graph).
- **The site table**: one entry per return pc of a runtime call, γ landing, generator resume label and C-to-box road stub, `{pc, kind | rule << 16 | depth << 32, mask}`; rules 0-9 say how the frame's base is found (`reference.md` § 2).
- **The walk** starts at the poll (`rt_gc_poll`, `rt_gc_poll_slow`): look up the return pc; the frame's base by its rule; the spine between frames read as 16-byte cells (a cell visited only when its tag is known and its pointer lies in a live block); the frame by its map; follow the link word to the next frame; a miss inside runtime C unwinds by frame pointer to the next hit; stop at the ROOT map. A parked co-expression's segment starts at its `park_rbp`. Nothing is scanned to find a frame.
- **Other roots**: registered ranges (`rt_gc_root_range_add`: the Prolog trail, co-expressions), the runtime's tables (`core_gc_roots`), the per-language root visitors.

## 3. The collection itself (asm, `src/runtime/rtx/rtx_gc.s` and `rtx_alloc.s`)

`gc_collect_ex` is an `RTX_FUNC` calling C-convention asm runs (Lon to hq_runtime 2026-10-15: "You are meant to re-write the GC collection, and then ALL C bottleneck C code into ASM."): the root runs, the chain-walk steps (`rt_gc_site_find_a`, `rt_gc_sw_links_a`, `rt_gc_sw_step_a`), the mark run (`rt_gc_mark_run` over a worklist), then the exact compactor on granule bitmaps (LIVE and START bits per 16-byte granule, a PREFIX popcount pass for destinations, `rt_gc_fix_run` rewriting each recorded slot, `rt_gc_slide_run` moving each run of live granules with one `rep movsq`), the trail relocation and the reset. Every run carries true CFI at every pc (`test_gate_rtx_every_leaf_carries_cfi_true_at_every_pc.sh`).

## 4. Instruments (each red once before trusted)

`SCRIP_GC_STRESS=1` (collect at every safe point; `3` for more) with `SCRIP_GC_PLANT_FLIP=1` (move every block, so a stale pointer becomes a located fault; filter the `[GC-` banner before diffing); `SCRIP_GC_CHAIN_CHECK=1..3`; `SCRIP_GC_SITES_REPORT=1` with `--compile` (the site records); `SCRIP_ZETA_TELEM=1` (per-collection regeneration lines: the identity proof of a collector landing); `SCRIP_GC_VERIFY`, `SCRIP_GC_TRAP`, `SCRIP_GC_MAPS`. The witnesses are `harness/scripts/gc_witnesses/` (programs with refs) and `gc_bare_poll_witnesses.tsv` (keyed by file and callee, re-keyed last). The window is set by hand with `SCRIP_HEAP_KB` (overrides `SCRIP_HEAP_MB`) and `SCRIP_HEAP_MAX_MB`, never a program's size.

## 5. Rules a landing here keeps

- The allocating table `src/templates/x86/gc_allocating_table.inc` follows the runtime binary: regenerate it after every runtime landing (`util_gen_gc_allocating_table.py`, `--check` reads stale); never edit it.
- A leaf that can allocate returns to a safe point; a poll is a register-preserving asm leaf; a recording poll form clobbers caller-saved registers, so a tail never re-stores registers after an arm polled.
- `ZGC-STALE` in an asm leaf after a C call is a clobbered register, not a root. A poll that DIFFs in every configuration names a reclaimed root, not a moved one. A hang under stress is often slowness.
- A GC witness may not print what the collector decides (counts, addresses); it prints the program's answer.
- The asm spine scans (`rt_gc_walk_words_a`, `rt_gc_frame_cells_a`) keep their cursor in `gc_mk` bytes 184..271 (draining, fc_*, sw_p, sw_hi); a visitor reached from `gc_visit_mblk` that walks stack words runs its own scans through the same fields and each ends by zeroing them, so it must save and restore the region around the walk (`gc_visit_pseg` does, since 2026-11-04). A red that appears only under `SCRIP_DIAG=0` while `SCRIP_DIAG=0 SCRIP_GC_MAPS=1` is green is this class: the C census walk has no shared cursor, the asm one does.
- Bound a collector experiment's memory with a cgroup, never a timeout. Grade a collector landing in both modes under stress on the witnesses, and the identity lines against a control worktree.

## 6. DESIGN (open, the cto's)

- **The block header counts granules** (CTO-492, 2026-11-04, pascal-packed-arrays step 5, hq_collector): `rt_hblk_t` is {fwd u64, size u32, type u16, flags u16} and `rt_gcheap_carve` wrote `(uint32_t)total`, so a block over 4 GiB kept its size mod 2^32 while the top advanced by the whole request, and every walker, the live bits (`size >> 4`) and the compactor read a short block (the cto's witness `pa08_wide`, 300,000,000 doubles = 4,800,000,000 bytes at a declared 6 GB, runs past 300 s at 4 GiB RSS where fpc prints in 3 s, and the same without its churn loop past 150 s: the hang is in the allocation road, before any collection). RULED: the field is renamed `gran` and holds `total >> 4` (every block is a multiple of 16; the verify walkers refuse `size & 15`), reach 2^32 x 16 = 64 GiB above the 32 GB page map, so the declared heap is the only cap on a block of any kind (RULES: declared sizes are hard caps, no fixed limits); every C reader is rewritten in place as the shift (a stale reader of `size` fails to compile), every asm reader of `dword ptr [r + 8]` shifts left by 4 after the load, every writer shifts right (no `(uint32_t)total`), `gc_vac_t.size` carries granules the same way; step 2's refusal of a payload over 0xFFFFFFE0 is retired, a request past the declared heap is error 204 by the ordinary road. The step is `test_design_pascal_packed_arrays_steps.sh --step 5` (witness pa08_wide in both modes at heap=6291456, probe `hdrfield=gran`); the gc witnesses, the stress suite and the flip plant stay green.
- **HB_RVEC (234), the raw vector block** (pascal-packed-arrays step 2, CTO-490, landed 2026-11-04): element bytes with no DESCR and no heap pointer inside, allocated by `rt_ws_alloc_raw(nbytes)` and grown by `rt_rvec_realloc`; its one reference is an ARBLK's `data` word. The type lies past HB_AGGV+27, so it is outside the move list and the `MK_MOVES` mask (a static assert pins both); `.Lmk_arr_raw` in `rtx_gc.s` marks the block live and records the data slot, then returns to the mark loop WITHOUT the element scan the DESCR path runs (that scan reads `hi - lo + 1` cells as DESCR tags, and over raw bytes it would read past the block); the compactor slides it like every live run and the recorded slot is re-pointed. Only a flat ordinal element type may be raw; a record is an `arr_make` slot array and stays DVEC. Until step 5 widens the header, both entries refuse a payload over `HB_PAYLOAD_MAX` (0xFFFFFFE0) with error 204. Its `gc_kind_witnesses.tsv` row is NO-PRODUCER until `arr_make_raw` lands (step 3).
- **The spine mask** (zeta-layout steps 4a and 4b; the cell-shape table's word-kind column, the planner's fact column, the site's third quad: at a rule-1 or rule-2 site NW << 32 | the byte offset of its mask words, blocks shared by prefix, CEO-2118): the walk visits exactly the declared words and the 8-byte reject loop (`.Lsw_reject` in `rtx_gc.s`, still present) is deleted. Step 4b is ASSIGNED to hq_collector.
- **Early reset is liveness by site** (2026-10-31; row `gc-swi-core-test-gc-early-reset-...`, PARKED): lower computes, for every clause-retry site, the cells the remaining alternatives read, the map at that site declares those cells only, and a second trail pass resets the entries no forward execution reaches.
- **The site record from the row** (zeta-layout step 3): the text-site rescan goes and rule 5 ceases.
