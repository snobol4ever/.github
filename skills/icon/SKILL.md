## 7. Rulings a landing must not break

- No software value stack; the activation record IS the frame (CEO-1542).
- **THE ICON STACK OVERFLOWS WHERE ICONX'S DOES: AN ACCOUNT OF ICONX'S INTERPRETER STACK, IN ICONX WORDS, NEVER A STACK** (the cto 2026-11-18 08:1x CST, row icon-the-stack-overflows-where-iconxs-does-and-301-prints-every-frame; Lon 2026-11-17: "We want 100% compatibility with Icon and Unicon."). MEASURED on iconx 9.5.25a under its default stack: a recursion of a procedure with no argument and no local stops after 711 frames with error 301, one with one argument and one local called as return r(n - 1) after 454; SCRIP went past 32,000 and its 301, from the machine stack's guard (core_overflow_exit), printed no frame. THE RULING: each Icon procedure activation charges a cost in iconx words against a limit on entry and gives it back when the activation is gone; a suspended generator keeps its charge while it can be resumed, as iconx keeps its frame. The limit is MSTKSIZE read from the environment as iconx reads it, else iconx's default, so an entry's MSTKSIZE sidecar holds on SCRIP too; past it 301 is raised at the call through the ordinary error road and the traceback prints every frame. The cost is a formula MEASURED on the oracle by probes (arguments, locals, the call site's expression depth, an IR fact of the call), never read from iconx's source. It is a counter beside the frame, not a value stack: the ruling above stands. Co-expressions (COEXPSIZE) are a later row.
- The scanning environment is (r13, r14, r15) at every instruction of an Icon graph: `&subject` is `{DT_S, r15d, r13}`, `&pos` is `r14 + 1`, derived at the read; no `scan_subj`, `scan_pos` or `in_scan` returns.
- A co-expression runs on the pthread's own mmap'd stack: never a heap block, never pinned.
- **A HANG IS NEVER AN ANSWER: A CO-EXPRESSION WHOSE THREAD IS NOT IN THIS PROCESS IS A RUN-TIME ERROR** (the cto 2026-11-17 01:1x CST, on the cao's item Q of row jupyter-step-10; built by row jupyter-step-10q). The session's checkpoint (row jupyter-step-10a) is a fork, and a fork carries only the calling thread, so a co-expression made before a cell that died has no thread after it. MEASURED on SCRIP 9901949e3: the activation waited on its semaphore with no answer. The co-expression's record keeps the pid of the process that made its thread, and activation compares it with `getpid()` before it waits. A mismatch is error 702 through the error protocol (skill runtime-calls section 4): "the co-expression was made before a cell restart and cannot be resumed after it". 702 is SCRIP's own 700 range, beside 701; Arizona's 401 means another thing.
- **HYPOTHESIS, NOT A ROW: A CO-EXPRESSION SWITCHED ON ITS OWN STACK WITH ITS REGISTERS SAVED IN MEMORY, SO A FORK CARRIES IT** (the cto 2026-11-17 01:1x CST). It is Arizona's own design, coswitch, a few instructions of assembly per platform. The Arizona 9.5.25a built here still switches by threads: its iconx holds the strings "sem_wait in coswitch", "new_context returned to nctramp" and "cannot create thread" (read by the cao with strings). The collector already walks a parked co-expression stack as a segment (gc_heap.c, gc_coexpr_records), not as a thread, so it would need nothing new. The cure rewrites rt_coexpr.c's switch, the trampoline, the stack-segment bookkeeping and every Unicon thread interaction. It waits until the Icon graphics queue is clear, and it is designed from a measurement first: how many container entries create co-expressions, and the cost of a switch today against a register swap, as instruction counts (skill speed-measurement). Until then the ruling above stands.
- An Icon call crosses no C helper (CEO-1488/1491); `main` is an ordinary procedure; no C function enters a box (CEO-1576).
- **LOADFUNC IS BUILT; ITS LIBRARY IS THE ORACLE'S OWN, NAMED BY ONE fpath CONTRACT LINE** (the cto 2026-11-17 17:5x CST, on Lon's word of that hour, "Get those tests cut, graded, and scored."; MEASURED on SCRIP 7d24bc08b). `loadfunc` dlopens and dlsyms (bn_41_sh.c) and the call goes through Icon's own C interface in `src/runtime/icn_extfn.c` (the descriptor layout, `alcstr`, `alcreal`, the `cnv_` functions): arizona_tests general/cfuncs, extlvals and cfunc_driver equal icont and iconx byte for byte. The C library is the oracle's build, one for the box (Icon's `/home/packages/icon/icon-master/ipl/cfuncs/libcfunc.so`, Unicon's `/home/packages/icon/unicon/bin/libcfunc.so`), never built by SCRIP's make or a run. iconx and unicon each set a default FPATH naming their own library and SCRIP sets none, so a package's CONTRACT line `fpath DIR` gives the builder's cut and the harness's grade the same FPATH. A missing library is answered by the same Icon code on both (io.icn's `pathload`), a missing symbol by error 216.
- Semicolons are settled law; one oracle; an outside-baseline ref is named or it is not a ref.
- The three zetas: every operand starts on the RSP spine; the planner alone decides; a retry never restores RSP.
- **The length is carried, never measured** (2026-11-01 IPL cures): a slice of a scanned subject (`tab`, `move`, `=`, a section of `&subject`) is `{DT_S, slen, ptr into the subject}` and is NOT NUL-terminated. When a library procedure is red, ask what differs between a `tab()` slice and a literal.
- **THE EVALUATION-STACK ACCOUNT: SCRIP'S 301 IS ICONX'S, IN ICONX'S WORDS** (the cto 2026-11-18, row icon-the-stack-overflows-where-iconxs-does-and-301-prints-every-frame, developer_01, SCRIP 10d071afc; Lon 2026-11-17: "We want 100% compatibility with Icon and Unicon."). MEASURED on iconx 9.5.25a (`/home/resources/progress/developer_01-stack-account`: FORMULA.md, probe.sh, pend_check.py, exits/exit_probe.sh): an activation is admitted iff 22 plus the costs of every live activation, itself included, is at most MSTKSIZE words (the environment, default 10000); cost = 14 + 2 a formal or local (implicit locals counted, statics not) + the words pending at the call in the caller (2 an operand or pnull, 4 an expression mark; the lowerer computes it per construct, `icn_pw_walk`, as the call's `IR_t.pend`, equal to the oracle on 79 shapes). The account is a field of the co-expression context (`scrip_coctx_t.icn_budget`, each context its own stack, so a co-expression's COEXPSIZE is one value to set; `g_scrip_co_current` is never null, the root context standing when no co-expression runs). The charge is the non-generator arm of `bcps_icn_block_arm`: add the cost once the argument block is built, refund where the gamma and omega landings meet; past the limit `rt_icn_stack_overflow` raises 301 through `core_icn_error` BEFORE the callee's frame exists, with the entering procedure in the traceback as iconx prints it (the 454th frame of r4) and the caller's line. 7 instructions a call (fib(27): +3.7 per cent).
