# The shared box (CEO-2041, CEO-2105, CEO-2108)

Nineteen seats share 16 cores and about 30 GB. The kernel divides CPU by weight inside each cgroup; the pools bound how many compiles and runs exist; the caches make every tree's build, check and oracle answer happen once. Detail and the forbidden forms are in `reference.md` beside this file.

## 1. Where your work runs (live values, read 2026-11-01)

- **Your session scope is the door** (CEO-2105): every child of your session inherits `cpu.weight 100`, `MemoryHigh 4G`, `MemoryMax 8G`, `MemorySwapMax 1G`, `TasksMax 2048`, set by the `SessionStart` hook (`harness/scripts/s4e_session_start.sh`) from `BUDGET.tsv`'s `@SEAT` row. A spawned seat's scope, `s4e-seat-<seat>.scope` under `s4e-seats.slice`, is made by `spawn_fleet.sh` with the memory caps and no CPU quota (section 3, THE ONE LIMIT), and the hook applies the row (the coo 2026-11-12 18:2x: before that cure all 33 seat scopes read no `MemorySwapMax` and no `TasksMax`). A seat's scope weighted wrong is restored by `s4e_session_start.sh --pid <session pid>`, never by hand.
- **The grader** (the coo's loops): `s4e.slice/s4e-grader.slice`, weight 300, `MemoryMax 10G`. **Batch** (identity runs, censuses, compile-all sweeps, callgrind, the DONE-WHEN sweep, cron): `s4e.slice/s4e-batch.slice`, weight 50, `MemoryMax 12G`, each job its own 8 GB scope. **The sessions** sit in `app-org.gnome.Terminal.slice` (weight 100, high 20G, max 24G). `s4e.slice` (weight 200) outranks `app.slice` (weight 100) at the top (box-scheduler step 7, CTO-496).
- **The graded runs live inside the one slice** (row `one-limit-universally-respected-every-seat-runs-at-will`, 2026-11-13): `util_mem_scope.py`'s `seat_slice` puts every seat's run, the cycle's and every harness run, in `s4e.slice/s4e-runs.slice/s4e-runs-<seat>.slice` (the grader's `s4e-runs-grader.slice` at weight 300, its drop-in `weight.conf`), under the fleet's one quota and no other; until then they ran in `app.slice/app-s4e.slice` at `CPUQuota=1000%`, outside `s4e.slice` (Lon 2026-11-12 18:1x had raised it from 2 cores: 98956 s throttled and 66-70% CPU pressure at load 2-3). Each seat scope carries its declared `MemorySwapMax=1G` and `TasksMax=2048` (`util_seat_census.py --budget-check` reads every knob).
- **A helper is never placed** (CEO-2108): Claude Code's own daemon and pty hosts are not sessions; a seat's scope is never weighted as Lon's.

## 2. The three kinds of run

- **A harness run** (a board, a smoke, a gate that runs programs): admitted by the harness's run slot; a board enters its mem scope in the batch slice (or the grader's under `S4E_CLASS=grader`).
- **A batch job**: only through `bash harness/scripts/util_batch.sh <cmd>`; one top-level batch job per seat; the scripts that are batch by nature enter it themselves.
- **A hand run** (`./scrip prog`, a two-tree diff, an oracle by hand): `bash ../harness/scripts/util_run_slot.sh <cmd>` inside your own scope. A live oracle run goes through `util_oracle.sh` under `timeout -k 5`.

## 3. The pools (`harness/scripts/lib_slots.sh`)

**THE ONE CORE BUDGET** (the cio 2026-11-13, row `one-core-budget-every-compile-and-run-takes-a-token-from-one-count`; Lon, verbatim: "how are we going to fix the fleet infra-structure?" / "does it not require a hard wired solution, not a soft brained solution?"; the coo's proposal he read: one budget counted in cores, taken at the door, grading's share first, the rest waiting without running). MEASURED before it (`/home/resources/fleet-ops-research`, files 01 and 08): 16 cores and 36 admissions at once by class (compile 6, run 18, land 12), each pool counting alone; load 43 to 87; the test runs fully stalled 47 % of the time. WHAT THE SOURCES SAY (the README there): limit what runs at once counted in cores; a small pool and the rest wait; one budget with a share for each kind; admit at the door. THE RULE: one file every taker reads at each take, `/home/resources/postoffice/CORES.conf`, `key=value` a line: `cores=N` the tokens in all, `grader=G` the top G tokens that only `S4E_CLASS=grader` may take and takes first, `seat=K` a seat's tokens in all, `wait=S` the seconds a taker waits before it refuses rc 2 (1800 when absent). A compile (`util_cc_slot.sh`, every gcc and g++ of the Makefile), a hand run (`util_run_slot.sh`) and a harness test entry (`corpus_suite_harness.py`) each hold ONE token of the SAME count for their life; the token files are the run pool's own (`/tmp/s4e-run-slots/slot0..N-1`, seat files beside them), so a taker still on the library of before contends on the same files for its runs. NO NESTED TAKE: a taker started under a held token (`S4E_CORE_HELD`, or `S4E_RUN_SLOT_HELD`) takes none and runs on its parent's, so a holder never waits for a second token (the pool-locking deadlock of one pool). With no file, or no `cores` line, the two pools below are the rule, unchanged: the budget is turned on, tuned and off on the live fleet by one line, and its numbers are the cio's to set, read against `SLOT_WAITS.tsv` and pressure. `util_run_slot.sh --probe-cores` proves it on a scratch pool. 

**THE ONE LIMIT** (row `one-limit-universally-respected-every-seat-runs-at-will`; Lon 2026-11-13 13:5x CST, in the cio's window, verbatim: "I wan tall descisions on when and when not to run a junior, senior, officer, or your GRANDMOTHER to STOP NOW! I want all seats to RUN at WILL." / "We do not want two or three limiters, we want ONE UNIVERSALALLY resepcted LIMIT."). MEASURED 13:5x: load 50 on 16 cores against 14 tokens, the kernel quotas of six slices and forty seat scopes each its own limit. THE LAW: `cores=N` of `CORES.conf` is the only limit. The door counts it (the tokens above) and the kernel enforces the same number: `box_tick.py` sets `s4e.slice`, which holds every seat scope, the grader, batch and the graded runs, to `CPUQuota=N*100%` each tick and clears every CPU quota below it and below `app.slice/app-s4e.slice` (`systemctl --user set-property --runtime`), so one edit of one line moves the door and the kernel together. Nothing chooses which seat runs: the tick's grader width W, its workers awake A and its FLEET live set are gone, and MODE keys no `FLEET:` or `WORKERS-AWAKE:` line. With a `cores` line the sem classes of `SLOTS.tsv` admit nothing (`s4e_sem_admit` passes, and the work's own compiles and runs take tokens), `lib_smoke_honest.sh` reads its load bar against `cores`, `BUDGET.tsv` declares no CPUQuota but `s4e.slice`'s, and `spawn_fleet.sh` gives a seat scope none. A weight shares and never limits. `box_tick.py --probe-one-limit` reads it all on the live box (`--scratch`: the planted arms alone). `grader=` and `seat=` are shares of the one count, kept while Lon keeps them.

**THE CAPS WITH NO `cores` LINE** (`harness/scripts/SLOTS.tsv` and `lib_slots.sh`'s `S4E_*_DEFAULT` lines, which agree; the coo 2026-11-12, on the grader's find that a reserve of 4 capped the cycle at 4 runs whatever its lanes): compile 6 (a seat 3); run 18, the grader's reserve 10 (its 8 fast and 2 slow lanes) and the seats' 8 (a seat 4); land 12. The 10 cores of `app-s4e.slice` bound the graded runs' CPU, and the numbers below are the history. Eight compile slots (`util_cc_slot.sh`, every compile through ccache) and eight run slots (`util_run_slot.sh`); a seat takes at most four compiles and three runs; two run slots are reserved for the grader. `make -j8` is the most any root runs. A nested harness under a held run slot takes no second slot (`S4E_RUN_SLOT_HELD`). The holders are read from `/proc/*/fd`; waits are in `/home/resources/progress/SLOT_WAITS.tsv`.

**Admission to a class by GNU sem (fleet-queue step 18, the cio 2026-11-05; the coo and the cio ruled 17:4x).** `harness/scripts/SLOTS.tsv` is the class table (class, id, cap, timeout_s by day, timeout_night_s): `compile` `s4e-compile` 8, `run` `s4e-run` 8 (the grader's `run-grader` 2 plus the seats' `run-seats` 6, so the reservation is a pool, not a third sem), the seat shares `compile-seat` 4 and `run-seat` 3 (id prefix plus the seat name); its caps equal `lib_slots.sh`'s `S4E_*_DEFAULT` lines (the pools gate's arm 5 checks it). `bash ../harness/scripts/util_run_slot.sh --admit <compile|run> <command>...` takes at most TWO sems (the seat's share, then the pool) through a fixed holder, `util_slot_holder.sh`, kept on fd 6 and inherited by the command (a killed holder frees it); a timeout is a NEGATIVE `--semaphoretimeout` and refuses rc 2 with nothing run (a positive one steals the slot after the wait). Use it for a take that is rare and long: a batch job (`util_batch.sh` does), a build, a whole suite run, a landing. The per-entry and per-compile slots stay FLOCK files (`s4e_slot_hold`, `corpus_suite_harness.py _run_slot`): MEASURED 2026-11-05 (`perf stat -e instructions:u`, load 51 on 16 cores) a sem take is 327 M user instructions against 12-19 M for a flock take, and a marginal harness entry is 0.28 G. sem re-parses its argv through a shell, so a user's command never goes through it. `util_run_slot.sh --probe-sem` proves the mechanism on a scratch pool (seat share, pool cap, the grader's pool, two sems at most, kill frees, nested admission, refusals recorded) and prints one `SLOT by=sem class=... id=... cap=... timeout_s=...` line per class. The pool lives in `/tmp/s4e-sem` (`S4E_SEM_HOME`).

## 4. The caches (a hit is the same computation, done once)

- **The build cache** `/home/resources/builds/scrip/<key>/`: `make` on a clean tree at a cached key copies the build in and prints `FETCHED <key>`; the first clean build of a tree publishes it. Keep the root clean so it fetches; a root holding an uncommitted cure builds locally.
- **The check cache** `/home/resources/progress/checks/`: `util_check_cache.sh <name> -- <cmd>` replays a deterministic gate's rc and output on the same four clean trees (`CACHED <key>`); `checks_nocache.tsv` names what never caches; `--fresh` bypasses.
- **The oracle cache** `/home/resources/progress/oracle/`: `util_oracle.sh` keys rc, stdout and stderr by the oracle binary, program, argv and stdin.
- **The progress store** `/home/resources/progress/results.tsv` is the one grading cache: read it with `util_score_row.py from-progress`; ask the coo for what it lacks (`s4e_test_request.sh`).
- **The shared files** (the cio 2026-11-12, on Lon's "Can not ALL the seats share a corpus repo?" / "We should save huge space this way."): one read-only checkout of corpus, harness and .github under `/home/resources/shared`, kept at origin/main by `util_shared_pristine.sh update` under one lock; `util_relink_root.py ROOT` makes each clean tracked file of a root whose blob equals the pristine's a hard link to it and marks the repo `s4e.shared`, and `util_sync_root.sh` relinks a marked repo after its merge. A root keeps its own directories, so every relative path works and there is no symlink; its objects are borrowed from the coo root (`git clone --shared`; `git repack -A -d -l` drops a converted root's copies). MEASURED on the cio root: 2.7G of files and 4.4G of packs freed in under a minute, `fsck` clean. A pull or checkout replaces a file by a new inode, so a tree moves only at its own sync; an in-place write to a linked file fails EACCES instead of reaching every seat (`util_shared_pristine.sh selftest`, eight arms on scratch repos). A worktree lives on /home beside the pristine, and one made with `--link` (the cycle's bases, which only read) is linked too (officer_02 2026-11-13; skill `seat-conduct` section 2). A seat root carries the FULL corpus; sparse is for worktrees only (`s4e_worktree.sh`), and the links make the full tree cost nothing (the coo 2026-11-12 18:0x, on junior_13's measurement: fifteen roots made sparse by `populate_numbered_seat.sh` hid `demos/` and `benchmarks/`, so every demos suite listed 0 members there; the cio ran `git -C corpus sparse-checkout disable` then the relink on each and cured the script). Never chmod a pristine or a linked file writable; never `git gc`, `prune` or `repack` the coo root, whose objects every root borrows. SCRIP and its `out/` stay copies (the cto 2026-11-12, measured: a file's mtime lives on its inode, so a linked `out/` would let one root's make or fetch move every root's build times and defeat make and `gate_require_fresh`; that waits on a freshness contract read from `out/buildinfo`'s key, SCRIP's to cut). In the shared repos only git reads the mtime: no Makefile rule has a prerequisite in `../corpus` or `../harness`. **A seat's root is its working tree** (Lon 2026-11-13 17:4x CST, verbatim: "I want you to work in /home/claude folder. We do not NEED duplication. Nope, dups not needed."): no seat makes a worktree (`s4e_worktree.sh new` refuses but for the grader's bases); a seat edits in its root, where the Edit tool breaks a link and leaves the pristine untouched; `s4e_land.sh` relinks a root's shared repos after its landing (`util_sync_root.sh --relink`), and `util_sync_root.sh` keeps a repo with local commits or edits as it stands (`KEPT`), so a sync never costs a seat its work (skill `seat-conduct` 2).

## 5. Memory and /tmp

- A runaway is killed inside its own cgroup: your scope at 8 GB, a batch or board scope at 8 GB. Bound an experiment's memory with a cgroup (`util_mem_scope.py`), never with a timeout.
- **systemd-oomd never chooses a seat's session** (Lon 2026-11-12 19:3x CST: "some seatds died."; MEASURED: at 19:02 systemd-oomd killed s4e-seat-junior_16.scope and s4e-seat-senior_08.scope under the box's memory pressure, each session's peak only about 300 MB, while big-heap runs elsewhere, fusc at a 5.3 GB heap and a rung at 6 GB, drove the pressure): every seat scope carries `ManagedOOMPreference=omit` (set at launch, `-p ManagedOOMPreference=omit`, and at runtime by `systemctl --user set-property --runtime`), so under pressure oomd kills the run that made it, never a session. A hand run with a declared heap over 2 GB goes through `util_mem_scope.py`, never bare in the seat's own scope.
- `memory.current` counts page cache: a scope over `memory.high` with small `anon` in `memory.stat` is file pages, and `echo 2G > memory.reclaim` in the scope's own cgroup frees them without killing anything.
- Large outputs die in `/tmp`, never under a root; the harness places its scratch under `/tmp/s4e/<seat>`; `util_tmp_sweep.sh` (cron, the batch slice) ages it out. `/tmp` is shared by every seat: an ENOSPC fakes reds, so `df /tmp` before believing one.

## 6. Measuring

Instruction counts (`util_instr_count.sh`) run at any load. A clock runs only inside `util_quiet_slice.sh` (it drains both pools and takes the top weight; it refuses inside a held run slot). The ledgers: `util_seat_census.py now | --check | --memory-check | --health | --grader-rate | --acceptance` over `LOAD.tsv` and `SEATS.tsv` in `/home/resources/progress/`.
