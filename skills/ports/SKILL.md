# The ports: snobol4dotnet and snobol4jvm

## 1. What they are

- **Two separate SNOBOL4 implementations, each the clone at its seat's root** (Lon 2026-11-17 15:5x CST, in the cio's window, verbatim: "Just like a SCRIP seat, the clone goes directly at the root." / "That is root being, /home/claude_dotnet and /home/claude_jvm."): `/home/claude_dotnet` IS the snobol4dotnet clone (C#, Jeffrey Cooper's, `Snobol4.sln` at its top, built there with `dotnet build Snobol4/Snobol4.csproj -c Release`) and `/home/claude_jvm` IS the snobol4jvm clone (Clojure, `project.clj` at its top, built with `lein uberjar` by `/home/harness/scripts/build_snobol4jvm.sh`, which also records an AppCDS class archive). The runners read the engine from those two roots (`S4E_DOTNET_ROOT`, `S4E_JVM_ROOT` name another); a script that still looks for a folder `snobol4dotnet` or `snobol4jvm` beside the harness is a bug of the one-disk cutover.
- **They are not SCRIP**: not its backends (SCRIP's own JVM and .NET targets are new template sets, skill `scrip-backends`) and not its oracle. The oracle of all three engines is SPITBOL, `sbl -bf` (`lib_oracle_flags.sh`).
- **Seats and lanes** (MODE `LANES:`): the seats are `dotnet` and `jvm`, windows DOTNET and JVM, seated Opus 5.5 high (Lon 2026-11-17 15:5x CST, in the cio's window, verbatim: "Let's have DOTNET and JVM join us as Opus 5.5 high. Each port grades its own suites (CEO-1822/1912). The record of a port is its rows and their batons (the GOAL files are deleted); the speed rows rest under Lon's hold (CEO-2049) until he lifts it.

## 2. How a port is graded (the same runners, the same refs)

- **snobol4jvm IS SNOBOL4++: SPITBOL'S SEMANTICS WITH EVERY EXTENSION, AND NEVER A CASE FOLDED** (Lon 2026-11-17 18:1x to 18:2x CST, in the JVM window, verbatim: "I think we should make snobol4jvm a bit more special that SPITBOL. Since SPITBOL restricts OPSYN for optimization. But Clojure will not see any of that optimization so let's do more of a SNOBOL4++ where it has all extensions and keeps the dynamic power of SNOBOL4. Have the INPUT and HOST be just like SPITBOL." / "We WILL NEVER support case-folding. We will always have upper-case built-in keywords and functions."). IT AMENDS for snobol4jvm alone his word of 2026-10-23, "The snobol4jvm will act like SPITBOL, not CSNOBOL4."; snobol4dotnet is not touched by it.
  - **Extensions run.** Asked, he chose to allow every extension: where `sbl -bf` ends in an error caused only by a SPITBOL restriction that CSNOBOL4 or SNOBOL4 lifts, snobol4jvm runs on. Examples: OPSYN of any operator, unary `^` among them (sbl: ERROR 156); CSNOBOL4's `&DIGITS` (sbl: ERROR 251); `FUNCTION`, `LABEL` and `VDIFFER`.
  - **I/O and the host stay exactly SPITBOL's:** `INPUT`, `OUTPUT`, `TERMINAL` and `HOST`.
  - **No case is folded.** Built-in keywords, functions and control cards are upper case only, as `sbl -bf` reads them: `&trim` is ERROR 251 and a lower-case `-include` includes nothing.
  - **Grading:** asked, he chose a per-engine declaration. The SPITBOL ref stands, and an entry whose answer turns on a lifted restriction is declared in `EXCLUDED.jvm.tsv` beside its package, class `SNOBOL4PP_EXTENSION_KEPT_BY_LON` (admitted on that file alone, `lib_excluded.sh`), with the oracle's answer as its evidence. **IT IS A PASS ON THE PORT, NEVER AN EXCLUSION** (Lon 2026-11-18 10:5x CST, in the JVM window, verbatim: "Well, no, we are not going to patch the oracle with SCRIP enhancements. You handle the difference in the test suite as a PASS, since the oracle is unable to grade."): the entry stays in snobol4jvm's denominator, and under `S4E_ENGINE=jvm` `corpus_suite_harness.py` records its output mismatch PASS, detail `snobol4pp-extension` (`PORT_EXTENSIONS`), a crash, a hang or an out-of-memory staying what it is; `util_score_row.py` keeps it in the row (harness 0ee93d27b, its cure forward 20261118T165120Z). No ref is cut from the port's answer and no oracle is changed for it; SCRIP's rows never read the file.

- One identity on every commit (`LCherryholmes`, `lcherryh@yahoo.com`); the port repo pushes before `.github`.
- A port's red is cured in the port; a disagreement with SPITBOL is the port's defect unless the ref was cut wrong (CEO-1696: no oracle answer is an exclusion, never a debt).
