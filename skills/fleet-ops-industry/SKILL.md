# Fleet operations: what the industry already solved (the cio, 2026-11-04; Lon: "consolidate industry best practices regarding load management of build and test systems, on concurrent development using a single repo, how to share and queue ... let's get grounded in what's possible")

The sources, with what each was read for and how far to trust it, are in `reference.md` beside this file. A claim marked VERIFY there was read from a secondary source. Every mechanism below ends with OURS (the step or instrument that adopts it) and GAP (what we still do by hand or not at all).

## 1. One box, shared compute: weights, quotas, pressure, a controller

- **Weights for fairness, quotas only for a hard ceiling.** cgroup v2 `cpu.weight` (1-10000, default 100) is a proportional share that bites only under contention: an idle box lets any group use everything. `cpu.max` is a per-period cap that throttles after the budget is spent; CFS bandwidth control throttles bursty work even when its average is under quota (the kernel's burst controller exists for that), and a runtime sized to the host's cores instead of its quota suffers latency artifacts. systemd exposes both as `CPUWeight=` / `CPUQuota=` and `IOWeight=`; a CI runner that swamped a box was tamed with `CPUWeight=20 CPUQuota=85% IOWeight=20`. OURS: s4e.slice weight 200 against app.slice 100 (step 7), per-seat `CPUQuota` as the actuator, the grader above the sessions. GAP: the sessions' cap is a quota, so a capped seat waits while cores idle (the coo measured busy 11-14 of 16 at PSI 61); weights should carry the fairness and the quota only the ceiling.
- **PSI is the signal, per group, not the box.** Pressure stall information (`cpu.pressure`, `memory.pressure`, `io.pressure` per cgroup) measures wall time lost waiting. Meta's oomd kills in userspace on PSI before the kernel OOM; its senpai agent drives reclaim up while measured pressure is below a threshold and backs off when it rises, with thresholds calibrated so paging never functionally hurts the workload (TMO: 20-32 percent memory saved fleet-wide). A `memory.high` clamp can stall the target; `memory.reclaim` is the gentler knob. OURS: BOX.tsv samples PSI per slice; `memory.high` per seat scope. GAP: the law judges box-wide PSI, which includes the caps' own throttling; judge per-slice PSI and busy (the coo's own finding).
- **A controller is PI-like, damped, rate-limited; never a bare P on a lagging signal.** Kubernetes' HPA is a delayed, rate-limited, saturating proportional controller; its tolerance band is a dead band, its stabilization windows are bolt-on hysteresis (scale up fast, scale down slow, ~300 s), and production controllers are wrapped in filtering, clamping and rate limits because the hard part is stability under delay and noise, not the PID terms. OURS: box_decide.sh moves each actuator proportionally to the PSI error from target 30 with a dead band of 5 and at most 3 cores a tick (steps 3-6, 26). GAP: no asymmetric windows (shed fast, restore slow), no per-slice signal, and `util_jobserver.sh set N` blocks while tokens are out (the actuator must be asynchronous or answer `pending=K`).
- **Interactive outranks batch.** Keep the human-facing slice's weight above build and maintenance slices; `nice` is only the fallback when the cpu controller is off. OURS: the grader slice (an SLO) above sessions above batch; maintenance admitted beside the lane (step 6). GAP: none measured.

## 2. Build load: one compile budget, caches that cannot lie

- **One box-wide jobserver.** GNU make 4.4's fifo-style jobserver (`--jobserver-style=fifo`, a named pipe with N tokens) can be shared by every build on the box; a fixed `-j` beside it overrides the tokens, so remove every hard-coded `-j`. Yocto measured 12 percent on two concurrent builds sharing one. OURS: `/home/resources/progress/jobserver.fifo` held by `s4e-jobserver`, every root's `make` through `util_jobserver.sh make` (steps 1-2). GAP: `set N` blocks (above); the holder runs from the cto's root, not the controller's scope.
- **A shared compile cache is two-level and keyed by content.** ccache: a group-writable shared dir read first, private writes so development objects never pollute the shared store; sccache: hierarchical caches with backfill, but absolute paths must match (build at the same path) and one server per local store or they race. Bazel's lesson for any shared cache: hermeticity is the foundation, keys are content hashes of every declared input (sources, compiler, flags), and one incorrect entry in a shared cache is served to everybody. Caching is not distribution: a lost cache or a low-level change still rebuilds everything locally. OURS: the FETCHED build cache keyed by the clean tree hash (`BUILDS.tsv`, ~60 entries), ccache per root. GAP: the cache evicts at 60 so a bisect over 130 commits misses almost every one (hq_prolog); key the index by tree hash and keep ccache shared across worktrees; a generated table edited by hand is the unhermetic input that poisons every consumer, hence regeneration not merge (step 19).
- **Distributed compilation** (icecream's central scheduler choosing the fastest free daemon, sccache-dist with auth and sandboxing; distcc's balancing is weak) is for many hosts. OURS: one box, not adopted.

## 3. Admission and queuing: slots by class, fair share, leases

- **A counting semaphore per resource class.** GNU `sem --id <class> -j N --fg -- cmd` is a named counting semaphore (default 1, a mutex); `sem --wait` drains; `--semaphore-timeout` bounds the wait; stale semaphores linger in `~/.parallel/semaphores/` after a kill. The CI products converge on the same primitive: GitLab `resource_group` (one job at a time per group across pipelines, `process_mode` oldest_first / newest_ready_first), Buildkite `concurrency_group` + `concurrency: 1` and paired gates for strict serialization, Jenkins Lockable Resources (`lock(resource)`, skip-if-locked, slot resources per agent). OURS: `util_run_slot.sh` (compile and run pools with per-seat caps), `util_batch.sh` (the batch slice), the identity lock. GAP: a slot has no class table and no timeout; step 22 (a background handle; a seat kills only its own) and the coo's `requests_median_min` SLO are the next two.
- **Fair share with decay, backfill, bounded preemption.** Slurm: priority = fair share (recent usage weighted more, decaying), a backfill scheduler starts any job that will not delay a higher-priority one, which only works when jobs declare accurate time limits; preemption only for genuinely urgent work, with a grace period and requeue. Kueue (Kubernetes batch): a job is created suspended and admitted only when its whole request fits the quota; StrictFIFO or BestEffortFIFO; cohorts share and reclaim guaranteed quotas by preemption. OURS: ranks on rows, the grader served first, one testing officer. GAP: no declared budget per row (step 34 gives the premise one; the sweep's 600 s per row is the symptom, step 38), no fair share across seats (one seat held 21 rows, another 4 ASSIGNED unstarted), no backfill: a long DONE-WHEN blocks the lane instead of running when idle.
- **Leases, not locks; fencing tokens; idempotent writers.** A queue's visibility timeout is a lease: hidden, not acknowledged; extended by heartbeat; loss of renewal is loss of the lease; each receive carries a token that every later write must present (LeaseQueue, SQS). Kleppmann's rule for distributed locks: a lock without a monotonically increasing fencing token checked by the protected resource is only an efficiency lock; a token narrows but does not close the window where two holders both believe they own it. Retries with exponential backoff and jitter; a dead-letter queue that never discards a payload unlogged; alert on DLQ depth. OURS: the claim file is the lease (step 8 keeps RUNNING or bare claims; step 28 holds the identity only for a write and refuses when the claim moved; the sweep's temporary claim carries a token). GAP: no heartbeat on a claim (a seat that dies holds it until a 48 h escalation, step 9); no DLQ: a row that refuses rc 2 should retire to a named list with its reason (step 9); `assign` of an unstartable row is a lease the holder cannot act on (step 32).

## 4. Concurrent development on one repo

- **Trunk-based, small batches, branches that live hours.** DORA: trunk-based branches last no more than a few hours; small batches are the main enabler; the 24 h and three-branch figures are secondary (VERIFY). OURS: every seat lands on main from a worktree; a row is one landing. GAP: a worktree that lives a day accumulates the rebase and generated-file conflicts the seats report (hq_runtime: "gc_allocating_table.inc conflicts on most rebases").
- **Test the combined state before it lands: the merge queue.** Bors (serial, bisects a failed batch), Zuul (speculative parallel gating, built because OpenStack approved faster than it could test), GitLab merge trains (speculative, restart on failure, a land-now button), GitHub's queue (speculative, no priorities), Trunk's batching (~90 percent cheaper per PR, a failed batch must be split). Uber's SubmitQueue (EuroSys 2019): always-green master at thousands of commits a day by probabilistic speculation over a binary tree of pending changes, a conflict analyzer, and a model of build success and time; the chance of a conflict rose from 5 to 40 percent as the number of concurrent, potentially conflicting changes grew; the 2025 follow-up cut CI resources 53 percent and p95 wait 37 percent. The unstated assumption every queue rests on: the checks it reruns actually catch the problem. Chromium's CQ separates a dry run (results as a comment) from a full run (lands on green) and a Mega-CQ (the wide set). OURS: a lander's proof is the dry run (its program both modes, the feature reps, the smokes), the coo's reading on origin is the full run, step 18's landing command is a serial queue of one (fetch, rebase, regenerate every generated table, rebuild, gate, push code first, `.github` last). GAP: nothing tests the combined state before the push, so a corpus witness reached origin before its SCRIP cure (hq_raku) and a rebase merged a generated table textually into a hybrid that did not compile (hq_icon); the cao asks for a request against a pushed branch graded off results.tsv, which is a dry run on the grader.
- **Conflicts are predicted from touched files, and the warning is early.** Co-editing the same file or method predicts conflicts with high recall (83 percent on method and dependent-method edits) and middling precision; a trained filter screens out safe merges well (its F1 on conflicting merges is 0.57-0.68), so prediction works as a filter, not a verdict. Microsoft's ConE detects concurrent edits across pull requests and warns while both are open. OURS: the claim notice by touched-path overlap (step 21: `TOUCHES:` on the baton, computed from the branch's diff; a non-overlap needs no reply). GAP: today the notice goes to every seat with a live row; 5486 of 10237 archived messages since 2026-10-20 are claim notices.
- **Generated files are regenerated, never merged.** Bazel's hermeticity and the shared-cache lesson apply to `gc_allocating_table.inc`, `rt_entry_table.inc`, `builtins.tsv` bids: a textual merge is an undeclared input. OURS: step 19 (a merge driver or the landing command regenerating every table). GAP: not built; bids are still picked by hand and race at every rebase (cfo, hq_runtime).

## 5. Test selection and reliability

- **The affected set from the diff and the dependency graph.** Nx `affected --base --head`, Turborepo `--affected`, Pants `--changed-since --changed-dependents=transitive`, Bazel `rdeps` over a declared graph: a setup job computes the set, downstream jobs read it; a shallow clone makes every package "changed" (safe but slow); undeclared inputs are the failure mode. Google's TAP evaluates whether a change touches a test's transitive dependency closure and skips repeated runs of frequently affected targets between milestones; Meta's predictive test selection (ML on CI history) halves infrastructure cost while catching over 95 percent of individual failures and 99.9 percent of faulty changes (VERIFY), explicitly probabilistic. OURS: step 13 (the proof sized by the change-impact set: a Makefile line owes the build gate, not eight smokes), step 24 (a blast-radius query names the eight programs for `s4e_test_request.sh`). GAP: both unbuilt; a lander today guesses the eight programs and runs every smoke, and the shared-code smoke set costs an hour per slice (hq_runtime).
- **Flaky tests are quarantined, still run, never gate; quarantine is temporary.** Detect by history (10+ runs, any failure); isolate from pass/fail; define when a quarantined test is fixed or removed. Sharding cuts latency, not cost; task-level caching skips a test whose package and dependencies did not change. OURS: `-dirty` is UNREAD, NO_ORACLE_ANSWER is excluded never debt, a smoke that cannot measure under load refuses rc 2. GAP: a refusing smoke under load costs the rerun (hq_icon, hq_zetas, cqo): take a slot and wait, or decline before starting, and rerun once when the load drops, saying so.
- **Culprit finding is machine work.** Chromium's Findit checks flakiness first (reruns on Swarming, no try job if flaky), bisects the regression range with try jobs, auto-reverts a compile culprit, and posts to the culprit's code review. OURS: the sweep closes a green row (step 8), retires a refusing one and escalates a stale ASSIGNED one (step 9); step 20 records the red set per origin hash. GAP: a red a lander finds on origin is re-attributed by hand by every next lander (hq_icon, hq_runtime: the same arm red for hours before anyone claimed it); the machine should file the row to the owning seat the moment the pristine control shows the same red.

## 6. Outcomes, toil, automation that proves itself

- **Toil is capped and automated away.** Google SRE: toil is manual, repetitive, automatable work with no enduring value that scales with the service; operations are capped at 50 percent of a team's time; the goal is systems that run and repair themselves, with people who still understand them when automation fails. An error budget (1 minus the SLO) decides when to push features and when to stop for reliability.
- **Measure the system by its outcomes.** DORA's four keys (deployment frequency, lead time for changes, change failure rate, time to restore; 2024 adds reliability against SLOs). CI health: median and p95, never averages; queue time separate from run time; headline cards filtered to the main branch; time in queue p50/p95/p99 per day (Trunk); Uber's green-mainline percentage (52 percent before SubmitQueue, 10 percent reverts on the worst days, VERIFY). OURS: the request SLO (30 min; every suite row in 24 h, step 5), FLEET.tsv per tick with bars (step 39: idle-with-work minutes, hand wakes, lock refusals, unanswered-wake minutes, assign-to-first-ledger minutes), the controller's LAP line (step 40). GAP: 39 and 40 are the open rows; today the fleet is judged by Lon noticing.
- **Auto-remediation with guardrails.** The maturity ladder runs from tribal knowledge through runbooks to systems that detect, diagnose and remediate with humans reviewing after; guardrails are cool-downs so a remediation does not re-fire, freeze windows, and human approval for destructive steps; roll out one alert at a time and build trust. OURS: the wake by hook (step 10: a Stop hook continues a seat that holds work; a cap of 12 continuations an hour is the cool-down), the sweep, the dispatcher's WAKE-UNANSWERED re-raise. GAP: a seat Lon resets has no turn to block, so one SendMessage from a session is still needed (the cio's Monitor on wake.pending); an orphan is told, not killed (step 22).

## 7. Many agents, one repo (the newest literature, thin and vendor-heavy)

Worktrees give filesystem isolation and nothing else: coordination is a separate layer (a task file or a queue an orchestrator manages); git operations on main are serialized; work is decomposed by boundary; an integration branch is used for a large parallel effort; a single reviewer integrates three or four agents well, more poorly (a heuristic). State outside files (databases, caches) needs its own isolation. OURS: one baton per row with GOAL, DONE-WHEN, NEXT, LEDGER; claims; a landing per row; the coo as the one grader; `S4E_HOME` per worktree. GAP: no whole-root worktree helper (step 36: four repos, the build fetched, under the 4 GB cap, sparse corpus), so four seats built one by hand today.

## 9. What we do not do, knowingly

Distributed compilation (one box); predictive (ML) test selection (the affected set from the graph is enough at our size); a hosted remote cache (the FETCHED cache is local); gang scheduling; a true merge queue with speculation (a serial landing command with a pre-push combined-state check is the right size); Redlock-style multi-node locks (one box, one filesystem, `noclobber` and a token suffice).
