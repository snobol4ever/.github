## 1. The rulings this layer obeys

- **No C function enters a box** (CEO-1576): a C road that would transfer control returns an address and the box jumps; `longjmp` into or across emitted frames is a transfer and is forbidden in new code.
- **Logic lives in emitted boxes, not in C** (CEO-985); a runtime entry is named on the node as data (CEO-1836); language identity stops at lower (CEO-1838): the runtime never decides by a name's spelling.
- **No interpreter**: one hash lookup for a run-time name is a lookup, never a dispatch loop.
- **A port transfer carries no value**; only procedure-exit wiring promotes rax:rdx to the returned DESCR (skill `scrip-architecture` § 5).
- **One error voice, spoken once, at the root** (CEO-625: `core_error_voice`, its equivalences in `util_render_error_voice.py`).
- **A compile-time refusal is the same voice: the words from the front end, the shape from the renderer** (CTO-639, the cto 2026-11-12 17:5x CST, on senior_01's rung-3 ask relayed by officer_02, row icn-rungs-red-rung16-seqexpr-gen-basic). A front end never prints an oracle's shape: ONE ERROR VOICE (Lon 2026-09-12, R-623/625) holds at compile time as at run time. It refuses through `core_error_voice_at(code, text, file, line, 0)` (core.c; the SNOBOL4 lexer already calls it), nothing on stdout, exit 1, and mode 4 writes no `.s`. The TEXT is the oracle's own words for that diagnostic and comes from the parser, the one place that knows which diagnostic fired (Arizona's `";": missing right parenthesis`, SPITBOL's error text); FILE is the source file holding the line (an include's when inside one). The SHAPE (prefix, basename, line order, wrap) is `util_render_error_voice.py`'s alone, and the renderer never invents, maps or drops a word. ## 2. The procedure call protocol as built (`src/runtime/rt/rt.c`)

- **The record** `rt_proc_t` (`src/runtime/rt/rt_proc_block.h`): name, function, `nformals` (formals only: they bind) against `nparams` (every name saved and nulled, SPITBOL ch. 8), `rest_kind`, `jmp_entry` (the regime: a jmp-entry blob against a call-regime body, recorded, never re-derived), `zstatic`, the generator and dynamic-scope bits. Offsets the asm reads are `_Static_assert`ed; new fields are appended last. Mode 4 registers each procedure at startup through `rt_proc_register_rec`.
- **A call** is open, frame, transfer, epilogue: the open families (`rt_proc_call_open`, `_det`, `_det0` to `_det4`, `_fnret`, `_p`, `_pn`; `rt_call_open_staged`, `_tail`, `_tail_lex`, `rt_call_open_by_name`, `rt_call_named_open`), the prologues (`rt_proc_call_prologue`, `_lex`), the landings (`rt_call_land_γ`, `rt_call_land_ω`) and the epilogues (`rt_proc_call_epilogue_γ` and `_ω`, their `_named_` and `_idx_` twins). RETURN and NRETURN are γ, FRETURN is ω; there is no fifth port.
- **Arguments** ride the staged-arguments medium `g_call_args` (`rt_call_args_need`, `rt_call_args_clear_from`).
- **Generator procedures** (`rt_genp_*`): each activation runs on its own pthread stack (`rt_genp_thread_entry`), delivering by `rt_genp_yield` and `rt_genp_deliver_γ`/`_ω`; destroy joins the parked thread.
- **A C function an Icon program calls through the oracle's descriptors** (a `loadfunc` library, the 48 translated window functions) is entered by THE ADAPTER, `src/runtime/icn_extfn.c` (skill `icon` reference.md section 9, step W5; the cto 2026-11-16 08:4x to 08:5x CST, on officer_01's measurement): `rt_extfn_invoke_h` (loadfunc's protocol, 0, -1 or an error code) and `rt_xwin_call_h` (iconx's own, A_Continue or A_Resume, variadic or fixed arity padded with null). The argument array is sized by the call on the adapter's stack, with one word in front of slot 0 holding the address of the collecting record (`icnx_coll_t`, `push` first), or 0; `interp(G_Csusp, r_args)` reads that word, pushes slot 0 and answers A_Resume, so no global holds the hook. A call that suspended is a generator over what it collected, served through the call-value box's resume slot (`rt_call_value_gen_h`, `rt_call_value_resume_h`). THE HELD VALUES live in the ct arena, copied off the collected heap (string bytes, real, large-integer, external and file blocks), so nothing is rooted between resumes; they are released at the last value (`rt_extfn_resume`) and, when the generator is abandoned, at the box's next entry, where `rt_proc_drop_frame_h` destroys it: the residue is one generator a box, bounded only while its held array is. A COLLECTED GENERATOR IS A MEMBER OF THE GENERATOR LIST, NEVER A WORD SNIFFED (the cto 2026-11-16 09:2x CST, on the regression of 746fa602a, which read a magic number through the slot's word and died with signal 11 on rosetta-icon repeat.icn and twelve more): a call-value slot holds null; a generator procedure's record (`rt_genp_s`); an operator generator of the gen road (`ICN_OPGEN_t`, read by its magic only on the resume road that wrote it); a collected generator; or, on the spine road, the token the prep answered, banked into the cell (`(gen ? 0 : 2) | blk << 8 | flags << 16`, or `3 | blk << 8 | ftc << 32`), which with no argument is the first argument cell itself and can be 16-aligned. So nothing reads through the slot's word before it is proved: `rt_genp_s` carries `held` and `release` (per-instance fields, appended last), `rt_genp_hold` links a member owning a held pointer, `rt_genp_held` answers it only for a member whose release matches, and `rt_genp_destroy` calls the release; the drop and the resume find a collected generator by membership, as they find a generator procedure (SCRIP 100793232). No tag either: a mode 4 string sits at an odd address. TWO MEASURED CAUSES a release must not reopen (SCRIP 4ca395572, a loop of a loaded function suspending 200 strings and abandoned after one value, SCRIP_HEAP_KB=256: maxrss 13984 KB at 100 calls, 188004 KB at 10000; 12320 and 12276 KB after 746fa602a): (1) a drop of the slot that only clears it leaks the collected generator; (2) `ct_grow` extends a block in place at the arena's bump pointer and never releases a block it copies, so a run-time array grown and dropped once per call climbs every size class in fresh space and is dropped into the largest bin, which the next call, starting small, never reuses (live arena bytes equal, mapped bytes 16.8 MB to 54.5 MB). THE RULE: a run-time array in the ct arena that is grown and released per call grows by a fresh `ct_alloc` of the doubled size, a copy and a `ct_drop` of the old block, never by `ct_grow`. The proof is the abandon arm of `/home/resources/progress/icon-xwin-w5/gate_w5_adapter.sh` (100 and 10000 calls of 200 values, and 3 and 30 calls of 100000 values, the size of a Pixel over a window, each within 2048 KB).
- **Mode 3's entry** is the thunk `rt_outer_call` (and `rt_outer_call_root`) in `src/driver/scrip.c`: it saves the caller's r12, seeds r12 from `RT_DCAP_TOP`, reserves headroom, and enters the graph with the landings pushed.
- **A declining leaf** returns `RTX_NOT_HANDLED` (0xFF in al, never a tag's low byte) with its arguments as received; the box then calls the C twin itself under the C convention (the verdict road; first built for the arith leaves).

## 3. DESIGN: the one builtin table (CEO-2016; `/home/harness/designs/builtin_table/STEPS.tsv`)

## 4. DESIGN: the one error protocol (CEO-2020; `/home/harness/designs/exceptions/STEPS.tsv`)

The Prolog road, made the law for every language. **P1** one ball record in the context (`{class, code, text, value, src_node, stno, exit_code}`, a GC root; class FATAL, HANDLED or CONVERTED). **P2** a raise records the ball and RETURNS `FAILDESCR`; every C caller returns the verdict; no `setjmp`, `longjmp`, snapshot or `exit`. **P3** a box that can receive a ball tests the class at the head of its ω road and jumps to its enclosing catch gate's ball entry, wired at compile time. **P4** a catch construct is BOUND + body + UNMARK + a GATE whose ball entry restores rsp to the gate's planned depth, unwinds the islands to the BOUND's marks and runs the handler. **P5** the chain root's ball exit is the one voice site and exits with the oracle's code. **P6** SNOBOL4's SETEXIT and `:(CONTINUE)` are if-type gates through stored slots. **P7** an exhausted stack or a refused heap request is a raise where the language makes exhaustion an error term (Prolog's `resource_error`), and stays fatal where it is fatal (SNOBOL4's ERROR 246).
