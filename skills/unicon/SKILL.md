## 1. The rulings

- **R1 the markers and the Icon fallback**: a file is a UNICON PROGRAM when its code (outside comments and strings) carries a declaration-level `class`, `package` or `import` header, or the words `thread`, `critical` or `abstract`; in a Unicon program the eight words (`class method initially import package thread critical abstract`) are reserved everywhere as unicon reserves them; a markerless file is plain Icon and its plain identifiers stay identifiers. `icn_source_is_unicon` (icon_lex.c) is the one reader; the parser sets the lexer flag `lx.unicon` from it.
- **R2 the oracle**: `unicon_bin()` in `harness/scripts/lib_oracle_flags.sh` (`$UNICON_ORACLE_BIN`, `/home/resources/unicon/bin/unicon`, never a bare name; built by `build_unicon_oracle.sh`) answers every program that carries a marker and the UniTests package whole. A markerless Icon program's oracle stays Arizona `icont`/`iconx`; the IPL, Arizona, Jcon and IcnRungs refs do not move. One oracle per package. Compile `unicon -s f.icn -o f.uni` (an output named `*.u` is taken for ucode and fails), run `./f.uni`, never `unicon -E`. A ref is run twice and identical.
- **CTO-473, a markerless program graded by the unicon oracle is Unicon because the package says so** (option a): `scrip --dialect=unicon` (scrip.c, `icon_compile_as` in icon_driver.c) forces the Unicon state exactly as a marker does and stamps the root of the parse tree (`TT_PROGRAM` `v.ival`); nothing past the driver sees a flag (CEO-1838/1840). `corpus/packages/icon/unicon_tests/CONTRACT.tsv` carries `unmarked_compile_args --dialect=unicon`; `util_build_package_suite.py` writes it into `ALL.csv` compile_args for the entries `icn_marked` finds unmarked (138 of 163); `--dialect=unicon` is in `COMPILE_ARGS_ADMITTED` (corpus_suite_harness.py). The vendored sources stay verbatim. Gate `test_gate_icn_a_markerless_unicon_program_prints_unicons_name_form_when_the_driver_is_told_so_in_both_modes.sh`.
- **The Unicon state is read in lower**, not in the runtime (no new global): `cx->prog->v.ival` in lower_icon.c selects the Unicon form of a builtin or an iteration. Today: `name()` of a variable reference becomes `ICN$UNAME` (`table_1["abc"]`, `list_1[3]`, `record complex_1.r`, a section `s[2:4]`; the list-element and field traps carry their container in the `sv` word, rtx_icnsub.s and its C twin), `key(list)` becomes the IR_ITERATE form `ukey` (`rt_list_bang_ukey_at`, indices 1 to *L; plain Icon still raises 124), `system(s)` becomes `ICN$USYSTEM` (the exit status; Arizona returns the raw wait status, 768 for exit 3). - **R3 the class model is Unicon's own translation, done by lower**: the parser builds a `TT_CLASS` node as written (name, superclasses, fields, methods as procedure subtrees, `initially`, `abstract method`); `lower_icon_class.c` translates it as unicon does (the two records, the operations record, the constructor, dispatch, inheritance, initially chaining). ## 2. The pattern type: `s ?? p` on the scan road (ARCH-UNICON 2.1, 2.2 and CTO-476, now in this page)

- `s ?? p` is an Icon scan (`lower_pmatch` in lower_icon.c) whose body is the SNOBOL4 match boxes on the scan registers r13 r14 r15 (Σ δ Δ): `|( \1( i := nx to *&subject+1 & &pos := i & PATTERN-BOXES & en := &pos & nx := (en > i | i+1) & &subject[i:en] ) )`. There is NO MATCH_BEGIN/END. unicon's rule, measured: matches are non-overlapping, the next attempt starts at the previous END, an empty match repeats forever (a test needs limits), `Pos(n)` is cursor n-1 and n <= 0 counts from the end, Tab/Rtab can move backwards, a failed attempt commits no `->`.
- Inline boxes for Len Pos Rpos Tab Rtab Any NotAny Span Break Breakx Rem Arb with constant or computed operands; every other element is a VALUE built by the `SNO$PB*` constructors, assigned to a hidden global `$pmgN` and matched by IR_MATCH_DEFER. A pattern with such an element is a COMMIT pattern: `lower_pm_boxes` brackets it with `IR_MATCH_CASMARK`: ival 0 pushes the SCAN MARKER on the r12 island, ival 2 syncs Σ/Σlen, ival 1 pops; the FLUSH (IR_MATCH_FENCE0 with the literal 3) runs the conditional assignments recorded since the marker.
- **The scan marker (CTO-476)**: a 24-byte island entry whose first word is null (the pump and the FLUSH walk skip it as before), word 1 = the activation base (rbp), word 2 = a pointer to the procedure's name, both compile-time facts (the emitter hands the name through the node's sval; CASMARK reuses `ival` for the variant, so a name is told apart by magnitude: `(uintptr_t) ival > 0xFFFF`). Readers: `rt_dcap_pump` walks its entries down from `c->cur` to the first null varname, resolves a capture target with `rt_icn_local_cell_in` (locals by `rt_proc_loff`, parameters by the frame map's argument offset read BY NAME with `rt_icn_proc_args_off` in gc_heap.c, never a frame walk) and skips the asm fast run (its name cache answers from the NV table); `ICN$UPVAR` (builtins row 1258) reads the island top mirror (`RT_DCAP_TOP`) and walks down to the nearest marker. A deferred call inside a recursive procedure therefore sees the activation whose attempt is in flight (witness `uni_pm_defer_rec`).
- **Lowering**: `=>` is a conditional capture whose target name carries a leading \005 (committed at once) followed by the deferred call of ONE hidden procedure `$imm` (`return ICN$IMM() & ""`, builtins row 1268, `rt_icn_imm_assign` in pattern_match.c): it runs the pump over just the top island entry with the tag stripped, so a local, a parameter or a file target is written at that moment, and the final pump skips \005 entries. NOTHING CUTS (the old form, capture plus FLUSH, was a FENCE0 and cut: `(A => a | B => b) || Fail()` and `Arb() => out || Fail()` never retried; failss balss sawss). `.>` is the same with the name \005\003x (the pump assigns cursor+1, 1-based, as unicon). A backquoted expression becomes a hidden procedure `$dfN` (`icn_expand_deferred`, lower_icon_class.c) whose free variables read through `ICN$UPVAR`, a call being a success test (the call and the empty string: unicon does not match its value), a variable matched as its value; a DOUBLE backquote ``e`` (TK_PUNEVAL2, a TT_DEFER with slen -2) is matched by VALUE (a string function call); a backquote as the sole argument of Len Pos Rpos Tab Rtab Any NotAny Span Nspan Break Breakx defers the whole call (the hidden procedure returns the built pattern, so `Len(`n`)` reads n at match time); `&&` is `||`. `Pos(n)` and `Tab(n)` with a variable n choose the forward or the from-the-end form at run time (n-1, n<=0 from the end). In a Unicon program `match(x)` with one argument tests `type(x) == "pattern"` and, for a pattern, matches it anchored at &pos (the boxes in a LIMIT, &pos restored, the end position returned), so `=p` and `=Pos(-3)` work. A capture target is a NAME resolved at match time (R-B5), a file target writes the text.
- **Cured 2026-11-04 (hq_zetas, SCRIP 44e942a61)**: a DEFER inside an `every` loop no longer ends the loop (the flush FENCE0 cut now bills its release in plan_facts.cpp); ladder__rung46_alternation reads PASS. Still declined by the planner, not a regression: a graph holding a call to a generator, an unknown callee or a create/activate keeps the old answer (a create body holding every plus a defer; every j := gen() do { s ?? p } leaks 112 bytes a pass). The flush FENCE0 stays a cut at the END of a commit pattern; only the immediate captures left it.

## 3. Threads (rung 48: the deterministic subset is built; the scheduler is DESIGNED in section 7 D12, step 12)

Built (SCRIP c9bea75ee lineage, STATE-GLOBAL `g_runtime.misc.mutex_serial`, CTO-501): the parser makes `thread E` the call `spawn(create E)` (unicon's own translation) and `critical M: E` the internal call `ICN$CRIT(M, E)`; `th_form` in lower_icon.c rewrites `spawn(create E)` to `(t := create E) & every @t & t` (the thread runs to completion at creation) and `ICN$CRIT` to `mv := M & lock(mv) & ((rv := E \ 1) | (unlock(mv) & &fail)) & unlock(mv) & rv` (the region is limited to its first result, as unicon's `1(crit_expr, unlock(mtx))`). In a Unicon program `wait lock unlock trylock` of one argument are `ICN$UIDENT` (they return the argument) and `mutex()` is `ICN$UMUTEX` (a fresh integer: unicon's `type(mutex())` is integer), builtins rows 1276 and 1277. `icn_callee_is_a_value` and `is_resumable` know these names and every `ICN$` name as non-generators; without that a failing continuation after `lock(m)` re-entered the call forever (the 3.9-core spin). Witnesses: ladder__rung48_thread_wait, _critical, _thread_forms. NOT done: the thread's results are consumed at creation (unicon keeps them for `@t`), `type(t)` is co-expression (unicon: thread), `&features` lacks `concurrent threads` (thread/hellothr, mutexfun and sum test it), and every blocking form (channels, `@>>`, `<<@`, `<@`, condition variables, `send`/`receive`, `pull`, a thread that waits for its creator, `delay`-ordered output) needs a real scheduler: a thread is a co-expression a run queue switches at its blocking points. That scheduler is a SCRIP DESIGN question and goes to the cto (CTO-503) before it is built.
