A program that never opens a crypto mode loads nothing, so no instruction count moves.
- **THE OPEN IS CHOSEN AT LOWER.** In a Unicon program `open` lowers to a leaf row `ICN$UOPEN` that claims the crypto modes (`e` `er` `eh` `re` `we`, and `ne` `nue` `naue` once C5 and C6 land) and otherwise is plain `open`, the hook placed where the window open's is (`rt_icn_window_open`, src/runtime/lib/bn_41_sh.c line 2145). A plain Icon program's open does not move. The handle is a file value that carries the crypto state; `read`, `reads`, `write`, `close`, `h[name]`, `key(h)` and `Attrib` (row `ICN$UATTRIB` exists) dispatch on that file kind, never on a language flag. Who owns the state's memory and when an unreached handle is freed is read on the file value's own road first (C1 says it in its LEDGER and asks the cto before it adds a field or a collector case).
- **TEXTS AND NUMBERS ARE UNICON'S**: every `&errortext`, error number (1302, 1316, 1326 and the rest of unicon's `src/runtime/data.r` list) and peek name is read from the oracle's own answers, run twice. Algorithm and cipher names pass through to OpenSSL; the defaults are `alg=sha256` and `cipher=aes-256-gcm`.
- **THE FEATURE AND ITS SYMBOL LAND TOGETHER**: the stage that makes the first crypto program pass adds `secure sockets layer encryption` to the Unicon features list and `_SSL` to the predefined symbols of `icon_lex.c` in the same landing; `general/prepro` checks the two agree.
- **THE STAGES, MEASURED from the 27 programs' modes and `op=` values (each one row, one landing, the programs named its criterion, the order the proof)**: C0 the object, its interface table, its load and `ICN$UOPEN` with no operation yet; C1 hash, `eh` and `re` with `op=hash` (hash, sha512, badalg, midattrib, filehash); C2 symmetric ciphers, `e` and `er` key material, AEAD with automatic and explicit IV, `re` and `we` transforms (encrypt, iv, freshiv, tamper, opswitch, badkey, filekey, filekeyattr, filetamper); C3 HMAC and the peek (hmac, peek); C4 sign and verify over PEM keys and certificates (sign, badverify, badrole); C5 TLS, `ne` over SCRIP's sockets (posix tcp, udp, uxsocket, sockpeek and mcast read PASS on 8c757a3bc1), with tlsplain's linked `tlsutil.icn` given to the harness road (tlsplain, tlsauth, tlscipher, tlshandle, tlspeek, tlsproto, tlsverify); C6 DTLS, `nue` (dtlsecho). The certificates and keys the programs read are the package's `crypto/data`.
