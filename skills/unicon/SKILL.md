## 1. The rulings

- **R1 the markers and the Icon fallback**: a file is a UNICON PROGRAM when its code (outside comments and strings) carries a declaration-level `class`, `package` or `import` header, or the words `thread`, `critical` or `abstract`; in a Unicon program the eight words (`class method initially import package thread critical abstract`) are reserved everywhere as unicon reserves them; a markerless file is plain Icon and its plain identifiers stay identifiers. `icn_source_is_unicon` (icon_lex.c) is the one reader; the parser sets the lexer flag `lx.unicon` from it.
- **R2 the oracle**: `unicon_bin()` in `harness/scripts/lib_oracle_flags.sh` (`$UNICON_ORACLE_BIN`, `/home/resources/unicon/bin/unicon`, never a bare name; built by `build_unicon_oracle.sh`) answers every program that carries a marker and the UniTests package whole. A markerless Icon program's oracle stays Arizona `icont`/`iconx`; the IPL, Arizona, Jcon and IcnRungs refs do not move. One oracle per package. Compile `unicon -s f.icn -o f.uni` (an output named `*.u` is taken for ucode and fails), run `./f.uni`, never `unicon -E`. A ref is run twice and identical.
- **CTO-473, a markerless program graded by the unicon oracle is Unicon because the package says so** (option a): `scrip --dialect=unicon` (scrip.c, `icon_compile_as` in icon_driver.c) forces the Unicon state exactly as a marker does and stamps the root of the parse tree (`TT_PROGRAM` `v.ival`); nothing past the driver sees a flag (CEO-1838/1840). `corpus/packages/icon/unicon_tests/CONTRACT.tsv` carries `unmarked_compile_args --dialect=unicon`; `util_build_package_suite.py` writes it into `ALL.csv` compile_args for the entries `icn_marked` finds unmarked (138 of 163); `--dialect=unicon` is in `COMPILE_ARGS_ADMITTED` (corpus_suite_harness.py). The vendored sources stay verbatim. Gate `test_gate_icn_a_markerless_unicon_program_prints_unicons_name_form_when_the_driver_is_told_so_in_both_modes.sh`.
- **The Unicon state is read in lower**, not in the runtime (no new global): `cx->prog->v.ival` in lower_icon.c selects the Unicon form of a builtin or an iteration. Today: `name()` of a variable reference becomes `ICN$UNAME` (`table_1["abc"]`, `list_1[3]`, `record complex_1.r`, a section `s[2:4]`; the list-element and field traps carry their container in the `sv` word, rtx_icnsub.s and its C twin), `key(list)` becomes the IR_ITERATE form `ukey` (`rt_list_bang_ukey_at`, indices 1 to *L; plain Icon still raises 124), `system(s)` becomes `ICN$USYSTEM` (the exit status; Arizona returns the raw wait status, 768 for exit 3). Sixteen-digit real printing is the ONE runtime word the cto ruled (2026-10-31) and Lon granted (CTO-501, 2026-11-04 15:3x CST, Lon: a global that holds state and is not a value stack is granted; named STATE-GLOBAL in the commit and the baton): `g_runtime.misc.real_digits` (g_runtime_misc.h, zero for Icon), set by the call `ICN$UDIGITS(16)` (builtins row 1269, `bt_ICNx24UDIGITS` in string_ops.c) that lower_proc_body places at the start of `main` when the program's Unicon state is on; `icon_real_str` then prints `%.16g` and appends `.0` when the text has neither a point nor an exponent (unicon: 0.3333333333333333, 1e+16, 1000000000000000.0), which turns checkc checkx ck checkfpc checkfpx overflow tprintf ilib and uni_class_hello.
- **R3 the class model is Unicon's own translation, done by lower**: the parser builds a `TT_CLASS` node as written (name, superclasses, fields, methods as procedure subtrees, `initially`, `abstract method`); `lower_icon_class.c` translates it as unicon does (the two records, the operations record, the constructor, dispatch, inheritance, initially chaining). No method table searched by name at run time, no new DESCR kind. **The state record's prefix `__s` and `__m` is hidden by a mark lower sets, never by its names** (CTO-643, the cto 2026-11-12 21:1x CST, on officer_02's ask, row unicon-uni-red-lib-attr): unicon hides the two prefix fields from `*x` and from integer subscripts (rvalue, lvalue, negatives), while string subscripts and `!x` still see them. icont decides this on the compile side, in its linker (lcode.c marks a record type with a field `__m` as ndynam -3, and omisc.r and oref.r read only the mark), so in SCRIP lower decides it and the runtime reads the mark (CEO-1838): `DatType` carries a type-level `nhidden` set by `dat_set_hidden(name, 2)` when the Icon lowerer registers the `<C>__state` record that `lower_icon_class.c` built with its lead fields; mode 4 replays it at startup by an emitted call, as it replays `dat_set_field_rw` and the sigils; `dat_alloc_fill` copies it into `DATBLK_t.nhidden`, an int in the 4-byte hole after `nfields` (offset 12, sizeof stays 40, the GC row unchanged); `rt_rec_hidden` reads that word, and the size and integer-subscript roads subtract it. A user record whose own first fields are spelled `__s`, `__m` stays unhidden; that is its witness. **`variable("self", , 1)` inside an initially is the constructor's self, read and written as `self.__s`** (CTO-645, the cto 2026-11-12 21:3x CST, row unitests-red-general-utf8 cause (b), on officer_03's rung-5 escalation): unicon's translation (idol.icn) is `self := C__state(...); self.__s := self; self.__m.initially(self) | fail; return self`, so the initially's level-1 caller is its constructor, and uni_lib's utf8.icn (lines 5381, 5399, 6793 and 6852, its author's own note) replaces the constructor's self that way; SCRIP's constructor (lower_icon_class.c) is the same text. So in the body of a class's initially method, `variable(S, C, L)` with S the string literal `"self"`, C omitted and L the integer literal 1 lowers to the field `self.__s`, as an lvalue and as an rvalue, and the constructor that calls that initially returns `self.__s` instead of `self` (unchanged when nothing wrote it); every other class's constructor stays as it is. MEASURED: in corpus only those four calls give `variable` a level; the upstream rest are the udb debugger. NOT RULED: a level anywhere else (an ordinary method or procedure, the witness `escalations/unitests-red-general-utf8.variable-level-probe.icn`) stays on the leaf, and frame reflection of a caller's locals by name is a design of its own, owed only when a graded program needs it; an initially reached by an explicit super call writes its caller's local in unicon, which this does not model. Witness: `escalations/unitests-red-general-utf8.initially-self-witness.icn` with its `.oracle` (unicon: `object A_1(1)`, `object B_1(1)`, `42`; SCRIP: error 111).
- **R4 packages, import and link**: `package p` mangles every global of its file to `p__name` at lower (so its `main` is `p__main`: a package file is not a program); `p::name` names it; `import p` makes p's names visible and links the package's files, found by `icn_resolve_imports` as `p.icn` or as the `.icn` files of a directory that declare `package p`, searched beside the program and then in `IPATH`/`ICONPATH`; `::name` names the unmangled global.
- **R5 the builtin families, ranked**: class reflection; the list and string extensions and `&now`, `&errno`, `&pick`; the pattern type; then posix, thread, crypto and loading as their own rows. **R6 the syntax beyond the words**: class, package and import declarations, `obj.m(args)`, `::name`, `??` and the pattern operators in `icon_parse.c` and `icon_lex.c` under the marker flag. **R7 the suite**: UniTests to 100 of its graded denominator.

## 3. Threads (rung 48: the deterministic subset is built; the scheduler is DESIGNED in section 7 D12, step 12)

Built (SCRIP c9bea75ee lineage, STATE-GLOBAL `g_runtime.misc.mutex_serial`, CTO-501): the parser makes `thread E` the call `spawn(create E)` (unicon's own translation) and `critical M: E` the internal call `ICN$CRIT(M, E)`; `th_form` in lower_icon.c rewrites `spawn(create E)` to `(t := create E) & every @t & t` (the thread runs to completion at creation) and `ICN$CRIT` to `mv := M & lock(mv) & ((rv := E \ 1) | (unlock(mv) & &fail)) & unlock(mv) & rv` (the region is limited to its first result, as unicon's `1(crit_expr, unlock(mtx))`). The exits of a region are rewritten earlier, in the PARSER (`icn_crit_walk` in icon_parse.c: unicon's `InsertLocks`, `/home/resources/unicon/uni/unicon/unigram.icn`, is the oracle for every form): each unlock is the fallible form `1(E, unlock...) | (unlock... & fail)\1` (`icn_unlock_after`, unicon's `mkUnlockFallibleExpr`, so an exhausted or failing expression releases once); a `suspend` unlocks every enclosing mutex before it yields and re-locks them in its `do` clause and after the statement; a `break` or `next` unlocks only the mutexes inside the loops it leaves (`IcnCrit.loops`, `icn_leaves`, `until` counts as a loop); a `return E` carries the fallible form inside its operand (a failing operand fails the procedure at once, so an alternation outside the `return` never runs); a literal or identifier body takes no lock (`icn_crit_plain`, unicon's `mkLockUnlock`). Witness: UniTests thread/critter (its 30 stderr lines were these four slips, cured 2026-11-13). In a Unicon program `wait lock unlock trylock` of one argument are `ICN$UIDENT` (they return the argument) and `mutex()` is `ICN$UMUTEX` (a fresh integer: unicon's `type(mutex())` is integer), builtins rows 1276 and 1277. `icn_callee_is_a_value` and `is_resumable` know these names and every `ICN$` name as non-generators; without that a failing continuation after `lock(m)` re-entered the call forever (the 3.9-core spin). Witnesses: ladder__rung48_thread_wait, _critical, _thread_forms. NOT done: the thread's results are consumed at creation (unicon keeps them for `@t`), `type(t)` is co-expression (unicon: thread), `&features` lacks `concurrent threads` (thread/hellothr, mutexfun and sum test it), and every blocking form (channels, `@>>`, `<<@`, `<@`, condition variables, `send`/`receive`, `pull`, a thread that waits for its creator, `delay`-ordered output) needs a real scheduler: a thread is a co-expression a run queue switches at its blocking points. That scheduler is a SCRIP DESIGN question and goes to the cto (CTO-503) before it is built.

- **Unicon's sources have no semicolons** (newline insertion) and SCRIP Icon requires them (CEO-495), so the package carries text with its semicolons already in it, committed once. NO PROGRAM ADDS SEMICOLONS (Lon 2026-11-10: "Ensure you NEVER do an on-the-fly semi-colon conversion by deleting any program that adds those semi-colons." and "We want all vendored Icon programs in the corpus repo with semi-colons already ready for prime time. no conversion needed by anyone that way."; CIO-99, CIO-100): a new or changed Icon or Unicon file gets its `;` by a seat's own edit, proved by the oracle giving the same answer for the edited text and by SCRIP parsing it; nobody writes a tool for it again. THE RULE A HAND EDIT FOLLOWS is Unicon's own, `/home/resources/unicon/uni/unicon/unilex.icn`: a `;` goes at a line end when the last token is an ENDER (a name, a literal, a backquote, `)` `]` `}` `$)` `$>`, `break` `fail` `next` `return` `suspend`) and the first token of the next line is a BEGINNER (a name, a literal, `(` `[` `{`, a reserved word that starts an expression, and EVERY operator that has a unary form or is `||` `|||` `++` `--` `**` `==` `~=` and kin; `%` `<` `>` `:=` and kin are not); never before `end` (that is Unicon's own translator; SCRIP's strict parser ALSO wants a `;` after the last statement of a procedure body before `end`, measured 2026-11-13, so a hand edit adds it there and then checks `scrip --dump-ast`), never after a `procedure`, `method` or `record` header. A line followed by `@B`, `/x := 0`, `*base = 63 | stop(...)` or `(a[i] := 1) | ...` parses SILENTLY as a binary operator when its `;` is missing (coexpr co, general collate mega mindfa pdco, pattern sawss, thread critter were such slips, never runtime reds); check every added `;` sits after a token end (`-0.5` once became `-0.;5`).
