## 1. The populations

- **The masters**: `corpus/tests/<lang>/` holds one flat container per language: `ALL.<ext>` (every entry, a CONTAINER, never a program), `ALL.ref` (each entry's ref, cut from the oracle; binary to git), `ALL.csv` (the index: entry, feature columns, declared sizes, `compile_args`, `oracle_args`), `PARTITION.tsv`, and `LADDER.tsv` for the construct ladder, beside the container (CIO-55). The one extraction authority is `corpus_suite_harness.py extract MASTER REF NAME OUT`.
- **corpus may hold any licence's test programs, GPL included** (Lon 2026-11-12 19:4x CST, verbatim: "So $/corpus is okay to contain GPL. correct? None of corpus will be contained in a product. Just SCRIP is the PRODUCT."): corpus is test data and never ships, and SCRIP alone is the product. A vendored program is copied into its package with its licence file beside it, so the class-A-only copying of CIO-92 does not bind corpus. A semicolon-ready Icon or Unicon copy lives in its package (skill unicon). A licence question about a corpus copy is answered here, never escalated.
- **The packages**: `corpus/packages/<lang>/<pkg>/` (vendored suites with their own tables, `EXCLUDED.tsv` with a reason per row, runners `harness/scripts/test_<lang>_<pkg>_suite.sh` taking `S4E_CHUNK=entry:<name>`).
- **The gates' test cases** (gates-zero; Lon 2026-11-12 16:0x CST, verbatim: "We want of course to keep test cases."): every program the retired `test_gate_*.sh` scripts carried is a file of `corpus/packages/<lang>/gate_cases_<lang>/` (`<gate>__<file>`; one folder name a language, so each records under its own key), its ref cut from the oracle by `util_build_package_suite.py --twice`, graded by the cycle as `gate_cases_<lang>`; rebus's 13 are kept as files, ungraded, rebus having no independent oracle. **What the builder cannot cut** (the coo 2026-11-12 22:1x, on the cio's `util_cycle_inventory.py` reading of 463 owed): a case whose oracle prints nothing (its retired gate read an asm grep, a dump or an exit code) stays a file and is declared `FAKEABLE_NO_OBSERVABLE`, shown in Excl, never an exit-code entry, since a silent engine would pass it; a case the oracle answers differently twice or dies on is `NO_ORACLE_ANSWER`; a Pascal case fpc refuses under `-Miso` gets its dialect cell first (skill `pascal` 1), and only a refusal in its own mode is `NO_ORACLE_ANSWER`; a case that cannot open its include carries the include as its file fence (`--file`), never an exclusion. **The fixture comes first** (the coo 2026-11-12 22:27 CST, on the cio's measurement that 121 of the 321 empty cases read input or open a file in their source, or are Prolog with no `initialization` goal): a case run without the stdin, file or goal its retired gate gave it first gets that fixture (the stdin or file as its fence, the Prolog goal the gate ran) and is re-cut from the oracle; only an empty answer that remains is `FAKEABLE_NO_OBSERVABLE`. The 200 empty cases whose source reads nothing and names its goal were declared (corpus 789f2553d, `util_declare_owed.py --empty-class FAKEABLE_NO_OBSERVABLE --names`); the rest are the nine `gate-cases-*` rows, tier-sonnet.
- **A demo that is a container** (`corpus/demos/<lang>/<name>/ALL.csv`, the files form) records its readings and writes its row like a package, keyed by its folder (`progress_suite_for`; `util_score_row.py`'s `FROM_PROGRESS_PACKAGES`): TeX is `corpus/demos/pascal/tex`, 1/1 (Lon 18:0x: "I would just love to see IcnPacks, TeX, and RakDemo with a Run stamp that it ran from the oracle.").
- **A language's demos folder is one container** (the grader 2026-11-13, row `cycle-greased-lightning-grader`; Lon: "go ahead, convert the demos and delete the old"): `corpus/demos/<lang>/` for snobol4, snocone, icon, prolog, pascal, raku and scriptix is the files form (`ALL.csv` with `path`, `ALL.args`, `PARTITION.tsv`, each answer `NAME.out`, its stdin `NAME.in`), recorded as `<lang>-demos`, a `pkg` row of `SUITE_RUNNERS.tsv`; a folder with its own `ALL.csv` (pascal/tex) is its own row, and `CONTAINERS.tsv` blocks stay out. ## 2. Grading one program (what a lander does)

```bash
python3 ../harness/scripts/corpus_suite_harness.py run ../corpus/tests/<lang>/ALL.<ext> ../corpus/tests/<lang>/ALL.ref --lang <lang> --modes m3,m4 --partition entry:<name>
S4E_CHUNK=entry:<name> bash ../harness/scripts/test_<lang>_<pkg>_suite.sh
bash ../harness/scripts/test_feature_reps.sh <lang> <feature>
bash ../harness/scripts/test_smoke_<lang>.sh
bash ../harness/scripts/s4e_test_request.sh <suite-key> <entry>...        # at most eight; the coo grades
```

`--modes m3,m4` is mandatory; the two modes may diverge and each is graded against the oracle. A program runs at its DECLARED sizes (the entry's heap and stack, CEO-1353/1281); the declared size is a hard cap and out of stack is a bigger declared `-s`, never data moved.

## 4. The rules

- **The compare cell** (`ALL.csv`'s `compare` column; `corpus_suite_harness.py` `validate_compare_cell`): empty is byte for byte; a `+`-joined set of `ignore-all-space` (each line without white space, as XSB's `diff -w`), `fresh-vars` (each line's fresh variables renamed `_V1`, `_V2` in order of first appearance, ISO 7.10.5), `error-context` (an `error(E, C)` graded with C masked, E exact), `verdict-line` (a generated case's one verdict line), `tap` (a TAP stream's plan and test skeleton) and `sorted-lines`. **`sorted-lines`** (the coo 2026-11-12 22:47 CST, on the cfo's measurement and the cio's proposal: a completed XSB table answers newest first only up to 8 siblings, in hash-bucket order from 9, and for 10 atoms in a different order on two runs, an accident of XSB's implementation, CEO-1934): both streams' non-empty lines are compared sorted, duplicates kept, as XSB's own `gentest.sh` compares. It is no exclusion, since every answer is still checked. It is set by hand only on an entry whose ONE measured divergence is a completed table's answer order, the measurement named in the entry's row: `xsb_examples` `shortest_path` reads `sorted-lines` and `first` reads `sorted-lines+fresh-vars` (harness and corpus of the landing that cut it; `corpus_suite_harness.py --probe-sorted-compare`).
- **A library's red is its driver's red** (officer_07 2026-11-13, row ipl-red-procs-abkform, after two rungs read it as a ghost row): in an Icon package `util_score_row.py`'s `board_key` files the readings of `NAME_driver` under `NAME`, so `SUITE_ROW_RED procs/abkform` is the newest reading of `procs/abkform_driver`; reproduce the driver (`--partition entry:NAME_driver`) and read the store's `partition=` note before calling a red a ghost.
- **A ref reads as the program's output reads**: the harness decodes a program's output utf-8 with `replace` before the comparison (`_read_stream_lines`), so a ref of raw 8-bit bytes is cut through the same decode, never latin-1, which writes each byte 0x80-0xFF as two UTF-8 bytes and reds a correct engine (`util_build_package_suite.py`'s beside-ref road, harness d961557d1).
- **A program is graded under the run sidecars its ref was cut under** (officer_04 2026-11-13 18:4x CST, row ipl-red-procs-ftype on junior_14's and senior_07's measurement; MEASURED on SCRIP 2b41579d6): the IPL refs were cut by the deleted IPL board, which ran each program under its NAME.pin clock-and-entropy shim (LD_PRELOAD of ipl_pin_shim.c), NAME.shims/ first on PATH, NAME.env, NAME.pty, NAME.alone, NAME.head, NAME.outfiles, NAME.mask and NAME.fixtures/ (lib_icon_ipl_isolation.sh, the one authority). The grader (corpus_suite_harness.py) stages only fixtures, so a program that reads the clock, the entropy, the host or a stand-in tool reads a false red: 31 of the 127 ipl m3 reds carry a sidecar, 16 of them a pin. progs/parens matches its ref under the pin and differs without it; procs/ftype_driver matches under its fixtures and its file stand-in. So the grader applies a program's sidecars in both modes, exactly as lib_icon_ipl_isolation.sh applies them, and the builder cuts under the same ones. One reader serves both, never a second copy that can drift. A sidecar it cannot apply refuses rc 2, never runs bare.
- **A ref is cut from the oracle, never from our output; no XFAIL.** An oracle that refuses, crashes or hangs gives NO_ORACLE_ANSWER: the program is excluded with the measurement, never counted as debt (CEO-1696/1934). A wrong exclusion costs more than a wrong cure.
- **A landed cure waiting on a reading is graded by the coo at once**, the program run through its suite's own road on a clean root, so a seat at its two-claim cap closes and takes its next row (the coo 2026-11-12).
- **A red no exclusion class fits stays red as debt**, never a new class made to hide it (the coo 2026-11-12, on officer_01's unitests unicon/list-test: SCRIP prints 8 extra FAILED lines from implementation-defined storage that no mask can delete; Lon 2026-11-11: "Keep all the test suite numbers honest").
- **Our own test case is converted, never excluded** (the coo 2026-11-13, on officer_04's rung 4 of raku hash_say_replace_2; Lon 2026-11-12: "We want of course to keep test cases."): a rung or gate case the oracle refuses only because it calls names SCRIP invented is rewritten in the oracle's own forms, keeping its intent, and its ref is cut from the oracle; `NO_ORACLE_ANSWER` is for a program we did not write. A case whose answer reads mutable state, such as a listing of its own package folder, reads a fixed fixture instead and is re-cut there (the coo 2026-11-13, on junior_11's measurement of the icon open_directory cases: the ref drifted from 334 entries to 347 as the folder grew, and SCRIP equalled the oracle).
- **The denominator identity**: PASS + FAIL + every named exclusion class equals the population the tree ships; no board prints a pass count whose denominator drops programs without naming them.
- **A row exists only while a measurement says so** (CEO-1386); a test that cannot measure refuses rc 2 (CEO-1680); no planted breakage.
- **A benchmark is a test**: every kernel has a ref and is graded for correctness; its speed is an instruction count (skill `speed-measurement`).
- **The masters carry no `.s`**; tests carry no artifacts (CEO-16).

## 9. THE GRADER IS A MOVING SANDBOX (Lon 2026-11-12 18:0x-19:2x CST; the grader builds it, row `cycle-greased-lightning-grader`)

Lon, verbatim: "The test-suite cycle runner better be GREASED LIGHTING. Each unit of work should be very small relative so that many requests from seats can go through FAST." / "You do not have to report a test suite ALL at ONCE. you report each chunk at it comes, and each chunk is bite-size regardless of which suite it came from. You can then report two date/time stampes, the earliest , and the latest most recent. Do not show the run range anymore. The source base will move forward with all checked-in repo fixes on each turn. one chunk updates. rinse. repeat. THEN, when a request for a quick APPROVAL comes in, you take your base apply the one change for each seat that is asking for special BASE+SPECIAL checks. THEN Rinse and Repeat. This waiting around is GOING to STOP!!!" / "So the GRADER is a SAND BOX that keeps moving forward with the latest that and seat can check against, and the SCORE keeps ALWAYS moving forward. up and down like a YO YO." / "seats ae asking before they push, not after."

- **No lap is a unit and nothing waits for one.** The score moves with every chunk, up or down; a row is never frozen until a suite or a lap finishes.
- **Every chunk reports at once** (LANDED, harness 887b8a727): a cell that graded (rc 0 or 1) rewrites its suite's row from the progress store the moment it ends, in the background, one lock a suite; a cell at rc 2 writes nothing. A row shows two stamps, **Earliest** and **Latest** (the box-clock MM-DD HH:MM of its oldest and newest reading), never a run range (`run_stamps` in `util_suite_banner.py`, the compact banner too).
