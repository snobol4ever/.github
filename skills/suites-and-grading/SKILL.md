# Suites and grading

The coo is the ONE testing officer (CEO-1342 as amended): it runs the suites, the boards, the blocking set and the `.s` regeneration, and alone writes suite rows. A lander grades ONE program in both modes and runs the feature reps and smokes; it asks for anything more by test request. Detail is in `reference.md` beside this file.

## 1. The populations

- **The masters**: `corpus/tests/<lang>/` holds one flat container per language: `ALL.<ext>` (every entry, a CONTAINER, never a program), `ALL.ref` (each entry's ref, cut from the oracle; binary to git), `ALL.csv` (the index: entry, feature columns, declared sizes, `compile_args`, `oracle_args`), `PARTITION.tsv`, and `config/LADDER.tsv` for the construct ladder. The one extraction authority is `corpus_suite_harness.py extract MASTER REF NAME OUT`.
- **The packages**: `corpus/packages/<lang>/<pkg>/` (vendored suites with their own tables, `EXCLUDED.tsv` with a reason per row, runners `harness/scripts/test_<lang>_<pkg>_suite.sh` taking `S4E_CHUNK=entry:<name>`).
- **Demos and benchmarks**: `corpus/demos/`, `corpus/benchmarks/` (the only trees with committed `.s`).

## 2. Grading one program (what a lander does)

```bash
python3 ../harness/scripts/corpus_suite_harness.py run ../corpus/tests/<lang>/ALL.<ext> ../corpus/tests/<lang>/ALL.ref --lang <lang> --modes m3,m4 --partition entry:<name>
S4E_CHUNK=entry:<name> bash ../harness/scripts/test_<lang>_<pkg>_suite.sh
bash ../harness/scripts/test_feature_reps.sh <lang> <feature>
bash ../harness/scripts/test_smoke_<lang>.sh
bash ../harness/scripts/s4e_test_request.sh <suite-key> <entry>...        # at most eight; the coo grades
```

`--modes m3,m4` is mandatory; the two modes may diverge and each is graded against the oracle. A program runs at its DECLARED sizes (the entry's heap and stack, CEO-1353/1281); the declared size is a hard cap and out of stack is a bigger declared `-s`, never data moved.

## 3. The record

- **The progress store** `/home/resources/progress/results.tsv`: one row per reading (`ts_utc scrip corpus measurer class suite lang program mode outcome secs note fingerprint config`). A reading on a dirty tree is unread (CEO-2060). Read it with `util_score_row.py from-progress`.
- **The suite table** `/home/resources/progress/SUITES.tsv` (`key ... today_pass today_total tree ...`), shown by `.github/SCORE.md` § THE SUITE TABLE and printed by `.github/scripts/util_suite_banner.py` (the textual banner, verbatim, when Lon asks).
- **Stored partitions** (CEO-1676): `util_suite_partition.py build <ALL.csv>` writes the core (every distinctive feature covered three times), a shell per distinctive feature and chunks of at most 100 entries; `check` and `test_gate_suite_partitions_are_current.sh` refuse a table edited without its partition rebuilt. The coo's tier 2 runs the core plus the shells of the features a landing touches (`area_map.tsv`).

## 4. The rules

- **A ref is cut from the oracle, never from our output; no XFAIL.** An oracle that refuses, crashes or hangs gives NO_ORACLE_ANSWER: the program is excluded with the measurement, never counted as debt (CEO-1696/1934). A wrong exclusion costs more than a wrong cure.
- **The denominator identity**: PASS + FAIL + every named exclusion class equals the population the tree ships; no board prints a pass count whose denominator drops programs without naming them.
- **A row exists only while a measurement says so** (CEO-1386); a test that cannot measure refuses rc 2 (CEO-1680); no planted breakage.
- **A benchmark is a test**: every kernel has a ref and is graded for correctness; its speed is an instruction count (skill `speed-measurement`).
- **The masters carry no `.s`**; tests carry no artifacts (CEO-16).

## 5. DESIGN-PLAN batch-grader: the grader moves into SCRIP as `scrip --harness` (Lon 2026-11-05; the cio's plan; the SCRIP side CTO-515 as amended by CTO-522)
- **Lon's words (the cio's window, 2026-11-05, verbatim)**: 14:5x "For the test harness, you should move INTO SCRIP. - **MEASURED (the cto, 2026-11-05 17:1x, SCRIP f8f173ebb, `perf stat -e instructions:u`, `strace -f -e execve`)**: grading ONE SnoRungs entry in both modes through `corpus_suite_harness.py smoke` is 14.95 G instructions and 36 s wall, of which `util_require_fresh.sh --gate corpus_suite_harness` is 33 s (694 `stat` forks, md5sum over every tracked source, a 5.7 s `scrip --compile` of the build-behaviour witnesses) and the program is 0.37 s compile, 1.05 s gcc, under 0.1 s of running; ten entries in one launch are 17.46 G, so the marginal entry costs 0.28 G both modes and the launch 14.7 G (the cio read 19.2 G on 52f53c466). Per stage of a hello program: SNOBOL4 m3 run 8 M, `--compile` 14 M (1,066 lines), `as` 8 M, `ld` 80 M (45 M under `-fuse-ld=gold`; mold and lld are not installed), m4 run 1 M; Pascal and Raku the same shape; **Prolog m3 run 4.4 G, `--compile` 11.3 G writing 429,563 lines, `as` 4.9 G, and an EMPTY .pl costs the same (4.37 G, 428,237 lines): the Prolog prelude is parsed, lowered and emitted into every program in both modes**, which is why Logtalk m4 reads 20.8 s a case, Puzzles 74 s, XSB 34 s against SnoRungs 0.27 s (results.tsv, 2026-11-05). A `python3 -c pass` is 58 M; importing the harness module alone is 515 M. The population: 18,018 tests in two modes (BOX.state lap_tests), 913 rows an hour at grader width 4, lap ETA 7 h.
- **The switch is `scrip --harness`** (Lon's spelling; `--batch` is withdrawn, CTO-522). Two forms, one loop: `scrip --harness LIST.tsv --record FILE` (the loop's road: the list file carries what argv cannot) and `scrip --harness a.sno b.sno c.pl` (Lon's spelling: every argument after `--harness` is a program of its own, each row defaulted to stdin /dev/null, stdout and stderr beside the record under `--out DIR` or the cwd, the shipped sizes, 60 s). The polyglot reading of several files on the command line (CTO-511 (3)) applies only without `--harness`. `--compile --harness` writes every row's asm. **The list file**: one row per program, tab-separated `name source stdin stdout stderr heap_kb stack_kb timeout_s [argv...]`, an empty stdin cell is /dev/null. **The record** (one row per program, list order): `name rc kind secs maxrss_kb`, kind one of RAN HANG CRASH REFUSED; maxrss_kb is the row's ru_maxrss from wait4 (brk_kb is withdrawn: under a fork a row's brk is its own).
- **The reset between rows is a fork from a warm parent (CTO-522, amending CTO-515 (2), (3), (4))**: the image is the parent process itself and the kernel restores it by copy-on-write, exactly, every mapping and every static, with nothing to census. The parent runs no program: it reads the list, and per row forks; the child `setpgid`s, `dup2`s the row's stdin stdout stderr, applies the row's sizes as main does for one file, runs the program and leaves through the exits it has today (`exit(` sites stay as they are: deciders deleted means nothing new is added either); the parent `wait4`s with the row's `timeout_s` as its deadline (a bound, never a measurement, CEO-1912), kills the process group on the deadline and records HANG, records CRASH from WTERMSIG, RAN with WEXITSTATUS (the oracle's code: &CODE, the ball's exit_code, Icon's and Prolog's), REFUSED when the source cannot be read; secs and maxrss_kb from rusage. No sigaltstack, no handler set, no siglongjmp, no rt_exit, no /proc/self/maps: the restore-the-image design of CTO-515 (2)-(4) is withdrawn as work the kernel already does. The parent must hold no thread when it forks (libscrip_rt.so imports pthread_create for Unicon threads and the profiler; the parent runs no program, so it starts none). **The warm point**: the parent forks AFTER every per-process set-up that does not depend on the row (`rt_pin_init`, the constructors, and for Prolog the prelude load: an empty .pl costs 4.4 G today, a forked child of a prelude-warm parent pays it once per list), so a Prolog list of N rows pays the prelude once, not N times (batch-grader step 8). The kernel (CTO-512) is the OTHER switch of the same loop: the row runs in the parent with no fork, state standing.
- **The steps** (`corpus/tests/shared/batch_grader/STEPS.tsv`, `test_design_batch_grader_steps.sh --list | --step N | --cut`): 0 the baseline (cio, done); 1 `--harness` runs every row of a list in one process with its own stdin stdout stderr and writes the record (worker_09); 2 a row sees nothing of the row before: the fork reset (worker_09); 3 a fatal mid-list is that row's record and the list goes on (worker_09); 4 a hang or a crash is that row's record and the list goes on (worker_09); 5 the harness road: one `scrip --harness` per partition cell and mode, every record graded through `_grade_output`, a board byte-identical to the per-process road (cqo); 6 `--compile --harness` writes every row's asm (worker_09); 7 a SnoRungs chunk under the harness road costs less than half its per-process instructions (coo); 8 the warm point: twenty hello.pl rows under `--harness` cost under 0.6 G instructions a row (worker_09, a Prolog-engine reading first: where the prelude load sits relative to the program's parse); 9 mode 4 pays the Prolog prelude once per tree: `--compile` emits the prelude as its own asm unit, byte-identical across programs, assembled once and linked beside the program's own (the cto rules its shape in skill prolog-engine before a worker lands it). A scrip refusal of the switch reads RED, never REFUSED.

## 7. DESIGN-PLAN test-cycle: the loops redesigned for 10x (the cto, CTO-522, 2026-11-05; Lon in the cio's window 16:5x, verbatim: "We must speed up the test suite runs by 10x. Yipper skipper!!!" / "CTO is to complete redesign the test suite CYCLE loops."; the coo executes the grading steps, the cio the queue and the tick, the cqo the ledger)

**MEASURED 2026-11-05 (the cto; results.tsv, BOX.state, LOAD.tsv, the coo's GOAL-COO COO-458/466/470, `/home/claude_coo/.scratch/verifier/`)**: the cycle today is two bash loops in `s4e-grader.slice`, `loop8.sh` (1,862 lines, v19: tier 2 per landing range through area_map.tsv, tier 3 as a round robin of stored-partition chunks and package chunks, a freshness pool, a request fill, a slow lane, a landing queue, the ZSM censuses, the .s regen, the README re-render, the digests) and `tier1.sh` (240 lines: the eight smokes per landing in its own worktree), kept alive by a cron watchdog and fed by one `box_controller.sh` tick; 34,700 readings on 2026-11-05 (22,250 package, 11,836 rungs, 582 benchmark, all the coo's); 913 rows an hour at width 4 by day and 8 by night; the lap of 18,018 tests in two modes never finishes by morning (ETA 7 h at 17:07 with 14,829 fresh; the last full lap 106 h wall, COO-470); Logtalk, Puzzles and XSB took 39 of 62.7 unit-hours (four Logtalk units at 54,149 s each) and their per-case means are 20.8, 74 and 34 s in mode 4 because every Prolog program compiles the prelude (section 5); a request waited a median 59 min and the oldest 166 (box-scheduler's measurement), served one at a time; 40 package runners, 21 through the harness, 5 calling scrip directly, 14 with their own driver; one harness launch is 14.7 G instructions (33 s of freshness guard) against 0.28 G an entry. The 10x therefore has four parts, each measured: (a) the launch cost paid once per cell, not per program (v19 batching began it; `--harness` finishes it: 0.28 G an entry falls to the program's own 0.1 G when scrip is one process per cell and the link is gold); (b) the Prolog prelude paid once per list and once per tree (section 5 steps 8 and 9: 4.4 G and 16 G a program today); (c) selection: a landing grades its impact set and the night grades the lap, never a round robin by day (box-budget 3 and 4, box-scheduler 13 and 24, adopted); (d) the cycle itself as a queue with N consumers under systemd instead of a 1,862-line loop, so the width is the controller's number and nothing waits behind one slow program.

**THE DESIGN.** One grading queue, the fleet queue's tubes (skill fleet-bus section 8, beanstalkd; a second queue beside the tubes is forbidden there, so grading rides the same daemon): tube `grade`, a job is ONE CELL `suite key, cell (core | shell:F | chunk:NN | entry:a,b,...), modes, tree, requester`, priority 100 for a test request, 200 for the landing smoke (tier 1's eight smokes as one job), 500 for a landing's impact set (core plus the shells of the touched features per touched language, every language on a shared node), 900 for the nightly lap (every cell of every suite table, put at 22:00 by the tick), TTR the cell's declared budget (the sum of its rows' `timeout_s` plus the launch). The consumers are `s4e-grade-worker@N.service` (systemd --user, templated, `Restart=always`, in `s4e-grader.slice`), N instances where N is the controller's width (`box.width` today: 4 by day, 8 by night; the tick starts and stops instances, never the workers' code); each worker reserves one job, runs the cell as ONE harness launch (`corpus_suite_harness.py run ... --partition <cell>` or the package runner with `S4E_CHUNK=<cell>`), which under step 5 of section 5 is one `scrip --harness` per mode, touches the job while the cell runs, deletes it on completion, buries it with the reason on a refusal (rc 2), and writes exactly what the loop writes today: progress rows to results.tsv, the suite row through `util_score_row.py from-progress`, a request's verdict to `test_requests/done/`, SMOKE.tsv for the landing smoke, a NEW RED (a program that read PASS before and not now) as a telegram to its designer with the range (the loop's `tell_part_reds`, kept as a library function). The tick (fleet-queue steps 10-15, 60 s) does the feeding: a new origin landing puts the smoke job and the impact-set job (within 60 s of the push); 22:00 puts the lap; a request file puts its job; a suite with no reading on origin HEAD in 24 h and no job in the tube gets one (the freshness rule, bounded: the lap is the floor); the .s regeneration and the README re-render are tick members with their three-hour and once-a-lap cadence; the ZSM and ZD censuses are jobs at priority 700 per officer landing, as today. **The deep lane**: a program whose last reading took over 300 s in either mode belongs to the night only (the loop's slow lane as a selection rule, not a second loop); every table gains a `timeout_s` column (declared beside heap and stack, CEO-1353's third size) and a cell's TTR is their sum; Logtalk's units are cut to cells of at most one hour of previous readings. **The board**: `util_seat_census.py --lap` (box-budget 1) prints, beside rows_per_hour and the ETA, `instr_per_entry` (perf stat over the worker's launches, both modes, divided by its records) and `ready_age_p95` per priority band; `fleet` prints the grade tube's line. **The retirement**: loop8.sh and tier1.sh stop when steps 1-6 are green and one lap has run through the tube (step 7); their functions that live on (`prun`, `pkrun`, `tell_part_reds`, `assemble`, `fresh_plan`) move into `harness/scripts/lib_grade_cell.sh` first, each with its gate.

**THE ACCEPTANCE (step 8), measured over one working day on the ledgers**: entries graded an hour at or above ten times the recorded baseline (`corpus/tests/shared/test_cycle/BASELINE.tsv`: 913 rows an hour, 14.95 G a one-entry launch, 0.28 G a marginal entry, both modes); instructions per graded entry at or under a tenth of the launch baseline; the nightly lap done by 06:00 (box-budget 4); a request's verdict within 10 minutes at the median and 30 at p95; no minute in which the grade tube held a ready job while a worker instance sat idle; zero hand restarts of the cycle. **The steps** are `corpus/tests/shared/test_cycle/STEPS.tsv` (`test_design_test_cycle_steps.sh --list | --step N`), each a probe that reads RED until the mechanism exists: 0 the baseline recorded (cto, green today); 1 the grade tube and its job shape (cio; after fleet-queue step 1); 2 a cell is one launch, one `scrip --harness` per mode (coo; after batch-grader 5); 3 the mode-4 road links with gold (coo); 4 the templated worker units run the cells and the tick sets their count (cio); 5 the tick feeds the smoke and the impact set within 60 s of a landing and the lap at 22:00 (coo; after box-budget 3); 6 every table declares `timeout_s` and a slow program is night-only (coo); 7 the loops retired, one lap through the tube (coo); 8 the acceptance (cqo). Adopted, not duplicated: box-budget 1, 3, 4; box-scheduler 5, 13, 20, 24; fleet-queue 1, 10-15. **Forbidden**: a second grading loop beside the workers; a worker launching the harness once per program; a cell without a declared budget; a hand edit of results.tsv or SUITES.tsv; a bash loop as a daemon; a width set anywhere but the controller.
