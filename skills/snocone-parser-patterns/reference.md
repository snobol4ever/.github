## 1. The oracle and the rule: SPITBOL semantics, one closed set of patterns, the tree built once

- The parser is a Snocone program under SPITBOL semantics: `sbl -bf` runs the transpiled `.sno` twin and is its oracle for the LANGUAGE (`scrip --transpile`), except for `FLUSH`, SCRIP's own primitive (ANNOUNCEMENT, CEO-1245/1340: *"FLUSH runs all the conditional assignments up to that point INSTEAD of waiting until the end of pattern matching"*; *"For the oracle set FLUSH = FENCE pattern and all will work the same"*). The parser's own oracle is the C parser of its language: the tree it builds is graded tree-for-tree against `out/parser_<lang>` (§ 5).
- **ONE CLOSED SET.** Every pattern is a global defined ONCE by assignment at module init and referenced only through the unevaluated `*name`, so the set is mutually recursive and built before any match: `Expr1 = *Expr2 *Expr1t;` and `Expr1t = FENCE(*$'?' *Expr2 . *Reduce('TT_SCAN', 2) *Expr1t | epsilon);` (parser_snobol4.sc 120-121). A pattern never names a pattern by value (that would copy it at build time and break the recursion) and never a function the grammar calls (§ 7).
- **THE TREE IS BUILT ONCE, IN RECOGNITION ORDER, BY RAW SHIFT AND REDUCE** (Lon 2026-09-30, CEO-1377/1378: *"It is one which requires nothing more than raw Shift and Reduce calls in the PATTERN. ... You are allowed only Shift and Reduce."*): a leaf is `(pat) . thx . *Shift(kind, thx)`, an interior node `. *Reduce(kind, n[, v])` popping n children; no pass walks, reorders, rewrites or re-parents a node after it is built; the C tree converges onto the same pruned parse tree and a disagreement is settled by the rule, never by a post-process (CEO-1532).
- `&FULLSCAN = 1; &MAXLNGTH = 16777216;` (global.sc 1-2) and the alphabet captures (`&ALPHABET ? (POS(10) LEN(1) . nl);`, global.sc 7) are the library's first lines; `TRUE = 1; FALSE = 0; digits = '0123456789';` follow.

## 5. The suites, the gates and how one parser is proved

- **THE SHAPE OF A PARSER** (each quoted from its file): the whole file is ONE match of `Compiland`:
  - `Compiland = epsilon . *PushCounter() POS(0) ARBNO(*Command FLUSH) *EndStmt . *IncCounter() (ANY(' ' CHAR(9) CHAR(10) ';') | RPOS(0)) ARB RPOS(0) . *Reduce('Parse', nTop()) . *PopCounter();` (parser_snobol4.sc 282-285)
  - `Compiland = epsilon . *PushCounter() POS(0) ARBNO(*Command FLUSH) RPOS(0) . *Reduce('Parse', nTop()) . *PopCounter();` (parser_rebus.sc 263); snocone 260 the same with `*$' '` before `RPOS(0)`
  - `Compiland = epsilon . *PushCounter() POS(0) ARBNO( FENCE(*$' ' *top_form . *IncCounter()) FLUSH ) *$' ' RPOS(0) . *Reduce('Parse', nTop()) . *PopCounter();` (parser_prolog.sc 450-453); raku 497-500 with `*top_stmt`
  - `Compiland = ( epsilon . *PushCounter() POS(0) *$' ' *TopStar RPOS(0) . *Reduce('Parse', nTop()) . *PopCounter() );` (parser_icon.sc 517-521)
  - `Compiland = epsilon . *PushCounter() POS(0) *$' ' ( *UnitBody | *program_head *Block . *IncCounter() ) *$' ' FENCE(*$'.' REM | epsilon) *$' ' RPOS(0) epsilon . *PasStamp() . *Reduce('Parse', nTop()) . *PopCounter();` (parser_pascal.sc 759-761)
  The text is matched ONCE from `POS(0)` to `RPOS(0)`; `ARBNO(*Command FLUSH)` consumes the file command by command, `FLUSH` after each replaying that command's queued actions so the match's memory stays linear over a whole corpus (the reason FLUSH exists); the `ARB RPOS(0)` tail lets the trailing white space be consumed.
- **THE TREE BY CONDITIONAL ASSIGNMENT.** `.` is DEFERRED: `(pat) . thx . *Shift('TT_QLIT', thx)` queues the Shift and `. *Reduce('TT_STMT', nTop())` queues the Reduce; the queue REPLAYS in queue order only after the whole match (or at the next FLUSH), so the C tree's node order IS the order of the Reduces and a global written during the match holds its LAST value by replay time. `$` is IMMEDIATE (scan time): `*Id $ tx *IDENT(tx, 'if')` (parser_icon.sc 83) tests the token as it is scanned. SnoCase needs both (parser_snobol4.sc 34-52): `((ANY('123456789') | epsilon) $ SnCaseNow . SnCase)` captures the digit twice, `SnCaseNow` at scan time for the next control line's guard and `SnCase` at replay time for every Shift that folds, *"the deferred assignments replay in source order, so each token sees the state written before it"*. A VALUE A SHIFT CARRIES IS A MEMO TABLE KEYED BY THE RAW TEXT (§ 7 correction (1): two literals `ab` and `cd` shifted as `cd cd` when a global carried them): `IcnIntFill` decodes the digits under `iik` at match time and files `IcnIV[iik] = '' iiv` (parser_icon.sc 75-79); the queued Shift reads `*Shift('TT_ILIT', IcnIV[thx])` through its own capture (81); a decoded value is a pure function of its text, equal texts share one entry, the per-parse reset clears the table; the variant that reads the global is each step's NEGATIVE CONTROL.
- **THE COUNTER STACK** for variable-arity nodes: `Stmt = epsilon . *PushCounter() FENCE((*StmtLabel) . thx . *Shift('TT_QLIT', ...) . *Reduce('TT_ATTR', 1, ':lbl') . *IncCounter() | epsilon) ... FENCE(*Goto | epsilon) . *Reduce('TT_STMT', nTop()) . *PopCounter() *$' ';` (parser_snobol4.sc 250-266): every arm that adds a child increments, and `nTop()` is read INSIDE the Reduce's argument at replay, so the count is the children actually pushed. `X_sub = epsilon . *IncCounter() (*expr | epsilon . *Reduce('TT_NUL', 0)) FENCE(*$',' *X_sub | epsilon);` (parser_rebus.sc 114) counts a list; `call_or_id = FENCE( epsilon . *PushCounter() (*Id) . thx . *Shift('TT_VAR', ...) . *IncCounter() *$'(' FENCE(*X_args | epsilon) *$')' . *Reduce('TT_FNC', nTop()) . *PopCounter() | ...)` (116-118) a call. **PushVal/PopVal** hold a value from the token that names a node to the one Reduce that builds it, when the arguments' own actions run in between: `(*Atom) . p_name *$'(' . *PushVal(p_name) *compound_args` (parser_prolog.sc 288) and `compound_args = ( epsilon . *PushCounter() FENCE(*args | epsilon) *$')' . *Reduce('TT_FNC', nTop(), PopVal()) . *PopCounter() );` (275); `op_goal` (217-223) pushes `'op'` and its three arguments then reduces with `PopVal()`.
- **ASSOCIATION AND PRECEDENCE.** Left association is a TAIL LOOP: `Expr6 = *Expr7 *Expr6t;` `Expr6t = FENCE(*$'  ' ('+' *$'  ' *Expr7 . *Reduce('TT_ADD', 2) | '-' *$'  ' *Expr7 . *Reduce('TT_SUB', 2)) *Expr6t | epsilon);` (parser_snobol4.sc 129-130): each operand reduces with the node already on the stack, then the tail recurs. Right association is RIGHT RECURSION: `Expr0 = *Expr1 FENCE(*$'=' *Expr0 . *Reduce('TT_ASSIGN', 2) | ... | epsilon);` (119) and `Expr5 = *Expr6 FENCE(*$'@' *Expr5 . *Reduce('TT_OPSYN', 2, '@') | epsilon);` (128). Precedence is the CHAIN OF LEVELS `Expr0 → Expr1 → ... → Expr14` (119-128 and on), each level naming the next through `*`.
- **TOKENS AND WHITE SPACE.** `Cont = CHAR(10) ANY('+.') FENCE(SPAN(' ' CHAR(9)) | epsilon) FENCE(*Cont | epsilon);` `White = ( SPAN(' ' CHAR(9)) FENCE(*Cont | epsilon) | *Cont );` `Gray = FENCE(*White | epsilon);` `$'  ' = White; $' ' = Gray;` (parser_snobol4.sc 83-88): `$' '` (one blank) is OPTIONAL white space and `$'  '` (two blanks) REQUIRED white space, with continuation lines inside both. Every operator is a pattern named by its spelling: `$'=' = *$'  ' '=' *$'  ';` (89), `$':=' = *$' ' ':=' *$' ';` (parser_icon.sc 155); a longest-match guard where a prefix is also an operator: `$'<' = *$' ' '<' @lt_a FENCE(ANY('-=<') | epsilon) @lt_b *EQ(lt_a, lt_b) *$' ';` (parser_icon.sc 152: two cursors around the body, the test after). A keyword is `*$' ' *Id $ tx *IDENT(tx, 'if')` (parser_icon.sc 83) or a TABLE lookup sized to its list (Lon 2026-09-29: *"use simple TABLE() lookups with exactly sized TABLE parameters"*): `FunctionsT = TABLE(123);` filled once by `kw_s = Functions; while (kw_s ? (POS(0) BREAK(' ') . kw_w ' ' REM . kw_s)) { FunctionsT[kw_w] = 1; }` and read as `Function = SPAN(...) $ tx *DIFFER(FunctionsT[REPLACE(tx, &LCASE, &UCASE)]);` (parser_snobol4.sc 53, 58, 63); a keyword that SELECTS a pattern: `kw_cmd = *$' ' *Id $ tx *DIFFER(CmdT[tx]) *CmdT[tx];` (parser_snocone.sc 249), `CmdT['begin'] = compound_cmd_rest; CmdT['if'] = if_cmd_rest;` (parser_pascal.sc 764). A dialect-conditioned keyword: `$'uses' = *$' ' *Id $ tx *IDENT(lwr(tx), 'uses') *DIFFER(dialect, 'iso') *$' ';` (parser_pascal.sc 59, the one granted global `dialect`).
- **FENCE, FLUSH, ARBNO AND ANCHORING.** `FENCE(...)` wherever a choice is final (62 in snobol4, 139 in raku): once an alternative's head matched, no backtracking into it, so a failure is the construct's own and the match reports at the construct rather than exploring every earlier alternative; `FENCE(*$'?' ... *Expr1t | epsilon)` is the tail-loop form. `FLUSH` after each Command (3 in snobol4, 1 to 3 elsewhere). `ARBNO` is SHORTEST FIRST: match-time work placed after an ARBNO'd capture and before its closing delimiter runs on every prefix (§ 7 ruling (a): one literal decoded 985 times, 1.15 s to 97 s); the form is two cursors around the body and the work after the closing quote: `"'" @iua (*csetchars) . thx . *Shift('TT_CSET', IcnUC[thx]) "'" @iub *IcnCsetFill` (parser_icon.sc 313). A NESTED MATCH THAT MUST CONSUME IS ANCHORED: `X ? (POS(0) ARBNO(P) RPOS(0))`, because `X ? ARBNO(P)` succeeds at once with zero repetitions (§ 7 correction (2); the unanchored form is the negative control). `(*IDENT(...) | *IDENT(...) | RPOS(0))` as a lookahead from the cursor leaves the text for the next statement (parser_snobol4.sc 50, 273-281).
- **THE PREPROCESS STAGE** is labelled top-level code, line-oriented, over `Src` (§ 7 step C, C1 landed): `SnoPP: if (~(Src ? *pp_find)) goto SnoMatch;` (parser_snobol4.sc 336); the directive line is REPLACED IN `Src` by the file's text and the scan restarts at that line (no recursion, no output buffer); the `$ifdef` nesting is the counter stack; `SUBSTR(S, I, 0)` is the REST of S, so a splice with an empty head never calls it; a runtime error inside a pattern action is a FAILURE of the match, the same call at top level is an error.
- **HOW A PARSER IS PROVED.** `bash harness/scripts/run_scrip_parser.sh <lang> [file]` (the library chain plus the parser, concatenated, on `./scrip`); `python3 harness/scripts/test_bootstrap_parsers.py` over every corpus source of the language in the arms `sbl` (the transpiled twin on SPITBOL), `m3`, `m4` (the twin on SCRIP), `sc3`, `sc4` (the `.sc` chain on SCRIP `--run` and `--compile`); `bash harness/scripts/test_gate_snocone_parsers_match_the_c_parsers_tree_for_tree.sh` (the C parser `out/parser_<lang>` and the `.sc` print the same tree file by file, through `tdump.sc`; `:line :lline :file :stno :src` omitted); `bash harness/scripts/test_gate_bootstrap_parse_stage_ir_identity.sh` (a parse-stage change leaves `--dump-ir` and rc, the `.loc` sequence and the asm after the slot-base normalisation identical over the module-mode programs: the module's run shifts every GVA slot, so a raw byte diff across a module change is not a finding); `python3 harness/scripts/util_parser_sc_census.py --lang <l>` (does the parser parse the population), `bash harness/scripts/util_parser_sc_grade.sh LANG LIST CDUMP` (match/diff/fail against the C dumps, smallest differing files first), `util_parser_sc_recognition.sh <lang>` (recognises everything the C parser recognises), `test_gate_bootstrap_parsers_define_no_functions.sh` (the function floors, finish 0; `--finish`), `test_gate_parser_demos_match_bootstrap.sh`. A parser is one program of its language's corpus: the lander grades the one program it cured in both modes (`SCRIP_PARSE_STAGE=sc` for the linked stage) and the coo runs the gates' sweeps.

## 6. Debugging a parser red

1. `bash harness/scripts/monitor_run.sh prog.sno --oracle` on the transpiled twin against SPITBOL when a LIBRARY or language question is suspected (the parser is a Snocone program; GOAL-SNOCONE-100's method: transpile, make it run on `sbl -bf`, then monitor SCRIP against SPITBOL); the deferred-capture defect of 2026-09-16 (a user function called inside a deferred capture target failed the match, Snocone only) was found that way and is history.
2. The tree first: `out/parser_<lang> file` against the `.sc` dump (`util_parser_sc_grade.sh` names the smallest differing file); `xTrace = 3` prints every `Shift(` and `Reduce(` as they REPLAY, `xTrace = 4` the stack and counter traffic, `xTrace = 5` the tag stacks (counter.sc, stack.sc, ShiftReduce.sc).
3. Ablate the construct to a five-line probe and a sibling that differs by one ingredient; a pattern after a queued Reduce is evaluated at MATCH time, when nothing queued has run, so a check that reads the stack top inside the match reads it empty (§ 7 ruling (b)) -- the symptom of a semantic check written as a pattern.
4. The timing instrument is the parser's own `PARSER-METRICS` line (parse_first_us, parse_us) and `util_parser_sc_census.py --timeout`; a file that takes seconds has an ARBNO prefix explosion (§ 7 (a)).
5. Only then the C-level tools: `scrip --dump-ast` of the `.sc` itself for a Snocone parse question, ASM-DIFF-FIRST of the twin within one mode, gdb last.

## 7. What a parser may not do, and the style it keeps (receipts in RULES.md and GOAL-CEO.md)

- **DEFINE NO FUNCTIONS** (CEO-1532; `test_gate_bootstrap_parsers_define_no_functions.sh`, floors snobol4 0, icon 8, pascal 48, the others 0, finish 0): a helper becomes F1 INLINE (the body at each call site), F2 PATTERN (a recognizer with conditional or immediate assignment, built once at init, its result in a memo table keyed by the raw text), F3 ACTION CHAIN (`*DIFFER(x = e)`, `*IDENT(a, b)`, `*LE(p, n)`, `*DIFFER(s ? pat)` standing where the call stood; an if/else as an alternation; nothing returned except through a global) or F4 LABELLED CODE at the top level for what runs OUTSIDE the match (the driver, the per-parse reset, the preprocess stage); a match cannot goto out and come back, so inside the grammar only F1-F3.
- **EVALUATE OR CHECK NOTHING** (D1/D2: the refusals of a value where a name is required and the constant fold are the LOWERER's, `lower_snobol4.c`): a parser never evaluates, never checks meaning, never desugars.
- **RE-ORDER NOTHING** (A PARSER MOVES NOTHING, CEO-1371): no keep-aside, no `Swap2` (parser_pascal.sc 221, the named debt E5), no post-process; where canonical order differs from source order the parser records source order and the lowerer imposes the semantics.
- **INVENT NO WRAPPER NODES** (the pruned parse tree, CEO-1369/1371): one node per rule that fires, the operator's name in the node's value, `TT_NUL` for an absent operand.
- **KEEP NO SIDE TABLE** past the tree (CEO-1322, CEO-1715): only `tree_t` crosses to lower; the position is ONE field per node, the byte offset from the cursor (`p(s) = MATCHAT()` in ShiftReduce.sc, written at Shift for a leaf and in the Reduce for an interior node), converted to `line` by the exporter; a memo table lives for one parse and is cleared at the per-parse reset.
- **SPITBOL's limits**: a string literal of at most 130 characters (a table moved into a literal is built in chunks); `SUBSTR(S, I, 0)` is the rest of S; the upper-cased reserved words (`END` is `END`); `-CASE` folding as `sbl -bf` reads it.
- **STYLE**: NAME-16 (descriptive lower-case names of at most 16 characters, spelled out, Lon 2026-08-21), the 200-column rule for `.sc` as for every source we write (CEO-1565), comments only as `/* ... */` blocks above a pattern that explain the C lexer's rule the pattern mirrors (`snobol4.l W ({WS}|{CONT})+ ...`, parser_snobol4.sc 82); the driver tail byte-identical in shape across the seven (parser_pascal.sc 763).
- **NEVER REWRITE A `parser_*.sc`** (Lon 2026-09-24: *"At most a few characters will need to be changed to fix a bug."*); a construct is added as one pattern in the closed set, proven on the tree-for-tree gate and the IR-identity gate, the function floor never rising.

## 8. DESIGN: the seven parsers linked into SCRIP as its parse stage (stage 1 of the bootstrap)

- **Lon's rulings**: the seven `parser_<lang>.sc` are added to the SCRIP executable and replace the C, bison and flex parsers (CEO-1375: "We will add these seven parsers to the SCRIP executable and replace the old C/Bison/Flex based parsers."); stage 1 of the bootstrap (CEO-1383); each parser has its own namespace, an imported library the caller's (CEO-1567); a SCRIPtix program may load three languages at once (CEO-1568).
- **The module**: native code linked in (the mode-4 assembly), one module per compiland; SNOBOL4 keeps INCLUDE (one namespace across the includes), Snocone alone gains IMPORT; the C entry `src/runtime/rt/rt_sc_module.c` runs the module's top level once (the library and the parser build their patterns) and then matches; only `tree_t` crosses to lower.
- **Zero functions** (the cto 2026-10-28; RULES.md since CEO-1532: a bootstrap parser defines NO functions; `ParseOne` goes too): every function becomes one of four forms, F1 INLINE, F2 PATTERN, F3 ACTION CHAIN, F4 LABELLED CODE. The ratchet `test_gate_bootstrap_parsers_define_no_functions.sh` (no build, floors only fall) read on 2026-11-01: snobol4, snocone, rebus, prolog and raku 0; icon 8; pascal 48. The row is `snocone-the-seven-bootstrap-parsers-define-no-functions-...` (hq_snocone).
