Measured on the oracle: `type(obj)` is `"Point3__state"`, `image(obj)` is `object Point3_1(3)`, `type(Point)` is `"procedure"`, `classname(obj)` `"Point3"`, `membernames(obj)` counts the fields plus the two reserved ones, `methodnames(obj)` names `"Point_sum"`. The book (unicon-book-large.txt 595-611): *"the compiler reserves field names s and m for internal use"*; the names `foo__state`, `foo__methods`, `foo__oprec`, `foo_bar` are reserved per class. A superclass method is reached as `self.Super.m(args)` (`uni/lib`: `self.Struct.initially(list)`, 24 and 22 uses of the form); a global hidden by a method of the same name is `::write(...)`; a package's symbol is `pkg::name` (unicon-book-large.txt 500-560: a package mangles every global of its file to `pkg__name`, `import pkg` is a link plus scope).

## 1. THE RULINGS

- **R1 THE MARKERS, AND THE ICON FALLBACK.** A file is a UNICON PROGRAM when its text, outside comments and strings, carries a DECLARATION-LEVEL `class <ident>`, `package <ident|string>` or `import <ident>` header (a line whose first token is one of the three), or the words `thread`, `critical` or `abstract` anywhere in code (zero IPL code uses: measured); in a Unicon program the eight words are reserved everywhere, as unicon reserves them. A file with NO marker is an ICON PROGRAM and the eight words are identifiers, so `progs/when.icn` and `procs/gdl2.icn` keep parsing and keep their Arizona refs (the superset keeps every Icon program running: Lon's condition for no switch). `method` and `initially` alone are never markers (they occur only inside a class, which is a marker already). The decision is the DRIVER's, made once over the whole source before the lexer runs (the driver holds the text; `icon_lex.c`'s `keywords[]` table takes the eight words under one flag the driver sets per compile, the same shape as Pascal's dialect field of `g_pascal_cenv`: a field of the parser's state struct, never a global past the driver, CEO-1838). No `--unicon` switch, no `--compat`, ever; `SCRIP_ICON_DIALECT` or any environment knob is refused.
- **R2 THE ORACLE.** `unicon_bin()` in `lib_oracle_flags.sh` (hq_icon's oracle row; `test_gate_no_bare_unicon_outside_the_accessor.sh` in the shape of the XSB gate) is the oracle of every program that carries a marker and of the UniTests package whole; a markerless Icon program's oracle stays Arizona `icont`/`iconx` (`icont_bin()`, CEO-390), and the IPL, Arizona, Jcon and IcnRungs refs do not move. One oracle per package (CEO-391's shape): UniTests refs are cut from unicon, never from a `.std` alone; a `.std` the oracle contradicts is recorded beside the ref. What unicon refuses, crashes on or hangs is `NO_ORACLE_ANSWER`. The monitor fork `unicon-mon` is built only when a bracket needs it (the Icon plug `icx` already covers the Icon-compatible arm).
- **R3 THE CLASS MODEL IS UNICON'S OWN TRANSLATION, DONE BY LOWER.** The parser builds the pruned parse tree of the class as written (a `TT_CLASS` node: name, the superclass list, the field list, the methods as procedure subtrees, the `initially` as one more method subtree with its optional parameter list; `abstract method` a method node with no body; `obj.m(args)` is the ordinary field access plus call the tree already has; `self.Super.m()` the same; `::name` a `TT_VAR` carrying a global mark; `pkg::name` a qualified name node). LOWER builds what idol.icn writes: the two records `C__state` and `C__methods` as ordinary record declarations (the record road exists: `bb_create`, `bb_field_get`), the one global `C__oprec` as a global of the PROGRAM (its standing storage, declared by the program's own class: not a runtime global, no grant needed), the constructor procedure and the per-method procedures `C_m(self, ...)` as ordinary Icon procedures, the method dispatch `obj.m(args)` as `obj.__m.m(obj, args)` (two field reads and a call: no table lookup by name at run time, the slot is resolved at lowering through the record), inheritance by copying the superclass's fields and methods into the subclass's records in Unicon's order (the subclass's own first, then each superclass's in declaration order, the first definition winning), `self.Super.m()` as `obj.__m.Super.m(obj)` through the superclass's oprec held in the methods record, `initially` chained exactly as idol.icn chains it. `type`, `image`, `copy`, `===`, `*`, `!`, `?`, field access and the record builtins read the state record and answer as unicon answers (`"C__state"`, `object C_n(k)`); `classname`, `membernames`, `methodnames`, `methods`, `oprec`, `fieldnames`, `paramnames`, `localnames`, `staticnames`, `globalnames` are leaves over the record shapes lower built (the builtin table, ARCH-BUILTIN-TABLE.md). Nothing new reaches the planner, the emitter or the collector: a class is records plus procedures. The two reserved fields and the reserved names are the program's, as unicon reserves them.
- **R4 PACKAGES, IMPORT AND LINK.** `package p` mangles every global declaration of its file (variables, procedures, records, classes and their generated names) to `p__name` at LOWER, and `p::name` names the mangled global; `import p` makes p's names visible unmangled in the importing file and LINKS the package's files; `::name` names the unmangled global (the one hidden by a method of the same name). The package's files are found by the import name as `link` finds a file today (the source's own directory, then IPATH/`library`): a file `<p>.icn`, else every `.icn` of the directory whose first declaration is `package p` (the one-file-per-package convention of the suites and of Unicon's own `uni/lib`); Unicon's compile-time package database (`uniclass.dir`) is replaced by that read, built by lower, never persisted. A class imported from a package is lowered in the importer's compile like a linked procedure. `link` keeps Icon's meaning. No file-level flag crosses lower: a package is a renaming the lowerer performs.
- **R5 THE BUILTIN FAMILIES, RANKED** (section 5 names each; the rank is the order the UniTests families and the Rosetta/IPL populations reach them): (1) the class reflection leaves (with step 2); (2) the list and string extensions Unicon broadens (`insert`, `delete`, `reverse` on lists, `sortf`, `min`, `max`, `keyword`, `Len`/`Pos`/`Rpos`/`Rtab`/`Tab` as functions over lists) and the keywords `&now`, `&errno`, `&pick`; (3) THE PATTERN TYPE: `??` matches a string against a pattern VALUE (a string is a pattern), the pattern functions `Arb Any Bal Break Breakx Fence NotAny Nspan Pos Rem Rpos Rtab Span Tab Succeed Fail Abort` and the operators `.>`, `->`, `=>`, `` ` `` (unevaluated), `.|`, `||`, `pattern_*` -- this family is SNOBOL4's pattern machine, which SCRIP already has as Byrd boxes: a Unicon pattern value is the SNOBOL4 pattern DESCR and `s ?? p` is the match box with the scanning environment of section 10 of ARCH-ICON-RTX (ruled: ONE pattern engine, the SNOBOL4 one, under a second syntax; no second matcher); (4) THE POSIX FAMILY (`stat`, `lstat`, `chdir`, `mkdir`, `rmdir`, `chmod`, `chown`, `umask`, `utime`, `truncate`, `readlink`, `symlink`, `hardlink`, `getpid`, `getppid`, `getuid`/`geteuid`/`getgid`/`getegid`, `getpw`/`getgr`/`gethost`/`getserv`, `gettimeofday`, `ctime`, `gtime`, `system`, `pipe`, `fdup`, `fcntl`, `flock`, `ioctl`, `select`, `ready`, `receive`, `send`, `trap`, `signal`, `kill`, `wait`, `fork`, `exec`, `filepair`, `sys_errstr`, `setenv`, `crypt`): leaves over libc through the one runtime, each a row of the builtin table, ranked by the 32 posix tests' use counts; `fork` and `exec` after the rest; (5) THREADS: `thread expr`, `critical mutex expr`, `mutex`, `lock`, `unlock`, `trylock`, `condvar`, `signal`, `wait`, `spawn`, `@>`, `<@`, `@>>`: on the co-expression road (a thread is a co-expression on its own pthread stack, Lon 2026-09-02) with the SysV mutex leaves; the 13 thread tests; (6) CRYPTO (30 tests: Unicon's `uni/lib` crypto classes over bignum arithmetic: a LIBRARY family that rides steps 2-4, not a builtin family); (7) LOADING AND MONITORING: `load`, `loadfunc`, `callout`, `EvGet`, `EvSend`, `eventmask`, `opmask`, `keyword`, `variable`, `istate`, `cofail`, the `udb` and `mt` families: EXCLUDED as the multiple-program monitoring of Unicon's VM (no SCRIP VM to load a second program into), named in UniTests' EXCLUDED list with the reason; (8) DATABASE (`dbopen` through `sql`, `fetch`, `dbcolumns`, ...; 9 tests, no refs): an ENVIRONMENT class, EXCLUDED unless the box's unicon was built with ODBC or SQLite (measure `unicon -features`); (9) GRAPHICS and AUDIO (`WAttrib`, `DrawCube`, `PlayAudio`, ...): EXCLUDED (CEO-1315).
- **R6 THE SYNTAX BEYOND THE WORDS.** The recursive-descent parser (`icon_parse.c`) gains: the class declaration (`class C : S1 : S2 (f1, f2)` with methods, `initially [(params)]`, `abstract method`), `package` and `import` declarations, `obj.m(args)` (field access is Icon's; the call form exists), `::name` and `pkg::name`, `??`, the pattern operators of R5 (3) under the pattern family's step, `thread`/`critical` expressions, `@>` family, `&now`/`&errno`/`&pick`, `[: expr :]` list comprehension, `const`? Each production is one tree node per rule that fires; the lexer's operator table gains the new operators; nothing is desugared in the parser (CEO-1532).

## 3. WHAT THIS PAGE FORBIDS

A switch or environment knob that selects Unicon; a marker read from a file name or a comment; a reserved word in a markerless program (the IPL's two files are the witnesses); a second pattern matcher beside the SNOBOL4 boxes; a class model that is not records plus procedures (no method table searched by name at run time, no new DESCR kind, no runtime table a program did not declare); a global the lowerer did not derive from the program's own declarations; a persisted package database; `tree_t` carrying a desugared class; a C function entering a box for dispatch; a graphics, database or monitoring program graded as debt (they are exclusions with their reason).
