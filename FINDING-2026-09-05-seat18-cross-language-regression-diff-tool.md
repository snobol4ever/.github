DESIGN: reuses `corpus_suite_harness.py run <ALL.ext> <ALL.ref> --by-modes-column --modes m3,m4 [--lang icon|prolog]` as the SOLE per-entry runner — never reimplements PASS/FAIL logic, and inherits the harness's own ast-vs-run "mirror trap" handling and rc=2 refusal (stale binary / empty suite) for free. Classifies each (mode, entry) as REGRESSION / FIXED / CHANGED / IMPROVED (stale-XFAIL-surfacing, explicitly not counted as a regression). Exit ladder: 0 clean, 1 regression found, 2 could not measure — a partial refusal aborts the WHOLE run rather than omitting the language that failed to measure, per the GOAL's central demand ("an instrument that reports the empty case as the healthy case is the exact shape this HQ was opened to stop").

`--selftest` (~60-90s): builds once, samples a small `--shard` of each master TWICE (same binary) to prove the measure→parse→diff pipeline is wired correctly without needing a real code change. Default (no flag): full real tool, full masters, both modes, auto-stash-and-rebuild or explicit `--base <ref>`, trap-guaranteed tree restoration (checkout-back happens before stash-pop when both apply, so a stash never gets popped against the wrong base).

VERIFIED (this review pass, not just the building pass): the stderr-parsing regex was checked against REAL `corpus_suite_harness.py` output (a live Prolog `--shard 1/15` run), not only synthetic fixtures — matched exactly (`FAIL ast simple_assign_11: ...` → `ast\tsimple_assign_11\tFAIL`, etc.). This matters because a broken regex would fail identically on both sides of an A/B, so `--selftest` alone cannot catch that class of bug — it only proves internal self-consistency, not correctness against the real format. Two robustness gaps found on code review and fixed: (1) `--base` given with no following value spun forever — bash's `shift N` is all-or-nothing when fewer than N positional args remain, so the arg-parsing loop never advanced past `--base`; now refuses immediately (rc=2). (2) the crash/Ctrl-C cleanup trap silently swallowed a failed `git checkout`/`stash pop` (stderr to `/dev/null`, no check) while the normal-path restoration already refused loudly on the identical failure; the trap now warns loudly too instead of leaving a confused tree with no explanation. Selftest and both refusal paths (bad `--base` ref; `--base` with no value) reconfirmed rc=0/rc=2 as expected after the fixes; `git status --porcelain` / `git rev-parse --abbrev-ref HEAD` confirmed the tree was left untouched in both refusal cases.
