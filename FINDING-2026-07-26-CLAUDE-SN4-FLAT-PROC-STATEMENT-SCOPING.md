# FINDING — SN4-FLAT-PROC: statement-level scoping, IR_SAVE_RESTORE linkage, DIVERGE→0 (s176, 2026-07-26)

## What landed
SNOBOL4 is now scoped at exactly ONE STATEMENT. DEFINE body extraction is deleted; the body statements live only in the one main graph. Each entry-label DEFINE compiles to an ENTRY-STUB blob: jmp-entry prologue (fresh MAIN-layout frame via `g_flat_frame_floor`) → `IR_SAVE_RESTORE` role-3 WIRE-ADOPT → `IR_GOTO_DEFERRED` resolving the entry label AT CALL TIME through the same registry `rt_goto_transfer` serves (SPITBOL manual Ch.19 DEFINE: entry resolution is a call-time fact). RETURN/FRETURN/NRETURN are program-wide FLOATER BBs (`IR_SAVE_RESTORE` roles 1/2; NRETURN keeps its SNO$NRET pre-chain) registered under the reserved labels, so any goto — direct or `$`-computed — returns from any depth. Floaters PEEK the open activation's wire quad (`rt_flat_ret_snap`), restore rsp/rbp, and jmp the port wire; the pop + pushdown-restore + result protocol (manual Ch.8) executes unchanged in the existing `c_rt_proc_call_epilogue_γ/ω` leaves the wires land on — the peek-not-pop split is what makes a double-pop structurally impossible. The wire quad rides a PARALLEL `g_pcall_wires` array because `rtx_call.S` bakes `sizeof(rt_pcall_t)==64` (stride `shl 6`); growing the record would have sheared that assembly silently. Level-0 `:(RETURN)` routes through `core_runtime_error(18, "Return from level zero")` — trappable, oracle-consistent.

## Three defects found and fixed en route
1. **ZLS label-span grants** (`zeta_storage.c`). The optimizer's GOTO-fold deletes label anchors with no static in-edge — exactly the flat function bodies — so s174's wiring-root repair had nothing to root and body spans went ungranted (`drive_value_slot` FATAL, IR_COERCE_STRING). Fix: root every labeled span using the group marks the lowerer already records. Diet preserved for unlabeled/static code.
2. **Enterable-set emission** (mode 4). The old regime never emitted main's copies of function bodies (dead code; the extracted graphs did the work), and mode 4's chain BFS had no roots for label-only-reachable chains. Fix: `zls_group_mark_anchor` captures each label's anchor BY POINTER at lower time (orphan-proof against the fold); `codegen_flat_chain_body` seeds those anchors as BFS roots. Mode 4 now emits the same runtime-enterable set mode 3 pulls lazily through the label registry. **This is what fixed the long-standing 214/215/216_indirect_goto* + 213_indirect_name divergences — DIVERGE is now 0.**
3. **α-binding bug** (`scrip.c:883`). The m4 text loop passed the graph `->entry` instead of `bb_proc_entry(...)`, binding `proc_LBL__<x>_α` at MAIN'S FIRST STATEMENT; a call's transfer then re-ran the whole program inside itself → recursion SEGV (m4 collapsed to 284/28 mid-session). One line to the canonical fallback loop 1513 already used.
