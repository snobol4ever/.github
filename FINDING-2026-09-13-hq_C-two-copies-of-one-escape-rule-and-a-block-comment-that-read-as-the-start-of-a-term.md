# FINDING 2026-09-13 (hq_C) — two copies of one escape rule, and a bracketed comment that read as the start of a term (CEO-650)

**Claim.** The Logtalk ISO **syntax family** — `atoms` `comments` `double_quoted_terms` `numbers` `case_variables` `escape_sequences` — read 64 FAIL per mode of 111 cases on origin `520a07361`, and 40 of those 64 were four defects in `read/1`'s own text handling plus one defect in the shared harness. None was in the construct each case was written to test. Cured at SCRIP `8749641d7`: family 24 FAIL per mode, four of the six groups at FAIL=0, whole `logtalk_iso` 1752/3617 both-modes → 1797/3617.

**Measured.** Baseline on origin `520a07361` **clean** (stash, rebuild, grade), cured arm on the same tree plus the one change. `bash scripts/util_logtalk_family_done.sh atoms case_variables comments double_quoted_terms escape_sequences numbers`: `atoms` 8→17/17, `comments` 4→7/7, `double_quoted_terms` 3→20/20, `numbers` 32→43/43; `case_variables` 0/12 and `escape_sequences` 0/12 unmoved and named below.

**The control arm is per-case, and the obvious way to compute it is wrong.** `util_logtalk_grade.py` writes one row per case per mode to `/tmp/logtalk_progress_rows.tsv`. Joining before and after on `group:name|mode` reported **12 PASS→FAIL regressions**. There are none. The suite carries **duplicate `group:name` keys** — the `:- if/elif/else/endif` pairs (`op_3` 10/20/21, `format_2`, `format_3`, `nl_1`, `bagof_3` 09, `setof_3` 11, `discontiguous_1`), where the same case name appears twice with contradictory expectations — so `join` cross-pairs the two rows and manufactures a transition out of two files that are byte-identical on those lines. ⭐ **The artifact is indistinguishable from the real thing it imitates**: it names real cases, in the right groups, with a plausible count, and it appears only in the direction that blocks a landing. The row order in that file is the runner's own enumeration and is stable across runs, so the sound diff is **positional**: `paste <(cut -f4,5,6 before.tsv) <(cut -f6 after.tsv) | awk -F'\t' '$3!=$4'`. Positionally: **90 rows moved, all 90 FAIL→PASS, zero PASS→anything** (CEO-589).

**Cause 1 — a bracketed comment is layout, and `read/1` had its own scanner that did not know it.** `pl_read_term_text` (`by_name_dispatch.c`) pre-scans the stream for one term's text before handing it to the parser. It skipped spaces and `%` comments, and nothing else: a file holding only `/* abc */` therefore looked like a term that ran out, and `read/1` threw `syntax_error(end_of_file)` where ISO 6.4.1 says the term read is `end_of_file`. The parser's own `skip_ws` had handled bracketed comments correctly since forever — the pre-scanner is a **second, partial copy of the lexer's layout rule**, and only the copy was wrong.

**Cause 2 — the same escape rule, written twice, wrong in both.** ISO 6.4.2.1 closes the octal and hex escapes with a backslash and makes every other form exactly one character. Both `pl_read_term_text` and `pl_text_is_unbalanced` instead scanned forward to *a backslash or a letter*, so `0'\'` (the character code of a quote) consumed the rest of the file. ⭐ **Two copies of one rule is worse than one wrong copy**: `pl_text_is_unbalanced` is a veto that runs before the parse, so curing the scanner alone left the witness red with a *different* message, and the natural reading of "I fixed it and nothing changed" is that the diagnosis was wrong — not that there is a second gate downstream (see `a-cure-in-one-of-two-duplicate-spellings-changes-nothing`).

**Cause 3 — an end-token test that reads a byte whose owner it cannot see.** `.` ends a term unless the byte before it is a graphic char (so `=..` stays one token). In `0'\\.` that byte is a backslash **belonging to an escape**, so the term never ended. Cured by carrying "the last thing I read was a literal" forward, rather than by re-reading the buffer — a byte cannot tell you which token it came from.

**Cause 4 — accepted tokens the standard rejects, each silently given the value the author meant.** `\128\` read as octal `12` followed by the text `8\`; `0b101020` read as `0b1010` with the rejected tail left on the stream to break the *next* token; `1e33` lexed as a float, though ISO 6.4.5 hangs the exponent off the **fraction**, so `1e33` is the integer 1 followed by the name `e33`. ⭐ Every one of these fails by **printing a plausible answer**, and in the `1e33` case the answer is exactly the one the programmer wanted — which is why an over-permissive lexer survives a corpus indefinitely. `\s` (32) and `\d` (127) are the two extensions the suite names; a raw newline or tab inside a quoted token is now a syntax error.

**Cause 5 — the `double_quotes` flag was stored and never read.** `set_prolog_flag(double_quotes, chars|codes)` wrote into the flag table; nothing consulted it, and every double-quoted token became an atom. The shape is now built in `prolog_parse.c` at the point where the token is still known to be double-quoted — a quoted atom spelling the same text must **not** become a list, so it cannot be decided downstream on `TT_QLIT` — and the parser asks the runtime through a new `rt_pl_double_quotes_mode()` rather than keeping a second copy of the value. (Two places that can disagree about one flag is Cause 2 again.) A doubled `""` inside a double-quoted token now means one `"`.

**Cause 6 — the shared harness, and it could only ever produce reds.** `lib_logtalk_lgtunit.pl`'s `lgt_atom_to_file` wrote a **list** argument with `write/2`, so `set_text_input(['(  a', '; b', ').'])` put the literal text `[(  a,; b,).]` on the stream and the case reported a syntax error **about its own subject**. A list is now written piece by piece. Two cases settle the semantics independently of any manual: `double_quoted_terms` 01–06 spell a parenthesised disjunction one line per element, and `atoms` 17 spells `'enchanted evening'` as a list whose middle elements are a backslash and a newline. hq_R was told by telegram, same file, same sitting.

**Named, not cured.** `unicode/case_variables` 0/12 and `unicode/escape_sequences` 0/12 — the whole remaining family. Three parts: code points where the engine counts bytes (`atom_length('αβγ')` answers 6); `\uXXXX` / `\UXXXXXXXX` unimplemented; and **`write(Alias, Term)` — writing by a stream's alias atom rather than its handle — exits rc=1 with no output and no ball**, while `write(S, Term)` on the same stream is fine. The last is hq_R's stream lane (MODE line 2) and is an ASK to the cto, not a landing here; it blocks 6 of 12 `case_variables` and 2 of 12 `escape_sequences` on its own, because every unicode case opens with `^^set_text_output(st_o, '', [encoding('UTF-8')])`.

**The mint lesson.** This row's DONE-WHEN names `directives` **twice**, and `directives` is not a group — it is a *parent directory* whose children are the groups. `util_logtalk_family_done.sh` REFUSES rc=2 on it, so the criterion cannot exit 0 however perfect the cure. ⭐ It read as **green** in the mint's own measurement (`directives=0 directives=0`) for exactly the reason it refuses here: **a name that matches no file has no failures**, and zero failures is the shape of success. A group list is a set of names that must be *proven to resolve*, not a set of names that produced no complaints.
