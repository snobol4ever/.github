## The design: a key registry in dynamic cell 0

Cell 0 is reserved by the parser's own mark scan (`pl_dyn_mark("$db_registry", 0)` before any program mark), so it exists in every program and every mode. At program start `main` runs one `$db_bind(k, Name, Arity)` per compile-time cell -- the registry then knows every predicate the compiler named -- and `rt_pl_db_get_by_key(root, key, create)` answers a compile-time cell, an off-root store created earlier at run time, or (on `create`) a fresh off-root store for a predicate the compiler never saw. The `_t` leaves (`$db_assertz_t`, `$db_asserta_t`, `$db_n_t`, `$db_at_t`, `$db_erase_t`, `$db_abolish_t`, `$db_retractall_t`) take the TERM and derive the key from its head; `pl_db_enum` with `k < 0` is the same three boxes as the compile-time enumerator over those leaves. One guard leaf, `$db_t_guard(Term, Op)`, raises the ISO terms first: instantiation_error, type_error(callable, H | B) (the body walked for a number in goal position), permission_error(modify, static_procedure, PI) or (access, private_procedure, PI) when the key is a control construct (`pl_control_names.h`, ONE list included by the lowerer and the runtime), a registered procedure that the registry does not know as dynamic, and abolish's type_error(predicate_indicator | atom | integer), domain_error(not_less_than_zero), representation_error(max_arity). The guard runs for compile-time heads too whenever the clause body carries a variable, so `asserta((foo :- F))` with `F = 4` raises type_error(callable, 4) instead of storing a number as a goal.

## Three things the design uncovered

1. **A predicate created at run time was unreachable by name.** `pl_runtime_define_pred` set the generator/jmpentry flags BEFORE `rt_proc_set_fn`, and every setter is a no-op on a key the registry has never seen -- so the recompiled `qq/1` existed as a function pointer with no hash entry and `call(qq(B))` raised existence_error. Now the key is registered (with its arity) before the flags. And an ABOLISHED predicate stayed callable through its stale compiled clauses: `rt_pl_db_abolish` now redefines the predicate as one clause that throws existence_error(procedure, PI), which is ISO's answer.
2. **Seeding the file clauses of dynamic predicates eagerly from `main` blew the root frame.** Each seeded clause term is renumbered from a 4096 base (256 apart, so the lazy per-site seeds never collide with user slots), and a Logtalk case with 14 file clauses gave `main` 4113 slots and `rt_icn_zframe_args_install` wrote past the frame (rc=-11 on all 65 cases of five groups). The seeds now live in their own `$db_seed/0` graph, renumbered from slot 0 (17 slots for that case), called once from `main` before any directive.
3. **`$fc/3` was compiled to its own existence_error.** The helper that splits a meta-called conjunction is emitted BEFORE it is registered, so its recursive calls `$fc(A, PA, QA)` went through `pl_user_call`'s unknown-predicate path -- a `$existence_error` leaf. Every meta-call of `','(G1, G2)` whose G1 was itself a conjunction raised existence_error('$fc'/3) (pre-existing: cut_0 cases 09 and 18, and `findall(X, (G = ((X=1;X=2), !), call(G)), L)`). Unknown predicates now lower to a run-time meta-call (`pl_meta_call_dyn`), which is also what a call to a predicate that assert will create needs; `$fc/3` itself is pre-registered so its recursion stays a staged call -- and that matters, because routing the helper's recursion through IR_CALL_VALUE grew three wrapper frames (2464->2784, 896->1168, 3008->3328 bytes) and, with those sizes, ONE program shape exited 1 in mode 4 (`main :- (compound(foo(1, 2)) -> write(yes) ; write(no)), nl.` -- identical `main` asm in both builds, `yes` printed, then main conceded; renaming `foo`, dropping `nl`, or appending a goal made it pass). That is a latent frame-size defect in the mode-4 root/wrapper layout, not cured here, filed by this paragraph with its reproduction: lower `$fc`'s recursion through the meta-call path and run the program in mode 4.
