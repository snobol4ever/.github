# FINDING 2026-08-30 seat16 — icon-nlocals-zero-when-snobol4-precedes-in-polyglot-compile FIXED: Icon procedures now register their IMPLICIT locals (assign-without-declare), scoped entirely to Icon's own namespaces. demo05/fib.scrip and the row's own 4-way table now pass; Icon rung watermark re-measured against a zero-touch stash baseline and confirmed byte-identical (259/9/1/28/297) — zero regression.

## ROOT CAUSE (seat02's own framing, confirmed)
`graph_has_local()` only ever checked `g->pnames`/`g->lnames`, which `lower_icon_proc`/`lower_icon_stage2` populated from formal params and EXPLICIT `local` declarations only. Icon's actual scoping default — verified against the canonical source before writing any code (`refs/icon-master/src/icont/lsym.c:173-190`, `putlocal`'s "implicit local" fallback) — is that any bare identifier reference in a procedure body that is not a param/explicit-local/static and not a known global/proc/record/builtin name defaults to being an ordinary LOCAL. SCRIP never populated this class at all, so `zeta_storage.c`'s vslot builder (and every other `graph_has_local` call site in `emit.cpp`) treated an Icon implicit local as a GLOBAL the moment `is_global()` happened to be true for that text name — which happens whenever a co-compiled SNOBOL4/Pascal/Raku section registers a variable of the same name anywhere in the polyglot unit, since `global_register()` is a single shared cross-language table.

## THE FIX (`src/lower/lower_icon.c`)
Two new functions, both scoped deliberately to Icon's OWN namespaces and never to the shared `is_global()`:
- `icn_collect_own_globals()` — scans `prog`'s top-level `TT_GLOBAL` declarations directly from the AST.
- `icn_collect_implicit_locals()` — recursively walks a procedure body collecting `TT_VAR` references, excluding a caller-supplied name list plus anything `icn_builtin_is_known()`/`dat_find_type()` recognize.

`lower_icon_stage2` builds the per-procedure exclusion set (own globals ∪ params ∪ explicit locals ∪ this program's own procedure names ∪ mangled statics/INITFLAGs) and feeds the result into `g->lnames`/`g->nlocals` alongside the pre-existing explicit-locals list.

## TWO REGRESSIONS FOUND AND FIXED DURING VERIFICATION, NOT JUST THE FIRST DRAFT
This was NOT a one-shot fix — measuring against a real zero-touch baseline (`git stash`, rebuild, re-run) is what caught both of these; neither was visible from the umbrella/child rows' own targeted repros alone:

1. **Procedure names used as first-class values** (`plist := [3, p0, p1]`, `rung37_proc_lookup`): my first draft only excluded params/explicit-locals/own-globals, not Icon's OTHER procedure names — a bare `p0` got wrongly adopted as an implicit local of `main`. Fixed by adding `g_stage2.proc_table[]`'s names to the exclusion set (Icon's own proc namespace is pre-registered as global in canonical Icon too, `tsym.c:101`).
2. **`initial`/`static` synthesized flag variables** (`rung25_global`, `rung21_global_initial` — 3 of their sub-cases each): `icn_statics_prepass` mints mangled globals on the fly (`pname__STATIC__name`, `pname__INITFLAG__N`) with **no corresponding `TT_GLOBAL` AST node** — `icn_collect_own_globals`'s scan structurally cannot see them. My first draft tried to re-derive the INITFLAG names by re-scanning the body for `TT_INITIAL`, but by the time that scan runs the tree has already been rewritten (`TT_INITIAL` → `TT_IF`) by the earlier `icn_statics_prepass` call, so the re-scan silently found nothing. Fixed by capturing the names AT MINT TIME: `icn_statics_prepass` now pushes each synthesized name into a shared static-scratch vector (`g_icn_synth_excl`, same pattern this file already uses for `pnv`/`lnv`), reset per-procedure by `lower_icon_proc`, read back by `lower_icon_stage2` right after `lower_icon_body` returns for that same proc.
