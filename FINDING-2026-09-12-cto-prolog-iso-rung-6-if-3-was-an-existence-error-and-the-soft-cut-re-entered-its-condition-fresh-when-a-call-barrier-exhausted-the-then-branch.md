# FINDING 2026-09-12 (cto, CEO-617/650 lane: THE PROLOG ISO LADDER, rung 6) — if/3 was an existence_error, and the soft cut re-entered its condition fresh when a call/1 barrier exhausted the then-branch

**Claim.** After SCRIP `c2a902ed8`, the soft-cut predicate `if/3` (Logtalk `control/if_3`; SICStus/YAP/ECLiPSe/Ciao `if(:C,:T,:E)`) is `(call(C) *-> call(T) ; call(E))`: the condition is opaque to cut (`if((!,fail),true,fail)` fails into its caller's next clause), every solution of the condition drives the then-branch, the else-branch runs only when the condition has none, and a non-callable in any arm raises `type_error(callable, Arm)` — as a compile-time body goal and as a term built at run time and reaching `call/1`. A program that defines its own `if/3` keeps it. And the shared soft cut is fixed underneath: `(a(X) *-> call(b(Y)) ; E)` with a nondeterministic then-branch entered through `call/1` yielded `1-6 1-6 1-6 …` forever (a stack overflow under `findall/3`); it now enumerates the nine pairs. Logtalk `if_3` 1→12/12 in both modes; the other eleven control groups, `call_1`, `findall_3`, `once_1`, `forall_2`, `not_1` unchanged.

**How it was found.** CTO-36's NEXT kept control constructs and exceptions for the cto. A per-group read of the twelve Logtalk control groups on the clean origin build `43638b186` put 23 reds on the table; eleven were one class — `if_3_01…11: existence_error(procedure, if/3)` — the largest single red in the lane. The gate was written and proven red first (4 red of 5 arms). The first cure (inline lowering + run-time wrapper) took `if_3` to 11/12; the survivor `if_3_05` (`findall(X-Y, if(a(X), b(Y), c(_)), L)`) overflowed the stack. Six isolating probes split it: `(a(X) *-> b(Y) ; c(_))` fine, `(call(a(X)) *-> b(Y) ; c(_))` fine, `(a(X) *-> call(b(Y)) ; c(_))` overflow — the defect was the then-branch, not `if/3`. ASM-DIFF-FIRST on `--dump-ir` of the working and failing shapes showed one new node: the call/1 barrier `GOTO γ=7 ω=7` whose γ edge landed on `a/1` (node 7, the condition's redo point) UNMARKED, where the working shape's `b/1` had its ω edge to node 7 marked β.

**Where it was.** Two sites in `src/lower/lower_prolog.c`. (1) `goal()` had no case for `if/3`, and the run-time wrapper block minted `,/2 ;/2 ->/2 *->/2` and `$fc/3` but no `if/3`, so both the compile-time body goal and the run-time term fell to the unknown-predicate wrapper and `$pl_declared` raised. (2) `pl_lower_softcut` lowers its then-branch conjunction with the condition's redo point `credo` as the conjunction's fail base and then `pl_mark_into(cx, before, credo, NULL, "β")` — ω edges into `credo` were marked β, γ edges were not. `pl_lower_conj` handles a call/1 barrier (an `IR_GOTO`) by rewiring its γ to the current fail point with `lc_γ_to_β` only when that point is a redo it created itself (`last_res_beta`); the base handed in from outside starts as `last_res_beta = 0`, so the barrier's γ was a plain α edge into `a/1`. Exhausting `b(Y)` therefore re-RAN `a(1)` with `X` still bound (it succeeds once), re-ran `call(b(6))` (succeeds once), and looped.

**The cure.** No new box, no interpreter, no global. (1) `goal()`: `if(C,T,E)` lowers as `pl_lower_softcut(call(C), call(T), call(E))` when the program has no clauses for `if/3` (`pl_db_owned`, `pl_file_defines`, `pl_bb_lookup("if/3")`); the wrapper block mints one clause `if(C,T,E) :- (call(C) *-> call(T) ; call(E))` under the same guard, registered like the control-construct wrappers, so a run-time `if/3` term dispatches through `rt_proc_is_registered`. (2) `pl_lower_softcut`: `pl_mark_into(cx, before, credo, "β", "β")` — a γ edge from the then-branch into the condition's redo point is always a resume (no then-branch node legitimately enters the condition's last goal fresh), so it is marked β like the ω edges. No corpus program defines an `if/3` (grepped), so the admission shadows nothing.

**Proof.** `scripts/test_gate_pl_iso_rung6_the_soft_cut_if_3_predicate.sh` (wired into `make test` and `gate_wiring.tsv`): a 26-line witness in both modes (the twelve Logtalk shapes as a program, the run-time `call(if(...))` term, the three type errors, the bare soft-cut shape under `findall/3` and under a clause), an own-`if/3` guard program, and the Logtalk `if_3` floor at 12 both modes. Red on `43638b186` (arms=5 red=4), green on `c2a902ed8` (arms=5 red=0). Rung 1–5 gates green; smokes pl 5/5 sno 7/7 icon 15/15; preflight 33/0; comment gate 0; digest gate 0/66. Prolog bench `.s` regenerated (corpus `65b8c1921`: 23 emitted, all 23 changed — every Prolog program now carries the `if/3` wrapper proc `FN__if$2F3`, which renumbers the labels; a second regen after the rebase read 23 emitted 0 changed).

**What it is not.** `predicate_property(if(_,_,_), built_in)` is not asserted (the Logtalk object-level `condition` is not evaluated by the grader; `pl_control_names.h` is name-keyed across arities and adding `if` there would classify a user's `if/1` and `if/2`). The wrapper costs every Prolog program one proc it may not call, exactly as `,/2 ;/2 ->/2 *->/2 $fc/3` already do.
