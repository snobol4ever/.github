## 3. Five C-parser defects found by the comparison and cured at the source (all in `src/parsers/raku/rk_tree.c`, the phaser half in `src/lower/lower_raku.c`)

1. **`%%` precedence.** The oracle: `raku -e 'say 1 + 2 %% 3'` prints 1, i.e. `1 + (2 %% 3)`; the C put `%%` on its own level between the junctions and the comparisons (`x_divis`), grouping `(1 + 2) %% 3`. Cure: `%%` joins `lv_mul` (index 12, `b_mul` → `TT_DIVIS`); `lv_divis` is empty. Master entry `simple_program_15` prints `yes` either way, which is why nobody saw it.
2. **Routine tails dropped their assignment.** In a sub or method whose last statement was unterminated, `@a[0] = 1`, `%h<k> = 1`, `$x.y = 1`, `$x := $y` and `$x .= foo` were lowered to the bare LHS (`RETURN(ARR_GET(@a, 0))`), the store silently gone; the guards `(!tail || bk == BK_BLOCK …)` in `assign_forms` excluded them. Cure: the guards are gone, `.=` goes through `stmt_plain`, and every assignment tail of a sub/method is `RETURN(<assignment>)` like any other tail value (the method `$!count = 0` tail changes from a bare `ASSIGN` to `RETURN(ASSIGN)`; `ladder__rung13_classes_private_attribute` still passes both modes).
3. **A colon-form method call dropped an assignment in its argument.** `$r.push: @sums[$x] += @x.shift` lowered to `push(ARR_GET(@sums, $x))` — the `+=` vanished (`rc-9-billion-names` depends on it). Cure: `method_call` builds a single assignment-carrying argument through `stmt_plain`.
4. **A nested index target dropped its assignment.** `@dst[$i][$j] = v` lowered to the bare `ARR_GET` (the `t0->npost == 1` test). Cure: `npost >= 1`, the store is `ARR_SET(ARR_GET(@dst, $i), $j, v)`.
5. **Phasers were placed by the parser.** `rk_phasers_place`, `rk_phaser_inline_tree` and `rk_loop_phasers` hoisted BEGIN/CHECK/INIT/ENTER/PRE to the front, dropped KEEP at mainline, desugared FIRST/NEXT/LAST into `__rk_ph_g<line>` guards — a post-process over the finished tree, the class Lon ruled out on the Icon case default. Cure: the parser emits `(TT_FNC __rk_phaser_<WORD> (TT_VAR …) <block>)` where the phaser is written (also `do`, `once`, `quietly`, `react`); `lower_raku_stage2` opens with `rk_place_phasers`, a tree pass that performs the same placement in post-order (blocks, then sub/method bodies from `v.ival`, then loops, then the program) with a per-program guard counter instead of a line number. Verified on the whole Raku master, both modes: `m3 915 pass / 14 fail / 25 xfail`, `m4 913 / 8 / 25`, identical to the coo's last board line (`44dacedfb`, board-lines/2026-09-30-coo.tsv); the first cut printed every hoisted phaser twice because the program-level loop mutated a statement's subject before its rank-4 pass, caught by `test_stmt_pfx_PRE` printing `pre` twice.

Also: `src/ir/ast_print.c` prints a node whose text value is the empty string with no value (`(TT_VAR)`), as `bootstrap/tdump.sc` must (SNOBOL4 cannot tell `""` from null); `sub a(\) {}` was the only witness (`mb-for_param_sigil`).

## 4. THE CRASH WITNESS — a compiled Snocone grammar dies in emitted code (rowed apart)

`scripts/fixtures/parser_sc/raku_nest8.raku` (eight nested `while ++$v <= 9` loops with `next if` guards; seven nested loops parse) makes the mode-4 binary of `parser_raku.sc` die: `fatal signal 11 at pc 0x3`, gdb frame 1 `n10987_match_assign_cond_bx`; the box jumps to address 3. Every collector window (16m, 64m, 2000m) and stack size (8m, 100m, 2000m) reproduces it, `SCRIP_GC_STRESS=1,3` does not change it, peak RSS is 56 MB, `g_dcf` (RT_CAS_DCF_MAX) is bound-checked, the deferred-capture island (64 MB) holds at most 401 pending entries at depth 7, and the fixed `g_sno_defer_cells[4096]` is index-guarded at both ends — so none of the known fixed limits is the cause; the writer of the bad target is unfound (a hardware watchpoint on the GOT slot the crashing box reads did not fire). `scripts/test_gate_parser_raku_sc_nest8_witness.sh` reads RED(1) while it stands and PASS(0) when the tree prints; it is not wired into the blocking set (a defect gate, fail-once proven). The earlier observation that the full 955-file run died at file 883 at any window while the file parsed alone is the same defect reached through the shared process state, which is why the grader runs one file per process.

## 5. C behaviours mirrored in the grammar rather than judged (each with the C shape the grammar now reproduces)

`X::AdHoc.new(payload => v)` is `v`; `when X::AdHoc` is `TT_NUL`; core type names (rk_core_names.h, uppercase, no `::`, not True/False/Less/Same/More/Inf/NaN/Empty/Nil) are `__rk_typeobj`; `$x ~~ Name` is `.does`; `!~~` wraps a name in `__rk_typeobj`; a scalar postfix `++` is always the `__post_N`/`__twpost_N` sequence and a prefix one a plain store; `return`/`die`/`exit` keep their first argument only, `take`/`reverse` with several wrap them in `__rk_arr`; a `for` loop as a routine's last statement is `RETURN(FOR_RANGE …)` (TT_FOR_RANGE is missing from `rk_tail_is_statement`); a block followed by more on the same line is refused (rakudo agrees: "Strange text after block"); `no`/`need`/`require`/`import` leave no statement; a regex declaration body is brace-balanced with quotes ignored; `:$name` in an argument list is `__rk_mkbool(1)`; a declared constant, enum value or sigilless name followed by ` + 1` is a term where an unknown word is a listop call (`foo + 1` is `foo(+1)`, as rakudo does).
