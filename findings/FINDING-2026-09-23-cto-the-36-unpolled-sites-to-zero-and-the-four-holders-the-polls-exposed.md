## THE FOUR HOLDERS THE NEW POLLS EXPOSED, EACH MEASURED BEFORE IT WAS CURED

1. THE BINARY MEDIUM'S CALL VENEER DESTROYED rax AT EVERY MODE-3 POLL. x86_rtcc_call's MEDIUM_BINARY arm loaded the spill block into rax for the write-back (movabs rax, block) and the call target into rax (movabs rax, ptr; call rax). A poll at a call's return therefore lost the call's result in mode 3 only: 61 of 157 credited bare sites read DIVERGING in mode 3 and WITNESSED in mode 4 on the first reading, with values arriving as zeroed strings. This is the mechanism of the ceo's bb_goto_deferred revert (7a1361373, "function return from level zero") and of the collector-off class at bb_call_value 67/70. Cure: when r11 is in the mask the veneer pushes r11, uses it as the block base, pops r11's old value into its slot, and calls through r11; the reload also bases on r11, so rax and rcx survive as they do in the text medium. Encodings verified byte-for-byte against gcc/objdump.
2. THE C POLL HANDED THE WALK AN ODD FLOOR. rt_gc_poll took the address of a char local as the floor; gc_walk_words steps 8-byte words from that floor and never aligns it, so every cell above the floor was read off-grid at every collection that fired through a poll_res or rec_* site. Cure: the floor is the caller's stack pointer, __builtin_frame_address(0) + 16, 16-aligned by construction (static-asserted at the site).
3. THE NAMED-ENTRY TRAMPOLINES PARKED THE CALLEE'S NAME POINTER RAW ON THE C STACK. rt_proc_enter_named and rt_proc_enter_frag pushed rsi (a heap string) and handed the pushed word to rt_proc_call_epilogue_named after the body; a collection inside the body slid the block, the owner's slot was fixed up, the parked copy was not, and the epilogue read "" (user_function_opsyn_8 printed empty at stress 0 with one collection, right on the control tree where the collection fires later). This is row 867's holder. Cure: the trampolines park the procedure's TABLE INDEX and the epilogue re-derives the name from the rooted, slot-fixed g_rt_gen_procs (the index road at rt_call_land_γ already did this).
4. THE ASSOCIATION TAP'S BARE POLL STOOD WHERE THE VALUE WAS ONLY IN REGISTERS. Every "OUTPUT = ..." passes through mon_var_trace_tap before the name-table store; a bare poll there collected with the DESCR in rax:rdx unrooted, which reddened several hundred SNOBOL4 pattern entries at stress 1 in both modes. Cure: poll_res at the tap.
5. A STORE OF THE SAME REGISTERS AFTER THE POLL OVERWRITES THE RELOCATED SLOT. After an arm stored rax:rdx into its mapped slot and polled, the shared tail stored rax:rdx into that slot again; the collection had relocated the slot's pointer but not the registers, so the second store put the stale pointer back (hb_pl_findall's collected list read as [[_G0|_G1]|_G2] with the collector idle on the control tree). The contract checker's four clauses do not grade a store AFTER the poll; that is a clause owed (a store of a result register into a mapped slot after a poll without a reload in between is a MEMBER).
Also rooted: every cached parameter cell pointer in the procedure table (rt_gc_root_args visited the pcells vector but not its elements).
