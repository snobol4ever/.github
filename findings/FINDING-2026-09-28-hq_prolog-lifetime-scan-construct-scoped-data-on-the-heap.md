# FINDING 2026-09-28 hq_prolog — Lon's lifetime scan: construct-scoped data on the heap, every language

**The rule** (Lon, in-chat 2026-09-28 16:3x CDT, verbatim): *"Does the memory live for a lifetime directly tied to a program construct. If so it belongs on the stack. If the lifetime lives past the scope that data was created, then it belongs on the heap."* — asked per site as his two questions: is it scoped to one invocation of a program construct, and does it live past the stack frame that existed when it was created. And: *"next time you run out of stack then change the command-line switch or the environment variable to allocate more memory to get what is needed."*

**Method.** Every allocation call in `src/` (the collected heap: `rt_gcheap_alloc`, `rt_ws_alloc_descr`, `rt_wsb_alloc`/`_realloc`, `rt_pvec_alloc`/`_realloc`, `rt_heap_strdup_c`, `rt_str_alloc`/`_dup`, `rt_*_struct_alloc`, `gv_*`, `PL_CELL_ALLOC`; the arena `ct_alloc`/`ct_grow`/`ct_strdup`; libc `malloc` family; `rt_slab_*`) triaged by `scripts/util_lifetime_triage.py` (the enclosing function is the span between the style's separator lines; the pointer is followed to RETURNED / STORED / FREED / LOCAL / PASSED, with stores into a local aggregate and raw pointers returned by static helpers split out), then every FREED, LOCAL, PASSED, STORED_LOCAL and RETURNED_PTR site read by hand (`scripts/util_lifetime_fate.py` prints a site's variable's fate). Runtime: 821 sites (the 16 allocator definitions excluded). Compiler: 447 sites.

**Correct (heap, the data escapes):** string VALUES handed to the program (64 `STRVAL(...)` sites and the like), Prolog terms (compound argument blocks, list cells, the cells a binding boxes), aggregates' element blocks, interned names, tables, streams, registered procedures — about 590 of the 821 runtime sites.
